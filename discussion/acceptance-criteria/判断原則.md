# Private 2D Rigging Lab Acceptance Criteria System Draft

## 判断原則

ある要素をACに含めるか迷った場合、次の問いで判断する。

1. それは Private Authoring-to-Viewer Prototype が成立するための本質能力か。
2. それがなければ private GUI editor / private runtime core / private viewer / validator / AI assistant の一周が成立しないか。
3. それがなければ project-defined model package として保存、再読み込み、runtime評価、validation、provenance追跡が成立しないか。
4. それがなければ AI assistant が dry-run、diff、validation、repair suggestion を安全に扱えないか。
5. それは Cubism Editor、VTube Studio、既存Live2Dモデル、Cubism形式、SDK/Core の都合ではなく、独自2Dキャラクター制作結果と制作支援UXに関わる能力か。
6. それは Demo and Proposal Hygiene、すなわち自作/明示許諾素材、非互換・非提携説明、配信デモで見せる範囲、Live2Dへの機能提案境界を保てるか。

上記のいずれかに強く該当するなら、現在MVPまたはPrivate PrototypeのAC候補とする。

該当しないなら、後続の仕様、シナリオ、UI設計、便利機能、Live2D Feature Proposal、Future Public Clean Subset、将来拡張に降格する。

次は現在MVPの成功条件にしない。

- Cubism形式 import / export。
- `.cmo3`、`.moc3`、`.model3.json`、`.physics3.json`、`.motion3.json`、`.pose3.json` の検査、読み込み、解析、変換、再構築。
- Cubism SDK/Core の利用。
- 既存Cubismモデル、公式サンプル、第三者Live2Dモデル、nizima素材の利用。
- Cubism Editor UIの模倣。
- VTube Studio compatibility。
- Future SDK。
- Future integration surface。
- Future streaming app。
- OBS output。
- plugin system。
- marketplace / registry。
- public sample distribution。
- MotionSync / LipSync。
- Video Editor。

これらは、必要なら別途 track を切って再検討する。現在のRoot/MVP ACへ暗黙に戻してはいけない。
