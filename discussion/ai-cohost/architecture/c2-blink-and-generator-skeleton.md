## 1. スコープ: まばたきを当面のゴールにする(ユーザー決定 2026-07-10)

呼吸のkeyformはユーザーのモデルに未作成のため、C2の観察可能ゲート「入力ゼロで死体に見えない」は**まばたき**で立てる(まぶたのパラメータはトラッキング駆動の実績があり存在が保証されている)。ただし生成器の骨格はレパートリー拡張可能に切る——呼吸keyformが将来できたとき、生成器に振る舞いクラスを一つ足すだけで乗る形。

## 2. 体験=無(設計としての無)

「生理層は自動起動。読み込まれた身体は生きて生まれる」(Accepted済み)の帰結として、C2のユーザー体験は:

```
自律ホストの扉を開ける → Runtime Exportを読み込む → もう瞬きしている
```

設定画面・チェックボックス・ウィザードは一切挟まない。**設定が要らないことそのものが設計**である。ツマミはC3(生理プロファイル)の領分であり、C2でユーザーが相対する面は「30秒眺めて死体に見えないか判定する」ゲートの行為のみ。

C2では四層優先順位の上三層(パッケージ宣言/プロファイル補正/魂の変調)が全て不在のため、まばたきは**普遍既定値だけ**で動く。この美的ゲートは「第一段(質感)の賭け——普遍既定値でも生きて見えるか」の最初の実地検証を兼ねる。負ければC3のツマミで拾い、それでも駄目なら梯子の第二段が浮上する。

## 3. 構造判断: 生成器は意味スロットで喋る(もう一人の入力ソース)

生成器は具体パラメータIDではなく**セマンティックスロットのフレーム**(`eye.*.open` 等)を出し、既存の「意味スロット→パラメータ写像」層で解決する。

### 3.1 (i)意味スロット相乗り vs (ii)パラメータ直書き — 差は知識の置き場所

まばたきに要る知識は二種: **(A)振る舞いの知識**(いつ・どう瞬くか。モデル非依存の普遍ロジック)と**(B)身体の知識**(このモデルのまぶたはどのID・どの向き・どの範囲か。モデル依存)。(ii)では生成器が(A)(B)両方を持つ。(i)では生成器は(A)だけ持ち、(B)は既にそれを持っている写像層に限定する。(i)の保護は:

1. 生成器がモデルを知らずに済む(任意モデルで動く普遍部品=エンベロープ三分割の①振る舞いクラス。**意味スロットは①/②境界の物理的な実装位置**)。
2. 「まぶたの解決」の二重化を防ぐ(写像を直せば全駆動源が同時に恩恵を受ける)。
3. 失敗の作法が既存挙動で揃う(写像できないスロットは写像層が黙って落とす)。
4. 生成器のfixtureがモデル非依存になる(「種X→この意味スロット列」)。

逆向きの保護: 写像層は誰がフレームを作ったかを知らない。駆動源N×モデルMが掛け算にならない。C4の操縦チャネルも意味インテントで喋る予定であり、「**器に入る駆動はすべて意味スロット/インテントの層を通る**」という一貫した文法になる。

### 3.2 事実接地(リポジトリ事実。research doc参照)

- 写像層は存在し(B)を持つ: セマンティックスロット16種 → calibration/invert/strength → `createRuntimeParameterFrame()`(`live-mapping/runtime-parameter-frame.ts`)。
- 継ぎ目はソース非依存として**設計済み**: 「将来のinput source追加時はnormalized tracking frame以降を再利用する」(`tracking-input-mapping-baseline.md` §3)。相乗りは器の設計意図そのもの。
- tickはフレーム駆動(「フレームが来なければdynamicsも進まない」)→「生成器=基底フレーム源」の決定と整合。
- 現状は単一ソース前提(複数ソース合成レイヤ未実装)だが、C2の自律ホストではトラッキング不在で生成器が唯一のソースのため合成不要。合成が要るのはC5——閉問題の切り方と現実が一致。

### 3.3 未検証(C2 planning gate棚卸しの必須項目) → 検証済み(2026-07-10)

1. ~~写像機構が「頭無し」に回るか~~ → **回る**(auto-mappingはpayloadのみの純関数、UI非依存)。ただし**意味スロット値を受け取る口が未実装**という構造ギャップが発見され、頭無しリゾルバの非破壊抽出(Option B)+**トラッキング経路も同一リゾルバを呼ぶ**(知識一箇所)をユーザー裁定([../implementation/orchestration/c2-planning-inventory.md](../implementation/orchestration/c2-planning-inventory.md)、wave計画Status)。
2. ~~素の既定でまぶた写像はまともか~~ → **まとも**(`eye-blink` の defaultInvert:true/strength:1 は正しい向き。キャリブレーション依存はTrackingFrame→活性度の変換段のみで、活性度を直接出す生成器には無関係)。
3. 追加裁定: 生成器の極性=既存スロット語彙の意味論(blink活性度 0=開/1=閉)、左右同値供給、フレーム心臓=60Hz(生成器芯は「種+設定+論理時刻→スロット列」の純関数、fixtureは固定タイムステップ)。

**実装事実(C2 wave 完了、2026-07-10。リポジトリ事実)**:

- **Option B が実装された**: 頭無しリゾルバ `resolveSemanticSlotParameterValues` を新規ファイル `apps/runtime-player/src/main/live-mapping/headless-slot-resolver.ts` として非破壊抽出。`createRuntimeParameterFrame()` は「活性度計算段(TrackingFrame+calibration→slotIdごとのスカラー)→リゾルバ呼び出し」の二段構成に書き換え、**トラッキング経路も同一リゾルバを通る**(裁定1「まぶたの解決の知識を一箇所」を実現)。上記1の構造ギャップ(意味スロット値を受け取る口の不在)は、`{slotId→活性度}+slots→parameterValues` を受けるリゾルバの新設で解消。退行ゼロは等価性 golden(代表 TrackingFrame 20シナリオの完全一致)+既存 frame テスト19件の無変更全通過で機械固定。
- **生成器骨格**: `apps/runtime-player/src/main/physiology/`(Electron import ゼロ・壁時計/Math.random 非依存の純関数群)に実装。まばたき振る舞いクラス(内部スキーマ6要素・baseline×modulation・C2 は恒等 modulation)、hash-seed 決定論、レパートリー拡張点(`PhysiologyBehavior`)。決定論 fixture(固定 16ms×900frame の golden、同種同列・異種異列)で機械固定。極性 0=開/1=閉・左右同値供給を実装。
- **フレーム心臓**: `apps/runtime-player/src/main/role-composition/autonomous-frame-heart.ts`(main の 60Hz 周期タイマー、壁時計→論理時刻変換、生成器→リゾルバ→`publishFrame`、単調 sequence/timestamp、ライフサイクル)。autonomousHost composer(`input-subsystem.ts`)の中身を inert→生成器駆動へ差し替えて結線。**実行時 `if (role===...)` 分岐ゼロ**(役割差は C1 の合成テーブル一点のまま)、trackingHost composer は無変更。
- **ゲート状態**: 機械ゲート(等価性・fixture・typecheck・アプリ回帰)は green、3レーンレビュー全 PASS。§2 の手動美的ゲート(30秒眺めて死体/機械ループに見えないか)はユーザー実施待ち。

## 4. 失敗も沈黙

まぶたに写像できないモデルを読んだ場合は**黙って静止のまま**。エラーダイアログは出さない。生理は身体の内在機能であり、失敗して人間に泣きつく類のものではない。診断的な表示が必要になればC3/C4の画面の仕事。

## 5. 決定論と種

- 生成器はシード付き決定論。C2ではシードはユーザーに一切露出しない(セッション内部で決定)。
- **固定シード+fixture(「同じ種と同じ設定→同じ意味スロット列」)がC2の機械ゲートの背骨**。美的判定は人間、回帰は機械の分担。ツマミ設定値もfixture入力の一部(設定を変えても決定論は保たれる)。

## 6. ツマミ語彙の先行解剖(C3の材料。C2は普遍既定値のみ実装)

ツマミの語彙=生成器の設定スキーマ=将来パッケージへ移る②③エンベロープの語彙であるため、骨格の切り方を先に固定する(ユーザー要請 2026-07-10)。

### 6.1 内部スキーマ(生成器の設定面。全てシード付き決定論の入力)

| 系 | 要素 | 備考 |
|---|---|---|
| タイミング | 平均頻度 | 人間は毎分15〜20回。性格が一番出る |
| タイミング | 間隔のばらつき+最短不応期間 | **等間隔=メトロノーム=即死体**。生死の分かれ目 |
| タイミング | 二連瞬きの確率 | まばたきはクラスタする。たまの「ぱちぱち」は低コスト高効果 |
| 形状 | 閉じる速さ/開く速さ(非対称) | 人間は素早く閉じ(約100ms)ゆっくり開く(150〜300ms)。対称だと機械 |
| 形状 | 閉じ切りの保持時間 | 一瞬止まるか、触れてすぐ戻るか |
| 形状 | 閉じの深さ | 全閉が基本。半閉じは眠気・気だるさ(魂の変調が触りたがる領域) |

### 6.2 意図的にツマミにしないもの

- **左右のずれ**: 両目同時で固定。ずらすと不気味。片目だけ=ウインク=**意図**(C4のインテント語彙)であって生理ではない。
- **視線移動との連動**(サッカードに伴う瞬き): 実在する生理だが視線はC3の住人。C3で「連動カップリング」として再訪する(名前だけここに置く)。
- **イージングカーブの形**: 普遍既定でよい。露出しない。

### 6.3 露出は質感語に束ねる(C3のUI設計方針)

内部スキーマをそのままUIに並べたら工学であって質感ではない。C3の露出ツマミは質感語の少数本に束ねる——例:「頻度」「落ち着き(ばらつきの逆)」「きびきび(開閉速度)」「癖(二連確率)」。C3ゲート「ツマミで質感が変わる」はこの露出層で判定する。

### 6.4 baseline×modulation構造

全ツマミは「絶対値」ではなく**「基準値」**として定義する。四層の下三層(普遍既定→パッケージ宣言→C3プロファイル)が基準値を決め、**魂の変調は基準値への乗算**で乗る(緊張→頻度×1.5、まったり→開き速度×0.7)。スキーマを最初からこの形に切っておけば、C5で変調が来たとき接ぎ木にならない。
