## 0. 呼吸を後回しにした理由(ユーザー判断 2026-07-11)

1. トラッキング側はStage Motionがあるため、呼吸パラメータが無くても完全静止にはほぼ見えない。
2. AI側はC3で体が動くようになれば、それだけで「何かしてる感じ」が立つ。生命感は胸の上下ではなく**注意が動いていること**から来る。

よって呼吸keyformはそのうち作るとしても重要度が低い(C2 §1の骨格拡張点で将来吸収)。

## 1. 三つの現象の解剖

### 1.1 サッカード+固視(視線 `eyeball.x/y`)

目は**滑らかに動かない**。「留まる(固視、200ms〜数秒)→跳ぶ(サッカード、20〜80msの弾道的ジャンプ)→留まる」の離散列であり、連続的な漂いではない。C2のまばたきと同じ「離散イベント+エンベロープ」の文法で書ける。固視の構造は二つの分布:

- **着地点分布(どこに留まるか)**: カメラ(=視聴者)がホームで支配的。たまに脇(相方側)、たまに斜め上/下(考え事の目)、たまにさまよう。C3では魂が不在のため、これは**意味を持たない空間バケツの重み付き抽選**でよい——「何を見ているか」ではなく「どのへんを見がちか」(ユーザー強合意 2026-07-11)。
- **固視時間分布(どれだけ留まるか)**: 等間隔は即機械。ばらつき+最短不応期。

### 1.2 多時間軸ノイズ(頭 `face.angle.*`)

頭は静止しないが、動きは単一周波数ではない。三層:

- 速い層(1秒未満〜数秒): ごく微小な揺らぎ(姿勢維持の微調整)。
- 中間層(数秒〜十数秒): 数度規模のゆっくりした彷徨(注意の重心)。
- 遅い層(数十秒〜数分): 「中心」そのもののドリフト。

多時間軸が本質である理由: **C3ゲート「30秒眺めて機械のループに見えない」への直接の回答**。単一周波数は30秒で周期が検出される。時間軸の違う層の重ねは合成周期を知覚の外に出す——美学ではなくほぼ数学。実装意味論は**ホームへのバネ付きの滑らかな乱歩の層重ね**(単調正弦波は禁止、physiological設計§1どおり)。

### 1.3 姿勢ドリフト(体 `body.angle.*`)

二階建て:

- **常時のドリフト**: 数十秒スケールの極めて遅い重心の揺らぎ(振幅小)。
- **稀な組み替えイベント**: 数分に一回オーダーの「座り直し」——姿勢の基線そのものが別の位置へ移り、そこに留まる。

人間の姿勢の本質は「同じ姿勢を保たない、しかし常に動いてもいない」。基線ごと動く瞬間が「自分の意志で座っている」感を作る。下流の既存dynamicsが二次揺れを付けるのはC2と同じ。

## 2. 三つを貫く文法

```
ホーム(帰る場所) + 層状ノイズ(連続) + 離散イベント(跳ぶ・組み替える)
```

| 現象 | ホーム | ノイズ | イベント |
|---|---|---|---|
| 視線 | カメラ | 微小 | サッカード |
| 頭 | ドリフトする基線 | 3層 | (視線への追従=§3) |
| 体 | 組み替わる基線 | 遅い1層 | 座り直し |

C2のまばたき(イベント+エンベロープ)も同じ文法の一員。生成器骨格に足す新語彙は**「層状ノイズ」と「ホーム/バネ」の2つだけ**で、あとは振る舞いクラスの追加で済む。

## 3. 結合(単体の質より結合が生命感を売る)

バラバラに動く目・頭・体は三台の機械に見える。三つの結合:

1. **目が先、頭が後**: 大サッカード時、目は瞬時に着地し、頭が300〜700ms遅れて**途中まで**追従する(全部は向かない)。
2. **大きな視線移動に瞬きが乗る**: 大サッカードの瞬間、確率的にまばたきが同期(C2 §6.2で予約済みのカップリング)。
3. **体は頭の親**: 姿勢の組み替えは頭の基線ごと動かす(階層)。

## 4. アンチパターン集(死因の言語化)

1. **滑る視線**(目標点間のlerp) — 幽霊の目。死体より不気味。
2. **単一周波数** — 30秒でループがばれる。
3. **無結合** — 三台の機械。
4. **完全な中心回帰** — 毎回きっちり同じホームへ戻ると「リセットされる人形」。ホーム自体が微妙に揺れているのが正解。
5. **動きすぎ** — 常時ゆらゆらは「落ち着きのない機械」。**静止に句読点が打たれる**のが生きている状態。動作の総量ではない。

## 5. Stage Motion(体の存在感)の扱い(ユーザー裁定 2026-07-11)

回転だけして平行移動しない体は「回転台の胸像」に見える危険があり、Stage Motionはその平行移動+奥行きの装置。調査([../research/stage-motion-for-autonomous-idle.md](../research/stage-motion-for-autonomous-idle.md))により、純計算器 `composeRuntimePlayerStageMotionTransform` は既にhead-less(正規化-1..1入力のみ)で、生理の姿勢信号を直接供給できる(候補c。偽TrackingFrame/偽キャリブレーション不要、コスト小〜中)ことが確定。裁定:

1. **C3に同梱し無条件で実装する**(ユーザー修正 2026-07-11: 「実装はするけどon/offできるようにしておくのが望ましい。これ込みで人間がチェックする」)。ドメイン順序としては姿勢生成器の下流なので最後に置くが、実装は姿勢の美的合否に条件付けない。トグル(既定Off)を備え、**人間ゲートのチェック項目に「onにして比較する」を含める**。気に入らなければOffのまま運用(コードは残る)。
2. **設定の家は生理プロファイル側の独立ツマミ**(Stage Presence)。トラッキングホストの既存 `stageMotion.settings`(カメラ/キャリブレーション前提)には相乗りしない(意味論の濁り回避)。
3. **駆動信号は姿勢連動のみ**(body基線と同一信号→結合が構造的に保証される)。視線連動は不気味(目が跳ぶと画面位置が動く)、専用ゆらぎは無結合アンチパターンのため却下。strengthは小さく、**既定Off**。
4. 既知リスク: 同一信号の二重適用(body.angleリグ変形+Stageオフセット)による過剰運動 → strength小・既定Offで手当て。Wave12 quick toggleの実体特定はC3棚卸しへ。

## 6. ツマミとの対応(露出質感語 → 内部スキーマの素子)

露出はUX定義([../implementation/screens/c3-physiology-profile.md](../implementation/screens/c3-physiology-profile.md))の質感語。内部対応の初期案(wave計画時に精緻化):

| 質感語 | 内部素子 |
|---|---|
| Blink: Frequency / Calmness / Crispness / Quirk | C2内部スキーマ6要素への写像(平均頻度 / ばらつきの逆 / 開閉速度 / 二連確率)。**C2でUI無しだったBlinkはC3で初めて露出し、即時反映経路に載る**(棚卸し§4の指摘によりC3スコープと確定。ユーザー裁定 2026-07-11) |
| Gaze: Camera Focus | 着地点分布のホーム(カメラ)重み |
| Gaze: Restlessness | サッカード頻度+着地点の空間的広がり |
| Gaze: Dwell | 固視時間分布の中心 |
| Head: Sway | 層状ノイズの振幅(3層比は普遍既定) |
| Head: Follow | 目頭協調の追従深さ |
| Posture: Drift | 常時ドリフトの振幅 |
| Posture: Restlessness | 組み替えイベントの頻度 |
| Stage Presence: Strength | Stage transform供給の強度(既定Off) |

全てbaseline×modulation形(C2 §6.4と同一。C3ではmodulation=恒等)。イージング形状・3層の周波数比・目頭協調の遅延分布などは普遍既定で露出しない。
