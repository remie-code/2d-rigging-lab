# C6設計: 口が話せる(モーラ契約と時間仮説)

> Status: 設計方向=Accepted(ユーザー合意 2026-07-11)。閉問題C6「口が話せる」のwave化前設計討議のまとめ。
> 親設計: [c5-composition-and-envelopes.md](c5-composition-and-envelopes.md)(曲線状態機械。§6でC6の前方互換を予約済み)、[c4-control-channel-v0.md](c4-control-channel-v0.md)(additive kind追加)。
> 事実接地: [../research/runtime-player-input-integration.md](../research/runtime-player-input-integration.md) §2(凸ブレンド不変条件 Σvowel = s = mouth.open)。

## 1. スコープとゲート

- 音素タイムスタンプ列の注入で口パクが見える。**TTSは実物ではなくfixture音素列でよい**(実物TTSはS系列=魂の仕事)。
- ゲート: 機械=タイムライン再生の決定論fixture+凸不変条件+C5曲線機構への相乗り検証。人間=一目(§5の比較法)。

## 2. 契約: モーラ単位(案c。ユーザー裁定 2026-07-11)

新kind(例: `intent.speech`)のpayloadは**モーラ単位の (時刻, 母音1個, 開き強度) の列**:

```json
{ "timeline": [ { "timeMs": 0, "vowel": "o", "s": 0.6 }, { "timeMs": 140, "vowel": "a", "s": 0.8 }, ... ] }
```

- **知識の置き場**: 音素→母音の写像(言語知識)は魂側(TTSを知る者)に住む。器は意味スロットの文法のまま言語中立。
- **凸ブレンド不変条件は検証ではなく構造で保証**: 器は一拍一母音の列を受け、母音間の相補的クロスフェードをC5曲線で描く。凸×凸のクロスフェードは凸。重みの列を受けて検証する形(案b)は浮動小数の脆さと「拒否はクランプしない」規律の衝突があるため不採用。
- Σ(vowelスロット) = s = mouth.open を器の合成が構成的に満たす。

## 3. 定常ブレンド問題と時間仮説(本設計の核)

### 3.1 問題(ユーザー提起 2026-07-11)

発話中の「え」の口は「え」100%の形にならない——「え」を主成分に他成分が混ざる。これは音間の遷移とは別の「ある音における最終形のブレンド」という課題。**注意: `test_data/iFaceMocap/vowels` はキャリブレーション用=各音の100%到達形であり、発話中のブレンドの証拠には使えない**(ユーザー訂正)。

### 3.2 採用: 時間仮説(想定先行)

「100%にならない」の正体は主に**時間の問題**(coarticulation=調音結合)と仮定する。口はローパス系であり、100〜150msのモーラで目標を渡り歩くと各頂点に途中までしか登れない。実装的には:

1. **attack≈モーラ長のクロスフェード**: 届く前に次の目標へ折れる=undershootが構成的に発生し、混合が時間から自然に湧く。定常ブレンド表は持たない。
2. **発話時の開き強度への普遍縮小係数**: 100%形(キャリブレーション到達形)まで開かない。

### 3.3 実測を初手にしない理由(ユーザー判断 2026-07-11)

実発話からの定常ブレンド実測は「**特定のゴール形へ変形を繰り返す口**」を作り、それ自体が機械的に見えるリスクがある(C3のアンチパターン「完全な中心回帰=リセットされる人形」と同型)。到達しないこと・揺らぐことが生きた口の条件であり、時間仮説はそれを構造で持つ。

### 3.4 梯子(負けたときの退路)

時間仮説が§5のゲートで敗れた場合のみ、実発話データの取得へ(既知フレーズの読み上げ→トラッキングフレーム記録→推定器オフライン解析。**rawトラッキングの採取路は現在の器に無く、小さな工事が挟まる**)。実測を使う場合も§3.3のリスク(固定ゴール化)への手当てを議論してから。

## 4. C5曲線機構への相乗り

- タイムライン=タイムスタンプ付き曲線目標の列。C5のスロット曲線状態機械の上で再生する(新機構を作らない。c5設計§6の前方互換の回収)。
- 発話中の口スロットはチャネルが生成器に勝つ(C5のスロット単位優先規則そのまま。生理の口は元々「静止時基本閉口・微小変化のみ」)。
- タイムライン終端・途中切断はC5のrelease機構で口が閉じる(生きた基底へ)。

## 5. 人間ゲートの方法: 実物との並置比較

**同じフレーズを、(a)ユーザー自身がトラッキングホストで発話した口と、(b)同フレーズのfixture音素列で駆動した自律ホストの口で、並べて見る。**「自然な発話中の口」の正解データは毎配信動いているユーザーの口そのものであり、比較対象が実在するゲートは強い。判定: (b)が(a)と同種の生き物に見えるか(同一である必要はない)。

## 6. スコープ外

- 実物TTS・音声出力・音声と口の同期運用(S系列)。
- 音素→母音写像(魂側。ただしfixture音素列の作成例は参照ドライバ/fixtureに含めてよい)。
- 発話の感情表現(変調の領分)。
- 実測採取路の工事(§3.4の条件付き追撃)。
