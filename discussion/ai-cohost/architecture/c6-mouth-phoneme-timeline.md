# C6設計: 口が話せる(モーラ契約と時間仮説)

> Status: 設計方向=Accepted(ユーザー合意 2026-07-11)。閉問題C6「口が話せる」のwave化前設計討議のまとめ。
> 親設計: [c5-composition-and-envelopes.md](c5-composition-and-envelopes.md)(曲線状態機械。§6でC6の前方互換を予約済み)、[c4-control-channel-v0.md](c4-control-channel-v0.md)(additive kind追加)。
> 事実接地: [../research/runtime-player-input-integration.md](../research/runtime-player-input-integration.md) §2(凸ブレンド不変条件 Σvowel = s = mouth.open)。

## 1. スコープとゲート

- 音素タイムスタンプ列の注入で口パクが見える。**TTSは実物ではなくfixture音素列でよい**(実物TTSはS系列=魂の仕事)。
- ゲート: 機械=タイムライン再生の決定論fixture+凸不変条件+C5曲線機構への相乗り検証。人間=一目(§5の比較法)。

## 2. 契約: モーラ単位(案c。ユーザー裁定 2026-07-11)

新kind(例: `intent.speech`)のpayloadは**モーラ単位の (時刻, 母音1個, 開き強度) の列**:

```json
{ "timeline": [ { "timeMs": 0, "vowel": "o", "s": 0.6 }, { "timeMs": 140, "vowel": "a", "s": 0.8 }, ... ] }
```

- **知識の置き場**: 音素→母音の写像(言語知識)は魂側(TTSを知る者)に住む。器は意味スロットの文法のまま言語中立。
- **凸ブレンド不変条件は検証ではなく構造で保証**: 器は一拍一母音の列を受け、母音間の相補的クロスフェードをC5曲線で描く。凸×凸のクロスフェードは凸。重みの列を受けて検証する形(案b)は浮動小数の脆さと「拒否はクランプしない」規律の衝突があるため不採用。
- Σ(vowelスロット) = s = mouth.open を器の合成が構成的に満たす。

## 3. 定常ブレンド問題と時間仮説(本設計の核)

### 3.1 問題(ユーザー提起 2026-07-11)

発話中の「え」の口は「え」100%の形にならない——「え」を主成分に他成分が混ざる。これは音間の遷移とは別の「ある音における最終形のブレンド」という課題。**注意: `test_data/iFaceMocap/vowels` はキャリブレーション用=各音の100%到達形であり、発話中のブレンドの証拠には使えない**(ユーザー訂正)。

### 3.2 採用: 時間仮説(想定先行)

「100%にならない」の正体は主に**時間の問題**(coarticulation=調音結合)と仮定する。口はローパス系であり、100〜150msのモーラで目標を渡り歩くと各頂点に途中までしか登れない。実装的には:

1. **attack≈モーラ長のクロスフェード**: 届く前に次の目標へ折れる=undershootが構成的に発生し、混合が時間から自然に湧く。定常ブレンド表は持たない。
2. **発話時の開き強度への普遍縮小係数**: 100%形(キャリブレーション到達形)まで開かない。

### 3.3 実測を初手にしない理由(ユーザー判断 2026-07-11)

実発話からの定常ブレンド実測は「**特定のゴール形へ変形を繰り返す口**」を作り、それ自体が機械的に見えるリスクがある(C3のアンチパターン「完全な中心回帰=リセットされる人形」と同型)。到達しないこと・揺らぐことが生きた口の条件であり、時間仮説はそれを構造で持つ。

### 3.4 梯子(負けたときの退路)

時間仮説が§5のゲートで敗れた場合のみ、実発話データの取得へ(既知フレーズの読み上げ→トラッキングフレーム記録→推定器オフライン解析。**rawトラッキングの採取路は現在の器に無く、小さな工事が挟まる**)。実測を使う場合も§3.3のリスク(固定ゴール化)への手当てを議論してから。

## 3.5 再調音ディップ(ユーザー合意 2026-07-11)

相補式(§7裁定2)だけでは**同母音連続(例:「のところど」= o×5拍)で口が凍る**(weight恒常・s同値なら完全静止)。実際の口は子音のたびに閉じて開き直す(再調音)。モーラ契約は子音を落としているため、この動きを**器側の普遍既定**で補う:

- **すべてのモーラ境界で、sに短いディップを掛ける**(モーラ頭で開き強度が一瞬〜40%程度へ沈み30〜50msで回復。子音の閉鎖ジェスチャの近似)。
- 同母音連続でも拍ごとに口が動き、異母音間の遷移も閉じ→開きの自然な経由を持つ。
- 契約は不変(魂は一拍一エントリのまま)。ディップはsへの乗算であり凸恒等(Σvowel = s = mouth.open)は無傷。
- 子音ごとの厳密な閉鎖の違い(m全閉/s半閉等)は出ないが、**トラッキングホストの駆動でもその粒度は見えない**(ユーザー判断)ため普遍ディップで足りる想定。負ければ子音情報の契約追加を議論する退路つき。

## 4. C5曲線機構への相乗り

- タイムライン=タイムスタンプ付き曲線目標の列。C5のスロット曲線状態機械の上で再生する(新機構を作らない。c5設計§6の前方互換の回収)。
- 発話中の口スロットはチャネルが生成器に勝つ(C5のスロット単位優先規則そのまま。生理の口は元々「静止時基本閉口・微小変化のみ」)。
- タイムライン終端・途中切断はC5のrelease機構で口が閉じる(生きた基底へ)。

## 5. 人間ゲートの方法: 実物との並置比較

**同じフレーズを、(a)ユーザー自身がトラッキングホストで発話した口と、(b)同フレーズのfixture音素列で駆動した自律ホストの口で、並べて見る。**「自然な発話中の口」の正解データは毎配信動いているユーザーの口そのものであり、比較対象が実在するゲートは強い。判定: (b)が(a)と同種の生き物に見えるか(同一である必要はない)。

## 6. スコープ外

- 実物TTS・音声出力・音声と口の同期運用(S系列)。
- 音素→母音写像(魂側。ただしfixture音素列の作成例は参照ドライバ/fixtureに含めてよい)。
- 発話の感情表現(変調の領分)。
- 実測採取路の工事(§3.4の条件付き追撃)。

## 7. 実装裁定(C6棚卸し後、ユーザー裁定 2026-07-11。「実際できた結果を見ないと厳密にはわからない」の留保つき=最終審は比較ゲート)

1. **載せ方=口グループ・タイムライン評価器の新設**(storeの新種エントリ。per-slot独立のC5機械では6スロット連動の相補が構造にならない。C5前方互換は外周=cadence/合成/release/契約には真、核は新規)。
2. **相補式**: 一遷移=隣接2母音のみ、単一進行度p(smoothstep)で `weight_next=p, weight_prev=1−p, 他=0`、`s=lerp(s_prev,s_next,p)`、各母音スロット値=weight×s。**Σvowel = s = mouth.open が恒等式**。
3. **調停=後着置換**: 新しい口駆動(タイムライン/個別インテント)が古い口駆動をrelease経由で置換(C5 re-attack規則のグループ拡張。新規則を発明しない)。
4. **タイムライン長上限=512モーラ**(初の可変長payload。超過は既存 `invalidPayload` で拒否——拒否語彙の不増殖)。一発話=一タイムライン。
5. **attackはpayloadに非搭載**(モーラ間隔から導出——時間仮説の帰結)。s縮小係数は普遍既定0.8前後から開始(非露出、比較ゲートで調整)。
6. 棚卸しの接地事実: 母音スロット経路はC5でenum済み・開通済み(C6で新設しない)。生理は口を産まないためrelease先=閉口が自動成立。
7. **fixtureフレーズ=「これじっさいのところどうなってるの」**(全母音+同母音連続を含む——再調音ディップの試金石。ユーザー選定)。テストモデル=ユーザー本番Runtime Export(mouth.vowel.*+mouth.open のexternal-input保有をユーザー確認済み)。

### 7.1 実装後の状況(C6実装完了、Domain C統合 2026-07-12)

§7の留保「実際できた結果を見ないと厳密にはわからない=最終審は比較ゲート」に対し、**機械ゲートは実装・検証で満たされた**(Domain A/B 合格、Domain C モノレポ検証済み):

- **凸恒等 Σvowel = s = mouth.open**: 全tick性質テスト(代表フレーズを4ms刻み全域走査)で成立。相補式が単一進行度pと単一sから代数導出し、後段補正(Σを計算して合わせる)は一切書いていない=構造保証。
- **再調音ディップ**: 「のところど」(o×5)で境界<中央・非静止を assert。相補式だけなら凍る区間が拍ごとに動く。
- **undershoot**: fastモーラの母音ピーク < slow(頂点に登り切る前に折れる混合)を assert。attackはモーラ間隔から動的導出(payload非搭載)。
- **512拒否**: timeline長 > 512 を `invalidPayload` で拒否(クランプ/切詰め禁止)。単調違反/空配列/未知vowelも `invalidPayload`、s域外は `slotValueOutOfRange`——新rejection code不増。
- **無退行**: C4/C5契約fixture・圧縮/知覚シナリオ・physiology golden・リゾルバ・トラッキング経路が無変更で通過。実行時role分岐ゼロ。

**ただし比較ゲート(§5の二体並置=「生きた発話中の口に見えるか」)は未実施——ユーザーの人間ゲート待ち**が正しい状態。機械が保証できるのは性質(凸恒等・非静止・undershoot・拒否・無退行)までで、最終審は依然として本設計§5の比較ゲート。実運用手順は [../implementation/waves/c6/c6-comparison-gate.md](../implementation/waves/c6/c6-comparison-gate.md)。

**オープン項目(Undine裁定待ち)**: 後着置換 direction(a)——発話開始時(`setSpeech`)に既存の口per-slot曲線を **delete で専有する**か **release経由で置換する**か。実装は現状 delete(口idleの常況では連続、Domain A報告§5-5の裁量)。裁定が済むまで実装は現状維持。
