# 設計方向: 会話パイプライン

> Status: Draft(2026-07-10)。ユーザーと大枠議論済みだが個別のAccepted判断はまだない。
> 根拠となる調査事実: [../research/human-ai-cohost-precedents.md](../research/human-ai-cohost-precedents.md)、[../research/aituber-landscape-2026-07.md](../research/aituber-landscape-2026-07.md)、[../research/llm-cost-estimate.md](../research/llm-cost-estimate.md)。

## 1. 全体像(Draft)

```
[ユーザーの声] → ローカルASR(常時、転写バッファへ蓄積)
                    ├→ 反射層(ローカル): ポーズ検出→相槌音声ポン出し+口形注入
                    └→ 発火判定(宛先判定/トリガ) → LLM(Opus 4.8, streaming)
                                                     → 文単位分割 → TTS(逐次) → 音声再生
                                                     → 感情タグ → 表情パラメータ注入
                                                     → 音素タイムスタンプ → 口形パラメータ注入
[視聴者コメント] → チャット取得層(差し替え可能に抽象化) → 同上のLLM経路
[AI共演者モデル] ← runtime-player 操縦チャネル(別文書)
```

基本原則: **「AIは全部聞くが、全部では考えない」**。ASRは常時回して転写を蓄積し、LLMは発話に値する瞬間だけ、蓄積した転写ごと起こされる(=起こされた時には直近の話を全部読んでいる)。

## 2. 設計方向(Draft)

### 2.1 テキストパイプライン採用(ASR→LLM→TTS)。speech-to-speech不採用

理由: キャラ声制御不可 / 実測でも大差ない遅延 / 高額 / 自前リップシンク資産(音素タイムスタンプ直駆動)と不整合 / 発話前の最終テキスト検査が効かない。詳細は research/ 参照。

**GPT-Live(2026-07-08発表)による再検証済み(2026-07-10)**: full-duplexネイティブS2Sの新世代でも不採用理由は覆らない([../research/gpt-live-impact-2026-07.md](../research/gpt-live-impact-2026-07.md))。あわせて戦略判断をAccepted: コモディティ化の線は魂の内側にあり、**魂の初版は金メッキしない**(交換可能な最小構成で実機ゲートへ)。再評価トリガは「S2S級応答+カスタム声+外部アバター同期面」の三点セットが揃った製品の出現。

### 2.2 二層設計: 相槌=反射層、意見・会話=LLM

- **反射層(ローカル、費用ゼロ)**: 人間の相槌は発話の切れ目から300〜500msの反射であり、LLM往復(2秒前後)では遅すぎる。ポーズ検出+パターン選択で事前生成済み相槌音声を即再生する。相槌に知性は要らず、タイミングが全て。日本語(ターン間隔世界最速級)では特に効く。
- **LLM層(Opus 4.8)**: 話題の区切り・名前呼び・一定時間ごと等に発火。応答は文単位ストリーミングTTSで、フィラー先出しと合わせて体感600ms〜の初動。2〜4秒の本応答遅延は配信文脈で許容範囲(成功基準Draftと連動)。
- 費用面でも同じ設計が効く(発火頻度が支配項。research/llm-cost-estimate.md)。

### 2.3 宛先判定(D6、解決 — ユーザー決定 2026-07-10)

ユーザーは常時発話するため(前提P2)、「独り言/視聴者向け/AI向け」の判別が最重要設計点。

- **初手は(a)キー操作で明示**(先例あり・事故最少)。実機ゲートを通して (b)名前呼び検出 → (c)セマンティック自動判定へ段階的に自動化する(P5)。

### 2.4 割り込み(barge-in)

ユーザーが話し始めたらAIのTTSを即停止し、「途中で遮られた」事実をLLM文脈に記録する(2026年の標準実装)。

### 2.5 音声ルーティング

Voicemeeter等の仮想オーディオでバス分離し、**TTS出力をASR入力に構成的に混ぜない**(自己聴取ループの排除)。ユーザーがイヤホンモニターならエコー対策不要。

### 2.6 安全弁

コメント・発話は信頼できない入力として扱う。**TTSに渡る直前の最終テキスト検査**+NGワード+キルスイッチ(緊急ミュート)。プラットフォームのAI利用開示設定を行う。

## 3. 候補スタック(Draft、実装着手時に再確認)

| 要素 | 第一候補 | 理由 |
|---|---|---|
| 会話LLM | Opus 4.8(API) | 前提P1。Fable 5は常時思考で会話役に不利 |
| ASR | kotoba-whisper系+VAD(ローカル) | 無料・日本語特化・準リアルタイム |
| TTS | AivisSpeech(ローカル) | 無料・高品質・**audio_queryの音素タイムスタンプで口形を決定論的に合成前構築できる** |
| 感情駆動 | インラインタグ方式 | ストリーミングと相性が良く、声と表情を同一タグで同期 |
| チャット取得 | YouTube(D4解決、ユーザーの既存配信環境) | 非公式ライブラリは壊れる前提で差し替え可能に抽象化+公式APIフォールバック |
