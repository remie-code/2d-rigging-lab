# 設計: 生理層生成器と演出エンベロープ

> Status: 意味レベル設計=Accepted(ユーザー合意 2026-07-10)。実装粒度は未着手。
> 概念上の位置付けと責務論は [../concept/behavior-model.md](../concept/behavior-model.md)(特に§6 梯子・§7 エンベロープ責務)が正。本文書はその意味レベルの具体化。

## 1. 表現レパートリー(第一段)

生成器の語彙は既存プリセットパラメータの範囲内に限る:

| 表現 | パラメータ | 生成規則(意味レベル) |
|---|---|---|
| 呼吸 | `breath` | 周期揺らぎ+深さ揺らぎ(単調正弦波にしない)。情動で速さが変わる |
| まばたき | `eye.*.open` | 離散イベント。ポアソン的間隔+たまに二連。情動で頻度が変わる |
| 視線 | `eyeball.x/y` | サッカード(跳ぶ)→固視(留まる)。固視先候補=カメラ(視聴者)/ユーザー側/所在なくさまよう。どこを見がちかは情動の関数 |
| 頭の向き | `face.angle.*` | 多時間軸ノイズ(数秒/数十秒/数分)+「聞く時に軽く傾げる」等のイベント |
| 姿勢 | `body.angle.*` | ごく遅いドリフト+稀な組み替えイベント(体の向きの非一様性) |
| 口・眉 | `mouth.form`, `brow.*` | 静止時は基本閉口、微小な緊張変化のみ。大きな開閉は生理層の仕事ではない |

パラメータが動けば髪・体の二次揺れは既存dynamicsが下流で付いてくる(生成器は上流を揺らすだけ)。

## 2. 定義の所在

- **生成の機構**(ノイズ、イベントスケジューラ、合成規則): モデル非依存の普遍的機械。決定論(シード付き乱数)でテスト可能。**第二段でEditorのアイドルプレビューと共有されるため、最終的にはpackages側に住む**(§5)。**繰延注記(ユーザー裁定 2026-07-10、C2棚卸しを受けて)**: 物理的なpackage新設はlockfile変更を伴うため、Editorが消費者になる日(第二段)まで繰延。当面は `apps/runtime-player/src/main/physiology/` にElectron importゼロの純関数として置き、「package-readyな純度」をレビューのblocking観点で守る(「Editor責務は繰延」と同じ賭けの一貫)。
- **演出エンベロープ(③)の供給**: 四層の優先順位で積む:

```
普遍既定値(生成器のコード)             ← 何も無い時の底
  < パッケージのエンベロープ宣言(作者)   ← 第二段で主役
    < Player側プロファイル補正(ユーザー) ← 第一段の主役。第二段で「補正」に格下げ
      < 魂の変調(実行時)               ← 情動によるその場の揺らぎ
```

- Player側プロファイルはDynamics Tune profileと同格・同方式(Runtime Export fingerprintごとに`<electron userData>`配下へ自動保存、export成果物に触れない、決定性境界の外=前提P4)。
- **Player消費側は最初から四層を想定して作る**(第二段で作り直しが要らないため)。

## 3. 駆動と合成

- 生成器は**自律ホストインスタンスの基底フレーム源**(Playerの自前クロック)。keep-aliveを魂に背負わせない。
- **魂の注入は基底の上のオーバーレイ**。パラメータ群ごとの優先規則: 発話中は口を魂が奪い生成器は譲る / 「カメラ見て」指示中は視線固定 / 指示が無ければ生成器。
- **劣化の意味論**: 魂の沈黙・切断でオーバーレイが剥がれ、基底だけが残る(=ぼーっとして呼吸している状態)。放送事故耐性は合成規則の自然な帰結。
- **変調**: 魂は情動ツマミ(少数の名前付き状態+強度)をチャネル越しに設定し、生成器がツマミ→統計(まばたき頻度、視線の落ち着き先、呼吸の速さ)の写像を持つ。

## 4. 第二段: Editorの第一弾機能(意味レベル)

範囲は**エンベロープ宣言のみ**(ポーズ語彙は同段内の後の増分)。

- **宣言の中身**: パラメータ単位の自然域(中心・幅・非対称)+動きの強度ヒント。
- **データモデル**: パラメータの意味的メタデータ区画(`presetAlias`/`runtimeRole`/`externalInput`の隣)にオプショナル区画として座る。宣言が無ければ普遍既定値に落ちる。人間駆動モデルの制作では開かれない区画。
- **UX**: パラメータスライダーの内側ハンドル(ブラケット)で自然域を括る+**アイドルプレビュー** — Playerと同じ生成器が宣言中のエンベロープでプレビューを動かし続け、作者は「生きて見えるか」を見ながら詰める。静的なブラケットだけでは時間の中の自然さが分からないため、プレビューが本体。
- **機械向けの顔**: エンベロープ設定はoperation-coreの操作(dry-run/diff/承認経路)として定義し、Fableがauthoring-host越しに宣言できる。「身体を作った本人が、その身体の自然な動き方も宣言する」。

## 5. 等価性検証

preview/viewer equivalenceの文化をそのまま拡張する: **同じ生成器+同じエンベロープ+同じシード → EditorのアイドルプレビューとPlayerの生理層は同じ動きをする**。決定論・シード付きのため、fixture契約テストとして検証可能。
