> 裏付けの事実: [../discord-vc/research/restructure-cockpit-map-2026-10.md](../discord-vc/research/restructure-cockpit-map-2026-10.md)(組み立ての地図・場の散らばり・器に頼る所)、[../discord-vc/research/restructure-role-state-2026-10.md](../discord-vc/research/restructure-role-state-2026-10.md)(記憶の置き場・設定のキー・頭と名前・声)、[../discord-vc/research/layer-classification-2026-10.md](../discord-vc/research/layer-classification-2026-10.md)。

## 1. 何を変えて、何を変えないか

- 変える: 頭を選ぶ代わりにロールを選ぶ。ロールが名前・性格の指示・声・動かすモデル・しゃべり方の方針・体を持つ。記憶はロールごと。「配信を始める / 終える」で場を開け閉めする。体の無いロールでもしゃべれる。設定のダイアログを配信の準備・ロール・運転に組み直す。
- 変えない: 配信中のメイン画面の見た目。1 段目のつまみ(KILL・自発・かぶり)の置き場。記憶の書き出し役・思い出し役への指示と、チャッピーの `_conventions.md` の文面。判定の問いの中身(配信の判定は配信のもの、§5)。外回りの起動(AivisSpeech・runtime-player・AHK・ターミナル)。

## 2. ロール

### 2.1 置き場と形

- `apps/soul/agent/roles/<role-id>/`(git に入れない。`.gitignore` に足す)。
  - `role.json`: 下の表の値。
  - `instructions.md`: 性格の指示(今の会話指示)。無い・空なら今の既定の本文。
- role-id は英小文字(`chappy`、`cody`)。見せる名前は `role.json` の中。
- 1 起動で開ける場は 1 つずつ。場の途中でロールは替えない(替えるなら場を作り直す)。

| 持ち物 | 中身 | 今の置き場(移す元) |
|---|---|---|
| 名前 | 呼び名・見せる名前・ローマ字 | `model-identity.mjs` の cody / chappy の表 |
| 名前の手がかり | whisper の手がかり・声での呼ばれ方・コメントでの呼ばれ方・hotwords | 同上と、設定 `localSttHotwords` |
| 性格の指示 | `instructions.md` | 設定 `conversationInstructions.overrides[頭の id]` |
| 動かすモデル | 頭の id(今の 6 つのどれか) | 設定 `brainChoice` |
| 声 | 方式(AivisSpeech / ElevenLabs)・AivisSpeech の話者・ElevenLabs の声の id | 設定 `ttsEngine`・起動引数 `--speaker`・コードの既定 |
| しゃべり方の方針 | 口数・話し始めの方式 | 設定 `verbosityMode`・`speakStartMode` |
| 体 | 使う / 使わない | (無い。今は器が必須) |

- 頭の性質(Codex の残量・fast・文脈の圧縮、Claude の env ガード)は、頭に付いたままにする。ロールは「どの頭で動かすか」を指すだけ。
- 記憶の書き出し役・思い出し役の頭は、今と同じ決め方(ロールの頭が Codex 系ならその頭、そうでなければ Codex)。

### 2.2 ロールの外に残る設定

- 配信の準備(体験): YouTube の URL、ゲームの窓、器の URL、マイク、文字起こしの方式、声の出力先、忙しい間のコメント。
- 1 段目(あなたが握る): 自発、かぶり。KILL は場の始まりで OFF に戻す。
- 技術のつまみ(手で書くもの): 遅延の警告、圧縮のしきい値、Codex の fast、ローカル文字起こしの調整(hotwords を除く)、合いの手の間隔。

### 2.3 記憶

- 置き場はロールのフォルダ `memories/<role-id>/`。git もロールごとに 1 つ(`memories/<role-id>/.git`)。
- 書き出し役・思い出し役の作業フォルダをロールのフォルダにする。指示の文面にはパスが入っていないので、文面は変わらない。ほかのロールのフォルダに書けない・ロールのフォルダを話題と取り違えない、もこれで済む。
- `_conventions.md` はフォルダに無いときだけ種から書く(今と同じ)。チャッピーのものは移すだけなので一字も変わらない。新しいロールのときは、種の「チャッピー」をそのロールの呼び名に差し替えて書く。

### 2.4 今のものをロールへ移す(移し替え)

- **新しい版を最初に起動したときに、自動で移す**(ユーザー 2026-10-31、scope §20)。`roles/` が無く、古い設定か `memories/` の直下に記録があるときだけ動く。1 回だけ。
  - 移す前に、元の設定ファイルと `memories/` を丸ごと写しておく(置き場は `apps/soul/agent/` の下の git に入らない所)。
  - ロール: 設定ファイルから `chappy` と `cody` の 2 つを作る。
    - チャッピーの指示は GPT-6.1 Sol の上書きを優先し、無ければ ほかの GPT 系の上書き、それも無ければ既定。モデルは今の `brainChoice` が GPT 系ならそれ、そうでなければ GPT-6.1 Sol。
    - こーでぃーの指示は Claude (Opus 5.5) の上書きを優先し、無ければ Claude (Opus 4.8)、それも無ければ既定。モデルは Claude (Opus 5.5)。
    - 声・口数・話し始めは今の設定の値を両方に写す。体は両方「使う」。
  - 記憶: 今の `memories/` の中身を `.git` ごと `memories/chappy/` へ移す。履歴はそのまま残る。こーでぃーの記憶は空から始まる。
  - 古い設定のキーは消さずに残す。読むのはロールのほうだけになる。
  - 移したあとで 1 回だけ、何が起きたかを出す(どの指示を使ったか、移した記録の件数、写しの置き場)。

## 3. 場(配信を始める / 終える)

- 場の外(閉じている間)でできること: ロールを選ぶ・直す、配信の準備を直す。
- **配信を始める**(1 つの関数にまとめる。今の耳の Start を広げる形):
  1. ロールを固める(場の途中は替えられない)。
  2. 場の記録を作り直す: 記憶の本体のファイル名、頭の文脈の記録のファイル(今は起動 1 回に 1 つ → 場 1 つに 1 つ)。
  3. KILL を OFF に戻す。判定・発火の予定・コメント反応・思い出しの係の積み残しを捨てる。
  4. 耳(と会話の正本)、目、声の出口を起こす。
  5. 頭のセッションをロールのモデルと指示で作る(今は最初の発火まで遅らせている)。
  6. ロールに体があれば器につなぐ。**つながらなければ場は開かない。** そのとき「runtime-player が起動していないか、channel が開いていない」と分かる言葉で知らせる(ユーザー 2026-10-31)。体が無ければ何もしない。
  7. YouTube の URL が前もって入っていればつなぐ。つながらなくても場は開く。**ふだんは場を開いたあとで URL を入れて Connect する**(ユーザー 2026-10-31)ので、YouTube の欄は場が開いている間も触れる。
- **配信を終える**(1 つの関数にまとめる。今の耳の Stop と Ctrl+C の保存を 1 本にする):
  1. 会話の正本の写しを取る。
  2. YouTube・判定・発火の予定・目・耳・頭のセッション・器を畳む。
  3. 記憶の最後の保存をして待つ(画面に「記録中」を出す)。
  4. 場を閉じる。ロールを選び直せる。
- Ctrl+C: 場が開いていれば「配信を終える」と同じ道を通ってから終わる。
- 20 分ごとの保存と「今日を記録」は、場が開いている間だけ動く。
- マイク・文字起こしの方式は、場が閉じている間だけ変えられる(ユーザー 2026-10-31。変えたことがなく、変えないほうが安全)。

## 4. 体なしで声を出す

- 今は 4 段で止まる: 器の URL の確かめ 2 か所、器への接続、口の時間割を器が受け取ったかの待ち。
- やり方: **運び手の約束を「器は任意」に変える**(地図の候補 2)。体の無いロールのときは器を渡さず、運び手は器への送信を飛ばして手元の再生器だけで鳴らす。器の URL の確かめは「ロールに体があるときだけ」にする。
  - 何でも受け取る器の代わりを差し込む案(候補 1)は採らない。体が無いのに「表情を適用した」と数えてしまい、体が無いことが見えなくなるため。
- 割り込みの「どこまで声に出たか」は、器ではなく声の engine の時間割と再生器の合図で決まるので、そのまま動く。時間割は体が無くても作る。
- 体が無いとき: 表情のタグは剥がして捨てる(診断は出さない)。頭への表情の教え(`skills/expression.md`)は渡さない。
- 遅延の記録の「声」の区間は、体が無いと器の往復を含まない値になる。記録に「体なし」と分かる印を付ける。

## 5. 判定は体験のもの

- 芯が持つのは、判定を呼ぶ仕組み(speak-now・コメント反応・従来の発火の予定・2 段の門)まで。**問いの中身と選択肢は体験が持つ。** 配信の判定が「配信」に触れているのはそのままでよい(scope §18)。
- ロールが判定に渡すのは、性格の 1 文(口数から作る今の文)と名前。
- この組み直しでは判定の文面は変えない。変えるのは、口数・話し始めの値の出どころ(設定 → ロール)だけ。

## 6. 画面

- 設定のダイアログのタブ: **配信の準備 / ロール / 運転 / 記憶 / ログ**。
  - 配信の準備: 毎回見るもの(YouTube の URL、ゲームの窓、ロールに体があるときだけ器の URL)と、たたんだもの(マイク・文字起こし、声の出力先、忙しい間のコメント)。select は保存した値を選んだ状態で出す。場が開いている間は、マイク・文字起こしは触れない。YouTube の URL とゲームの窓は触れる。
  - ロール: 今日のロールの選択(場が閉じている間だけ)と、ロールの編集(名前・モデル・性格の指示・声・口数・話し始め・体)。新しいロールは、今のロールを写して作る。
  - 運転: 自発・かぶり・手動の発火。口数・話し始めはここから外す(ロールへ)。
  - 記憶: そのロールの記憶。「今日を記録」は場が開いている間だけ。
- メイン画面: 場が閉じているとき、中央の「準備・設定を開く」を「配信を始める」(とその横に「準備・設定」)にする。場が開いているときは今のまま。上の帯にロールの名前、下の帯の運転設定の表示はロールの値。
- 「何をする?」の最初の画面は作らない(Discord を足すときに作る)。

## 7. Discord を後で足せるか(確かめ)

| Discord で要るもの | この設計で | 残る仕事 |
|---|---|---|
| 同じロールを使う・記憶をたどる | ロールと記憶がロールごとになったので、そのまま使える | 書き出しの頼み方(配信の語が入っている)を Discord 用に持つか(scope §4) |
| 入る / 抜ける | 場の始まりと終わりの関数に、Discord の入口と出口を挿す | — |
| 体なしでしゃべる | §4 で済む | — |
| 声を Discord に流す | 運び手は再生器を `{open, write, end, stop, onEvent}` の形で受け取るので、Discord 向けの再生器を作れば運び手は変えずに済む【推測】 | Discord 向けの再生器 |
| 人ごとに聞く | 耳は今も 1 本で、会話の正本が耳の中にある | 会話の正本を耳の外に出す(地図の候補 F)・話者を名前付きにする(今は you / soul / viewer の 3 値) |
| しゃべるかの判定 | 判定は体験のもの(§5) | Discord 用の判定 |

- 正本を耳の外に出すのは Discord のときに回す。配信では耳 1 本のままで困らないため。

## 8. wave の切り方(案)

各 wave の人間ゲートは「実際に配信(か試しの配信)が回る」こと。

1. **ロールの土台**: ロールの置き場と読み書き、起動時の引っ越し(ロールの分)、名前・名前の手がかり・性格の指示・声・口数・話し始めをロールから引く。頭の選択をロールの選択に替える(画面は今の頭脳タブの中で最小限)。
2. **記憶をロールごとに**: 記憶の置き場をロールのフォルダに、起動時の引っ越し(記憶の分)、新しいロールの種の名前の差し替え。
3. **体なしで声を出す**: 運び手の「器は任意」、器の確かめをロールの体に従わせる、表情タグと教えの扱い、遅延の記録の印。
4. **場**: 配信を始める / 終える の関数、Ctrl+C の道、場ごとの記録、場の間のロールの固め、メイン画面のボタン。
5. **画面の組み直し**: 配信の準備・ロール・運転・記憶のタブ、ロールの編集、select の初期値。

- 1 と 2 は順に(2 は 1 のロールの id を使う)。3 は 1 のあとならいつでもよい。4 は 1〜3 のあと。5 は最後。
