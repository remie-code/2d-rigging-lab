# AI共演者の振る舞いモデル(存在の解剖学)

> Status: 構造=Accepted(ユーザー合意 2026-07-10) / 一部詳細はDraft(本文に明記)
> Owner: Undine / ユーザー
> 目的: 「ai-cohostによって登場するのは何者か」を、振る舞いの提供責任の観点で言語化する。境界改定([mvp-boundary-amendment.md](mvp-boundary-amendment.md))の前提文書。
> 対象は(i)存在の解剖学(どの層がどの振る舞いを提供するか)のみ。(ii)存在の人格(誰なのか、名前、性格、声)は persona/ を切る段階で扱い、リポジトリ外の責務になる可能性もある(ユーザー合意)。

## 1. 分解: 三層+一知覚(Accepted)

```
知性層(魂・Opus)      ← 発話・意見・意図的表情・Variant切替
情動層(魂寄りローカル)  ← 聞く姿勢・感情の残存・生理層への変調指示
生理層(器・決定論)     ← 呼吸・まばたき・視線・姿勢の生命感
知覚(魂側)            ← 耳=転写(常時) / 目=段階的注意
```

## 2. 生理層(Accepted)

**役割**: 「生きて、そこに居る」まで。**意味を持たないことが仕様** — 統計から出る背景のざわめきであり、何かを伝えようとする動きは担わない。意味を持つ動きは上位層(情動・知性)の仕事。

**提供元**: 器(runtime-player)内の決定論的な手続き生成器(シード付き)。方針(a)+変調をユーザー合意(2026-07-10)。生成器は**AI用インスタンスの基底フレーム源**になる(Playerの自前クロックで連続フレームを打つ)。これにより「フレームが来ないとdynamicsが進まない」問題とkeep-alive契約を構造的に解消し、**魂が死んでもキャラは呼吸し続ける**(放送事故耐性)。

**表現レパートリー**: 既にモデルが持つプリセットパラメータの範囲内に限る(ユーザー合意: 「圧倒的に正しい切り分け」)。単調振動ではなく、多時間軸ノイズの重ね合わせ+離散イベント(まばたき、サッカード+固視、姿勢組み替え)で構成する。詳細は [../architecture/physiological-layer-and-envelope.md](../architecture/physiological-layer-and-envelope.md)。

**表現できないもの(明確に対象外、ユーザー合意)**: モデルにリグされていない動き(腕のジェスチャ等)、意味を持つ表情切り替え(Variant=知性層)、作り込まれた仕草(梯子の第二段以降)。

## 3. 情動層(Accepted、詳細Draft)

発話と発話の間の状態: 聞く姿勢、頷き(相槌の視覚版)、感情の残存(笑った後しばらく機嫌がよい)。提供元は反射層+直近のLLM感情タグの減衰というローカル手続きで、LLM費用はほぼゼロ。生理層への変調(まばたき頻度・視線の落ち着き・呼吸の速さを情動が揺らす)もここが指示する。

## 4. 知性層(Accepted)

発話、意見、意図的なジェスチャ、表情・衣装の切り替え。Opus 4.8(前提P1)の仕事。魂(外部オーケストレータ)に住む。

## 5. 知覚構造(必要性=Accepted、段階の詳細=Draft)

背景: ユーザーの配信はほぼゲーム配信であり、ゲーム画面に全く反応しないのは不自然。だが逐一の画面確認はコスト構造上不可能。よって「外部情報に対する知覚構造」を独立に定義する(ユーザー提起 2026-07-10)。

- **耳(常時・無料)**: ユーザーは配信中ほぼ常時しゃべる(前提P2)ため、**ユーザーの実況そのものがゲーム状態のテキスト化ストリーム**であり、ASR転写として既に魂に届く。画面を見なくても「実況越しにゲームを追う」だけで会話の大半は成立する見込み。
- **目(段階的注意、Draft)**: (1) 低頻度サンプリング — スクリーンショットを安価モデルで1行要約しOpusの文脈へ注入(2h配信で$1前後) / (2) オンデマンド注視 — 「これ見て」等のトリガや会話が画面に言及した時だけ高解像で見る。
- 前例: model-authoringにおけるFableの目(render-view)と同型の思想 — 「AIの知覚は、必要な時に必要な解像度で与える」。
- **境界上の位置**: 知覚は全て魂側(リポジトリ外)に住む。画面キャプチャもLLM呼び出しも器には入らない。

## 6. 梯子: 意味の階段(Accepted)

生理層の表現力は段階的に上げる。各段の意味的な区別は「**意味を持つか・作者の意図が刻まれるか**」:

| 段 | 意味構造 | 内容 | 新たな責務 |
|---|---|---|---|
| 第一段 | 質感(無意味) | 手続き生成器のみ。演出エンベロープは普遍既定値+Player側目視調整で**暫定近似** | Editor責務ゼロ(ただし「繰延」— §7) |
| 第二段 | 単語(意味の単位) | モデルが演出メタデータ(エンベロープ+ポーズ語彙)を自分で持つ。「首をかしげて上目遣い」のような協調した構え=身体言語の単語 | **Editor(制作行為)**。作者はauthoring-host越しのFableになり得る |
| 第三段 | 文(時間構造) | 作り込まれたモーションの再生 | MVP除外だったタイムラインアニメーションの再開を意味する。第一・第二段が実機ゲートで敗れた時のみ検討 |

## 7. 演出エンベロープの責務(Accepted — ユーザー「説得された」2026-07-10)

「単一パラメータの見せたい範囲・ランダム性・パターン」のデータは三片に分かれる:

- **①動きのパターン(振る舞いクラス)**: モデル非依存の普遍的機械。生成器のコードが持つ。
- **②機械的可動域**: `min/max/default`。既にEditor/モデルパッケージの責務(既存)。
- **③演出エンベロープ(見せたい範囲)**: 新しいデータ。**本来の所有者はモデル作者**であり、住処はモデルパッケージ。

③がパッケージに住むべき根拠(合意済み):

1. **対称性**: ③はあらゆる駆動源が必要とする知識。駆動源が人間なら calibration/mapping として実行時に人間が供給しており、書き置きが不要だっただけ。駆動源が生成器なら calibrationすべき人間がいないため、制作時に作者が宣言するしかない。「人間駆動モデルには過剰」ではなく「供給源が違うだけ」。
2. **前例**: Dynamics — 揺れの質感は実行時にしか意味を持たないのにEditorで制作されパッケージに載り、PlayerのDynamics Tuneが実行時補正する。エンベロープは同一パターン。
3. **消去法**: Player側永住=制作行為の置き場所違い・非ポータブル / サイドカー=パッケージ単独真実とprovenance機構からの逃亡 / 魂側=身体の知識が魂と一緒に出ていくのはおかしい(魂は交換可能、身体の知識は身体に付く)。
4. パッケージのオプショナル区画として足せば人間駆動モデルの制作フローには一切現れない。

**第一段の正直な位置付け**: 第一段のEditor責務は「ゼロ」ではなく「**繰延**」。③を普遍既定値+ユーザーの目視調整で代行する明示的な賭けであり、実機ゲートで「調整が制作の粒度になってきた」と感じた時が第二段へ上がる合図。

**留保(記録)**: 第二段で③が「リグの属性」でなく「人格の属性」と判明した場合は二層に割る — パッケージは安全域と自然域(身体の知識)、魂がその中でのクセ(人格の知識)で変調。どちらに転んでも「身体の限界と自然域はパッケージ」の芯は変わらない。
