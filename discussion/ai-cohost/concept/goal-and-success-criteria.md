# AI Cohost: 目標像と成功基準

> Status: 目標像=Accepted(ユーザー合意 2026-07-10) / 成功基準=Accepted(ユーザー合意 2026-07-10)
> Owner: Undine / ユーザー

## 1. 位置付け

当初MVP(Private Authoring-to-Viewer Prototype)は、LLM(Fable)によるriggingまで含めて全達成された(ユーザー宣言 2026-07-10)。ユーザーが現在配信で実運用しているモデルは、Fableが確立済み手順を再走して制作したものであり、ユーザー自身の制作物よりクオリティが高い。

本構想は、その達成の上に載る次期構想である。既存資産のうち特に以下を前提にする。

- runtime-player: フェイストラッキング(iFacialMocap)駆動、リップシンク(母音推定→口形ブレンド)、OBS Browser Source配信経路が実運用中。
- 決定論ランタイム(runtime-core)とセマンティックなパラメータ制御面。
- Fableによるモデル制作の再現可能な手順(model-authoring)。

## 2. 目標像(ユーザー合意 2026-07-10)

> 私は私のモデルを使い、フェイストラッキングと連動してモデルを動かし、AIはAIで別のモデルを使い、完全AI自律で動かす。そして二人で一緒に配信する。私とAIの間の自然な会話が可能であり、AI側も自然な感情表現としてモデルを動かす。

要素分解:

1. ユーザー: 自作モデル+フェイストラッキング(現行runtime-playerの実運用形態そのまま)。
2. AI共演者: 別モデルを完全自律で駆動する。表情・所作は発話内容と感情に連動する。
3. 会話: ユーザーとAIの間で自然な音声会話が成立する。相槌と意見の両方が望ましい。
4. 制約事実: ユーザーは配信中ほぼ常時しゃべっている。

## 3. 成功基準(Accepted — ユーザー合意 2026-07-10)

**「人間と完全に同じ会話テンポ」を成功要件にしない。「AIらしい少しの間があっても、キャラクターとして面白く、会話として成立している」を成功要件にする。**

根拠(調査事実、[../research/human-ai-cohost-precedents.md](../research/human-ai-cohost-precedents.md)):

- 先例(Neuro-sama)は明確な「AIの間」を持ちながら商業的に成立しており、視聴者は間を演出として受容している。
- 噛み合わない瞬間は人間側(ユーザー)がその場でリカバリでき、ツッコミ対象=コンテンツにできる。共演形式はAI単独配信より成立させやすい。
- 技術的な下限として、フィラー/相槌の反射層により体感600ms程度の初動反応は実現可能。

この基準が受け入れられない場合、要求水準(full-duplex级の会話)は2026年時点の技術で実用未達であり、構想全体の再検討が必要になる。

## 4. 非目標(Draft)

- AI単独の完全自律配信(共演なし)は当面の目標にしない。
- 人間同士のターンテイキング(日本語平均7ms)の完全再現は目標にしない。
- speech-to-speech API(音声直接対話)の採用は目標にしない(キャラ声制御不可・高コスト・リップシンク資産と不整合。[../research/aituber-landscape-2026-07.md](../research/aituber-landscape-2026-07.md) 参照)。
- Cubism互換・既存Cubism資産の利用は従来どおり行わない(root規約 §7 を継承)。

## 5. 4トラック / MVP境界との関係

- 本構想の成果は配信画面に出るため、**Streaming Demo Surface の衛生規約([../../demo/](../../demo/)、root `_conventions.md` §7)が適用される**。コード・内部形式・Cubism語彙を配信に出さない制約は本構想でも不変。
- root `_map.md` 次の行動2は「external HTTP / WebSocket / MCP API work と LLM provider integration は、MVP境界が明示変更されるまで Future scope」と定めている。本構想は runtime-player への外部操縦チャネル追加と外部LLMオーケストレータを必要とするため、**MVP境界の明示変更に相当する。ユーザー合意による境界更新が必要(未決)**。
- リポジトリの憲法「リポジトリ側は決定論の器、知性は外部」([../../design/codex-friendly-automation-policy.md](../../design/codex-friendly-automation-policy.md))は本構想でも維持する方向(architecture/ 参照)。リポジトリ内にLLM呼び出しを埋め込まず、runtime-playerは決定論的な操縦APIを公開し、魂(オーケストレータ)は外部に住む。

## 6. 用語

- 本トピックの独自語彙として **AI共演者(ai-cohost)** を使う。外部技術地形の記述では一般語「AITuber」を出典文脈でのみ使用する。
