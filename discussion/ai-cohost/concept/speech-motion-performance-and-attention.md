## 1. 出発点とユーザーの訂正

安堵v1を見て、ユーザーは上下ありを基本的に採用し、最後の機械的に上へ戻る部分を滑らかにしたいと述べた。同時に、なぜ最初からチャッピーの右（画面左）を向いているのかを問い直した。

エージェントは「相方は画面左」という前提で相方への注意を固定していたが、ユーザーは次を明示した。

- 基本姿勢は**正面を向いたニュートラル**。右向きの状態から始まる固定クリップでは、通常状態からの接続がおかしくなる。
- 安堵と向きは別の要因。向きは「意識を向けている対象」によって決まる。
- 状況・ゲームへの安堵なのに相方を見る必要はない。相方に対する表現なら相方を向く。
- モーションは複数要因の組み合わせとして発生する。

正面は制作の基準姿勢であり、毎回機械的に正面へリセットしてから演技を始める、という合意ではない。実行時の現在姿勢からの接続方法は別途確認する。

制作担当について、ユーザーは表現力を理由にroot自身、またはAstraのサブエージェントを希望した。Solのv2修正作業は停止し、Astraによる修正も向きの議論より先には起動していない。今後の創作モーション制作はこの希望を引き継ぐ（実装オーケストレーションのSol指定とは別）。

## 2. 安堵の実例を動きの意味で分けた案

対象は2026-11-11の同一場 `5446aa19-499b-461e-be96-b1b4bc10165f:1`。ローカル `apps/soul/agent/tmp/speech-intent-none/` の安堵を明示した意図等16件を、直前の会話も含めて確認した。以下は**記録された発話＋演出の解釈案**。実際の顔の向き・動作を観測した結果ではない。全未対応区間の網羅的な分類でもない。

| パターン | 実際の発話例 | モーションとしての流れの案 |
|---|---|---|
| 1. 危機の途中で、一息だけ抜く | 「耐えた……！ でも柱と馬車の間、逃げ場が狭いね。」「回復できたね。向こうもあと少しだけど、最後まで怖いな。」 | 見守る→短く緩む→見守り続ける。注意を切らず、休み切らない |
| 2. 心配の解消を確かめて緩む | 「ちゃんと術もトレントも残してくれるんだね。安心して見送れる。」「挟まれる心配が減るだけで、ずいぶん違うね。」 | 確かめる→腑に落ちる→力を抜く |
| 3. 安全な場所でようやく休む | 「円卓の安心感すごいなあ。今日は王都をずいぶん歩いたね。」 | ゆっくりほどける→楽な姿勢に落ち着く。構え直さず余韻を保てる |
| 4. 救いを発見してほっとする | 「祝福あったんだ！ よかった、これでようやく探索した先を拠点にできるね。」 | 注意が集まり顔が上がる→発見を受け止める→緩む |
| 5. 相手の言葉で安心して応じる | 「じゃあ、今できるかは気にせず、僕がしたい動きを添えていけばいいね。」 | 相手の説明を受け取る→相手への注意を保って緩む→応じる |
| 6. 無事に終えた安堵を挨拶に乗せる | 「最後の挨拶まで声がもってよかった！ 今日もありがと、次の王都探索も楽しみにしてるよ。」 | 緩む→相手へ挨拶を届ける。原意図は笑顔と手振りを含む |

安堵の原因と、表現・注意を向けたい対象は必ずしも同じではない。「ゲームに安心し、その気持ちを相方に共有する」演技も考えられる。ただし、今回の発話記録だけから「安堵した後は必ず相方を見る」とは決めない。

これら6分類を、そのまま6つの製品候補として追加すると合意したわけではない。初回制作の題材「回復できたね。ちゃんと立て直せる隙もつかめてきた。」は、直前に敵の攻撃・回復のやり取りがあり、1に相当すると解釈した。一次記録は `13c15bfa13dc039c78f1c6920f59f67c0017f88d975ad3c1ffd704f47a65c100.json`。

## 3. 選択肢数と演技の作り込み

議論した案:

- 全演技・全対象の完成モーションを単一候補群に並べる。
- 意味を階層化し、複数の判定で絞る。
- 演技の種類と注意対象を分けて選び、実際の動きを組み立てる。

最後の案に対し、ユーザーは**演技と対象は別々に判定するが、その組み合わせのモーションはそれぞれ作り込んで持っていてよい**と提案し、この方向で合意した。

例:

| 演技 | 注意の対象 | 制作済みの具体的な演技 |
|---|---|---|
| 短く息を抜く | 相方 | 相方への注意を伴って短く緩むクリップ |
| 短く息を抜く | ゲーム画面 | ゲームを見守ったまま短く緩むクリップ |
| 短く息を抜く | 視聴者 | 視聴者に向けて短く緩むクリップ |

これは候補例で、全クリップが存在するわけではない。向きだけの機械的な置換や、その場での手続き的モーション合成を採用したのではない。各クリップで視線の先行、顔の向き、緩む時点、戻りまで個別に作り込める。

選択肢の直積をAPIへ列挙しなくても、制作資産の数は増える。全組み合わせを先に制作せず、実例をもとに必要なものから育てる。未制作の組み合わせを、別対象向けの演技で無理に埋めない。

## 4. 判断と機械処理の分担（合意）

| 項目 | 担当 | 意味 |
|---|---|---|
| 意図の表現 | チャッピー本人 | 自由な意図を区間へ添える。許可語彙の選択に制限しない |
| 演技の種類 | Decision | 原意図と発話・直前の文脈から既存演技または「どれでもない」を選ぶ |
| 注意の対象 | Decision | 同じ材料から相方・ゲーム画面・視聴者等の意味的な対象を選ぶ |
| 具体的なモーション | 機械処理 | 演技×対象の制作済みクリップを引く |
| 曲線・視線・姿勢・上下動・順序 | 事前の共同制作 | ユーザーとエージェントが目視して作り込み、定義に保存する |
| 再生と解除 | 機械処理 | 発話区間、世代、終了・中断に従う。音声開始は待たせない |
| 未対応記録 | 機械処理 | 原意図、発話、文脈、選択結果と未対応理由を保存する |

ユーザーは**判定に発話と文脈もあった方がよい**と了承した。同じ「ほっと肩の力を抜く」が危機の途中にも安全な場所にも出るため。本人の意図と本文の一致を採点・訂正する目的ではない。

未対応は少なくとも以下を区別する方針:

1. 演技そのものが未対応（「どれでもない」）。
2. 演技と対象は決まったが、その組み合わせが未制作。

通信失敗、拒否、中断はこれらと混ぜない。現在の単問・preset ID・none記録の実装を、この新方針に対応済みとして扱わない。

## 5. 一回のDecisionリクエストで二問（採用方針）

ユーザーは仕様確認後、**一回のリクエストで演技と対象を別々の質問として判定する**方針を了承した。全演技×全対象の組み合わせをchoicesへ列挙しない。

2026-11-11にSylphが確認した公式仕様:

- `POST /v1/decisions` は同じトップレベル `input` に対し、`questions` に複数問を入れられる。各問固有の `choices` を持てる。choiceは一問につき一候補を選ぶ。
- 回答は質問順・`name`で対応させられる。
- 同じ入力を使う**独立質問**。先の答えを踏まえて後の問を判断する保証、二回答の共同最適化や制作済み組み合わせへの整合保証はない。先の答えに依存する場合は別リクエストとする。

出典: [公式ガイド・複数問](https://developers.openai.com/api/docs/guides/decisions#ask-multiple-questions)、[API reference](https://developers.openai.com/api/reference/resources/decisions/methods/create)。これは調査時点の仕様確認で、今回の二問構成による実API測定ではない。

リポジトリ事実: `apps/soul/agent/src/mind/speak-now-decisions.mjs` の `createDecisionsQuestionsJudge` は質問別候補・name対応・質問ごとの返答検証を扱う。`createDecisionsJudge` は単問用。複数問helperがあることと、意図モーションへ今回の二問を接続済みであることは別。

今回の二問構成の選択品質・遅延は未測定。「一回だから必ず速い」「二回答が必ず整合する」とは保証しない。

## 6. 今回制作する一覧と未決事項

当初エージェントが「次に作る一作」としてゲーム画面向けへ話を狭めたが、ユーザーの求めていたものは**この演技として揃えるモーションの一覧**だった。相方・ゲーム画面・視聴者の3案を作ることで合意した。対象の時系列上の前後関係を過度に考えず選べる方針。各案は制作上、正面ニュートラルから接続する。

| 今回の案 | 注意の向き・演出 | 状態 |
|---|---|---|
| 短く息を抜く／相方 | キャラから見て右、画面左。正面から相方へ注意を向けて短く緩む | Astra試作をユーザー承認。保存先 `tmp/speech-motion/brief-relief-variants-v1/partner.mp4` |
| 短く息を抜く／ゲーム画面 | 正面。画面を見守る注意を保って短く緩む | 最新の方向指定で生成し、ユーザー採用 |
| 短く息を抜く／視聴者 | 正面より上。上方の相手へ注意を向け、応答を届けながら短く緩む | 最新の方向指定で生成し、ユーザー採用 |

相方版と後二者の配置案に対し、ユーザーは「この試作も向きについてもいい」と了承した。相方版は旧安堵v1の横向き開始を改め、Stage Yを基準位置まで一続きで戻し、解除後も含む約5.2秒の無音試作。製品の選択・再生への登録ではない。

その後、ユーザーが「ゲーム画面はむしろ正面でいい。視聴者の方向は上で頼む」と修正した。**上表のゲーム＝正面、視聴者＝上を現在の正とする。** 先のゲーム＝少し下、視聴者＝カメラ正面は撤回済み。相方版の採用は維持。

引き継ぐ条件:

- 上下ありを採用。最後の機械的な上昇・復帰は修正したいというユーザー評価。
- 笑み追加は後。モデル造形の変更を先に必要としない。
- 最初から相方向きの固定姿勢を前提にしない。
- 直前に大きく身構える動きをわざと作り足さない。安堵を短く表し、まだ状況を見守っている注意を保つ、という方向を検討する。
- 横向き80%上限は継承する。制作はroot自身またはAstra担当で行う。

未決:

- 対象の空間配置は上表で合意済み。実際の配信配置が変わる場合の変更方法は未設計。
- 対象候補の最終一覧。「現在の対象を維持する」の意味と保持状態、対象を判定できない場合の扱い。判定不能を維持したい意図と同一視しない。
- 演技名/対象名の機械識別子、登録・lookup構造、未制作理由の記録形式、既存3presetの移行。
- 発話のどの範囲・文脈量をいつ判定へ渡すか。二問の実測と非待機の維持。
- 現在姿勢から各クリップへ入る接続、既存視線等との所有権、次区間へ移るときの終わり方。
- 「短く息を抜く」の長さ・振幅・視線/目/頭/上体/Stage Yの動き、最後に保つ姿勢。今回の実験で何を比較するか。

今回の3案の試作はユーザー承認済み。API接続や登録構造などの未決事項を、試作了承だけで製品実装へ拡大しない。

## 7. 製品接続のcontext-check（2026-11-12確定）

3案を見たユーザーは「いいんじゃないかな」と評価し、演技と注意対象の組み合わせでモーションを選ぶ方式への対応、および元のモーションの適切な配置を依頼した。context-checkで棚卸しし、以下のユーザー判断を確認した。

| 論点 | 確定した方針 |
|---|---|
| 注意対象を読み取れない | 対象不明として記録し、その区間の演技を足さない。現在対象への自動置換を行わない |
| 発話がモーションより先に通常終了する | 動きは自然な終わりまで続ける。通常終了による短時間の強制解除で承認済みの戻りを切らない |
| 割込み・kill | 通常終了と区別して解除する |
| 「元のモーション」の意味と配置 | 既存receive/interest/askも新方式へ移す。受け取る・関心を向ける・問いかけるの3種はいずれも相方向けへ配置 |

初期登録は、既存3演技×相方、および短く息を抜く×ゲーム画面/相方/視聴者の計6組を想定する。他の未制作組み合わせを埋めるために対象を勝手に置き換えない。原意図・発話・文脈とともに、未対応演技・対象不明・未制作組み合わせの理由を区別して残す。通信失敗・拒否・中断とは別の軸で扱う。

棚卸しで確認した技術課題（ユーザー判断を代替するものではない）:

- 現行の意図判定は複数問helperに1問を渡している。2問への拡張、演技×対象lookup、記録の理由・選択値拡張が必要。
- 会話窓は取得済み。逐次経路の本文は後から確定するため、音声開始を待たせず、どの本文範囲を判定へ渡すかを実装・検証で詰める。
- 新3案のうち相方版の胴Xは、モデル値ピーク−5.8/終端−5.0に対し、現行の既定slot mappingは±3.5まで。了承した動きを弱めず再現する手当てが必要。全体の既定strengthを一律変更して既存idle等へ波及させない。
- 試作は正面開始・対象向きの終端保持。製品の現在姿勢からの接続、自然終了と中断、次の区間への遷移を実表示で確認する。現在の動作を一度正面へ不自然に引き戻すことを、単なる定義移植の結果として放置しない。
- 制作原本definition、provenance、再現手順と代表プレビューは、Git管理外tmpだけに依存せず版付きの資産として保存する。実行用登録との対応を持ち、外部モデル本体は版/hash参照を維持する。

context-checkの結論は **Plan directly**。方針を支える前提と技術的な差分を列挙でき、今回ユーザーだけが決める必要のあった3点は確定した。実装・再生等価・判定品質の検証まで済んだことを意味しない。次はこの合意を引き継いだwave構成を論じる。
