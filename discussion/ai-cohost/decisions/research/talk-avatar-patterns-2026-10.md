# 知人のトークアバターの知見(スライド 2 枚の読み取り)

> Status: 読み取りをユーザーと合意(2026-10-20)。先読みは「いったん置く」(§4)。
> 出典: ユーザーの知人のトークアバター(VRChat 内のアバターが LLM でそのまま喋る)のスライド 2 枚。画像はリポジトリに置かない。読み取りは推測を含む。

## 1. 「自然な間は、部品のあいだで生まれる」

- 相手の声を中心に、5 つの部品が回っている。
  - 言い終えたか
  - 相づち
  - 待つ間に作り始める
  - 重なった声の判定
  - 返事のストック(返しそびれた問いを溜めて、あとで拾う)
- 目指す振る舞い: 聞きながら相づちを打ち、言い切ったらすぐ返し、割り込まれたら譲り、返しそびれた問いはあとで拾う。
- 主張:「どれか 1 つでは起きない。組み合わさると起きる」。自然さも壊れ方も、部品単体ではなく、つなぎ目で決まる。
- つなぎ目で壊れた例:
  - 場の人数の判定が立たず、相づちに雑学: public なワールドで話し相手が複数いて、誰と話しているか分からなくなった(ユーザーの解釈)。
  - 関数の使い回しで、読まない質問を聞く: 意味は制作者にしか分からない。いったん無視する。
  - 前の気分を見せて、気分が張り付く: 前回の気分を判定の材料に渡したら、その気分に引っ張られて変わらなくなった。「つながり」の型の落とし穴(合意)。

## 2. 「判定の組み立て方 — いま使っている 6 つの型」

| 型 | 中身 | 例 |
|---|---|---|
| 相乗り | 同じ材料・同じ瞬間なら 1 回の問い合わせにまとめる | 言い終えたか + ガード + 返事の形 |
| 並行 | 材料が違えば別々に、同時に聞く | 話題の運び |
| 先読み | 速さのために先に聞き、外れたら捨てる | 相づちの下見 |
| 門 | 答えを使える場面でだけ聞く | 体があるときだけ顔と体 |
| つながり | 前の答えを次の判定の材料にする | センサー → 統合 |
| 締め切り | 間に合わなければ使わない | 話題の運び 0.15 秒 |
| 段階(未使用) | 粗く先に聞き、要るときだけ細かく聞く | ポーズ 27 択 |

- 答えの使い方は 4 つ。
  - しきい値で分ける
  - 確率のまま抽選する
  - 状態の目標にする(そこへ寄せる慣性はコードが持つ)
  - 次の判定の材料にする
- 判定に使っている「Jev」はサービスで、Decisions API の亜種。Decisions API に読み替えてよい(ユーザー)。
- 知人は Claude をセッション型ではない API で呼び、複数のモデルに別々のことを考えさせて Jev で統合している(ユーザーが本人に確認)。

## 3. チャッピーへの示唆(ユーザーとの対話から)

- **確率のまま抽選**: チャッピーは今、判定の答えのうち一番強いものだけを使っている。抽選は盲点だった(ユーザー)。自然さになるか、気まぐれに見えるかは要検討。未着手。
- **先読み**: ユーザーの関心の中心。目指すのは「言い終わりや判定の確定を待たずに、頭に返事を作らせ始め、外れたら捨てる」。そのために、複数の候補を並行で作って Decisions API で選ぶ形まで考える必要があるかもしれない。

## 4. 先読みの前提と、いったん置く判断(2026-10-20)

- **頭は Codex のセッション型のまま(ユーザー)。**
  - ChatGPT Plus のサブスク枠でしゃべれるのが最大の利点。Claude の Max プランの API クレジット(月 100 ドル分)もあるが、しゃべらせたいのはチャッピー(GPT)。
  - 従量課金になるのは困る。記憶を頭の側が持つ利点も大きい。
- セッション型では、先に聞いた分が会話に残るので「捨てる」がそのままではできない。Codex app-server の中断・巻き戻し・会話の複製・途中で足す、が使えるかは未調査【推測で挙げただけ】。
- 先読みで縮むのは、主に「言い終わり → 文字起こしの確定 → 話し始めの判定」の 1〜2 秒。頭そのものの待ちは前にずれるだけで、短くはならない。
- 直近の配信では、頭の最初の文字は中央値 2.4 秒で、ユーザーは「この速度なら不満はない」([../../research/context-growth-2026-10.md](../../research/context-growth-2026-10.md) §9)。
- **判断: 先読みはいったん置く(ユーザー 2026-10-20)。** 混む時間帯の配信で遅さが気になったら、また拾う。Codex app-server の機能の調査も、使う気になったときに行う(先に調べても古くなるため)。
