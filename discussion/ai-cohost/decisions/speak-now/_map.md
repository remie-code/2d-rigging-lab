# Speak-now Map

> decisions/ の子。配信者の発言の文字起こしが確定するたびに、チャッピーが「今どう反応するか」を判定 API で決める取り組み。話し始めの判定(区切り応答)の作り直しの中心。

## 1. Why / 合意(ユーザー × ウンディーネ 2026-10-16)

- 今の区切り応答(喋り終わり → 固定 2 秒 → 構え → 転写到着で発火)は不自然で、ElevenLabs STT では構えより先に転写が着いてほぼ動かない([../../implementation/screens/cockpit-stt-selection.md](../../implementation/screens/cockpit-stt-selection.md) §7)。
- 転写バッファに配信者の発言が 1 件確定するたびに判定を呼ぶ。入力は直近 3 分・最大 20 行の会話(配信者とチャッピーの両方)。
- 選択肢は当初 4 つ(続きを待つ / 相槌を打つ / 話し始める / 見送る)。02 で v2(待つ / 相槌 / 応答 / 自発)に変更: 話し始めるを応答と自発に分け、見送るは待つに統合した。
- 口数の性格(控えめ / ふつう / おしゃべり)を問いに入れ、キャラクター設定が判定にどれだけ効くかを見る。
- 問い: 「ゲーム配信で配信者の隣にいるサポート役の AI Tuber「チャッピー」として、配信者の発言がひと区切りついた今、どう反応するのが自然か？」
- 呼びかけ(名前を呼んだら即発火)は判定に明示的には入れない。ただし判定が呼びかけに答えないことがあるかは確かめたい。
- 判定中に配信者が喋り始めても判定は捨てない(人間と同じく、チャッピーには好きに振る舞ってほしい)。
- 判定エンジンは差し替えやすい作りにする(Decisions API 以外がデファクトになっても一帯を作り替えずに済むように)。
- 費用は気にしなくてよい規模(発言の確定ごと、テキストのみ)。
- (2026-10-16 追加の合意)
  - 問いは C を採用: 「{性格の 1 文} ゲーム配信で配信者の隣にいるサポート役の AI Tuber「チャッピー」として、配信者の発言をここまで聞いた今、どう反応するのが自然か？ 配信者の話がまだ途中なら待ち、話し終えていればどう反応するかを選ぶ。」選択肢は v2(待つ / 相槌 / 応答 / 自発)。性格は口数モード(控えめ / ふつう / おしゃべり)に対応。
  - チャッピーが考えて喋り終わるまで(忙しい間)は判定を呼ばない。
  - 喋り終わった直後に 1 回だけ判定を回す(忙しい間に配信者が話した内容を拾うため)。
  - 判定の入力範囲は、チャッピーが喋る前の内容も含む(チャッピー自身の発言が文脈になる)。直近 3 分のみとし、20 行の上限は外す(細かい区切りで実質 1 分程度しか入っていなかったため)。
  - アーカイブ実験ではチャッピーの発言が旧方式のもので、判定 → 発話 → 次の判定の流れを確かめられない。操縦席に組み込んで実地で試す(次の一歩)。
