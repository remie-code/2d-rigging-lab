# speak-now: 相槌の判定でも喋らせる — 合意

> Status: 合意 Accepted(2026-10-17)、context-check 済み。Gnome が実装済み・未コミット(`node --test` 1264/1264、check:soul-zone 通過)。ユーザー確認合格(「かなり自然。相槌で喋る設定は大成功」2026-10-17)。
> 前提: [integration.md](integration.md)(§2 で「相槌 → 何もしない」としていたものを改める)。

## 1. 動機(ユーザーの実地確認 2026-10-17)

- 操縦席のログで、配信者が話している 48 秒の間に「判定: 相槌」が 5 回(確率 .34〜.44)出たが、何もしないため黙ったままだった。配信者は「相槌だよっていう前提で推論して、サクッと返させるみたいな振る舞いにした方がいい」。
- 速さの懸念は小さい: codex-61-sol の LLM 部分は 2.2 秒(フィードのチャッピーの行は喋り終わってから出るので長く見えていただけ)。

## 2. 合意

- 判定が相槌のときも、通常と同じ頭・同じ会話の流れ(セッション)で発火し、喋らせる。相槌専用の別モデルは使わない。
- ~~画面は撮らない~~ → **画面も見る**(`fire({ vision: "preferred" })`。2026-10-17 改め、§4)。
- LLM には、その 1 回だけ先頭に「**今は配信者の話に相槌を打つタイミング。**」とだけ渡す。「短く」「一言で」「質問しない」などのやり方は指定しない(LLM の自主性を尊重。手段を示すとそれに縛られるため)。
- **歯止め**: 前の相槌を喋り始めてから 8 秒は、次の相槌を喋らせない(判定が相槌でも何もせず流す)。相槌どうしにだけ効かせる(応答・自発の直後の相槌は止めない)。秒数は設定で変えられるようにする。
- **相槌のあとは、喋り終わった後の判定(after-busy)をしない**(相槌は短く、配信者はずっと話しているので次の発言で判定が回る)。
- 応答・自発の振る舞いは今のまま。

## 3. 実装報告(Gnome、2026-10-17)

- speak-now.mjs: 相槌も発火の選択に加え、`SPEAK_NOW_BACKCHANNEL_INSTRUCTION`(「今は配信者の話に相槌を打つタイミング。」)と `SPEAK_NOW_BACKCHANNEL_MIN_INTERVAL_MS`(8000)。歯止めは判定結果が返った時点で確かめ、行き先 `skip-interval`(確かめる順は OFF・KILL → 忙しい → 間隔)。`markBackchannelSpoken()` で数え始め、その忙しさが明けたら after-busy を止めて溜まった発言を捨てる。
- cockpit-server.mjs: 相槌は `requestSelfFire("speak-now", { vision: false, instruction })`。相槌の発火中に orchestrator が `speaking` になった時点を数え始めにする。オプション `backchannelMinIntervalMs`。設定は `cockpit-settings.local.json` の `backchannelMinIntervalSec`(再起動で効く)。
- Gnome が決めた点: 数え始めは実際に喋り始めた時点(Codex 系・Claude 系とも `speaking` を通ることを確認したので代用なし)。喋らずに終わった相槌の発火は数えず、after-busy も止めない。設定 0 は「歯止めなし」。フィードの発火結果は応答・自発と同じ `self-fire (speak-now)`(直前の判定行で区別できる)。表情タグだけの返事は一括経路では「喋った」と数える近似がある。

## 4. 改め(2026-10-17、ユーザー)

- 相槌のときも画面を見る(応答・自発と同じ `vision: "preferred"`)。理由: 撮影の常駐化で撮影が約 0.05 秒になり、画面を見ても応答時間がほとんど変わらないため。それなら画面の情報を取った方がよい。
