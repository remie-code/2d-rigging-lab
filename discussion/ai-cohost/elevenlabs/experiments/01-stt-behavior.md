# Experiment 01 — リアルタイム STT の振る舞い

> Status: 3回実施(2026-10-16): 既定 VAD ×2(取り込み 500ms / 50ms)、VAD 0.3 秒 ×1。手動方式は実施しない(ユーザー判断: 0.3 秒未満にできないなら 0.3 秒で十分)。
>
> 結論(ユーザー合意 2026-10-16): VAD 0.3 秒で commit が喋り終わりから 1 秒以内に届くため、**commit を順に LLM へ渡す**方が素直。partial は文が揃うのが commit より遅く、短い相槌の扱いも不安定。

## 1. 目的

`scribe_v2_realtime` に実マイクの音声を流し、次を観測する。partial と commit のどちらを主に使うかを決める材料にする。

- partial がどの頻度で届き、どう書き換わるか(後ろに付け足すだけか、前の部分も直すか)。
- commit がいつ届き、最後の partial とどれだけ違うか。
- 確定方式(VAD 既定 1.5 秒・短縮 VAD・手動)ごとの、喋り終わりから commit までの時間。

## 2. 方法

- 入力: ユーザーが実際にマイクで話す(配信と同じ条件。ユーザー判断 2026-10-16)。マイクは soul の耳と同じ ffmpeg 取り込み(16kHz mono s16le)。
- 送信: 100ms ごとに `input_audio_chunk` で送る。`language_code=ja`。
- マイク取り込み: dshow の `-audio_buffer_size` を既定 50ms で指定(2回目以降。1回目は指定なし)。
- 遅延の物差し: 同じ音声を手元の Silero VAD + セグメンタ(speechPad 0、最小無音 400ms)にかけ、無音が始まった時刻を「喋り終わり」とする。手元 VAD は計測のためだけに使い、本番の仕組みではない。
- 手動方式では、手元 VAD が喋り終わりを判定した直後のチャンクに `commit: true` を付ける(喋り終わりから約 400ms 後)。
- 記録: 音声は保存しない。イベントの時刻と文字起こしだけを `tmp/elevenlabs-stt/runs/`(gitignore)に JSONL で残す。discussion には要約と数字だけを書く。
- スクリプト: [apps/soul/agent/scripts/probe-elevenlabs-stt.mjs](../../../../../apps/soul/agent/scripts/probe-elevenlabs-stt.mjs)

```powershell
node --env-file=apps/soul/agent/.env.elevenlabs.local apps/soul/agent/scripts/probe-elevenlabs-stt.mjs --strategy vad --seconds 60
node --env-file=apps/soul/agent/.env.elevenlabs.local apps/soul/agent/scripts/probe-elevenlabs-stt.mjs --strategy vad --vad-silence 0.3 --seconds 60
node --env-file=apps/soul/agent/.env.elevenlabs.local apps/soul/agent/scripts/probe-elevenlabs-stt.mjs --strategy manual --seconds 60
```

## 3. 観測

### 3.1 1回目(既定 VAD 1.5 秒、取り込みバッファ指定なし、60 秒)

- ユーザーの第一印象: 「思ったよりすごそう」。
- **取り込みの問題**: 手元の時刻がほぼ全部 0.5 秒刻み(x.49 / x.99)だった。マイク音声が約 0.5 秒ずつまとめて届いていたと見られる(dshow の既定バッファと推測)。このため ElevenLabs への送信も 0.5 秒単位の塊になり、物差しの精度も ±0.5 秒しかない。
- 接続から最初の partial まで: 最初のチャンク送信から約 2.3 秒(公式の「最初の約2秒をバッファ」と整合)。
- **partial**:
  - 発話中、約 1 秒おきに届く(公式の「約1秒単位で処理」と整合)。
  - 書き換えはほとんどが語尾・句読点(`か。`→`か？`、`ますか。`→`ますかー。`)。基本は後ろへの付け足し。
  - 冒頭が丸ごと置き換わる例が2回(「はい。」→「お、始まった。」、「いいですよ。」→「へー、」)。
  - 最後の partial は commit とほぼ同じ文になっており、その約 0.3〜1 秒後に commit が届く。
- **commit**: 直前の手元 VAD の無音開始から 1.5〜2.3 秒、だいたい 2 秒前後(8 件。±0.5 秒の誤差を含む)。既定 VAD では現行 whisper(≈1.9 秒)と同程度。
  - 比較の注記(2026-10-16、サブエージェント実測): 現行 whisper の ≈1.9 秒([../../experiments/s2-ears.md](../../experiments/s2-ears.md))は speechEnd 発火時刻を起点とし、模擬マイク(100ms 注入)で測った値で、dshow の取り込み遅れを含まない。実マイクの既定バッファでは MV7+ の音声が 500ms ごとに 500ms 分ずつ届く(実測)ため、実際の whisper 経路は平均 ≈2.15 秒・最悪 ≈2.4 秒と推定される。`-audio_buffer_size 50` で約 50ms ごとになり、欠落・警告・目立つ CPU 増は見られなかった(静かな状態で各 4〜5 秒)。
- **要約表の不具合**: 手元 VAD(無音 400ms で区切る)と ElevenLabs の VAD(1.5 秒)で区切りが合わず、手元の発話単位の対応付けが破綻した。2回目以降は commit 単位で直前の喋り終わりを探す形に修正。
- 聞き取りの正否が不明な箇所(1回目): 「貸し話していいんだっけ？」「貸し話。」「いいですよ。」(ユーザーも何と言ったか不明。「貸し話していいんだっけ？」と「いいですよ。」は手元 VAD が声を検出していない区間)。

### 3.2 2回目(既定 VAD 1.5 秒、取り込み 50ms、60 秒)

- 取り込み: チャンク間隔 中央値 52ms / 最大 65ms。0.5 秒刻みは解消。
- partial: 引き続き約 1 秒おき(取り込みではなくサーバー側の処理単位による)。喋った言葉から 0.5〜1.3 秒遅れて届く。句読点は最後の言葉からさらに約 1 秒後に付くことがある。
- commit: 喋り終わり(手元 VAD の無音開始)から 1.6〜1.9 秒(3 件)。無音しきい値 1.5 秒 + 0.1〜0.4 秒。
- **長く喋り続けると commit が来ない**: 1.5 秒未満の間で喋り続けた 34 秒間、commit が出ず partial が伸び続けた。最後は公式の「約36秒で自動コミット」により文の途中で確定された。
- 書き換え: 大半は語尾・句読点。短い発話の冒頭が揺れた例あり(「え？あ、これで」→ partial「お、お、これで」→ commit「え？あ、これで」)。最後の partial と commit が一致しないことがある。

### 3.3 3回目(VAD 無音しきい値 0.3 秒を指定 → 実効 0.5 秒、取り込み 50ms、60 秒)

- **訂正(2026-10-16)**: 0.3 を送ったが、この回の `session_started` の config は `vad_silence_threshold_secs: 0.5` だった(ログで確認)。サーバーは 0.3〜0.5 を 0.5 に丸めているとみられる(Gnome の実機確認: 0.8 を送ると 0.8)。以下の数値は実効 0.5 秒の条件のもの。

- ユーザーの所見: 「かなり良くできている」。
- **commit: 喋り終わりから 0.75〜0.98 秒(13 件、中央値 ≈0.89 秒)**。既定 1.5 秒(≈1.6〜1.9 秒)の約半分。実効しきい値 0.5 秒を引くと、処理分は ≈0.25〜0.48 秒。
- 区切り: 多くは文や句の自然な切れ目で確定した。短い断片の確定も混じる(「おー。」「なるほど。」「だから-」)。「0.4-- す-数-数百ミリ秒だな」のような言いよどみは1つにまとまった。
- **commit が最後の partial より先を含む**: 最後の partial と commit の一致は 13 件中 5 件。不一致の多くは、partial にまだ出ていない末尾の言葉を commit が含んでいた(partial「…コミットは早め」→ commit「…早めに出てるな。」)。この条件では commit が「完全な文が最初に届く地点」になっている。
- **短い相槌が commit から消える**: 手元 VAD が声を検出していない区間で「うん。」「はい。」「はい、うん。」の partial が繰り返し出て、次の発話で丸ごと置き換えられた(commit にはならなかった)。ユーザーは実際に小声で相槌を打っていたと思う、とのこと(空耳ではない)。小さく短い発話は partial に出ても commit に残らないことがある。発話途中で「11月」が出て commit で「しゃべり声から。」に直った例もある。
- サーバー VAD の無音しきい値は 0.3〜3.0 秒のみ受け付ける(0.2 / 0.1 は `invalid_request`。実機確認)。ただし 0.3 を送っても実効は 0.5(上記訂正)。それより短くするには手動方式(手元 VAD で commit)を使う。
