# 口パクの入力を ElevenLabs でどう作るか(調査 2026-10-18)

> Status: 調査済み(Sylph 3 本)。方針はユーザーと合意済み(2026-10-18、§5)。実装は未着手。
> 声とモデルの前提は [../experiments/02-tts-voice.md](../experiments/02-tts-voice.md)(声 = 案3、モデル = `eleven_v4_turbo` / `eleven_v4`)。

## 1. 今の口パク(リポジトリの棚卸し)

- **時刻はモーラごとに測っていない。** AivisSpeech の `audio_query` は `consonant_length` / `vowel_length` を全部 0 で返す。そのため「WAV の長さ − 前後の無音」をモーラ数で均等に割っている(`apps/soul/agent/src/voice/mora-timeline.mjs`、fixture は `voice/fixtures.mjs`)。
- **使う情報は母音だけ。** 開き量 `s` は母音ごとの固定値(a 0.85 / i 0.5 / u 0.55 / e 0.7 / o 0.65)。「ん」・促音・間・長音は要素を出さないが、時間の枠は消費する。
- **器へ渡す形** `{timeline: [{timeMs, vowel, s}]}`:
  - 1〜512 要素で、timeMs は厳密に増える。
  - 契約は `apps/runtime-player/src/main/control-channel/contract/channel-intent-speech-payload-schema.json`。
  - 器は口のスロット 6 つ(`mouth-open`、`mouth-vowel-a/i/u/e/o`)を前後の母音のクロスフェードで動かす。境界で少しすぼめ、最後は 400ms で閉じる。
- **同期**:
  - 文ごとに intent.speech を 1 本送る。WAV が全部できてから送り、ストリーミングはしていない。
  - 口の t=0 は器が受理した時刻。声はそのあと鳴り始め、そのずれを WAV 先頭の約 0.1 秒の無音が埋める設計になっている。
- **差し替え境界**: `prepareSpeech`(`voice/speak.mjs`)の 1〜4 手順(audio_query → synthesis → WAV 長 → timeline)だけ。
  - 成果物の形と `{timeMs, vowel, s}` を守れば、送り出し・再生・器は変えなくてよい。
  - 影響が出る所: `wavDurationSec` は RIFF(WAV)前提。barge-in の `computeSpokenPrefix`(`mind/barge-in.mjs`)は「要素数が本文の長さに比例する」と仮定している。
  - 時間割を作る処理は魂側に置く(`check:soul-zone`)。

## 2. ElevenLabs が返す時刻(ドキュメント + 実測)

- **形**: `/with-timestamps` の応答は `alignment` と `normalized_alignment` で、どちらも `characters` / `character_start_times_seconds` / `character_end_times_seconds`。音素や読みは返らない。
- **日本語での単位(実測、v4 / v4_turbo)**:
  - 入力 1 文字に時刻が 1 組つく。漢字は読みに展開されず、長い 1 区間になる(例: 「先」0.48 秒)。数字・英字も 1 文字ずつ。「ー」や小書きの文字も 1 文字として持つ。
  - 句読点の区間には、後ろの間(0.2〜0.6 秒)が含まれる。
  - `normalized_alignment` は `alignment` と同じだった。`apply_language_text_normalization` は v4 系では 400(未対応)。
- **細かさ**:
  - 80ms 刻みで、粗い区間を文字数で等分したような値が混じる【推測: 音響に合わせた文字単位ではない】。
  - Scribe の文字時刻と比べたずれ: v4 で平均 38〜67ms(最大 0.18 秒)、v4_turbo で平均 42〜96ms(最大 0.5 秒)。
  - 同じ台詞でも毎回少し変わる。
- **端**:
  - 最初の文字は必ず 0.000 から始まるが、実際の声の出だしは 0.10〜0.20 秒。
  - 最後の文字の終わりは mp3 の長さより 0.08 秒あと。
- **音声タグ**:
  - `[laughs]` は `[`・`l`・`a`…`]` と 1 文字ずつ入り、後ろの空白も 1 文字として入る。
  - タグ + 空白の区間は、笑い声などの「話していない発声」の区間にほぼ重なる。タグの文字も課金される。
- **経路の違い**:
  - HTTP stream/with-timestamps: 時刻は発話の頭からの通し値。最初のバイトまで v4_turbo 171〜284ms、v4 655〜790ms。
  - Text-to-Dialogue WebSocket(v4_turbo): チャンクごとに 0 から数え直す相対時刻で、足し戻せば通し値になる。最初の音まで約 0.31 秒(接続込み)。
  - TTS WebSocket(stream-input)は v4 系では使えない(1006)。
- **Flash**: `normalizedAlignment` は漢字が中国語のピンイン(今日 → "Jin Ri")になっていて、読みには使えない。声の評価でも外している。
- **Forced Alignment**(`/v1/forced-alignment`):
  - 公式: 文字と単語の時刻を返し、音素は返さない。日本語に対応し、料金は STT と同じ。
  - 実測できなかった: キーに権限がなく 401。
- **クレジット**:
  - 1 文字あたりの目安は v4_turbo 約 0.2、v4 約 0.4。
  - この調査で使ったのは約 130(5,020 → 5,142 以上)。

## 3. 母音(読み)を得る方法

| 案 | 中身 | 追加の遅れ | 弱点 |
|---|---|---|---|
| A1 AivisSpeech を読みだけに使う | `/accent_phrases` を合成なしで呼ぶ | 実測 5〜16ms / 文 | AivisSpeech を起動しておく必要がある。モーラと元の文字の対応が返らない。ElevenLabs の実際の読み(英字・数字)とずれうる |
| A2 kuromoji.js | 単語ごとに表記と読みの対が返る | 数 ms【推測】+ 起動時の辞書読み込み | npm の最終公開が 2018 年、41MB。数字・英字は読みが付かない |
| A3 Sudachi WASM 等 | 単語ごとの読み | 不明 | 164MB など重い |
| B1 音量だけ | 音の大きさで開き量を作る | ほぼ 0 | 母音の形は出ない |
| B2 音から母音推定(uLipSync 系 MFCC) | A/I/U/E/O を較正して推定 | 数〜数十 ms【推測】 | 較正が要る。Node への移植が要る |
| B3 Live2D MotionSync | Cubism 5 の音声解析 | 実時間 | 構成変更(描画側で鳴らす)・独自ライセンス |

- かなは表で直接母音を引ける(小書きは前に併合、ー・っ・ん は保持か閉じ)。漢字の読みだけが解析を要る。
- 組み合わせ D1: 時刻 = ElevenLabs の文字時刻、母音 = 読み(A1 か A2)、開き量 = 音量。今の `{timeMs, vowel, s}` にそのまま載る。音量を細かく追うと 512 要素の上限に近づく。

## 4. 見立て(Undine)

- 今の口パクは「文全体を均等割り」なので、ElevenLabs の文字時刻が粗くても、**句読点・漢字のまとまり・タグの区間で区切りが打てる分だけ今より良くなる**見込み【推測】。
- 素直な形: 文字時刻を「区間」(句読点・タグ・漢字のまとまりなど、読みが対応づく単位)に束ね、各区間の中に読みのモーラを均等に置く。タグ区間は口を閉じるか、笑いの口にする。
- 端の補正が要る。0.000 始まりの文字時刻と、実際の声の出だし(0.1〜0.2 秒)、それに器の受理から再生までのずれ。
- 音声の形式: mp3 のままなら WAV 長の計算と再生経路を見直す。`pcm_24000` 等で受け取って WAV に包めば今の経路に乗る【推測: 再生側の対応は未確認】。

## 5. 決めたこと(ユーザー 2026-10-18)

- 見立て(§4 の 1 点目)はユーザーも同じ見方。
- **読みは AivisSpeech から取る**(A1)。合成はさせず、読みだけ聞く。配信中も AivisSpeech は起動しておく。
- **最初から「今より良く」を狙う**。文字時刻を区間に束ね、句読点やタグの所で区切る。手間は「声だけ差し替え」とほぼ変わらないため。
- **開き量は今のまま**(母音ごとの固定値)。配信中はほとんどゲーム画面を見ているので、口の強弱まではあまり注視されない(ユーザー)。
- Forced Alignment の権限は付けない(要らない見立て。ユーザーから異論なし)。
