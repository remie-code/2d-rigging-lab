# 出先のCodexチャットからDiscordの場を開いて閉じる

2026-11-18。モデル追加をローカルmasterにマージした d57288fe から codex/discord-remote-venue を作成。両Waveの実装・独立レビュー・Windows全回帰2,591件合格。実Discordでの音声会話と、記憶を保存しての閉場を本人確認済み。[操作手順](../waves/discord-remote-venue/wave2-operation.md)・[実測と検証範囲](../waves/discord-remote-venue/wave2-completion.md)・[独立レビュー](../reviews/discord-remote-venue/wave2-review.md)。

## 合意した体験と合格条件

家のPCが稼働し、このCodexセッションからそこでコマンドを実行でき、Botや通常の音声設定は準備済みとする。Cockpitは都度起動する。スクショと「ここにチャッピー呼んで」を受けたCodexが、サーバーとVC名をBotから見える候補と照合する。確定できない場合は候補を尋ねる。家PC内の操作コマンドを使う。

- 初回接続から指定VC、読む先はそのVCの付属チャット、Discordの見る窓はなし、自発ON。ロールの保存済みモデル・声とDiscord準備の文字起こしを使う。明示された対象・ロール・モデル・読む先・見る窓・自発の指定はこの場だけに適用する。会話と担当モデルの解決にはこの場で有効なモデルを渡す。Codexを選んだ場合は記憶・小タスクも同じモデル、Claudeロールでは通常のCockpitと同じCodex担当を使う。
- 実際の接続先・有効ロール/モデル・チャットの選択と利用状態を確認して返す。操作元が終了したあとも会話できる。別ターンから同じ場を特定する。普段のCockpit操作を保ち、別の場を乗っ取ったり誤って閉じたりしない。
- 「VCを抜けて」は接続の退出のみ。「今日はここまで、場も閉じて」は、退出、進行中の小タスクの完了、通常の記憶書き出し・必要な整理と保存、場の資料解放、今回起動したCockpitの終了までを扱う。失敗や進行中を完了と表示しない。書く内容は担当LLMが決める。普段の設定は持ち越さず、書いた記憶は残る。

## Wave 1　今回の設定でDiscordの場を開く

保存値を後から戻す方法ではなく、開場時から今回の有効値を適用する。保存済み準備VC・読む先・見る窓・モデルなどを意図的に食い違わせ、最初の接続・受信・応答から正しいこと、次回の通常開場は従来の保存値になることを確認する。失敗・部分的な開場でも後続の場に漏らさない。対象を間違えたときの代替接続は行わない。

## Wave 2　Codexから起動・参加・退出・閉場を完結させる

Wave 1合格後に開始する。実行時に追える短い操作手順と、ローカルで安定して呼べる操作コマンドを用意する。利用者がDiscordのIDやプロセス番号を調べずに済むよう、候補照合と結果確認を支援する。起動元の標準入力が閉じてもCockpitが維持されること、別の呼び出しから対象を確認して退出だけ、または通常閉場・記憶保存・終了までできることを確かめる。

同じワークスペースで通常のCockpitと別ポートで起動しても、同じBotとサーバーで進行中の場を奪わない。競合時は元のプロセスを維持し、呼び出し元へ使用中と伝える。

合成Discordと隔離した状態を用い、Windowsでコマンドの起動・復帰・終了を実測する。記憶が保存されて残り、後片付け後に個別設定が普段の起動へ漏れないことを照合する。実Discordへの参加・本人との音声疎通は後日の本人確認。実際のサービス・テスト代替・未確認を記録する。
