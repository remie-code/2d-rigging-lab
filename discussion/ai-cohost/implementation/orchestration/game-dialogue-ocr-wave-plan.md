# ゲームの台詞を黙読しても、次の会話で一緒に振り返れる

2026-11-21。作業ブランチは `codex/game-dialogue-ocr`。Wave 1はA・Bを並行し、独立レビュー後にWave 2へ進む。各OrchはGPT-6.2 Solの実装ノームと別コンテキストのレビューシルフを使う。Undineが依存関係と配信者の最終確認を持つ。

## 完了の体験

実装・独立レビュー済み。保存済み録画146枚の再生と、Windowsの隔離した場での会話入力・範囲表示の照合を終えた。2026-11-22、配信者から文字起こしは概ね意図どおりとの確認を得た。[Wave 1A](../waves/game-dialogue-ocr/wave-1a-completion.md)・[Wave 1B](../waves/game-dialogue-ocr/wave-1b-completion.md)・[Wave 2の結果と配信者手順](../waves/game-dialogue-ocr/wave-2-completion.md)

いつもの配信の場で、相方が話す間にゲームを数ページ黙読し、消えた台詞に言及するとチャッピーがそれを踏まえて返す。Cockpitの会話欄には読めた本文が「ゲーム画面」として出て、返答時の「推論に使った範囲」を見ればどこまで渡ったか分かる。配信者の確認は最後の一回。開発中のテストは隔離した設定・場・記憶で行う。[体験と受け渡しの合意](../../game-dialogue/screen-text-blocks.md)

## Wave 1　独立した二つの担当

- **A　認識と追跡。** Windows標準の日本語OCRで指定窓から得た画像を読み、文字送り・一時的な空振り・左右分裂をまたいで追い、交代か消失で一件を確定する。独立した同時表示を分け、名前と本文など一緒に見えた行の順序・改行を保つ。意味づけは会話側に任せる。ゲーム固有の字幕矩形を要求しない。確定本文、表示順・重なりを追える時刻等を統合担当へ引き渡す。録画の三場面（35分台のダメージ、ミンホ、ティフォロス）と、片方だけが替わる同時表示で確認する。画像原本は一時作業域に置き、結果と再現手順を残す。[比較基準](../../game-dialogue/combat-damage-ocr-2026-11-21.md)
- **B　配信設定。** 窓を指定した配信の画面文字起こしは既定オン。設定でオフにでき、次回も引き継ぐ。発話文字起こし方式も選択時に保存し、Haas-jaを選んで開始前に閉じた場合と開始後に閉じた場合の両方で、次回表示と使用方式を照合する。Discordの個別設定と、現在稼働中の認識器とを混同しない。

## Wave 2　配信への接続と照合

配信の場の開閉に取得と停止を結び付ける。窓未指定、設定オフ、窓消失、再開・閉場時の遅延結果を扱い、次の場に持ち越さない。**OCRの周期はコード変更や再ビルドなしに外部設定できるようにする。** 設定の入口は既存の運用に合わせ、単位、既定値、反映時点、無効値の扱いを記録する。通常の起動経路で二つの値を設定して取得間隔に反映されること、OCRが周期を超えても仕事が際限なく積み上がらないことを確認する。Cockpitに周期入力欄は必要ない。

確定ブロックだけを配信者の発言と区別して履歴に載せる。OCR自体を発話のきっかけにせず、既存の発話機会に順序を保って新規分を渡す。会話欄の本文、モデルに渡す入力、範囲の線を同じ回について突き合わせる。直近5分・4,000文字の既定値を維持し、経過時間・文字量・渡した行・一度も渡らず落ちたゲームの行と理由を後から追えるようにする。時間と文字数の片方だけを超える例も試す。WindowsでOCR進行中も発話と従来の一枚撮影を操作できること、閉場で処理が止まることを検証する。自律的なゲーム反応の判定は後続の議論に残す。
