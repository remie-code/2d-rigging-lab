# 応答の遅れの直し(記録ファイルの掃除・締めの合図・句点)と、指示の切り分け — 計画

> Status: 実装済み(2026-10-27。突き合わせ合格 [../reviews/latency-fix/review.md](../reviews/latency-fix/review.md)、報告 [../waves/latency-fix/report.md](../waves/latency-fix/report.md)、soul 1668/1668)。実配信での確認待ち。文の途中のタグで文が分かれる件は、聞いてから決める(ユーザー)。

## 1. 原因(調査 2026-10-27、確定)

- **A: 句点の無い 1 文は、返事全体の締め(Codex の turn/completed)まで声に回らない。**
  - 文を声に回す部品は「。！？!?」で即座に出す(incremental-sentence-tag-buffer.mjs:18・:55-62・:201-206)。
  - 指示の例「そうだね<nod>」(fire-orchestrator.mjs:204)と「…見てくるね<recall …>」(skills/recall.md:7)が句点の無い形で、チャッピーが真似ている【推測】。
- **B: 使い捨てのセッションを作るたびに、記録ファイルの掃除がチャッピーの記録ファイルまで消している。**
  - `createCodexSession` は作られるたびに、共有の台帳(codex-rollouts.local.json)の thread の記録ファイルを全部消す(codex-session.mjs:588 → :204-207・:157-184)。書き出し役・思い出し係も同じ台帳を使う。
  - 消えた後、Codex は項目を書くたびに `flush_rollout … os error 2` を出し、1 回約 185ms かかる。
  - 最後の delta → turn/completed は、消された後が中央値 1.9〜2.4 秒、消されていないときは 0.10〜0.15 秒。
  - 最初の文字までも、使い捨てのセッションが初めて立った前後で 2.1→3.9 秒、2.9→5.2 秒、2.8→4.3 秒と遅くなった。
  - 「混む時間帯のせい」とした以前の推測(context-growth-2026-10.md §9)は、これで説明できる可能性が高い。
- 調査のスクリプトとログの写し: scratchpad の sweep-repro.mjs、buf-repro.mjs、gaps.cjs、diag\。

## 2. 直すこと(ユーザー決定 2026-10-27)

1. **掃除の範囲を絞る**
   - 掃除は起動時に 1 回だけ。
   - 今動いているセッションの記録は消さない。
   - 使い捨てのセッション(②書き出し役・④思い出し役)は掃除しない。
   - 可能なら、使い捨てのセッションは ephemeral(記録ファイルを作らない)で作る(Codex 0.163 で実機確認)。
2. **締めの合図を早める**: 声に回す締め(flush)を、turn/completed ではなく、最後の agentMessage の item/completed(commentary は除く)で出す。
3. **句点の無い 1 文の対策**(両方やる)
   - 指示の例を句点付きにする(「そうだね。<nod>」、recall の例も)。
   - 文の後ろに来たタグを文の区切りとみなす。
4. **指示の切り分け**
   - 会話指示(ユーザーが編集できる)の既定は、話し方の部分だけにする: 「あなたは配信の相方です。直前の会話を踏まえ、短く自然な日本語で一言だけ返してください。箇条書き・記号・長い説明はしないでください。」
   - 仕組みを教える部分(表情タグ 6 語の使い方と例、画面が渡されること)は、思い出す教えと同じく固定のファイル(例 `skills/expression.md`、`skills/screen.md`)にする。魂が①への固定の部分に足し、会話指示の画面には読むだけで出す。
   - ユーザーの設定ファイルにある上書き(codex-56-sol・codex-astra)は、「感情が動いたときだけ」より前の部分だけを残す。
5. **遅延の内訳を残す**: 返事ごとの遅延の内訳(文字起こし・判定・最初の文字・最初の文・TTS・声・合計、きっかけの種類、エンジン)を、配信ごとの記録(session-usage)に残す。会話の中身は書かない。配信どうしで比べられるようにする。
