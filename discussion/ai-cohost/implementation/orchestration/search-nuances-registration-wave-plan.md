# 探索・確認6ニュアンスの登録 — 1 Wave

2026-11-15。本人が[6案の比較](../../experiments/speech-motion-search-nuances-v1/README.md)を採用し、登録を依頼した。登録と必要な階層形式対応、普段の実行環境への反映までを扱う。新しい演技の制作・モデル変更は行わない。

## 受け取る体験と合意

- 「探す・確かめる」に属する6ニュアンスを、ゲーム画面向けとして使える。採用した動き・間・Stageなしを維持する。
- 外部データはセマンティクス→ニュアンスの階層で管理する。Decisionには制作されたセマンティクスとニュアンスの組を候補へ展開し、対象とは別の質問で一回のリクエストで選ぶ。依存する質問を同一リクエスト内で逐次実行する設計ではない。
- 原意図、発話、直前の文脈を読み、本人の意図を訂正せず選ぶ。「どれでもない」と対象不明を維持し、未制作対象へ別の版を無理に流用しない。
- 既存8演技のデータと動作を維持する。新形式を読む今回の製品更新後は、同形式の追加・変更を外部データと再起動で反映でき、追加ごとのビルドは不要。
- 選ばれた組と、アーカイブされた親演技の版・クリップから、どのニュアンスだったかを追える。全候補一覧の版保存は[後続候補](../waves/all-motion-recording/completion.md)として保留を維持する。

## 最小の対応方針

調査では現行ローダーが階層を受け付けないため、資産の追加だけでは実現しない。親の説明、ニュアンス別の説明と対象対応表、親で共有するclipsを持つ外部形式を追加し、既存のフラット形式と併存させる。

ローダーで各親・子の組に一意な選択IDを生成し、既存の候補・対象対応・再生スナップショットへ展開する方針を第一案とする。親のみの無印候補を新たに出さない。親ファイルのアーカイブを子の選択IDから参照できれば、Decision／playのwireに新たなニュアンス項目を追加する必要はない。具体的なschema名とID形式は実装担当で既存契約との整合を確認し、文書化する。

参照元試作のclipには表示用メタデータ、tracksとfixedの同名項目がある。原レンダラーはtracksを優先する。製品への変換では表示用情報をclipの実行項目へ混ぜず、重複fixedだけを除き、**全時点の実効入力と採用した時間を保つ**。試作原本は書き換えない。

## Wave構成・担当

単一Sol Orchの簡易構成。別コンテキストのGnomeが資産形式の対応・6案登録・対象検証・配布を担当し、別Review-Sylphが独立確認する。Orch自身は実装しない。

対象はPlayer外部資産ローダーと必要な型・対象テスト、外部親資産、Soulの配布資産用テスト補助の対応、運用／再現記録。既存Decision・play経路の再利用を優先する。無関係な未コミット変更を保持し、コミット／pushは行わない。

## 確認すること

1. 既存8演技・15対象組・12クリップの保持。追加後は14選択候補・21対象組・18クリップとなる見込み（親の数と候補数は区別）。
2. 新形式の読み込み、無効参照・選択ID衝突の拒否、空や不正な階層の扱い。既存形式の退行がない。
3. 6案がgameでのみ解決し、各クリップは試作の実効入力・時間と一致する。口パクを奪わず、Stageは固定。通常の接続・終了の挙動を保持する。
4. 判定候補の各説明から違いが読め、選択ID＋gameから適切なクリップを取得できる。「どれでもない」と未制作対象を保持。実APIの選択精度は未実測と分ける。
5. 選択IDとアーカイブされた親定義からニュアンスとクリップを辿れる。候補全体の版保存が入ったと主張しない。
6. 普段の `apps/runtime-player/dist/win-unpacked/Runtime Player.exe` とportableへ更新し、現用autonomous-defaultに親資産を配置する。対象の配布検証と既存資産不変を確認する。動作中なら勝手に終了しない。

実運用の発話／Decision選択は本人確認が残る。比較動画での採用と、実API選択精度の確認を混同しない。重い再生成可能な動画・PNG・ビルド証跡はtmpへ置く。
