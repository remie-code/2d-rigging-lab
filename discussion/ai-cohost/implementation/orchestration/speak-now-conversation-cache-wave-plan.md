# 配信・Discordの「今しゃべるか」で直前の会話を再利用する

2026-11-28。作業ブランチは `codex/speak-now-conversation-cache`。1 Waveで実装、独立レビュー、実APIでの確認まで行う。

## 採用判断

11/24・25の配信から再構成した計32回の判定では、従来の直近180秒方式がキャッシュ読み取り0件、方式Cが28件だった。費用は $0.003861 から $0.001718 に減少した。判定が変わった4件は許容できると合意した。実配信全体での削減率は運用後に観察する。

## Wave 1　会話の新しさを保ちながら方式Cで判定する

- 配信・Discord VCの共通の発話判定に導入する。会場ごとの問い・選択肢の意味、参加者の表示名、魂の名前と口数、5つの選択値、判定の発火条件と結果の扱いを保つ。
- 現在の分の開始を基準に、直前の完了した3分間と現在の分に履歴を分ける。判定の説明と選択肢の説明を開発者の指示に、履歴は過去分も現在分もユーザー入力に置く。過去分の末尾を30分の明示キャッシュ境界にし、現在分の新しい発言を同じリクエストに含める。
- 開始直後や発言が少ない場でも即座に判定する。分境界での欠落・二重取り、発話中に保留した人の声の取り落としを試験する。保留解除時に現在分が空でも窓内にある直前の会話は有効。共通の送信経路を使うモーション判定・コメント判定も確認する。

## 体制と完了条件

Orch-SylphがGnomeに実装と回帰テストを委譲し、別のReview-Sylphが計画・差分・テスト・実測を突き合わせる。

1. 配信・Discordそれぞれの入力と選択肢、最新発言の位置とロール、分境界・短い入力・発話終了後の再判定を関連テストで確認する。
2. 製品と同じ関数・送信経路で、キャッシュ対象になる長さの架空の会話を使い、発話判定 → モーション判定 → 同じ分の新しい一言を含む発話判定を実行する。初回の書き込み、最後の読み取り、判定結果を確認し、最後の一言が実際の入力に入ったことも確かめる。
3. 検証結果と制約をレビュー記録に残す。このWaveの完了は自動テストと上記の実測で判断する。
