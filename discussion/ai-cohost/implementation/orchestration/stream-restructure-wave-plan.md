# 配信の組み直しの wave 計画(Undine 2026-10-31)

> Status: 計画済み(2026-10-31)。ブランチ `ai-cohost/stream-restructure`。
> 根拠: 設計 [../../architecture/stream-restructure.md](../../architecture/stream-restructure.md)(Accepted)、決定 [../../discord-vc/scope.md](../../discord-vc/scope.md) §18〜§20、棚卸し [stream-restructure-inventory.md](stream-restructure-inventory.md)(触るファイル・重なり・テストの土台)。
> 進め方(ユーザー 2026-10-31): 1 本のブランチに全部積み、人間ゲートは最後の 1 回。ゲートに受かったら master へマージする。ドメインは依存に沿って**全部順に**作る(大きいファイルを共有するため並べない)。ドメインごとに Orch-Sylph が Gnome と Review-Sylph を回す(SKILL 本来の型)。見直しの粒度は §4。

## 0. 形

```
Domain A ロールと引っ越し(設定の分)
  → Domain B 記憶をロールごとに(引っ越しの記憶の分を含む)
    → Domain C 体なしの声
      → Domain D 場(配信を始める / 終える)
        → Domain E 画面の組み直し
          → 全体の突き合わせ(Sylph 1 回)
            → 人間ゲート(ユーザー 1 回)
```

- 各ドメインは前のドメインが合格して、Undine がブランチにコミットしてから始める。
- 実データ(`apps/soul/agent/cockpit-settings.local.json`、`apps/soul/agent/memories/`)に触れるのは、人間ゲートでユーザーが新しい版を起動したときの引っ越しだけ。**ドメインの作業とテストは一時フォルダだけを使い、操縦席を実データで起動しない。**

## 1. ドメイン

### Domain A — ロールと引っ越し(設定の分)(新しいロールの置き場、`model-identity.mjs`、`brains.mjs`、`fire-orchestrator.mjs`、`scripts/cockpit.mjs`、`cockpit-server.mjs`、頭脳タブの最小限)

- ロールの置き場 `apps/soul/agent/roles/<role-id>/`(`role.json` と `instructions.md`)の読み書きのモジュールを作る。`roles/` を `apps/soul/agent/.gitignore` に足す。持ち物は設計 §2.1 の表のとおり(名前・名前の手がかり・性格の指示・動かすモデル・声・口数・話し始め・体)。
- 名前を頭から切り離し、ロールから引く。cody / chappy の 2 値に固定された所(`model-identity.mjs` の型と既定、`fire-orchestrator.mjs` の名前の一文、`cockpit-server.mjs` の正規化、`ui/header.mjs` の `IDENTITY_PAIRS`)を、ロールの名前をそのまま使えるようにする。
- 性格の指示・口数・話し始め・声(方式・AivisSpeech の話者・ElevenLabs の声の id)・hotwords を、ロールから引く。声が替わったら engine を作り直す(今は種類が同じなら使い回す)。`--speaker` はロールの値を上書きする起動引数として残す。
- 頭の選択をロールの選択に替える(`/api/brain` → ロールを選ぶ口)。画面は今の頭脳タブの中で最小限(ロールの select と、会話指示の編集が今のロールの `instructions.md` に書く)。タブの組み直しは Domain E。
- **起動時の引っ越し(設定の分)**: 設計 §2.4。`roles/` が無いときだけ、設定ファイルから `chappy` と `cody` を作る。移す前に設定ファイルの写しを取る。古いキーは消さない。引っ越しは置き場を引数に取る関数に分け、一時フォルダでテストする。`main()` はそれを呼ぶだけ。結果(どの指示を使ったか・写しの置き場)は 1 回だけターミナルと画面のログに出す。
- 写しの置き場は `apps/soul/agent/tmp/` の下か、`.gitignore` に足した専用の所(Gnome の裁量。git に入らないことを `git check-ignore` で確かめる)。
- 期待値が変わる既存テストは、仕様変更に伴うものだけ直し、一覧を報告する。

### Domain B — 記憶をロールごとに(`memory-store.mjs`、`memory.mjs`、`recall` の結線、`scripts/cockpit.mjs` の記憶の 4 か所)

- 記憶の置き場をロールのフォルダ `memories/<role-id>/` にする。git もロールごと。書き出し役・思い出し役の作業フォルダをロールのフォルダにする。**②④の指示の文面は変えない。**
- 新しいロールのフォルダに `_conventions.md` が無いときだけ、種の「チャッピー」をそのロールの呼び名に差し替えて書く。**種のファイルそのものと、チャッピーの既存の `_conventions.md` は変えない。**
- **起動時の引っ越し(記憶の分)**: `memories/` の直下に記録があって `memories/chappy/` が無いときだけ、移す前に `memories/` 全体の写しを取り、中身を `.git` ごと `memories/chappy/` へ移す。Domain A の引っ越しと 1 つの流れにまとめ、結果の表示に件数を足す。一時フォルダで本物の git を使ってテストする(履歴が残ること・写しがあること・2 回目は何もしないこと)。
- Codex の頭がロールのフォルダから上へ git の根を探すかは、ロールごとに `.git` があることで止まる見込み(設計 §9)。テストで確かめられる範囲で確かめ、確かめられなければ人間ゲートの確認に回す旨を報告する。

### Domain C — 体なしの声(`speech-streamer.mjs`、`fire-orchestrator.mjs`、`soul-skills` の呼び出し、`scripts/cockpit.mjs` の器の確かめ、遅延の記録、器の状態の表示)

- 設計 §4。運び手の約束を「器は任意」に変える(器が無ければ器への送信を飛ばし、手元の再生器だけで鳴らす)。器の URL の確かめは「ロールに体があるときだけ」。
- 体が無いとき: 表情タグは剥がして捨てる(診断を出さない)。頭への表情の教えを渡さない。遅延の記録に「体なし」の印。器の状態の表示は「体なし」。
- 割り込みの「どこまで声に出たか」が、体なしでも今と同じに計算されることをテストで固定する。
- 体のあるロールの挙動は今と同じ(既存テストが通る)。

### Domain D — 場(配信を始める / 終える)(`cockpit-server.mjs` の耳の Start / Stop と close、`scripts/cockpit.mjs` の耳の hook と shutdown、メイン画面のボタン)

- 設計 §3 の「配信を始める」「配信を終える」を 1 つずつの関数にまとめ、API と画面のボタンをつなぐ。Ctrl+C は場が開いていれば「終える」と同じ道を通る。
- 始める: ロールを固める → 場の記録(記憶の本体のファイル名・頭の文脈の記録のファイル)を作り直す → KILL を OFF → 判定・発火の予定・コメント反応・思い出しの係の積み残しを捨てる(`reset` が無いものは作り直す) → 耳・目・声 → 頭のセッション → 体があれば器(つながらなければ場は開かず、「runtime-player が起動していないか、channel が開いていない」と知らせる) → YouTube の URL が入っていればつなぐ(つながらなくても場は開く)。
- 終える: 写し → 畳む → 記憶の最後の保存を待つ(「記録中」を出す) → 場を閉じる。
- 場が開いている間: ロール・マイク・文字起こしは変えられない。YouTube の URL と Connect、ゲームの窓は触れる。20 分ごとの保存と「今日を記録」は場が開いている間だけ。
- メイン画面: 場が閉じているとき中央に「配信を始める」(と「準備・設定」)。場が開いているときは今のまま。「配信を終える」の置き場は Gnome の裁量(誤って押しにくい所)。
- 耳の Stop のあとに発火の予定が動き続けるか(棚卸し §5)を、場の終わりで畳むことで消えるとテストで確かめる。

### Domain E — 画面の組み直し(`ui/settings-drawer.mjs`、`ui/control-bar.mjs`、`ui/bottom-bar.mjs`、`ui/header.mjs`、`view-logic/*`、画面のテスト)

- 設計 §6。タブを「配信の準備 / ロール / 運転 / 記憶 / ログ」にする。
  - 配信の準備: 毎回見るもの(YouTube の URL、ゲームの窓、ロールに体があるときだけ器の URL)と、たたんだもの(マイク・文字起こし、声の出力先、忙しい間のコメント)。select は保存した値を選んだ状態で出す。場が開いている間はマイク・文字起こしを触れない。
  - ロール: 今日のロールの選択(場が閉じている間だけ)と編集(名前・モデル・性格の指示・声・口数・話し始め・体)。新しいロールは今のロールを写して作る。
  - 運転: 自発・かぶり・手動の発火。口数・話し始めは外す。
  - 記憶: そのロールの記憶。「今日を記録」は場が開いている間だけ。
- 上の帯にロールの名前、下の帯の運転設定の表示はロールの値。
- 画面のテストの「タブは 6 つ」などの固定は、仕様変更として直す。

### ドメインの間の申し送り(次のドメインの完了条件に含める)

- 各ドメインの Orch-Sylph は、前のドメインの完了報告とレビューの「持ち越し」を読んでから始める。
- 前のドメインの持ち越しのうち、次のドメインの範囲に入るものは、次のドメインで扱う。

## 2. 依存と順

- A → B: B はロールの id と引っ越しの流れを使う。
- B → C: 依存は薄いが、どちらも `scripts/cockpit.mjs` の `main()` と `fire-orchestrator.mjs` を触るので順にする。
- C → D: D の「始める」は体の有無で器をつなぐかを決める。
- D → E: E の画面は場の API と「場が開いているか」を使う。

## 4. 見直しの粒度(ユーザー 2026-10-31)

**止めてよい指摘(直すまで次へ進まない)。根拠を必ず添える**(設計の節、決めごとの節、落ちたテストのどれか)。根拠を出せない指摘は止めない側に回す。

1. **設計とのずれ**: 設計 [stream-restructure.md](../../architecture/stream-restructure.md) か scope §18〜§20 のどこに反するかを言える。
2. **今の配信が壊れる**: 既存テストが落ちる。今までできていたことができなくなる。
3. **約束のテストが足りない**: §1 の各ドメインの本文にある作るもの・確かめることに、テストが付いていない。
4. **守りの決まり違反**: 鍵を読む・出す・環境変数に入れる。チャッピーの `_conventions.md`・種のファイル・書き出し役と思い出し役の指示の文面が変わる。引っ越しの前に写しを取らない。テストや作業で実データに触れる。

**止めない指摘(「持ち越し」に記録して先へ進む)**: 名前の付け方・書き方の好み・作り直しの案。根拠の無い端の場合。設計に無いことを Gnome が筋の通る形で決めた所(「裁量」として記録)。

**ループの決まり**:

- 2 回目以降の見直しで見るのは、前回の止めた指摘が直ったかと、直しで何かが壊れていないかだけ。新しい好みの指摘は足さない。
- 直しのループは上限 3 回。3 回で収まらなければ、設計の曖昧さとして Undine に上げる。
- 設計に書いていない判断の分岐が出たら、ループの回数に関わらず止めて Undine に上げる。

**機械ゲート(各ドメインの合格の条件に含める)**: `apps/soul/agent` で `node --test` が全件 pass。リポジトリの根で `pnpm run check:soul-zone` が pass。依存と lockfile は変えない(要るなら escalate)。テストは本物の LLM・外部 API を呼ばない。

## 5. 全体の突き合わせ

- Domain E の合格のあと、Sylph(opus)が 1 回だけ、ブランチの全体を設計と突き合わせる。ドメインの間のつなぎ目(場の始まりで体・記憶・ロールが正しく使われるか、Ctrl+C の道、引っ越しの流れの全体)を見る。止めてよい理由は §4 と同じ。止める指摘があれば、Undine が Gnome に直しを頼む。

## 6. 人間ゲート(ユーザー、最後に 1 回)

準備: ブランチの版で操縦席を起動する(外回りの起動は今まで通り)。

1. 新しい版を初めて起動すると、引っ越しが 1 回起きる。何が起きたか(使った指示・移した記録の件数・写しの置き場)が出る。`roles/chappy/`・`roles/cody/`・`memories/chappy/` ができ、チャッピーの記憶の履歴が残っている。
2. ロール「チャッピー」を選んで「配信を始める」→ 今まで通りにしゃべり、声も口も今と同じ。YouTube の URL を場の途中で入れて Connect でき、コメントに反応する。
3. runtime-player を起動しないで(または channel を閉じて)「配信を始める」→ 場は開かず、runtime-player が起動していない旨が出る。
4. ロールの編集で体を「使わない」にして「配信を始める」→ 体なしでしゃべる。割り込み(かぶり)も効く。
5. 「配信を終える」→ 記録中が出て、記憶が `memories/chappy/` に書かれ、記憶の git にコミットが積まれる。Ctrl+C でも同じ道を通る。
6. 設定のダイアログが「配信の準備 / ロール / 運転 / 記憶 / ログ」になっている。ゲームの窓と声の出力先は保存した値が選ばれている。
