# 配信中に再掲されたYouTubeコメントの取り込み

2026-11-25。作業ブランチは `codex/youtube-comment-redelivery`。11/24の配信では、挨拶を含む4件が元の順番で再び会話欄に現れた。通信復帰時に同じ投稿IDを返す模擬試験で二重取り込みを再現した。当日の再接続の有無は未確認。

## Wave 1　開いている場で同じ投稿を一度だけ受け付ける

- 動画IDと投稿IDを照合し、最初の受け付けで既読にする。ガード判定中に再到着してもガード・会話欄・発話判断に重ねて流さない。
- 場の寿命に沿ってメモリで保持する。自動復帰、同じ場での手動再接続、耳の停止と再開をまたぐ。場を閉じて開き直したら新規に受け付ける。配信URLの表記が変わっても、同じ動画かどうかは取得した動画IDで判断する。
- 同じ本文でも別の投稿IDなら新着。投稿IDを取得できない場合は従来どおり扱う。場の会話を蓄える転写バッファができる前に届き、取り込めなかったコメントは既読に数えない。バッファができていれば耳の起動前でも受け付ける。

## 検証と体制

同じ場で4件の取り込み後、再接続で「既読4件＋切断中の新着1件」を返す。既読分への再反応がなく、新着だけが一度流れることを確認する。複数の新着の順序、同文の新規投稿、投稿ID欠落、判定待ち、耳・接続・場の寿命は関連する自動テストで確かめる。ライブ配信への投稿は不要。

1 Wave・1ドメイン。Orch-Sylphが実装Gnomeと独立Review-Sylphを起動し、検証結果と残る制約を報告する。
