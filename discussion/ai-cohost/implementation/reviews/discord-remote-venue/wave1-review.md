# Discord 出先開場 Wave 1 独立レビュー

2026-11-18。codex/discord-remote-venue の Wave 1 最終作業差分を、[合意した計画](../../orchestration/discord-remote-venue-wave-plan.md) と照合した。

## 判定

**合格。Wave 2 着手を阻害する指摘はない。** 初回の接続・会話に場の設定が届くこと、通常閉場・開場失敗・部分開場後に普段の設定で再開できることを、コードと隔離した合成試験で確認した。

- 開場処理はロール・モデル、窓、自発を場と同じ寿命の状態に取り込み、各開場段階の前に有効にする。明示したサーバー・VC は取得結果と照合し、不一致のときは接続しない。読むチャットは初回の選択から指定 VC に付属するチャットを使い、明示指定と無効化も扱う。Discord の文字起こし方式は保存済み準備から読む。
- 合成 Discord で異なる保存値を用意し、初回 join、最初のチャットと自発応答、明示指定を使った手動応答、ロール別 Bot キーファイル、声の方式、文字起こしと目の起動を確認した。通常閉場および部分開場後に設定ファイルのバイト列が一致し、次の通常開場では保存済みの値を使用した。一時状態を手放す実装で、通常値の退避・復元処理はない。
- 本番 Cockpit の会話セッション、記憶の配置・書き出し・整理・想起、小タスクの呼び出しまで有効ロール／モデルを追跡した。記憶書き出しは依頼時のモデルを待機ジョブに保持する。担当モデルの解決では Codex を選んだ場合は同じモデルを使い、Claude ロールの場合は通常と同じローカル Codex を使う。HTTP 試験は合成の会話・小タスクと最終保存フックを観測した。本番エントリーポイント全体を外部サービス込みで通す検証はしていない。
- 不明なロール・モデルは接続前に拒否し、サーバー・VC の不一致では代替接続しない。Bot が入室してから失敗する試験では接続を破棄し、一時ロールを解放して、次の開場で通常値を確認した。自発と窓の POST は本文読み取りの前後で一時状態の同一性を確認する。

## 非阻害の指摘

[開場時の目の起動](../../../../../apps/soul/agent/src/cockpit/cockpit-server.mjs#L3187)後、セッションや器の完了を待っている間に窓の POST を受け付けると、[窓の同期処理](../../../../../apps/soul/agent/src/cockpit/cockpit-server.mjs#L3456)は開場中なので何もせず、開場完了後にも再同期しない。窓の値とキャプチャの起動・停止が一致しない可能性がある。通常 Discord にも同じ順序があり、開場リクエストに含まれた初期指定の適用は確認できた。この競合はコード確認の範囲。
