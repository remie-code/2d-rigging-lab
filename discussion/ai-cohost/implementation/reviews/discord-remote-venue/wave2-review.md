# Discord 出先開場 Wave 2 独立レビュー

2026-11-18。codex/discord-remote-venue の差分を[合意した計画](../../orchestration/discord-remote-venue-wave-plan.md)と[操作手順](../../waves/discord-remote-venue/wave2-operation.md)に照合した。

## 判定

**合格。合意した Windows の合成検証範囲で、残る阻害指摘はない。** 使用中の予約を記憶保存より前に解放していた問題、整理の巻き戻しに失敗した場合に再試行を許していた問題、通常 Discord の開場中断でクライアントを二重に破棄していた回帰は修正された。

- 候補照合は指定ロールの Bot で行い、名前と指定カテゴリから一意に定まらなければ起動しない。起動後は照合時の Bot、ロール、モデルと取得したサーバー・VC の ID を照合し、開場結果で実際の接続、モデル、読むチャットと閲覧・本文の利用可否を確かめる。CLI は同一の場の ID を要求し、通常 Cockpit や別の場への退出・閉場は拒否する。
- Windows で開場、状態確認、退出、閉場をそれぞれ別の Node CLI として呼び出した。開場コマンドの終了から 700 ms 後の呼び出しで同一 ID と `joined`、合成サーバー／出先の VC、`visitor`／`codex-astra`、資料チャットの `listening` を確認した。退出後は `open`／`outside` を確認した。
- 合成小タスクの完了前は閉場が終了コード 2 となり、書き出しは始まらなかった。小タスク完了後の一過性の書き出し失敗は終了コード 1 と `retryable: true` で報告され、資料は残った。同じ ID で再試行すると `saved`／`complete` となり、終了記録、待受消失、資料の解放、隔離記憶の実 Git コミット、設定ファイルの SHA-256 一致を確認した。自動試験は書き出し後に整理だけが失敗する場合も扱い、再試行で書き出しを重ねないことを確認した。
- 隔離した実 Git リポジトリで、合成書き出し役が本文を書いてから例外を返すと `needs-review` になり、再呼び出しでも担当を起動せず、先頭コミットが変化しないことを独立実測した。整理の巻き戻し失敗も最終差分では `needs-review` となり、再実行を拒否する。退出の確定に失敗した場合は成功を返さず、同じ場で退出処理を再試行できる。
- Windows 上の別ポートの通常 Cockpit と同一 Bot・サーバーの初回参加を両方向で競合させ、先に開いた場が維持されることを確認した。管理された場の予約は退出、小タスク待ちと保存失敗を経てもプロセス終了まで保持され、閉場完了後は通常 Cockpit が保存済みの VC で開場できる。

## 実行した範囲

- 独立実測で Windows の Node 子プロセス、detached 起動、ループバック HTTP、名前付きパイプの予約、Discord 体験と通常の記憶書き出し・資料の処理、実 Git を使用した。Discord SDK、音声、文字起こし、会話・担当 LLM、小タスクの応答、統合試験での整理本体は隔離した代替実装を使用した。
- 独立回帰で CLI、Cockpit、Discord 体験、記憶の書き出しと整理、Codex セッションの 402 件を実行した。二重破棄の修正後は 401 件合格で、失敗は記憶の配線をソース上で検査する 1 件だった。オプションの配置を修正した最終差分で、関連する配線検査 2 件と通常の Discord 開場中断 2 件を再実行し、4 件とも合格した。差分の空白チェックも通過した。
- Orch は設定・鍵・利用者データを含まない隔離コピーで本番 `scripts/cockpit.mjs` を起動した。通常モードは画面と状態 API が 200、管理用 API が 404、標準入力 EOF で終了コード 0。管理モードは Windows の detached 起動後に別呼び出しから同じ ID の空場を確認し、閉場は `not-needed`／`complete`、子プロセスは終了コード 0 だった。

## 未確認と範囲

- 実際の Discord 参加・音声疎通・チャット配送、稼働中の本番モデルや音声サービスとの通しは本人確認に残る。実ロールや既存の記憶・会話ログは検証に使用していない。通常と遠隔の Codex 会話の後片付け用台帳が別のパスを使い、使い捨ての担当セッションは台帳を使わないことをコードで確認した。
- 排他の単位は同じ PC の Bot とサーバー。別のサーバーや配信で同じロールの記憶フォルダを並行利用する場合の Git 相互排他は、この検証範囲に含まれない。
