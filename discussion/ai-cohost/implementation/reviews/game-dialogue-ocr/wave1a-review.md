# Wave 1A 独立レビュー

**合格。** Windows 日本語 OCR から表示単位の確定までの実装は、計画の三場面と、並行表示の一方が替わる検証例を満たした。配信での取得・停止や会話への受け渡しは Wave 2 の検証対象。[Wave 計画](../../orchestration/game-dialogue-ocr-wave-plan.md)

## 確認したこと

- 目の機能の Node テストを `node --test apps/soul/agent/src/eyes/*.test.mjs` で独立実行し、76 件すべて成功。文字送り、空振り、左右の断片からの復元、独立した左右の表示、消失後の再表示、短い台詞、名札と本文の改行、並行表示の交代と開始時刻・重なりを確認した。同じ本文座標で「次は北の祭壇へ向かいます。」から「次は南の祭壇へ向かいます。」に変わる例も、十分に異なる画素マスクを与えると両方が別の表示になる。[追跡テスト](../../../../../apps/soul/agent/src/eyes/game-dialogue-tracker.test.mjs)
- 実 Windows OCR で得た 146 枚分の結果と画素マスクを読み、追跡を独立に再計算した。確定・保留は戦闘 40・3、ミンホ 18・9、物語 26・6。ミンホと物語は数値除外を外しても本文・表示順・時刻が一致した。ミンホの短い問いと次の発言が順に残り、名札の一部と本文が別々に確定していた重複が解消した。物語では左右に割れた上部の一行が一件になり、「早めに北の雪祭司へ届けてやる必要がある」に対応する本文が一件で確定した。[三場面の再生手順と記録](../../waves/game-dialogue-ocr/wave-1a-endfield-replay.md)
- 戦闘の 2101.0 秒を実 Windows で別途読み、`ー 164 ア` → `16487`、`182 に` → `1821` の二件が同じ場所からの再読で除かれた。日本語の二桁入り本文は、合成画像を独立に作り、OCR の `残 り の 12 個 の 祭 壇 を 探 さ な い と 。` が除外なしで `残りの12個の祭壇を探さないと。` と追跡されることを確認した。実装担当の計測でも数字列 `12` で三つの再読が実行された。[再読の条件](../../../../../apps/soul/agent/src/eyes/windows-ocr.ps1)
- 有効画像・壊れた Base64・実行中の中止を実 Windows で試し、認識結果・`failed`・`aborted` を確認した。自動テストは空結果、言語パック未導入、プロセス異常、タイムアウト、停止と遅延出力の破棄も確認する。[OCR テスト](../../../../../apps/soul/agent/src/eyes/windows-ocr.test.mjs)

## 残る制約

- 名札には欠けや誤読があり、本文だけで確定した発言もある。操作 UI・クエスト・UID の誤読が候補に残り、クエスト行の重複も見える。戦闘の目視集計では、元 OCR に出たダメージ 11 件のうち 2 件が候補に残った。
- 画素で交代を判別できない近似文や、前の文を接頭辞に持つ別のページが同じ位置に出ると、文字送りと判断される可能性がある。今回の回帰例では、接頭辞が一致せず十分に異なる画素のあるケースを確認した。
- 画像一枚ごとに PowerShell を起動し C# を準備する。代表フレームの独立計測は約 1.46 秒。取得周期、処理の同時実行数、実ウィンドウからの撮影解像度、閉場時の停止を含む動作は Wave 2 の実際の取得経路で確認する。
