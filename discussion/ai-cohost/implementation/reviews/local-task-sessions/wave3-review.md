## ソースと回帰の確認

- `discord-companion-gateway.mjs` は選択中かつBotが閲覧できるチャットだけを受け付け、選択時刻・重複ID・通知世代で旧イベントを止める。切替や受信権限の喪失は通知と取得中の添付を無効にする。取得後にも中断を確認し、閉場中は場への登録を拒む。保存済み原本は場発行のIDを持ち、通知キャッシュの更新やチャット切替・VC退出を越えて同じ場から参照できる。集合の外のIDはPDFの道具から解決できない。短いチャット本文は主会話に付き、画像の直接添付と既存のバイト予算は維持される。PDFには原本情報と参照IDが付き、ページ画像はPDFを選んで調べる担当へ渡る。[前段Discordのレビュー](../discord-companion-inputs/wave2-review.md)
- Fireは一括応答と分割された逐次応答の両方で `<local_task 依頼文>` を発話から取り除き、元の場が開いているときに依頼を渡す。通常経路は受付時に `resolveWriterBrainDef` の作成口を確定する。Codexロールはその頭、Claudeロールは既存の補助担当と同じ既定Codexを使う。`local-task.mjs` と `recall.mjs` は `task-session.mjs` の共通処理で毎回新規の使い捨て担当を作る。主会話は担当の実行を待たず、記憶参照固有の指示・発話判断・実行一件と待ち一件の制御も維持される。[Wave 1レビュー](./wave1-review.md)
- 後着結果は元の場に結線される。Fire中とVC退出中は保留され、再参加時や次のFireで受け取れる。合成試験では自発発火が無効な状態で依頼中の別Fire、チャット切替・VC再参加、別のcwdで同じ資料を読む再依頼を確認した。返答Fireが拒否された場合や主会話のaskが失敗した場合は次のaskに持ち越す。askが成功した時点で会話側の受領となるため、それに続くTTSの失敗では再投入しない。閉場時に会話側が未受領でも、担当の完了した自由文は書き出し側が受け取れる。部分回答や読取不能の説明も自由文のまま届き、起動や通信の失敗は別扱い。
- `render_venue_pdf_page` は担当の受付時に参照できたPDFのIDと任意の1始まりのページ番号を受け付ける。ホストが場内で出力パスを発行する。担当は `view_image` で開ける。WinRTの時間・入力サイズ・ページ画像サイズの制約は一回の処理に適用され、資料の先頭3ページに固定する処理はない。局所的な道具の引数schemaはあり、担当の返答schemaや意味判定はない。
- `codex-session.mjs` はこの担当にのみ専用cwdを明示の書込ルートとする `workspaceWrite` を設定し、共有一時領域とネットワークを除外する。起動時とturn開始時に設定を渡す。主会話は従来の設定を使う。道具はApp Server接続世代、thread、turn、名前を照合し、設定を読めずユーザーMCPを無効化できない場合は担当の起動を止める。disposeは進行中のホスト描画が終わるまで待ち、App Serverの終了が確認できない場合は場の領域を保持する。描画の競合は実装を確認し、独立試験では正しいturnだけが道具に届くことを確認した。
- 通常の閉場とCLI終了は新規受付・会話配送を止め、受付済みの作業とセッションの片付けを待つ。会話の転写に加えて資料・返答・作業先を最終書き出しへ渡し、転写の増分がなくても資料や返答があれば保存する。90秒の競争待機は削除済み。書き出しとコミット・必要な整理を待ってから場が作った領域を片付ける。二度目のCtrl+Cは強制終了で、割当済みの作業領域があればターミナルにそのパスを表示する。[Wave 2レビュー](./wave2-review.md)

## 検証の範囲

- 独立実行は492/492件合格、失敗・スキップ0件。共通scope、Fire・recall、Codexセッション、Discord受信とWindowsのPDF描画、Cockpitの終端経路を含む372件と、合成Discordから実Fireと小タスクの共通scopeへ通す統合試験、書き出し・整理・強制終了を含む120件を実行した。管理sandbox内のループバックは `EACCES` となったため、同じ合成試験をループバックが利用できる外側で実行した。`git diff --check` は合格。書き出しの待機は制御した完了順序と上限撤去の差分で確認した。Soul全2,573件と依存・境界チェックの合格は実装担当の報告。
- 同梱App Server 0.163.0 と製品の担当・道具を使った `probe-local-task.mjs` の記録を確認した。Terraと既定chappyと同じSol/lowがそれぞれ、文字PDFの4頁・画像PDFの5頁で識別子に正答した。元のPDFに識別子の連続バイト列がなく、ページ描画、画像の表示、専用cwdへの書き出しと再読込が観測された。書込境界の実測は、自分の作業先への書込成功と原本・別担当・永続記憶・共有一時領域への書込拒否を含む。共有一時領域を許可した対照では書込が通る。レビューではモデル実行を再試行せず、Windowsの描画と合成の接続を独立試験で再実行した。[実験記録](../../waves/local-task-sessions/local-task-experiment.md)
- 通常の `npm run cockpit` は隔離したコピーで起動、閉場中のHTTP応答とEOF終了まで確認した記録がある。合成Discordの統合試験は実Fireと共通scopeの接続を担当のfakeで確認し、probeは同じ担当実装を実モデルと道具で動かした。起動から実Discordと実モデルを通した一連の会話は本人確認に残る。Windowsのpackage identity付き親からの起動では既知の障害があり、実モデルprobeはDesktop由来の登録情報2件を試験プロセスから外した通常起動相当の条件で実施された。Claudeロールは補助担当としてCodexを選ぶ接続を確認した。Claudeによる主会話の実モデル試験は未実施。[前段PDF実験](../../waves/discord-companion-inputs/pdf-path-experiment.md)
