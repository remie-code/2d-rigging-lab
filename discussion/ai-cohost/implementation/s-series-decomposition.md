# S系列の閉問題分解: 魂(apps/soul)の実装

> Status: 初期分解=Accepted(ユーザー合意 2026-07-12)。**ただしこれは最初の視座から見える景色であり、進行に応じて問題設定は変更され得る**(ユーザー留保を明記。C系列と同じ条項)。
> 前提: 器はC1〜C7で完成([closed-problem-decomposition.md](closed-problem-decomposition.md))。前提討議①(アクセス経路=[../soul/llm-access-path.md](../soul/llm-access-path.md))・②(会話パイプライン=[../architecture/conversation-pipeline-direction.md](../architecture/conversation-pipeline-direction.md) Accepted)はクローズ済み。
> 方式: C系列の分解原則(一問題=一つの観察可能な能力/人間ゲートと機械ゲートの分離/オーバーラップは継ぎ目の安定で殺す)をそのまま適用。**切る基準はユーザーのゲート認知負荷**(ユーザー決定 2026-07-12)。

## 1. S系列固有の前提

- 魂は特区 `apps/soul` に住む(憲章6条)。器との継ぎ目は**操縦チャネル契約のみ**(C4〜C6で凍結済み: intent.set/envelope/speech)。
- 知性は Max 20x + Agent SDK(討議①)。**転写バッファが正、SDKセッションは使い捨てキャッシュ**(討議②§2.7)。
- 原則「**AIは全部聞くが、全部では考えない**」を知覚にも延長する: 「**いつでも見られるが、常時は見ない**」(S5参照)。
- **S1着手と同時に `experiments/` を開設**し、以後全問題で `/usage`(枠消費)とレイテンシを計測し続ける(常設計器)。

## 2. 閉問題一覧(S1〜S9)

| # | 閉問題 | 観察可能なゲート | 主な検証者 |
|---|---|---|---|
| S1 | **一文が縦に貫通する**(歩くスケルトン): テキスト一文→Agent SDK(Opus)→TTS(AivisSpeech)→音声再生+intent.speechで口が動く | AIに一言(テキストで)話しかけると、**ステージの体が声で答え、口が合っている** | 人間(一目一聴)+機械(音素→モーラ写像fixture) |
| S2 | **耳が生える**: ローカルASR常時起動→転写バッファ蓄積+診断表示 | 普通に喋ると**転写が積もっていくのが見える** | 機械+一目 |
| S2.5 | **操縦席がある**(2026-07-12追補): 魂のローカルWebコクピット(127.0.0.1 HTTP+WS、ブラウザで開く)。マイク選択・耳の起動停止・転写タイムライン | ブラウザで操縦席を開き、マイクを選んで耳を起動し、**喋ると転写が積もるのが見える。CLIを一切触らない** | 人間(一目)+機械 |
| S3 | **呼べば応える**: 発火判定(キー操作=D6初手)+転写注入 | 独り言をしばらく→キー→**直前の話を踏まえた返事が声で返る**(原則「全部聞くが、全部では考えない」が初めて見える) | **人間** |
| S4 | **表情が乗る**(定義改定 2026-07-13): 「表情」=**基本顔操作の演出語彙**(視線・頭・目・口角・体の振り付け。素材に表情差分が無い現状の帰結。Variant差分はpersona/素材トラック・D7除外継続)。LLMのインラインタグ→魂のパーサ→演出語彙→intent.envelope群 | 返事の**内容に表情がついてくる**(困った話で目が泳ぐ・頷く) | **人間(美的)** |
| S5 | **目が開く**: 発火時スナップショット(ゲーム画面)を転写と共に注入 | ゲーム画面を出してキー→**画面に映っているものに言及した返事が返る** | **人間** |
| S6 | **会話が続く**: barge-in+ターン管理+セッション使い捨て運用 | **君が話し始めるとAIが黙る**。遮った事実を踏まえて会話が続く。長回しでも壊れない | **人間** |
| S7 | **視聴者が混ざる**: チャット取得層(YouTube、壊れる前提の抽象化)→文脈+発火経路 | テストコメントを投げると**拾って返す** | 一目 |
| S8 | **配信に耐える**: 安全弁(TTS直前最終検査・NGワード・キルスイッチ)+概要欄AI開示+通しリハーサル | **30分リハで事故ゼロ**、キルスイッチ即効、`/usage`で枠が持つと確認 | 人間+機械 |
| S9 | **間が生きる**(反射層=相槌): ポーズ検出→事前生成相槌の即再生+口形注入 | 相槌のタイミングが人間の呼吸(300〜500ms)に感じる | **人間(美的)** |

順序: S1→S2→**S2.5**→S3→…→S8 は直列。**S9のみ ③persona(声)の確定後**(②の順序制約: personaの声→相槌音声の事前生成)。③persona はS8完了後に着手(ユーザー決定 2026-07-12「ペルソナは最後でいい」)。

**追補(2026-07-12、留保条項の行使)**: S2閉鎖後のユーザー指摘(CLIは配信の利用シチュエーションで成立しない・発話/AI応答の表示表現の限界)により **S2.5「操縦席がある」を新設**。形の議論(器には作らない/魂がローカルWeb UIを配る/Electron不採用の根拠と唯一の劣位=グローバルホットキー)とUX定義は [screens/soul-cockpit.md](screens/soul-cockpit.md)。「一つの課題の中で二つ以上の問題を解くべきではない」(ユーザー)によりS3への同梱ではなく独立問題として挿入。S3以降の各ゲートは操縦席の上で観察される(拡張予約は同UX定義§3)。

依存の要点: S4(表情)をS6(会話が続く)より先に置いたのは**表情のない相手と長回し会話テストをしない**ため(ユーザー裁定)。S5(目)はS4の後・S6の前——表情のある相手と画面の話ができるようになってから長回しへ。人間ゲートの本丸は **S3〜S6の四連**(C系列のC2/C3に相当する、機械に判定できない層)。

## 3. S5「目が開く」の設計方針(新設能力のため先行明記)

1. **v0は発火時スナップショットのみ**: 起こされた瞬間にゲーム画面を1枚掴んで注入。「起こされた時には直近の話を全部読んでいて、画面も見ている」。
2. **常時ポーリングは初期スコープ外**: 画像はトークン消費が大きくMax枠の主敵になり得る。`experiments/` で「1回見るといくら」を実測してから、低頻度ポーリング(見どころへの自発言及)の追加を裁定する——宛先判定と同じ**段階的自動化の梯子**。
3. **キャプチャはゲームウィンドウに限定**(設計規則): デスクトップ全面は掴まない。通知・OBS画面・個人情報の写り込み事故の防波堤。
4. キャプチャ自体のCPU/GPU負荷は既知の二体負荷([orchestration/c7-closure-record.md](orchestration/c7-closure-record.md) §3)の上に乗る——S5のwave計画時の棚卸し項目。

## 4. 意図的に外しているもの

- **宛先判定の自動化**(名前呼び→セマンティック): キー操作の実機経験を積んでから(P5の梯子)。
- **視覚の常時ポーリング/見どころ検出**: §3.2の梯子の後段。
- **長期記憶・配信をまたぐ記憶**: 転写バッファは配信一回分。永続記憶は別問題系列。
- **persona の中身**(声・人格・身体): S8後の並行コンテンツトラック。身体はリグ要件を添えて model-authoring 手順へ。
- **Variant切替のAI制御**(D7): 当面対象外の継続。

## 5. 進め方

C系列と同一の規律([closed-problem-decomposition.md](closed-problem-decomposition.md) §6): 一問題ずつ議論→context-check→棚卸し(Inventory時はUndine自発派遣)→wave計画→実装→人間ゲート→完全閉鎖の**厳密直列**。実装中は人間の休憩。wave成果物は `waves/` / `reviews/` に収める(S系列用サブディレクトリを着手時に切る)。

特区固有の注意: 魂は決定論規律の非適用領域(憲章)だが、**チャネルへ出るモーラ写像・タグ→intent変換のような純関数部分はfixtureテスト可能に切る**(機械ゲートの担い手)。依存パッケージの導入(Agent SDK等)はユーザーの `pnpm install` で行う(エージェントはinstall禁止)。
