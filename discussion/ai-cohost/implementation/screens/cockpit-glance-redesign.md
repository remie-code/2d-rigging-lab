# 操縦席: 配信中に横目で見る画面への作り直し

> Status: 体験の合意 Accepted(2026-10-16、ユーザー × ウンディーネ)。実装は未着手。コメント判定の実験([../../decisions/_map.md](../../decisions/_map.md))の後に、まとめて作り直す(ユーザー合意)。
> 模型: Codex(GPT-6.1 Sol)の画像生成で 3 枚作り、3 枚目でユーザー合意。画像は `tmp/cockpit-mock/cockpit-mock-v3.png`(リポジトリ外)。

## 1. 使われ方(前提)

- 配信者はゲームをしており、操縦席は配信画面とは別のモニターにある。配信者だけが見る(配信には映さない)。
- 横目で 1〜2 秒ちらっと見るだけ。見るきっかけは「チャッピーは何に反応した？」「なんで黙ってる？」。
- **配信中は操縦席を操作できない**。発火と KILL はホットキー(`scripts/fire-hotkey.ahk`: Ctrl+Alt+F 発火 / Ctrl+Alt+G 画面を見て発火 / Ctrl+Alt+K KILL)。

## 2. 原則

- 大きさ = 大事さ。普段見たいのは会話なので、会話が一番大きい。
- 表示専用。配信中のメイン画面に操作部品を置かない(例外は KILL 中の復帰ボタン)。
- 縦スクロールなしで 1 画面。文字の大きさは今の操縦席に合わせる。
- プレースホルダ(空き枠)は置かない。今ある機能だけを置く。
- 知人の操縦席は参考にとどめ、ユーザーの使い方から組み直す(1・2 枚目は前の案に足し込んで右上が詰め込みすぎになり、却下)。

## 3. 画面の構成(3 枚目で合意)

- **上の細い帯**: 名前(チャッピー)・頭のモデル名・状態のピル 1 つ(聞いてる / 考えてる / 喋ってる)。異常があるときだけ小さな警告を出す(文字起こし切断・判定エラー・頭の停止など)。異常がなければ何も出さない。
- **会話タイムライン(主役、左 約 6 割)**: 時刻・話者・発言。最新が下。
  - 推論に使った範囲の行の左端に、つながった細い縦線(範囲の始まりに極小の「推論に使った範囲」)。
  - チャッピーが反応したきっかけの配信者の行の右端に、小さな札「応答 0.72」「自発 0.51」(speak-now の判定)。待つ・相槌などの確率の詳細は普段は出さない。
  - チャッピーの返事の行の右端に、遅延の細い積み上げ棒と合計(例 1.8 秒)。**区間の長さは実際にかかった時間に比例させる**(模型の画像は等分になっているが、それは画像の限界)。遅かったときだけ合計を琥珀色にする。
  - 反射・相槌: 起きたときだけ、会話の中に薄い灰色の 1 行(例「(相槌したかった 0.41)」)。
  - 最新の返事の行とそのきっかけの行の強調の仕方は実装時に詰める(案: 同じ色でつなぐ)。
- **コメント(脇役、右 約 3.5 割)**: 新しいものが上。投稿者名・本文・「通した」札。弾いたコメントは 1 行に畳んで薄く、「弾いた: 種類」の札だけ(本文は伏せる)。切り替えタブは置かない。中央に置かないのは、目が止まりやすい中央に主役以外を置くと目を取られるため。
- **下の細い帯(薄い文字)**: 左に運転設定の表示(自発 ON・口数・話し始め)、右にホットキーの案内と歯車「準備・設定」。

## 4. 状態ごとの入口

- **配信前**(耳が止まっていて会話が空): 会話の場所の中央に「準備・設定を開く」を大きく出す(ユーザー「非常に直感に合う」)。
- **配信中**: 右下の小さな歯車だけ。
- **KILL 中**: 上の帯を赤くし、「KILL 中」と復帰ボタンを出す(復帰は誤操作防止のため画面のボタン限定という既存の裁定を維持)。

## 5. 今の機能の行き先

| 今の機能 | 行き先 |
|---|---|
| マイクと文字起こしの開始・停止、声の出力先、画面を見る対象 | 準備・設定(今の「入出力」タブ) |
| 器への接続、YouTube の接続 | 準備・設定(今の「接続」タブ) |
| 頭の選択、会話指示の編集、記憶 | 準備・設定(今のタブ) |
| 自発の ON/OFF、口数、話し始めのモード、かぶり(barge-in) | 運転バーから準備・設定へ移す。メイン画面は下の帯の表示だけ |
| 発火(通常・画面を見て)、KILL | ホットキー。メイン画面はボタンを置かず案内だけ |
| KILL からの復帰 | KILL 中だけメイン画面に出る復帰ボタン |
| 文字起こし・ffmpeg・声などのヘルス表示 | 上の帯の警告(異常時のみ) |
| 観測フィードの全行・マーカー・ゴースト行、usage、uptime | メイン画面から外し、ログ画面または準備・設定側へ |

## 6. 後回し

- MIND(感情)の表示: ElevenLabs で喋らせるとき。
- 反射・相槌の本格的な見せ方: 相槌の検討のとき。
- 判定まわりの詳細(待つ・相槌・自発の確率、捨てた判定の理由)の見せ方。

## 7. 追加の合意(2026-10-17、2 本目の context-check の途中)

- **ホットキーは作るが、体験としては重視しない**。配信中はゲームで手がふさがっていて基本的に何も操作できず、操作するときはゲームを一瞬止めてマウスで触る(キーボードが使える状況ならマウスで操縦席を触れる)。そのため:
  - メイン画面に、マウスで押せる**小さな KILL ボタンを常に置く**(§2 の「操作部品は復帰ボタンだけ」を改める)。
  - 下の帯のホットキーの案内は消す。
- 遅延の棒: Codex と Claude それぞれで取れる区間は全部出す(Claude は「最初の文」が存在せず、「LLM の最初の文字」は実測値を捨てているので拾う)。凡例は**下の帯に小さな凡例を常に 1 行出す**(ホットキーの案内を消して空いた場所。ユーザー 2026-10-17「一旦これにしてみよう」)。
- 「推論に使った範囲」は画面を開き直しても復元しない(配信中に開き直すのは異常時だけ、という前提)。
- 設定ダイアログの初回自動展開はやめ、配信前は会話の場所の中央の「準備・設定を開く」だけにする。
- **残量のゲージ**: 意図せずチャッピーが止まる最有力候補なので、小さくても見えるようにする。Codex(週の使用率)と ElevenLabs(月のクレジット)を割合で。Claude は後回し。OpenAI API の残高は配信前に自分で確認し、ゲージは作らない(残高切れは警告)。根拠: [../../research/quota-sources-2026-10.md](../../research/quota-sources-2026-10.md)。
- 画面キャプチャの遅延(約 0.6 秒)は、常駐の撮影係に直す別作業で扱う([../../research/vision-capture-latency-2026-10.md](../../research/vision-capture-latency-2026-10.md))。
