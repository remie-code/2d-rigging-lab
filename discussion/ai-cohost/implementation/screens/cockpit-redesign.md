# 操縦席 UX 再定義: 観測ビューからコントロールルームへ

> Status: **Draft(議論中 2026-07-14)**。UI技術スタック改定(S8前の独立閉問題)のUX source of truth 候補。
> 前身: [soul-cockpit.md](soul-cockpit.md)(S2.5・Accepted)——「正本はプロセス側/UIは使い捨てビュー」を観測系について確立した。本文書はその思想を**観測系に限れば維持**しつつ、S3〜S7で積み上がった設定系・運転系を分離してIAを再設計する。
> 動機(ユーザー指摘 2026-07-14): 現操縦席は画面の約半分を設定項目が占有し、その大半は「一度設定したら記憶される・二度と触らない」もの。観測(常に見たい)の前を設定(滅多に触らない)が塞いでいる。「魂の様子が観測できるだけでいい」時代のUXが、機能増加で限界に達した。

## 1. 前提の再評価: 「使い捨てビュー」は半分だけ正しかった

S2.5の「UIは使い捨ての皿」裁定は、当時の操縦席が**観測系のみ**だったから正しかった。S3以降、性格の異なる要素が一枚のHTMLに積層した。要素を性格で仕分けると**三層**になる:

| 層 | 性格 | 中身 | 画面での扱い |
|---|---|---|---|
| **観測** | 常時見たい・流れる・状態を持たない | 転写(you/soul/viewer)・ゴースト行・発火マーカー・演出行(expr)・視覚サムネ・usage | **主役。画面の大半。** 使い捨てビューのまま(S2.5思想を継承) |
| **運転** | 配信中に触る・小さい・即届く | Fire・Fire+視覚・自発ON/OFF・口数モード・(S8)キルスイッチ | **常時手元。細い操作バー。** |
| **設定** | 一度きり・永続・記憶済み | 器Channel・YouTube URL・マイク・声の出力先・視界(ゲーム窓) | **普段は畳む。歯車で開く引き出し。** |

**核心の気づき**: 「自発ON/OFF・口数モード」は設定に見えて**運転**(配信中に切り替える)。設定の引き出しに入れると逆に不便になる。この仕分けが再設計の肝。

**S7の副産物**: 視聴者コメントは転写バッファに合流済み(viewer行)なので、**独立した「チャット欄」ペインは不要**。コメントは観測フィードにviewer行として流れる。「スクロールしないとチャットが見えない」煩わしさは統合で構造的に消える。

## 2. 定常状態(配信中)の画面

```
┌───────────────────────────────────────────────────┐
│ こーでぃー  ● Listening   耳↑ 声:ヘッドホン  [⚙設定] │
├───────────────────────────────────────────────────┤
│  ▓ 観測フィード(主役・自動スクロール) ▓             │
│                                                     │
│ 14:02:11 you    ボス強すぎ、詰んだかも              │
│ 14:02:14 ○ こーでぃー thinking…                     │
│ 14:02:18 こーでぃー パターン見えてきた？            │
│ 14:02:18   ↳ expr troubled ✓4/✗0                   │
│ 14:03:40 ▷ 自発(沈黙) 🖼画面を見た                   │
│ 14:03:44 こーでぃー セーブポイント戻る？            │
│ 14:05:02 viewer(taro) がんばれー                    │
│ 14:05:05 ▷ 自発(コメント)                           │
│ 14:05:09 こーでぃー taroありがと、いま正念場や      │
│                                          [最新へ↓] │
├───────────────────────────────────────────────────┤
│ [🎤Fire] [🖼Fire+視覚]  自発⦿ON  口数[ふつう▾] ■KILL│
└───────────────────────────────────────────────────┘
```

- **観測が縦を占有**。声・コメント・自発が一本のタイムラインに時系列で流れる(S7の単一タイムライン裁定がそのまま画面になる)。
- **下端の運転バーは常駐・細い**。Fire・自発トグル・口数モードが指の届く所に。
- **■KILL は場所だけ予約**(S8で中身が入る)。「土台を作る→安全弁を載せる」の順を画面でも体現。
- **ヘッダは一目の健康状態**(状態ランプ・耳↑・声の出力先)。

## 3. 設定の引き出し(⚙で開く・普段は畳まれている)

```
┌─ 設定 ────────────────────────────── ✕ ┐
│ 接続                                     │
│   器(Channel)  ws://…/channel  ●済 [変更]│
│   YouTube      未設定            [接続]   │
│                                          │
│ 入出力                                   │
│   マイク        MV7+             ▾       │
│   声の出力先    ヘッドホン(MV7+) ▾       │
│   視界(ゲーム窓) FooGame  ▾  [窓一覧更新] │
└──────────────────────────────────────────┘
```

一度設定したら畳まれて画面から消える。配信中に開くのは「ゲームを変えたので視界を選び直す」「チャットを繋ぎ直す」程度で、そのときだけ。トークン秘匿(Channel URLのredact)等の既存規律は維持。

## 4. 導線

```
起動: npm run cockpit  →  ブラウザが開く
        │
        ├─ 初回(設定が空) ──→ 設定引き出しが自動で開く
        │                      (マイク・器・出力先を埋める)
        │                            │
        └─ 二回目以降(記憶済) ──────┴─→ 観測フィードに直接着地
                                          ヘッダに状態・引き出しは閉じたまま
                                             │
              配信中: フィードを横目で見る
                      運転バーでFire/自発/口数を操作
                      ⚙は「何か変えるとき」だけ開く
```

肝は**「二回目以降は観測に直行」**。設定は記憶済みなので普段は一切目に入らない。現状(毎回設定が半分を占める)の逆。

## 5. 確定した設計判断(2026-07-14 議論)

- **三層の仕分け**(観測/運転/設定)を採用。自発・口数は「運転」に置く。
- **観測フィードは全部一本流し**(v0はフィルタなし。「viewerだけ/soulだけ」の絞り込みは将来の必要が生じてから)。
- **運転バーの構成**: Fire・Fire+視覚・自発ON/OFF・口数モード・(予約)KILL。過不足なしで合意。
- **チャット独立ペインは作らない**(viewer行として観測フィードに統合済み=S7)。

## 6. この再設計が技術要件を確定させる

前段の議論で立てたUI技術スタック改定の前提(a〜d再定義+新e)のうち、本UXが具体化するのは **(e) 操縦席が本物のIAを持てること**。具体の要求は:

- 設定引き出しを**畳む/開く**・初回だけ**自動展開**する。
- 運転バーを**常駐**させる。
- 観測フィードだけ**自動スクロール**する(引き出し・運転バーは固定)。
- 設定フォームは**条件付き表示・検証フィードバック**を持つ。

これらは現行の「append-onlyログに手でDOMを積む」方式では地獄、コンポーネント土台があれば素直、という差がはっきり出る領域。**技術選定の物差しは「モダンか」ではなく「このIAを組めるか」。**

守りの制約(a〜d)の再定義(議論確定 2026-07-14。出自検証: 「ビルド不要」のS2.5裁定のうち候補選定=preact+htm第一候補はS4閉鎖時の仮置き、「ビルド不要」自体は制約由来——ドグマにせず真に守るべき性質へ置き換えた):

- **(a) node起動だけで動く**: 真の要件=**配信時の起動信頼性**。`npm run cockpit` 一発・ビルド儀式なし。操縦席はS8でキルスイッチが載る主操作面になるため、むしろ強化される。
- **(b) node --testだけで検証できる**: 真の要件=**機械ゲートがブラウザ不要で速い**こと。描画のテスト手法は変わってよいが、ロジック(設定の永続・SSE→行の変換)はヘッドレスで検証できることを死守。
- **(c) ソース=実行物**: 真の要件=**gitにあるものと動くものが食い違わない信頼**。distコミット(乖離リスク)も起動時ビルド(a・dを削る)も「ビルドし忘れ」類のバグを特区に持ち込む。技術選定を最も強く縛る制約。
- **(d) 依存は軽い**: 真の要件=**ユーザーの手動install負担**への責任。「ちゃんとしたパネル」は薄い皿より重い依存を正当化しうる(バーは少し上がる)が、pure JS・ネイティブ非依存・総量責任は不変。

帰結: (c)+(a)が今なお「ビルドなし or それ相当の信頼性」を強く指す。足場が「皿が薄いから」でなく「信頼性のため」に置き換わった。

## 7. 視覚仕様(モック承認済み 2026-07-14)

ユーザー承認済み(「きれー、文句ない、この方向性でいこう」)。実装はこの意匠を正とする。

- **基調**: ダーク。こーでぃーのteal(#56d4b0系)をアイデンティティ色に。
- **話者の色分け**: you=青(#7fb3ff)・こーでぃー/soul=teal(#56d4b0)・viewer=紫(#c99be8)・自発マーカー=淡teal・barge-in=赤(#e0928f)・演出行=緑・ゴースト行=グレー斜体。
- **ヘッダ**: 名前+Listeningランプ(発光ドット)+一目の健康(耳↑・声の出力先アイコン)+右端に⚙。
- **観測フィード**: 時刻はmono小・話者ラベル色分け・演出はサブ行(インデント+arrow-back-up)・視覚マーカーは小サムネ枠+"saw title (WxH)"・barge-inは"interrupted (X/Y字, Nms)"。角丸14pxのパネルに収め、上下をヘッダ/運転バーで挟む。
- **運転バー**: 左=Fire/Fire+視覚(アイコン+ラベルのボタン)、右=自発トグル(pill)・口数モード(プルダウン: 控えめ/ふつう/おしゃべり)・KILL(赤枠・S8まで場所のみ)。
- **設定引き出し**: 接続/入出力の区画見出し・ラベル幅揃え・selectはchevron付き・状態は色ドット+文言。角丸14pxパネル・普段は畳む。
- モック実体はこのwaveの視覚仕様の正(会話内で承認)。実装はCSSカスタムプロパティでこの配色を表現(手書き・フレームワークなし)。
