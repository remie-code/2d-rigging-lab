## Windows 配布

通常版・portable のステージング版を隔離起動し、現用 r844 Export を読み取り、現用7演技のコピーから検証した。Soul Fire と Player は実 WebSocket で接続し、判定・合成・音声イベントには fixture を使った。同じ演技 ID の版 A で選択済みと未制作を記録した。起動中の編集と再接続後も A、再起動後は B を記録した。元 JSON の削除後も、両方の記録から SHA-256 を照合して定義とクリップを開けた。保存定義数は 7→8→8 で、内容が同じ定義は共有された。

通常版 `apps/runtime-player/dist/win-unpacked/Runtime Player.exe` と portable `apps/runtime-player/dist/Runtime Player 0.0.0.exe` へ配布した。両配布先からも隔離起動し、上記の全件記録と版復元のシナリオに合格した。配布物は候補と全ファイルの SHA-256 が一致し、両実行がロードした `app.asar` の SHA-256 は `4d61f49630afd41a6bb6a01bbdad36e4a36fca4599975352749bf2cce561eee9`。ASAR 内のビルド出力13ファイルは最終ビルドとバイト一致した。Electron のローカル ZIP を使ったため通常版には `version` と `resources/default_app.asar` も含まれる。

## アーカイブからの診断と後続の補強候補（2026-11-15）

### 運用の合意

意味に合わない動きの発見は、本人が配信アーカイブを見て違和感を感じることを入口とする。本人は配信とおおよその時刻だけでなく、「○○と発話している場面」という手掛かりも提供できる。本文検索と前後の文脈で区間を特定できればよく、動画時刻との自動対応は必須ではない。主な対象は最新の配信で、候補を更新していなければ現行定義と照合する運用でよい。自動的な意味適合判定・警告を必須にはしない。

### 調査で確認したこと

全件記録には原意図、区間本文、判定に渡した本文と会話文脈、判定結果、選択した演技定義の版とクリップ参照、要求応答と音声範囲がある。場面を特定した後の選択内容の調査には使える。`recordedAt` は保存時刻であり再生開始時刻ではない。要求の `accepted` は実描画の証明ではなく、画面での見え方はアーカイブを根拠にする。

選ばれた演技の版は保存されるが、その判定時に候補だった全演技・説明・対象等の組合せを一つの不変版として参照する情報はない。候補変更後に当時の候補全体を確定する点に不足が残る。通常運用の新ログディレクトリは今回の調査時点で未生成だったため、実会話での保存確認は引き続き未確認（配布後隔離検証とは区別）。

### 後続機能追加時に併せて検討する候補 — 今回は見送り

**判定時の候補一覧を版ごとに一度保存し、区間ログからその版を参照できるようにする。** これにより候補変更後も、正しい候補が存在しなかったのか、存在したのに別の候補を選んだのかを調べられる。「どれでもない」等の記録からも候補版を辿れる案とし、各区間に候補全文を重複保存する必要はない。

本人はこの補強を今は行わず、次に何か機能を追加するときに一緒に入れる候補として残すと判断した。実装の規模はまだ精査しておらず、次の実装への必須追加・着手承認ではない。発話による検索で始められるため、モーション制作を止める条件にも置かない。具体的な保存形式と実装範囲は、後続計画で改めて扱う。
