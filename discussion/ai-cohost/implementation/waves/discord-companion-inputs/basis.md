# Discordチャット資料とFireの接続

[合意済み計画とUser Gate](../../orchestration/discord-companion-inputs-wave-plan.md)を実装根拠とする。

## 場と投稿

- 投稿を場の世代、DiscordのサーバーID、チャットID、メッセージIDで識別する。添付は投稿内の添付IDを使う。本文、投稿者のIDと表示名、投稿時刻、共有先を会話入力に対応付ける。Discord Bot自身の投稿はWave 2の入口で除外する。
- 受信先はサーバーとチャットの組。新規投稿だけを扱う。同じ投稿の再配送で保持や取得を重複させない。受信先の設定が同じ値なら処理を継続する。切替や場の終了で保持を破棄し、取得／変換中の処理を中止できるようにする。古い処理が中止後に完了しても新しい保持へ書き込めないこと。再選択した同じチャットも別世代として扱う。VCの退出・再参加は保持の寿命に影響しない。
- 添付の状態を準備中、利用可能、部分的に利用可能、利用不可として扱う。取得失敗、未対応形式、上限、デコード・描画失敗は会話へ短い理由で渡せるようにする。Wave 2が添付の取得先とタイムアウトを検証し、取得サイズを読み込み中に制限する。Wave 1は実際に受け取ったバイト数・型を確認し、サイズを制限して画像をデコードできることを確認する。
- 保持はプロセスのメモリ内。新しい投稿を優先し、30分、最大12投稿を目安に収める。1投稿の本文は4,000文字、添付は4件、取得元は1件8 MiBを目安とする。Fireへ付ける直近資料もテキスト量と画像の合計数・バイト数を制限する。取得・変換・保持の上限で欠けた範囲が分かること。実装上の正確な上限と対応形式はWave完了報告・利用手順に記す。

## 音声会話への受け渡し

- `fire-orchestrator.mjs` の `askIncrementally` に通常と視覚Fireが集まる。ここで、現在のDiscordの場から取得した資料を既存の音声会話入力に付加する。用意済みの資料のスナップショットを使い、添付の取得や描画を音声応答の開始まで待たせない。資料の受信はFireのきっかけにしない。資料なしの既存入力と画面キャプチャの先行順序を保つ。
- `cockpit-server.mjs` が開いているDiscordの場の資料提供口を選び、既存 `fireOrchestratorFactory` 呼び出しを通じて `getChatMaterials` 相当の口をFireへ渡す。Wave 2で既存Discord体験が場・受信先世代ごとに資料を保持する。配信や他の場へ渡さない。
- 会話入力で外部由来のDiscord投稿、資料の種類、投稿者、時刻を示す。投稿や描画内の指示は外部資料として扱う。共有画像とPDFのページは過去の投稿としてラベル付けする。ライブのウィンドウ撮影や現在の視界として扱わない。未完了の添付については読み取れていない事実を伝えられるようにする。
- 本文、画像、PDFバイト列は `venueTranscript`、SSE、診断、エクスポートに載せない。URLとローカル絶対パスは内部の取得・変換・モデル輸送のみに使う。資料付き応答の失敗理由は既知の短い文で表示し、生の例外メッセージや資料を含む入力断片を公開診断に残さない。実際の会話で口にした内容は既存の音声会話の記録に従う。

## PDF

[合成実測](./pdf-path-experiment.md)の結果、Codexは絶対パスを開き、非圧縮の文字PDFの本文を直接検索できた。画像のみのPDFでは既存描画コマンドでページを得るためのファイル書き込みがread-onlyで拒否された。通常起動で利用できるWindows標準の `Windows.Data.Pdf` でプロセス側がページを準備し、両モデルへ既存画像ブロックとして渡す。

- Windows PowerShell 5の同梱WinRTを使う。外部PATHのPoppler・OCRやApp Server内のツール実行権限に依存しない。メモリまたはアプリ管理の一時ファイルを使い、添付のファイル名をプログラムの引数として解釈させない。子プロセスの期限、出力バイト数とページ数・縦横サイズを制限する。Windows以外、破損、暗号化、上限超過は短い利用不可の状態へ落とす。
- PDFを渡すときはファイル名と使用可能なページ番号を明示する。描画や入力の上限に達した場合は、全ページ数と渡せるページの範囲を伝える。合計上限の中で少なくとも直近のPDFが見える構成を採る。文字PDFと画像のみのPDFを同じ口で扱う。読み取れる文字の細かさは画像の解像度に依存する。

## 確認

資料の型・状態、重複、遅延取得、切替と再選択、終了、上限をテストする。通常と視覚の両方で実際に `session.ask` に入る内容を確認する。独立レビューで実差分、PDFの合成実測、テストの結果を対応付ける。
