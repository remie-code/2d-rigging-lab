# Discord モード: 人間ゲート 1 の確認手順(配信が今まで通り回るか)

> 対象: ブランチ `ai-cohost/discord-mode` の Domain A〜C(コミット `fdfc8e98` まで)。
> 根拠: 計画 [../../orchestration/discord-mode-wave-plan.md](../../orchestration/discord-mode-wave-plan.md) §1 の人間ゲート 1、各ドメインの報告 [domain-a-report.md](domain-a-report.md)・[domain-b-report.md](domain-b-report.md)・[domain-c-report.md](domain-c-report.md)。
> 各項目の「□」に印をつけ、いつもと違ったところはその場でメモしてください。全部見なくても、ふだん通り配信できたかが一番大事です。

## 何が変わったか(見た目はほぼ変わらない)

- **A**: 会話の記録(正本)を、耳ではなく「場」が持つようになった。話す人に名前を持たせられる形になった(配信では今まで通り名前は付かない)。
- **B**: 配信を始める・終える流れを、どの体験でも共通の段と、体験ごとの口(配信ならマイクの耳と YouTube)に分けた。声の用意と目(画面を撮る係)の起動を、耳の Start の中から場の段へ移した。
- **C**: 記憶を書く係・思い出す係への指示と、「今しゃべるか」の判定の問いを、体験ごとに言葉を差し替えられる形に組み直した。**配信の文面は一字も変えていない**(テストで固定)。
- 今回は引っ越し(データの移動)は無い。

## 0. 準備

- □ いつも通り、リポジトリの根の `start-cockpit.cmd` から操縦席を起動する(作業フォルダは今ブランチの版になっている)。外回り(AivisSpeech・runtime-player など)もいつも通り。

## 1. 配信を始める・しゃべる

- □ 「配信を始める」→ いつも通り開く。最初の返事が少し待つのは前と同じ。
- □ 声・口の動き・目(ゲームの画面を見て話す)がいつも通り。
- □ 話しかけると、いつもの感じで返事や相槌が出る(「今しゃべるか」の判定が今まで通り働いている)。
- □ YouTube の URL を入れて Connect し、コメントに反応する。
- □ しゃべっている途中に話すと止まる(割り込み)。KILL が効く。

## 2. 思い出す

- □ 「前の配信で○○の話したよね、思い出して」のように頼むと、今まで通り思い出して話す。

## 3. 設定の画面

- □ 設定 → 「ロール」タブの会話指示の編集で、`recall.md` の部分が `{{records}}` や `{{partner}}` のような印のままではなく、いつもの文で見える。**場が閉じているときと開いているときの両方**で見る。

## 4. 配信を終える・記憶

- □ 「配信を終える」(2 回押し)→ 「記録中」→ 「配信を始める」に戻る。
- □ 記憶がいつも通り書かれ、記憶の git にコミットが増える:
  `git -C apps/soul/agent/memories/chappy log --oneline -3`
- □ (見られたら)書かれた本体のファイルが、いつも通り「配信」の記録として書かれている。20 分を超える配信なら、途中の保存も同じ。

## 5. 終わったら

- 全部いつも通りなら合格。Undine に「ゲート 1 OK」と伝えてください。Discord の群(D〜G)に進みます。
- 違ったところがあれば、項目の番号とメモを Undine に渡してください。
