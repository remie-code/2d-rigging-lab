## 2. 設計の変更: 「VC から抜ける」と「体験を閉じる」を分ける(ユーザー判断 2026-11-01)

一番気になった点。今は VC を抜けると場が閉じ、頭のセッションと会話が捨てられるので、入り直すと前の話を覚えていない(思い出すには記録の呼び出しが要る)。

決まったこと:
- **体験(Discord の場)** が頭のセッション・会話の記録・記憶の書き出しを持つ。**VC 接続**は体験の中で入る・抜ける・移るができ、抜けても頭と会話はそのまま。TRPG の個別シーンで部屋を移る、休憩で「1 時間後に集合」して同じセッションのチャッピーが入り直す、を想定。
- 移る先は**同じサーバーの中の VC だけ**。別のサーバーへは移らない。
- **どの VC にもいない間**は、黙って待つ(耳は止める、頭と記録は持ったまま)。
- **閉じ忘れ**は自己責任(自動で閉じない・聞かない)。休憩のユースケースがあるため。
- **「通話を終える」**(体験を閉じて記憶を書く)は、配信の「配信を終える」と同じ今の場所に置く。これは場を閉じる操作で、Discord への操作ではないため。
- **記憶**は今までと同じ仕組み(体験の中でチャッピーが記録を何か所に残してもよい)。VC を抜けるたびには書かない。
- **20 分ごとの途中保存のタイマー**は体験の持ちものにする。起点は体験の始まり、そのあとは前の保存から 20 分。(今は操縦席の起動時に 1 回張るだけで、入り直して 1 分半で途中保存が走った。[gate-2-midwrite-investigation.md](gate-2-midwrite-investigation.md))
- 途中保存の書きぶり(途中か最後かを書き出し役に伝える)は**扱わない**。今の残し方で十分(ユーザー)。

そのほか決まったこと(context-check での確認、2026-11-01):
- 「Discord の VC に入る」は今と同じ。準備のタブで選んだサーバー・VC に入りつつ体験を開く(サーバーは体験の前に決める)。
- パネルの「抜ける」「移る」は 1 回押しですぐ。「通話を終える」は配信と同じく 2 回押し。
- パネルで移っても、準備のタブの「最初に入る VC」は書き換えない。
- 入った・抜けた・移った・人の出入りなど、人間が普通に気づく出来事はチャッピーも知ってよい(設計 §13.5)。
- 実装はこのブランチ `ai-cohost/discord-mode` に追加のドメインとして足し、人間ゲート 3 のあとにまとめて master へマージする。

### Discord の操作パネル

配信のときに YouTube のコメントを出している領域を、通話のときは **Discord の操作パネル**にする(通話中はユーザーが画面を操作する余裕があるため)。

| 操作 | 判断 |
|---|---|
| 今いる VC の表示・抜ける・同じサーバーの VC 一覧から入る/移る | 入れる |
| 「自発的にしゃべる」のオン/オフ | 入れる(確実に操作できること) |
| かぶり判定のオン/オフ | 入れる(確実に操作できること) |
| 見る窓の切り替えと「使わない」 | 入れる(GM から追加の資料が配られ、目を通すシーンがある) |
| VC にいる人の一覧・話している印 | **入れない**(Discord を見れば分かる) |
| 手動の Fire | **入れる**。判定(Decisions API)では話すと判断できなくても、チャッピーは発火されれば分かる場面が多いと見ている |
| KILL | 入れない(上の帯にある) |
| 「通話を終える」 | パネルではなく、配信と同じ今の場所 |
| 人ごとの「聞かない」 | **入れない**。Discord のミュートで足りる。Discord 側でできる体験をこのツールで持つのは責務違反 |
| 人ごとの呼び名 | **入れない**。通話中にチャッピーへ言えば足りる |

見た目の案: Codex(GPT-6.1 Sol)で生成した通話中のメイン画面の絵で、右の領域の配置を合わせた(上から 接続・しゃべり方・見る窓。今いる VC が一覧に 2 回出ているのは描き間違い)。**合わせたのは右の領域だけで、左の「会話」の表示は今のまま変えない**(絵の会話の欄は現状と微妙に違うが、意図ではない)。

スコープ外(今回はやらない。将来の候補):
- 秘匿ハンドアウトなどを、ユーザーを経由せずチャッピーが直接受け取る経路。
- Discord でチャッピーと個別にテキストチャットする(声に出さずに伝える欄より、こちらが望ましい)。
- VC についている文字チャットを読む・書く(「いつするか」も考える必要がある)。
