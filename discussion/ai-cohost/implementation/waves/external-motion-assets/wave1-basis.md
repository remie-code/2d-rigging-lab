# 外部演技資産 Wave 1 の受け入れ基準

[2 Wave計画](../../orchestration/external-motion-assets-wave-plan.md)の合意を、基盤と代表資産で確認する。既存6演技11組の全移行、苦笑の追加、Exportと普段のexeへの配布はWave 2。

| 確認 | 合格条件 |
| --- | --- |
| 追加・編集・削除 | 同一実行コードでJSONを追加、説明編集、削除し、ロードし直すと候補と再生解決の両方が追従する。起動中のsnapshotは変化しない。削除後の再作成は発生しない。 |
| 配置と異常 | 起動時に有効userData配下の絶対パスを特定できる。空・不正時は演技なしで発話でき、無効資産の理由を追える。有効な別資産は使用できる。 |
| 接続と選択 | Playerの実WebSocket helloとSoulの判定入力を照合する。再接続や接続切替で旧候補や古い判定を適用しない。演技と対象の独立二問、自由意図タグ、本文、直前文脈、none・unknown・未制作の記録を保持する。 |
| モデル能力 | 対象のパラメータ名と値域から全体の再生適否を決める。足りない能力の理由が分かる。新ID・異revision・異atlasで名前分岐やモデル識別子なしの再生を確認する。 |
| 既存挙動 | 初期3演技の現用設定から得られるパラメータ曲線、interest/askのPresence連動、askの待機、笑いの固定目、驚きのStage Y/scaleを新経路で比較する。 |
| 合成と接続 | Stage Presence Offでも明示Stage Y/scaleが動作する。自律設定を変更せず、演技が所有する目元は通常blink/gazeとの競合を抑え、音声口パクを通す。通常発話終了後の完走、キャンセル・次区間・切断による現在姿勢からの復帰を確認する。 |
| 発話優先 | 接続やDecisionの到着が遅い場合も音声開始を待たせない。再生に間に合わなかった古い選択は次区間へ持ち越さない。 |

独立レビューは根拠、差分、代表資産、テスト、実接続結果を照合する。最終の固定配布実行物とNative/Browserの描画比較はWave 2で再確認する。

## 既存挙動の根拠

- 採用済みの起点は `speech-motion-presets.json` と `speech-motion-state.ts`。初期3演技の試作文書は制作履歴として扱う。現用の正規化slot値は、`headless-slot-resolver.ts` で反転・強さ・範囲を経由してパラメータ値になる。BODY由来のStage入力は `autonomous-frame-heart.ts` がslot合成後に取り出すため、実値の移行と別に再現する。
- 初期3演技の互換基準は既存の採用プロファイルとr840。同じ意味と値を持つモデルへ直接再生できる。任意の別プロファイルでの旧slot反転・強さは互換基準の対象外。
  自律ホストの `input-subsystem.ts` は `createAutoMappingSlots(payload)` を使用する。現用Exportの `runtime/model.json` は顔xyzが±30、視線xyが±1、体x/zが±10で、いずれも既定値0。各slotの既定反転はfalse。体xの強さ0.35を含め、変換係数は顔30、視線1、体x 3.5、体z 10。現用値域が対称のためキーごとの変換後も補間が一致する。
- 笑いと驚きは現行のモデル値クリップと[驚き登録完了](../startled-recoil-registration/completion.md)を照合する。驚きの旧Stage倍率は試作の固定時計から復元され、Yとは接続タイミングも異なる。倍率を実値に焼く場合は補間と復帰を含め照合する。
