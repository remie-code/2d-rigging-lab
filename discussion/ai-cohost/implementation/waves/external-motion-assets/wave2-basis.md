# 外部演技資産 Wave 2 の受け入れ基準

[承認済み計画](../../orchestration/external-motion-assets-wave-plan.md) · [Wave 1 の資産契約](wave1-contract.md) · [Wave 1 の独立レビュー](../../reviews/external-motion-assets/wave1.md)

| 確認 | 合格条件 |
| --- | --- |
| 採用演技の移行 | 苦笑追加前に旧6演技11組を外部資産から再生できる。安堵3クリップは原曲線とStageを照合し、初期3演技の実値と保持、笑いの固定目、驚きのStageを維持する。旧候補一覧と旧再生経路の整理後も単独Stage Y診断を使える。 |
| 採用表情と正規Export | 採用r843の造形を保持して正規atlasとExportを生成し、再読込と描画で採用表情、通常顔、左右、笑顔、驚き、既存演技、音声口パクを確認する。 |
| データのみで追加 | 既存6演技でビルドを固定してから、採用原本の曲線を収めた苦笑JSONを外部フォルダへ置く。再起動で7演技13組になり、画面・視聴者が同じクリップを再生する。相方は未制作として記録する。演技説明は、共に困った状況を少しおかしがって苦笑し、小さく首を振る意味を伝える。 |
| 編集・削除・再接続 | 追加、説明編集、削除の各再起動でhello、実Decision入力、再生結果を照合する。起動中のsnapshotを保ち、再起動後に削除済みの資産が復活しない。接続世代に沿って候補を更新する。全段階で通常版・portableのexeと実行コードのハッシュが一致する。 |
| モデル能力 | 必要パラメータの欠落を理由付きで拒否し、同じパラメータ契約を持つ別revision・atlasで再生する。新しい演技IDも共通経路で再生する。 |
| 実描画 | NativeとBrowser Sourceを順に計測し、採用曲線、Stage、固定目、音声口パク、通常終了後の完走と、中断から通常制御への復帰を確認する。 |
| 実配布 | 候補の独立レビュー合格後、復元用バックアップを確保し、現用workspace・Export、通常exe、portable、現用スロットの外部資産を更新する。普段の配布先から隔離起動してモデルと資産の実ロード先と両描画経路を確認する。 |
| 本人確認 | 通常・portable・スロットの実ロード先、編集対象と配布元、追加・説明変更・削除と再起動の手順を記録する。本人は普段の会話で苦笑の自然さ、口パク、通常制御への復帰を確認する。 |

苦笑の動きは[採用原本](../../../experiments/speech-motion-wry-headshake-v1/README.md)に従う。モデルの採用表情は `C:/workspace/remie/rigging/astra-chan/workspace-notes/wry-smile-expression-v2/saved-r843` と現用r843を照合する。試作の静止口は音声口パクに重ねない。配布前のバックアップと隔離起動は[前回の配布記録](../startled-recoil-registration/completion.md)を参照する。通常の会話に使っているアプリは稼働状態を尊重し、隔離起動した検証プロセスを使用する。
