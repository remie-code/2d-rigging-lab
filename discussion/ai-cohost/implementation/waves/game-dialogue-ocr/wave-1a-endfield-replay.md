# 製品OCRでエンドフィールドの三場面を再生した結果

2026-11-21、Windows 11 ビルド 26200.9974、Node.js v24.19.0。保存済みのゲーム領域のPNG（1474 × 829）から、製品の日本語OCR・数値の再読・行のグループ化と追跡を通した。配信の場の操作や会話モデルへの送信はこの再生に含まれない。

## 再現手順

リポジトリ直下に `tmp/game-dialogue-endfield-probe/` の原画像と比較資料を置き、同じ場所から実行する。Windows標準OCRの日本語言語パックを使う。

```powershell
node apps/soul/agent/scripts/replay-game-dialogue-ocr.mjs
```

入力の一覧と時刻は、試作の各 `ocr.json` の画像名から取る。OCR結果はPNGのバイト列から読み直す。戦闘は `combat-35/verified/` の36枚、ミンホは `minho-44/replay-1s/` の一覧にある `minho-44/` の34枚、物語は `story/` の78枚からシークプレビューの先頭2枚を除いた76枚。PNG、過去の追跡結果、目視照合の表は[試作の比較資料](../../../game-dialogue/combat-damage-ocr-2026-11-21.md)を参照。

標準の出力先は `tmp/game-dialogue-endfield-probe/product-replay/`。各場面のJSONにフレーム時刻、OCR行の矩形、再読で除いた元行と数値、確定・保留の結果、試作の結果を収める。同一の認識から、除いた元行を戻して同じ追跡器にかけた結果も併記する。フレームのOCRエラーは空の認識として扱わず、エラーを記録してコマンドを非ゼロで終了する。標本末尾は表示中として保留に残す。JSONの `displayOrder` は表示開始順を表し、`closedAt` は確定時刻を表す。

`--scene combat-35`、`--scene minho-44`、`--scene story` で対象を選べる。 `--probe` で素材の場所、`--out` で出力先を指定できる。追跡器だけを再実行する場合は `--reuse-ocr` で同じ出力先のOCR・画素マスクのキャッシュを使う。OCRや再読の変更を検証するときは、原画像から認識する標準コマンドを使う。

製品のOCRにも対応するダメージ表示が11件出た。再読前の追跡に4件（確定3、保留1）、再読後の追跡に2件（確定1、保留1）が残った。再読前の候補のうち **2/4件（50%）**、生のOCRに出たうち処理全体で **9/11件（約82%）** を除外した。目視できた延べ57件以上を分母にすると、候補に残らなかったのは **55/57件以上（約96%以上）**。録画の全ヒット数や他の戦闘区間の割合までは測っていない。
