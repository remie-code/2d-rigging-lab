# 配信設定の保存と復元

Wave 1B は独立レビュー第2回で合格。関連テストは実装担当が602件、レビュー担当が10ファイル587件を実行し、すべて成功した。差分の空白チェックも通過した。[独立レビュー](../../reviews/game-dialogue-ocr/wave-1b-settings.md)

配信で使う STT は Cockpit で選択した時点で設定ファイルに保存する。新しいサーバーと設定ストアで、Haas-ja の選択だけで閉じた場合と、配信を開始してから閉じた場合の両方について、次の選択表示と認識パイプラインに渡る方式を確認した。Discord の準備設定とその場で稼働中の方式は別々に保持する。保存中は設定画面を閉じても場の開始操作が待機し、古い保存応答は新しい設定表示を巻き戻さない。

ゲーム画面 OCR は設定未記録なら既定オン。オフは設定ファイルに保存され、窓の変更と再起動をまたいで維持される。Wave 2 では既存の `createCockpitServer` が返す `streamOcrEnabled()` または同名のサーバー内関数で最新の真偽値を取得できる。場が配信かどうかと対象窓の有無はそこで別途確認する。設定の公開面は `snapshot.streamPrep`、`POST /api/stream/ocr-enabled`（`{enabled}`）、`POST /api/stream/stt-engine`（`{sttEngine}`）。成功時はスナップショットを返し、設定応答を受けた UI は `streamPrepRevision` を比較して配信設定の部分だけ反映する。

変更は Cockpit の設定ストアとデバイス設定配線、サーバーと HTTP ルート、設定ドロワーとメイン画面、設定表示ロジックおよび関連テスト。テストは一時設定ファイルと偽の認識器を使用した。実ブラウザ、実マイク、実ゲーム窓での操作は未検証。時計が逆行し、ページを保ったままサーバーを再起動した場合は、クライアントが再起動後の設定を旧版とみなす可能性がある。
