# 小タスクセッションの実装契約

[承認済みの計画と本人確認条件](../../orchestration/local-task-sessions-wave-plan.md)

## 別セッションでの実行と返答

- 呼び出し側が依頼を受ける場と能力を選び、依頼本文と実行設定を組み立てる。設定には担当の作成口、指示、作業フォルダ、実際に適用するサンドボックスを含める。共通層に会話の参照範囲や作業手順を決めさせない。
- 共通の実行口が依頼のたびに新しい担当を作成し、一度依頼を渡し、返答・障害・取消しの各経路で使用したセッションを片付ける。主会話の応答処理は担当を待たずに戻る。
- 自由文の返答を元の依頼と結び付ける。担当が作業の一部しかできなかった旨を返した場合も、返答として渡す。起動・通信・実行・中断の機械状態と返答は区別する。
- セッションを停止できたか確認できない場合は、返答と独立に片付けの障害を記録する。場は生存中のプロセスが使う可能性のある領域を保持する。
- 場または配線を作り直した後、旧依頼の結果を新しい場や次のロールへ配達しない。実行の完了と結果の会話への配達は個別に管理する。終える場では配達を停止したまま実行の終端を待てる形にする。
- 新しい共通の本文制限・生成時間制限を設けない。既存の記憶参照に固有の制御は記憶参照の接続部分で管理する。

## 記憶参照の接続

- `recall.mjs` が記憶ディレクトリを cwd に指定し、読み取り専用の使い捨て担当向けに従来の問いと文脈を組み立てる。共通口から得た返答を従来の found／summary へ変換する。記憶固有の打ち切りと失敗の扱いを保つ。
- `recall-desk.mjs` が実行一件・待ち一件の受付、発話中の保留、今話すかの判断、次の ask への前置きを扱う。場ごとの語と既存のログを保つ。`fire-orchestrator.mjs` の `<recall>` 受理と主会話の非待機を通常配線で確認する。
- Wave 1 では記憶参照を通常の Cockpit 起動から共通口へ通す。資料の所有と場終了の手順は Wave 2、Discord 原本とローカル小タスクの能力設定は Wave 3 で接続する。

## 場の所有権と終了順序

- 場ごとに管理下の領域を作り、資料の原本と担当の作業用ディレクトリをその場の終了まで保持する。担当ごとに新しい作業用ディレクトリを割り当てる。資料への参照は場が発行し、その場の後続依頼で解決する。場の外のパスや永続記憶を削除対象へ入れない。
- 依頼時点の場・ロール・担当設定と参照先で実行する。場の途中で変更できる既存設定は、変更後に受付する新規依頼から反映する。Discordのチャット変更・VC退出と再参加は受信の切り替えとして扱い、場の領域を破棄しない。
- 閉場に入った時点で受付と会話への発話を止め、受付済み担当の実行完了を待つ。結果の会話配送を待たず、保存側は付随する資料・返答を受け取る。開始済みの保存と最後の書き出し、必要な整理が完了または確定した失敗に至るまで、参照先を保持する。その後に場の領域を解放して次の場を開ける状態へ移る。
- 保存係に転写と資料・返答の参照を渡す。転写に変化がなくても資料や返答の追加によって最後の書き出しを頼める。参照先を読むか、何を記録するかは書き出し役が決める。閉場を90秒で進める待機上限を廃止する。

## ローカル処理の実行環境

- チャッピーは場が発行した資料の参照を使い、調べたいことを自由文で依頼する。会話から依頼を取り出した時点でその場と担当設定を結び付ける。資料名・本文・担当の返答は、指示のように見える記述も含めて内容として渡す。
- 担当には資料への参照と、依頼専用の書き出し先を渡す。実効サンドボックスが原本、別の依頼の作業先、永続記憶への書き込みを許さないことを確認する。`workspace-write` の cwd と Windows の一時領域の書き込み範囲をそれぞれ確認する。主会話の設定は既存のままとする。
- 普通のWindows起動から担当がPDFをページ指定で調べられるようにする。一回の道具呼び出しの実行単位を設けても、担当が繰り返して他ページを調べられることを実証する。読取確認には4ページ目以降に識別用の内容を持つ文字PDFと画像PDFを使う。

`<local_task 依頼文>` は Fire が逐次発話から取り出す内部タグ。依頼文は読み上げに含めない。担当モデルは記憶の書き出し・参照と同じ補助担当の選択を使い、現行の Codex ロールではそのモデル、Claude ロールでは既定の Codex を選ぶ。

Windowsの担当は専用の `writableRoots` を指定した `workspaceWrite` で動く。共有一時領域への書き込みとネットワークを無効にする。PDFの道具は、その依頼が参照できる場の資料IDと任意のページ番号を受け取る。ホストがWinRTで作成したPNGのパスを返し、担当が `view_image` で開く。描画した画像も場に属する。ホスト側の出力先は場が割り当てる。
