# 記憶の整理: 人間ゲートの確認手順

> 対象: ブランチ `ai-cohost/memory-organization` のドメイン A〜C(計画 [../../orchestration/memory-organization-wave-plan.md](../../orchestration/memory-organization-wave-plan.md)、設計 [../../../memory/organization.md](../../../memory/organization.md))。
> 上から順に試せるように並べています。各項目の「□」に印をつけ、思った動きと違ったところはその場でメモしてください。★ は特に見てほしい所です。一番大事なのは、**場を閉じたときに整理が走り、本体の中身が変わらずに年と月の棚へ移ること**です。

## 0. 準備

- □ 操縦席を止めていたら起動し直す。起動中のままだと古いコードのまま動く。作業フォルダはブランチ `ai-cohost/memory-organization` のまま。
- □ 記憶の置き場(`apps/soul/agent/memories/chappy`)は、まだ一度も整理していない。なので、**次に場を閉じたときに最初の整理が走る**。今ある本体 40 件の引っ越しも、このときにまとめてやる。量が多いので、数分〜十数分かかるかもしれない(上限は 30 分)。
- □ 走る前に控えが `apps/soul/agent/memory-backups/chappy/` にできる。何かあってもここから戻せる。

## 1. 1 回目の場(最初の整理)

1. □ いつもどおり場を開く(配信でも通話でもよい)。少し話して、途中保存が 1 回走るくらいまで続けると、書き出し役の新しい頼みも見られる(必須ではない)。
2. □ ★ 「配信を終える」(または「通話を終える」)で閉じる。Ctrl+C では閉じない。
   - 画面: いつもの「記録中」のあと、真ん中に「記憶を整理しています…」、状態の札に「整理中」が出る(Discord の画面でも「記憶を整理しています…」)。
   - ターミナル: `memory: organising (role chappy)` が出て、終わると `memory: organised (commit xxxxxxx)`。
   - 終わってから場が閉じる。
3. □ 走らなかったときは、ターミナルの `memory: organiser ...` の 1 行をメモする。例: `organiser rejected: the records' contents changed` は、見張りが止めたということ。変更は捨てられていて、記憶は前のまま。

## 2. Undine が見る

閉じ終わったら、Undine に「整理が終わった」と伝えてください。Undine が次を確かめます(記憶の中身を読むことは、ユーザーの了承の範囲)。
- 記憶の git に `整理役 <日時>` のコミットがあり、本体がすべて「中身はそのまま、場所だけ変わった」になっている。
- 本体が `<topic>/<年>/<月>/` に入り、トピックの直下に本体が残っていない。
- `_conventions.md` と目次が、新しい置き方を説明している。目次が探しやすくなっているかは、ユーザーにも見てもらう。
- 控えの bundle が 1 個できている。

## 3. 2 回目の場(書き出し役の新しい決まり)

1. □ もう一度、場を開いて少し話し、閉じる。
2. □ 閉じたときに整理は**走らない**。前の整理から 1 週間たっていないので、「整理中」は出ず、ターミナルにも organising の行は出ない。
3. □ Undine が見る: 新しい本体がトピックの直下に、`_conventions.md` の決まりどおりの名前でできている。トピックの目次に 1 行足されている。

## 3b. 1 回目の結果(2026-11-05)

- 整理は走った(記憶の git `224825b`)。本体 43 件はすべて中身そのままで棚へ移り、控えも 1 個できた。
- ただし話題の目次(サブトピック)は作られなかった → 計画の Domain D で直す。

## 3c. 来週の閉じ(Domain D のあと・前の整理から 1 週間後)

1. □ 操縦席を Domain D の版で起動し直しておく。
2. □ 前の整理(2026-11-05 18:15)から 7 日たったあとに場を閉じると、整理が走る。待つ上限は無いので、終わるまで待つ。
3. □ Undine が見る:
   - 各トピックの中にサブトピックのフォルダ(目次 `_map.md` だけ)ができ、棚にある本体(1 回目に移した分を含む)がどれかのサブトピックの目次に載っている。本体の中身はそのまま。
   - 月の棚ごとに時系列の目次 `<topic>/<YYYY>/<MM>/_map.md` があり、トピックの目次は入口(一言 + すぐ下のサブトピックの一覧)になっている。年のフォルダに目次は無い。
   - `_conventions.md` に、書き出し役の書く場所(月の棚)と足す目次、サブトピックの目次が「いつの整理までの分か」、新しい分は月の目次で探すことが書いてある。
   - この 1 週間の②の本体は、月の棚に直接書かれている。
4. □ ユーザーが見る: サブトピックの分け方が探しやすいか。

## 4. (やってもよい)Ctrl+C で打ち切る

整理中に Ctrl+C を押すと、整理だけすぐ打ち切って終わる。変更は捨てられ、時刻は進まないので、次の閉じでやり直す。確かめたいときだけでよい。ふだんの運用では場を閉じる操作で終える。
