# Wave 1の実装・受領基準

[2 Wave計画](../../orchestration/performance-attention-wave-plan.md)に従う。対象の配置、通常終了と中断の区別、既存演技の移行は[ユーザー判断](../../../concept/speech-motion-performance-and-attention.md#7-製品接続のcontext-check2026-11-12確定)を継承する。[承認試作](../../../experiments/speech-motion-brief-relief-variants-v1.md)を曲線と表示の比較基準とする。

| 確認項目 | 合格条件 |
|---|---|
| 原本 | 採用版の定義・provenance・再現手順・代表プレビューを実験記録と同名のディレクトリに保存。再現の入力は保存先と指定した外部r804モデルから取得できる。実行用定義の対応を曲線単位で追える |
| 登録と直接再生 | receive・interest・askの相方3組、短く息を抜くの相方・ゲーム画面・視聴者3組を解決し、実WebSocket経由で再生する。既存preset IDでの呼出しも通る。未制作pairは別対象で補わない |
| 再生曲線 | r804で相方Body Xの−5.8ピークと−5.0終端を保持。モデル適用条件を記載。頭・胴・視線・Stage Yが口や既存Stage配置と共存し、Stage Presence Offでも演技用Yが動く |
| 姿勢とライフサイクル | ニュートラルおよび別の現姿勢から進入を比較。短い区間の通常終了後は曲線を完走して解除。中断・kill・切断では解除。次区間・遅着・重複・接続所有者の競合で古い動作を積み残さない |
| 表示とレビュー | r804を用いた実表示と試作を照合し、曲線、進入、終端、表示条件の一致範囲を記録。Gnomeとは別のReview-Sylphが差分・試験・実表示を検証。実会話の美的評価は本人確認に委ねる |

GnomeはRuntime Playerの関連実装・試験・検証スクリプトと[制作原本ディレクトリ](../../../experiments/speech-motion-brief-relief-variants-v1/)を担当。Orch-Sylphはこのディレクトリの受領記録と後続契約を担当。独立Review-Sylphはレビュー記録を担当する。実運用中のアプリ・OBS・マイク・配信・外部モデルは変更せず、隔離した環境で検証する。

## 実装方針

- 演技候補と対象候補は登録を分離し、組合せを共有lookupで解決する。`intent.motion` は直接指定と従来のpreset指定を受ける。lookupの未対応理由とWSの受付結果は別に扱う。
- 新3組にはr804と対象パラメータを確認するクリップ限定のモデル単位経路を使う。保存曲線をそのままサンプルし、開始時の現姿勢との差分を短く減衰させて接続する。既存のmappingとidleの強さは従来どおり。対応モデル・mappingが揃わない場合は、意味上の未対応や未制作と区別できる再生不可を返す。
- 登録クリップの `end` はその区間に対する追加再生を閉じ、すでに始まった曲線と自然解除は継続する。次区間の `begin` は旧区間より優先する。従来のStage Y単体リクエストは通常終了時の既存解除契約を保つ。
