# Wave 2の受け入れ基準

[全体計画](../../orchestration/performance-attention-wave-plan.md)と[合意 §7](../../../concept/speech-motion-performance-and-attention.md#7-製品接続のcontext-check2026-11-12確定)を引き継ぐ。初期6組、理由の判定順、ワイヤーと受付の意味は[Wave 1の契約](wave1-contract.md)に従う。

## 判定と音声

- 原意図タグ、区間本文、発火時に取得した直前会話を共通入力にし、一回のDecisionリクエストで演技と注意対象を独立に問う。演技の候補に「どれでもない」、対象の候補に相方・ゲーム画面・視聴者・不明を含める。演技と対象の直積や逐次問い合わせを用いない。意図と本文の一致を評価しない。
- 逐次経路では最初に確定して渡せる本文を使い、一括経路では利用可能な区間本文を使う。送信時点と送信した本文の範囲を確かめる。音声の生成・再生を判定や記録で待たせない。逐次経路の最終本文は次の区間や終了で確定するため、判定入力と区別して保持する。
- 対象の候補は相方（キャラ右・画面左）、ゲーム画面（正面）、視聴者（上）、不明。直前区間の対象で埋めない。共有JSONから制作済みの組み合わせを引き、未制作の組み合わせに別対象の動きを当てない。
- 通常終了では開始済みクリップが自然に終わる。通常終了後の遅い結果は開始しない。割り込み・kill・次区間の開始・切断では解除し、古い世代・区間・接続の結果で動かさない。

## 記録と検証

- 意味上の未対応は `unsupported-performance`、`unknown-attention-target`、`unproduced-pair` を区別し、原意図、最終区間本文、判定へ送った本文、直前会話、二回答、識別子、観測した音声再生範囲を残す。再生範囲から聞こえた文字数を推定しない。拒否・通信失敗・中断・モデル不一致は別の診断とする。既存228件の形式と内容を保つ。
- 制御した実WSで、一括・逐次経路、遅い結果と順序逆転、通常終了・割り込み・kill・世代交代・切断、意味上の未対応と実行時の失敗を確認する。受付と画面への適用は別の証拠で確認する。少数の非私的な例で実Decisionの二問と対象の文脈依存を確認し、判定時間と音声初動は別に報告する。
- 一人の独立Reviewerが契約、実装、テストと証拠を確認する。合格後、普段のwin-unpackedとportableを更新し、asar内容と隔離起動でr804と再生を確認する。本人の実会話、動きの自然さ、実記録を辿れることは本人確認に残す。

## 本文を渡す時点

逐次経路では最初に確定した音声ジョブの本文を、TTSへのenqueueと同じターンで判定に渡す。判定の実行はマイクロタスクで開始する。一括経路では全区間を読み終えた時点の区間本文を使う。本文が空か空白だけの区間では判定とモーション開始を省く。判定時の本文と会話文脈は、その後に確定する最終本文と観測した再生範囲とともに保存する。
