# S4 人間ゲート手順書 — 「感情が動く話題を振る → 返事の内容に表情が乗る」

> Status: 手順確定（2026-07-13, Gnome / S4 Domain B）。**実行はユーザー**（実マイク・実器接続・
> 実スピーカー再生を伴うため Gnome / エージェントは実行しない＝規律）。
> ゴール: [../../orchestration/s4-wave-plan.md](../../orchestration/s4-wave-plan.md) §1 の人間ゲート——
> 会話して、**返事の内容に表情がついてくる**（困った話で目が泳ぎ、驚く話で顎が上がり、同意で頷き、
> 嬉しい話で笑む）。S3「呼べば応える」に**表情筋**が乗った状態を目で確かめる。
> 前提: S3 手順書 [../s3/human-gate-procedure.md](../s3/human-gate-procedure.md) と**同一**
> （`npm install` 済み・`/login` サブスク済み・ガード対象環境変数未設定・`vendor/` に whisper 一式 +
> kotoba + silero_vad.onnx 配置済み・ffmpeg が PATH・AivisSpeech + 器 + 耳 の全器官起動）。

## なぜ人間がやるのか（配線・実出現 ≠ 実機の見え方）

機械ゲート（魂の全テスト緑 + `preflight-fire.mjs` の演出縦貫通 + `observe-expressions.mjs` の実 SDK
5 ask）は「タグ教示 → 実応答にタグが出る（5/5・未知タグ 0）→ 剥離 → envelope 送出」までを証明済み
（[../../../experiments/s4-expressions.md](../../../experiments/s4-expressions.md)）。残る未検証は
**実機での見え方**——タグが実際に器の目・視線・頭・体を意図どおりに動かすか、符号（上下左右前後の
向き）が正しいか、`nod` が頷きに見えるか。これらは人間の目でしか判定できない。

## 1〜4. 全器官起動（S3 手順書と同一）

[../s3/human-gate-procedure.md](../s3/human-gate-procedure.md) の **§1〜§4 をそのまま実施**する:

1. **AivisSpeech を起動**（`http://127.0.0.1:10101`）。
2. **自律ホスト（器）を起動し Channel を開く**（`Open Channel` → Endpoint URL を控える）。
   身体モデルをステージに出し、**目・視線・頭・体の動きが目視できる状態**にする（S4 の要）。
3. **操縦席を fire 有効で起動**:
   ```
   npm run cockpit --prefix apps/soul/agent -- --channel "ws://127.0.0.1:<port>/channel?token=<token>"
   ```
   `fire enabled` の行が出ることを確認（`--channel` 忘れは Fire 503）。

   **リアクションをもっと大きくしたいとき（再ゲート・S4 追撃 domain-c）**: `--expression-gain <倍率>` を
   付けて起動する。全 peak が一括でスケールし、リアクションが大きくなる（1.0=従来・上げるほど大きく・
   上限 3.0）。**推奨初期値 1.5**——まず 1.5 で様子を見て、足りなければ上げる（2.0 以上は多くの peak が
   クランプ境界に張り付き頭打ちになる）。域外・非数値は起動時エラー（打ち間違いを弾く）。
   ```
   npm run cockpit --prefix apps/soul/agent -- --channel "ws://127.0.0.1:<port>/channel?token=<token>" --expression-gain 1.5
   ```
   gain が 1.0 以外のとき起動ログに `expression gain = 1.5 …` の行が出る。リアクションの大きさを見て
   数値を調整する（強さ調整は CLI のみ・操縦席 UI には調整ノブを置かない裁定）。
4. **ブラウザで開き、マイクを選んで Start**（ヘッダが `Listening`・`whisper: up` / `ffmpeg: up`）。

（S4 で新規に増える依存・追加コマンドは無い。器コード・契約・依存は完全不変。）

## 5. 感情が動く話題を振る（S4 の要）

ゲーム実況の独り言として、**感情がはっきり動く話題**を混ぜて数文〜十数文話す。魂は全部聞いて
会話ログに積む（まだ考えていない）。狙って振ると表情が観測しやすい:

| 振る話題（例） | 期待する語（表情） |
|---|---|
| 困った話（「ボス強すぎ、詰んだかも……」） | **troubled**（視線が斜め下へ泳ぐ・頭の傾げ） |
| 驚く話（「えっ、今の見た!? 敵が急に湧いた!」） | **surprised**（顎が上がる・体を引く） |
| 同意を促す（「この装備が最強だよね？」） | **nod**（頷き） |
| 嬉しい話（「やっとクリアできた、嬉しい!」） | **smile**（目を細め + 頭の傾げ。口角は見えない前提） |
| 照れ・気まずい話（「それは恥ずかしいから言わないで」） | **look-away** / **troubled**（視線を横へ逸らす） |

（実 SDK 観測ではこの 5 種で 5/5 タグが出た・
[../../../experiments/s4-expressions.md](../../../experiments/s4-expressions.md) §1。ただし**タグは
強制ではない**——モデルが感情を感じなければ付かないのが正常。）

## 6. Fire

**Fire ボタンを押す**。S3 の挙動（発火マーカー行 → `soul: thinking` → soul 行 → `soul: idle`）に加えて:

- Timeline に**演出イベント行**（`expr` ラベル・teal 色）が出る: 例 `smile ✓4/✗0`（適用 4 スロット・
  拒否 0）。器が一部スロットを拒否すると `✗N` に数が乗る（部分適用は正常）。
- 器のステージで、返事の声と**同時に**顔・視線・頭・体が動く（envelope は発話開始と同時送出）。
- モデルが**語彙外の語**を吐いた場合は Timeline に淡色の**ゴースト行** `(unknown tag: …)`（声にも
  演出にも出ないが痕跡は残る）。実 SDK 観測では 0 件だったが、出たら語を記録して報告する。

## 7. 合格判定 — 「返事の内容に表情が乗る」

- 返事の**声が鳴り、器の口が同期して動き**（S3 ゲートの再演）、
- **その内容に応じた表情**（目・視線・頭・体の動き）が声と一緒に出る（困った話で目が泳ぐ、
  驚く話で顎が上がる、同意で頷く、等）。

これが一目一聴で成り立てば **S4 人間ゲート合格**。あわせて
[../../../experiments/s4-expressions.md](../../../experiments/s4-expressions.md) §4 の記入欄
（各語が実機で意図どおり見えたか・符号の正/逆）を埋める。

### 見るときの注意（現素材の制約・正直に）

素材とリグの都合で「見えない / 近似 / 向きが未確定」の項目がある。**これらは魂のバグではなく素材・
契約の事実**なので、切り分けて観る（出典: Domain A [domain-a.md](domain-a.md) §9 質問 1・2）:

1. **`mouth-smile`（口角）は現素材で keyform 未設定 ＝ 見えない**。`smile` の見える本命は
   **目の細め（eye-blink 左右）+ 頭の傾げ**。口が笑わなくても異常ではない。
2. **`nod` は v0 は ADS 単峰**＝「顎を下げて 2 秒保持して戻す」近似。**頷き（上下のバウンド）に
   見えるか**を要チェック。「下げっぱなし」に見えたら報告する（多峰の頷きは将来 / sustain の
   微調整で改善余地・domain-a §9 質問 1）。
3. **符号（向き）はリグ依存で未確定**。head/gaze/body の「正 = どちらの向き」は入力プロファイルの
   学習符号次第。実機で**逆向き**に出た語があれば、その語を記録する（例: `nod` の顎が上がって
   しまう / `look-away` の左右が逆）。修正は `src/mind/expression-table.mjs` の該当行 peak の符号を
   反転するだけ（1 行・domain-a §9 質問 2）。`eye-blink-*` は 0=開/1=閉が契約確定で符号の曖昧さは無い。
4. **`look-camera` の単独発火**は gaze/head が正面復帰（peak 0）のため、直前に `look-away` が無いと
   **体の前傾のみ**が可視（意図どおり「逸らしから戻る」語・domain-a §9 質問 3）。

## 8. 終了

操縦席のターミナルで **Ctrl+C**（S3 と同一・全器官が畳まれて終了）。

## 9. うまくいかないときの切り分け

まず S3 手順書 [../s3/human-gate-procedure.md](../s3/human-gate-procedure.md) §10 の表（起動拒否・
`fire disabled`・`ears-not-running`・`empty-window`・`fire error`・声/口の不一致）で切り分ける。S4 固有:

| 症状 | 見るところ |
|------|-----------|
| 声は返るが表情が一切動かない | 演出イベント行（`expr …`）が Timeline に出ているか。出ていなければモデルがタグを付けていない（感情が動く話題を振る・§5）。出ていて `✗N`（拒否）なら器がそのスロットを拒否（`slotNotWritable` 等・器のモデルロード状態） |
| `expr` 行は出るが器が動かない | 器の Channel 状態・envelope 対応（器は C5 から `intent.envelope` 対応済み）。声は出るのに演出だけ来ないなら Channel の redact URL / 接続状態を確認 |
| 口だけ動いて顔が動かない | 上記（envelope 側の rejected）。口（speech）と演出（envelope）は独立経路 |
| `(unknown tag: …)` が出る | モデルが語彙外の語を吐いた。語を記録して報告（語彙拡張の判断材料・followup） |
| 表情の向きが逆 / 頷きに見えない | §7「見るときの注意」2・3（素材/符号の事実・演出表 1 行修正で回収） |
