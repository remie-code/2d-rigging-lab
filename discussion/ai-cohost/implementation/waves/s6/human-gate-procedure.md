## 0. 音響設営（S6 の要・§5 choke point・最初にやる）

アームマイク（例: Shure MV7+）が魂の声（スピーカー出力）を拾って自己割り込みを起こす事故を防ぐため、
**魂の声の出力先をマイクが拾わないデバイス（例: ヘッドホン）へ固定する**。

1. ヘッドホン等、マイクが物理的に拾わない出力デバイスを PC に接続しておく（Windows のサウンド設定で
   認識されていることを確認）。
2. 操縦席の「Voice output」セクションで **Refresh devices** を押し、`<select>` にデバイス一覧
   （例: `BenQ EX2510S (NVIDIA High Definition Audio)` / `ヘッドホン (2- Shure MV7+)` 等）が
   表示されることを確認する。
3. マイクが拾わないデバイス（例: `ヘッドホン (2- Shure MV7+)`）を選び **Set device** で確定する
   （`cockpit-settings.local.json` に永続化・次回起動でも復元される）。
4. **適用は常駐プレイヤーのその場再起動**（次に魂が声を出す瞬間から新デバイスに切り替わる。
   `scripts/cockpit.mjs` の設計判断・domain-d.md §）。設定直後に一度 **Fire** ボタンを押し、
   選んだデバイス（例えばヘッドホン）から実際に声が出ることを耳で確認する（人間ゲート⑥の前倒し
   確認・本確認は §8 で改めて行う）。

## 1〜4. 全器官起動（S3〜S5 手順書と同一）

[../s5/human-gate-procedure.md](../s5/human-gate-procedure.md) の **§1〜§4 をそのまま実施**する:

1. **AivisSpeech を起動**（`http://127.0.0.1:10101`）。
2. **自律ホスト（器）を起動し Channel を開く**（`Open Channel` → Endpoint URL を控える）。
3. **操縦席を fire 有効で起動**:
   ```
   npm run cockpit --prefix apps/soul/agent -- --channel "ws://127.0.0.1:<port>/channel?token=<token>"
   ```
4. **ブラウザで開き、マイクを選んで Start**（ヘッダが `Listening`・`whisper: up` / `ffmpeg: up`）。

（S6 で新規に増える依存・追加コマンドは無い。器コード・契約・依存は完全不変。）

## 5. 手動 Fire で無退行を確認（基準点）

まず **Fire ボタン**を 1 回押し、S3〜S5 と同様に会話ログの直近窓を注入した返事が返る（従来どおり）
ことを確認する。これが以後の barge-in / 自発発火の比較基準になる。

## 6. 人間ゲート① barge-in — 「声が止まり、口が閉じる」+「遮られた事実を踏まえた会話が続く」

1. **Fire ボタン**（または呼びかけ）で魂に発話させる。
2. 魂が喋っている最中（声が鳴っている間）に、**マイクに向かって話し始める**。
3. 確認項目:
   - **声が途中で止まる**（WinRT MediaPlayer の `STOP` が効く・S1 の「途中で止められない」問題の
     解消）。
   - **器の口が閉じる**（mouth-open へ `intent.set(value=0)` が送られ、speech タイムラインが強制
     release される・release は既定 400ms かけて基底へ戻る想定——**自然な閉じ方に見えるか**を目視
     で確認する。声の停止と口閉じの体感タイミングがずれて不自然に見えないか）。
   - 操縦席の Timeline に **barge-in 中断マーカー行**（`!! interrupted (N/M chars spoken, Xms)`）
     が現れる。
4. 中断後、**もう一度何か話しかける**（例: 「さっき遮っちゃってごめんね」）か、しばらく待って
   自発発火（呼びかけ/区切り）を待つ。**次の魂の発話が「遮られた事実」を踏まえた自然な受け答え**
   （例: 気にしていない旨・話が途切れたことへの反応）になっているかを確認する（機械観測は
   [../../../experiments/s6-conversation.md](../../../experiments/s6-conversation.md) §3 で実施
   済み・実マイクでの体感確認はここが初回）。

## 7. 人間ゲート② 呼びかけ — 「こーでぃー」と呼ぶ

マイクに向かって **「こーでぃー」**（または「コーディ」「コーティー」等の近い発音）と呼びかける。
**確実に返事が返る**ことを確認する（不応期・確率は掛からない設計・裁定4）。操縦席の Timeline に
**自発発火マーカー行**（`~ self-fire (call)`）が現れる。

- 呼びかけの発音がうまく拾われない/転写がずれる場合は、`discussion/ai-cohost/implementation/
  waves/s6/s6-followup.md` の照合集合拡張の項目へ実測（転写された文字列）を記録する。

## 8. 人間ゲート③ 区切り応答 — 「実況の区切りでたまに拾う」

配信の実況を続ける（マイクに向かって話し続け、時々止める）。**発話が一区切りついてから 2 秒程度
無音**が続くと、**確率 35%・不応期 8 秒**の条件を満たしたときに時々自発発火する。**全部には
返さない**（毎回は喋らない）ことを確認する。操縦席の Timeline に自発発火マーカー行
（`~ self-fire (turn-end)`）が現れる。何度か区切りを作って、体感の頻度（多すぎる/少なすぎる）を
記録する（followup 台帳の定数調整材料）。

## 9. 人間ゲート④ 沈黙発火 — 「しばらく無言でいる→そのうち画面を見て一言」

しばらく（45〜75 秒程度）マイクに向かって何も話さず黙っている。沈黙が続くと、魂が**画面を見て
一言**話しかけてくる（視覚発火相当）。**頻度がうるさくない**（連発しない・長い不応期 90 秒 +
セッション予算 6 回で希釈されている）ことを確認する。操縦席の Timeline に自発発火マーカー行
（`~ self-fire (silence)`）+「見た」マーカー行（サムネ付き）が現れる。

### 9-1. 再ゲート（S6 追撃・自発発火に画像同乗）の一点確認

> S6 Domain E（自発 call/turn-end への画像同乗）実装後の再ゲート項目。**視覚対象（§S5 手順で選んだ
> ウインドウ）を設定した状態**で行う（未設定なら従来どおり画像なしで発火するだけ＝退行なし）。

放置 45〜75 秒 → 沈黙発火が**画面に言及**する一言を返す（④沈黙発火の確認をそのまま兼ねる）。加えて、
S6 追撃で **区切り応答（turn-end）／呼びかけ（call）の返事も、視覚対象が設定済みなら画面に触れること
がある**（＝画像付きに格上げされた）ことを確認する。以下の一点だけ見ればよい:

- **区切りを作る／呼びかける → 返事がときどき「画面の話」に触れる**（対象設定済みのとき）。毎回では
  なくてよい（call/turn-end は会話文脈次第で画面に言及しないこともある＝自然）。
- **キャプチャに失敗した場合でも自発発火は止まらず、画像なしの普通の返事になる**（＝盲目劣化・
  誰もボタンを押していない自発発火は見えなくても嘘にならない設計・domain-e.md 裁定 2）。操縦席の
  Timeline に劣化のゴースト行（`diagnostic` の `fireVisionDegraded`）が残る。
- **手動 Fire・手動視覚 Fire・沈黙発火の挙動は変わっていない**（手動視覚 Fire は従来どおり「見えなければ
  中止」・沈黙も従来どおり）。ここに違和感がないことも併せて確認する。

## 10. 人間ゲート⑤ 自発 OFF トグル — 「OFF で②〜④が黙る・手動 Fire は生きる」

1. 操縦席の **Self-fire トグル**を OFF にする（`off` 表示に変わる）。
2. 「こーでぃー」と呼びかけても・区切りを作っても・しばらく黙っていても、**自発発火が一切起きない**
   ことを確認する（②③④がすべて黙る）。
3. **手動 Fire ボタンは引き続き機能する**ことを確認する（OFF は自発のみを止め、手動発火には無関係）。
4. トグルを ON に戻すと、再び②③④が機能することを確認する。

## 11. 人間ゲート⑥ 音響設営の最終確認 — 「魂の声が指定デバイスから出る」

§0 で設定した出力デバイス（マイクが拾わないデバイス）から、ここまでのすべての発話
（手動 Fire・barge-in 後・呼びかけ・区切り・沈黙）が**一貫してそのデバイスから鳴っている**ことを
耳で確認する。**アームマイクが自分の声を拾って誤反応する（自己割り込み）が起きていない**ことも
あわせて確認する。

これが一目一聴で成り立てば **S6 人間ゲート合格**。

## 12. うまくいかないときの切り分け（S6 固有）

まず S3〜S5 手順書の切り分け表を参照する。S6 固有の症状:

| 症状 | 見るところ |
|------|-----------|
| barge-in が効かない（声が止まらない） | 機械弁の最小持続時間（既定200ms）より短い発話だと確定しない可能性。少し長めに話しかけ直す。操縦席の Timeline に barge-in マーカーが出ない場合はログ（`diagnostic` の `bargeInStopError` 等ゴースト行）を確認 |
| 口が閉じない/不自然 | mouth-open の release（既定400ms）の見え方は実機未検証の既存意味論。followup へ実機の見え方を記録 |
| 呼びかけに反応しない | 転写が「コーディ/コーディー/コーティ/コーティー」の照合集合に入らない発音揺れの可能性。転写結果（操縦席 Timeline の you 行）を確認し followup へ記録 |
| 「コーディネート」等で誤爆する | 既知の受容事項（照合集合が部分一致のため）。実害の頻度を followup へ記録 |
| 区切り応答が全く起きない/毎回起きる | 不応期(8秒)・確率(35%)の体感。数回試して頻度を記録（v0 コード内定数・followup で調整） |
| 沈黙発火が起きない | 45〜75秒待っても発火しない場合、不応期(90秒)がまだ明けていないか、予算(6回)を使い切った可能性（セッション再起動でリセット） |
| 自発 OFF でも自発発火する | blocking 相当の不具合。再現手順を記録してレビューへ |
| 声が指定デバイスから出ない | デバイス変更は「その場再起動」設計——Set device 直後の Fire で切り替わっているはず。切り替わらない場合は cockpit のターミナルログ（`[cockpit] audio device set: ...`）を確認 |
| アームマイクが声を拾って誤反応する | 出力デバイスの選択を確認（§0）。物理的な音漏れ（ヘッドホンの音量が大きすぎる等）も疑う |

## 13. 終了

操縦席のターミナルで **Ctrl+C**（S3〜S5 と同一・全器官が畳まれて終了）。
