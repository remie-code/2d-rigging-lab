## 0. ToS グレーの事実の開示（Connect する前に読む）

S7 のチャット取得は **非公式 innertube 経路**（`youtube.com/watch?v=<ID>` の HTML から公開値を抽出し
`youtubei/v1/live_chat/get_live_chat` を叩く・**認証不要・依存ゼロの自前実装**）を採用している
（[../../orchestration/s7-planning-inventory.md](../../orchestration/s7-planning-inventory.md) §5・
ユーザー裁定「これでいこう」）。これは**公式ドキュメントのある公開 API ではない**（YouTube ToS は
自動化アクセスを原則制限する）。**自分の公開/限定公開のテスト配信のチャットを自分で読む**という文脈で
の利用であることを了解の上で Connect すること。公式 Data API v3 キーへの差し替えは器官内で完結する
梯子として [s7-followup.md](s7-followup.md) §1 に記録済み（quota 単価の実測もその時）。

## 1. テスト配信を立てる（限定公開でよい）

1. YouTube で**ライブ配信を開始**する（OBS 等から。**限定公開（Unlisted）でよい**——一般公開は不要）。
   - チャットが有効な配信であること（アーカイブのリプレイではなく**生きた配信**）。
   - コメントを自分で投げられるよう、同じアカウントか別アカウント/別端末を用意しておく。
2. **配信の URL を控える**。次のいずれの形でもよい（操縦席が受理する）:
   - `https://www.youtube.com/watch?v=<VIDEO_ID>`（最確実——videoId を URL から直接採るため）
   - 素の video ID（`<VIDEO_ID>` 11 文字）
   - `https://www.youtube.com/channel/<CHANNEL_ID>/live`（チャンネルの現行ライブを追う）
   - ※ チャンネル `/live` 経由は videoId を配信ページ HTML から解決するので、実ページのスキーマ次第。
     watch URL / video ID が最も確実（[../s7/domain-a.md](domain-a.md) §7-4）。

## 2. 全器官起動（S6 手順書と同一・★ マイク＝耳を Start する）

[../s6/human-gate-procedure.md](../s6/human-gate-procedure.md) の **§0（音響設営）〜§4（全器官起動）
をそのまま実施**する:

1. **音響設営**（出力デバイスをマイクが拾わないデバイスへ・§0）。
2. **AivisSpeech 起動**・**器を起動し Channel を開く**・**操縦席を起動**（`npm run cockpit --prefix
   apps/soul/agent`・Channel 欄に器の URL を入れて Fire 有効化）。
3. **ブラウザで操縦席を開き、マイクを選んで Start**（ヘッダが `Listening`・`whisper: up` /
   `ffmpeg: up`）。

> ### ★★ 最重要: マイク（耳）を Start した状態で Connect する ★★
>
> S7 のコメントは**転写バッファ正本の単一タイムライン**に合流する。この正本バッファは**耳
> パイプラインが所有**する（遅延起動）。**耳が未起動だと合流先のバッファが存在せず、コメントは
> 合流できず発火もしない**（操縦席 Timeline に `(chat: ears not running — comment did not merge)`
> のゴースト行が出るだけ）。**必ずマイクを Start してから次の §3 の Connect を行うこと。** これを
> 忘れると「コメントを投げても何も起きない」＝人間ゲートが静かに失敗する
> （[../s7/domain-b.md](domain-b.md) §5 の裁定・cohost はどのみち声も拾うのでマイク Start は自然）。

（S7 で新規に増える依存・追加コマンドは無い。器コード・契約・依存は完全不変・新規依存ゼロ。）

## 3. 配信を Connect する（コメント合流の開始）

1. 操縦席の **「Live chat」セクション**の入力欄に §1 で控えた**配信 URL / video ID** を入れる。
2. **Connect chat** ボタンを押す。
3. **状態表示**（`chat-status`）で接続の様子を確認する:
   - `connecting` → `live`（ポーリング開始＝コメント取得中）に上がれば取得成功。
   - **まだ配信が始まっていない/チャットが無効**なら `retrying` のまま**待ち続ける**（notLive の
     ゴースト行が出る・上限なしのポーリングなので害はない・配信が始まれば自動で `live` に上がる）。
   - `dead`（配信終了/停止）なら終端（再開には Connect を押し直す＝新しい配信を掴み直す）。
   - Connect した配信 URL は `cockpit-settings.local.json` に記憶され、次回起動で入力欄に復元される。

> 実疎通で **4 点抽出が通らない**（`retrying` のまま live に上がらない・`extractFailed`/`network` の
> ゴースト行が続く）場合、実 YouTube が cookie（CONSENT 等）や地域リダイレクトを要求している可能性が
> ある（[../s7/domain-a.md](domain-a.md) §7-5）。**その HTTP 詳細を [s7-followup.md](s7-followup.md)
> §4 の欄に記録**する（followup で cookie/consent 処理を器官内に足す・依存ゼロのまま fetch ヘッダ調整で
> 対応可能な見込み）。

## 4. 人間ゲート本体① コメントを拾って返す — 「こーでぃーがコメントに言及する」

1. テスト配信のチャットに**普通のコメント**を投げる（例:「今日の配信たのしい」「その敵つよそう」）。
2. 操縦席の Timeline に **viewer 行**（`viewer(投稿者名): コメント本文`・別色）が現れることを確認する
   （＝コメントが単一タイムラインに合流した）。
3. しばらく様子を見る。**魂がコメントに触れた一言を返す**ことを確認する（コメント発火＝不応期 8 秒 +
   確率 35% + 予算 30 で希釈されているので**全コメントには返さない**——何件か投げて「たまに拾う」
   体感を見る）。返事が**そのコメントの内容に言及**していれば合格（どのコメントに触れるかは LLM が
   選ぶ・機械信号は「来た」だけ・裁定 4）。
4. Timeline に**コメント発火マーカー行**（`~ self-fire (comment)`）が現れる。

## 5. 人間ゲート本体② 呼びかけの確実応答 — コメントで「こーでぃー」と呼ぶ

チャットに**「こーでぃー」**（または **Cody / cody / CODY / コーディ / コーディー** 等の表記）を含む
コメントを投げる（例:「こーでぃー元気？」「Cody こっち見て」）。**確実に返事が返る**ことを確認する
（comment-call＝不応期・確率・予算を掛けない・裁定 5・音声呼びかけと対称）。Timeline に**コメント
発火マーカー行**（`~ self-fire (comment-call)`）が現れる。

- 呼びかけ表記がうまく拾われない場合（特に `CoDy` のような**混在大小**）は、[s7-followup.md](s7-followup.md)
  §3 の「表記揺れ集合の実運用拡張」欄に実際に投げた表記を記録する（v0 の照合集合は `Cody/cody/CODY` の
  3 形 + 日本語表記のみ・混在大小は未収録）。

## 6. 相乗り① S6 持ち越し④ 沈黙発火 — 「放置 45〜75 秒 → 画面に言及・頻度がうるさくないか」

S6 の持ち越し（沈黙発火の実機体感）をこの同席で確認する。しばらく（45〜75 秒程度）マイクに向かって
何も話さず黙っている（チャットも静かにしておく）。沈黙が続くと魂が**画面を見て一言**話しかけてくる
（`~ self-fire (silence)` + 「見た」マーカー行）。**頻度がうるさくない**（連発しない・長い不応期
90 秒 + セッション予算 6 回で希釈）ことを体感で確認し、多すぎる/少なすぎる感触を
[s7-followup.md](s7-followup.md) §5（頻度の将来 Cockpit 可変・s6-followup §12 口数モードに合流）へ記録
する。

## 7. 相乗り② S6 追撃 E 再ゲート — 「自発発火の返事が画面に触れる」

**視覚対象（S5 手順で選んだウインドウ）を設定した状態**で行う（未設定なら画像なしで発火するだけ＝
退行なし）。区切りを作る／マイクで呼びかける／コメントで呼びかける → **返事がときどき「画面の話」に
触れる**（call/turn-end/comment/comment-call は視覚対象が設定済みなら画像付きに格上げ＝`fire({vision:
"preferred"})`）ことを確認する。毎回でなくてよい（会話文脈次第で画面に言及しないこともある＝自然）。
キャプチャに失敗しても自発発火は止まらず**画像なしの普通の返事**になる（盲目劣化・誰もボタンを押して
いない自発発火は見えなくても嘘にならない・劣化痕跡は `fireVisionDegraded` ゴースト行）。

## 8. 停止・切り分け

- **Disconnect**: 「Live chat」の **Disconnect** ボタンでチャット器官を停止（`not connected` 表示・
  以後コメントは合流しない）。魂の他の機能（手動 Fire・音声発火）はチャット停止と無関係に生き続ける
  （チャット器官は独立・死んでも魂に無影響）。
- **終了**: 操縦席のターミナルで **Ctrl+C**（S3〜S6 と同一・全器官 + チャット器官が畳まれて終了）。

うまくいかないときの切り分け（S7 固有・まず S6 手順書の切り分け表も参照）:

| 症状 | 見るところ |
|------|-----------|
| コメントを投げても viewer 行が出ない・何も起きない | **★ マイク（耳）を Start しているか**（§2 の最重要事項）。Timeline に `(chat: ears not running …)` ゴースト行が出ていれば耳未起動。マイクを Start してから再度コメント |
| `connecting`→`live` に上がらない（`retrying` のまま） | 配信がまだ始まっていない/チャット無効なら正常（待ち続ける）。`extractFailed`/`network` のゴースト行が続くなら 4 点抽出失敗——cookie/地域リダイレクトの可能性を [s7-followup.md](s7-followup.md) §4 へ記録 |
| viewer 行は出るが魂が全く返さない | comment は確率 35%＋不応期 8 秒で希釈（全部には返さない設計）。何件か投げて「たまに拾う」を見る。予算 30 を使い切っていないかも確認（セッション再起動でリセット） |
| 「こーでぃー」コメントに確実応答しない | comment-call の照合集合（`Cody/cody/CODY/コーディ/コーディー/こーでぃー` 等）に入らない表記の可能性。投げた表記を [s7-followup.md](s7-followup.md) §3 へ記録。busy（魂が発話中）なら沈黙するのは正常 |
| コメントの投稿者名が `viewer(名前)` で崩れて見える | displayName に `)` や改行を含むと表示が崩れうる（機能影響なし・[s7-followup.md](s7-followup.md) §8 の既知事項） |
| dead に落ちて戻らない | 配信終了で終端（正しい挙動）。別配信/再開は Connect を押し直す（新 source で器官を作り直す） |

これが一目一聴で成り立てば **S7 人間ゲート合格**（コメントを拾って返す + 呼びかけ確実応答 + 相乗り
2 件）。判定と体感の記録は [s7-followup.md](s7-followup.md) の各欄へ。
