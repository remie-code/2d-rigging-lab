# 配信の組み直し: 人間ゲートの確認手順

> 対象: ブランチ `ai-cohost/stream-restructure`(Domain A〜E と仕上げ)。上から順に試せるように並べています。
> 根拠: 計画 [../../orchestration/stream-restructure-wave-plan.md](../../orchestration/stream-restructure-wave-plan.md) §6 の 6 項目、各ドメインの報告、全体の突き合わせ [../../reviews/stream-restructure/final.md](../../reviews/stream-restructure/final.md)、仕上げの見直し [../../reviews/stream-restructure/final-fixes.md](../../reviews/stream-restructure/final-fixes.md)。
> 各項目の「□」に印をつけ、思った動きと違ったところはその場でメモしてください。

言葉の短い説明:
- **ロール**: 「誰としてしゃべるか」の一式(名前・性格の指示・声・口数・体を使うか)。チャッピーとコーディが最初から入ります。
- **場**: 「配信を始める」から「配信を終える」までの 1 回の配信のこと。
- **体 / 器**: runtime-player で動く Live2D のモデルのこと。体を使わないロールは、声だけでしゃべります。
- **写し**: 引っ越しの前に取るバックアップのこと。

---

## 0. 準備

- □ **最初の起動の前に、エクスプローラーやエディタで `apps/soul/agent/memories/` を開いたままにしない。**(開いていると Windows がフォルダの移動を断ることがあり、そのときは引っ越しが失敗します。失敗しても記録は元のまま残り、上の帯に警告が出ます。)
- □ 外回り(runtime-player など)はいつも通り起動しておく。ただし手順 3 では runtime-player を一度止めます。
- □ 操縦席はいつも通りリポジトリの根の `start-cockpit.cmd` から起動する(中身は今の作業ツリーの `node scripts\cockpit.mjs --open` なので、ブランチの新しい版が動く。器の URL は操縦席の画面に保存した値を使います)。

## 1. 最初の起動で引っ越しが 1 回だけ起きる(計画 §6-1)

- □ ターミナルと、画面の設定 → 「ログ」タブに、引っ越しの報告が **1 回だけ** 出る。中身は「使った会話の指示」「移した記録の件数(記録 N 件)」「写しの置き場」。
- □ 写しの置き場は `apps/soul/agent/tmp/restructure-backups/restructure-<日時>/`。その中に `cockpit-settings.local.json` と `memories/` の **両方** がある。
- □ `apps/soul/agent/roles/chappy/` と `apps/soul/agent/roles/cody/` ができている。
- □ `apps/soul/agent/memories/chappy/` ができていて、チャッピーの記録がそこに移っている。
- □ チャッピーの記憶の履歴が残っている。確かめ方(ターミナルで):
  `git -C apps/soul/agent/memories/chappy log --oneline -5`
  → 前からのコミットが並んでいれば OK。
- □ 上の帯に引っ越しの失敗の警告が出ていない。(出ていたら、ログのタブの文面を控えて、ここで止めて相談してください。写しがあるので元に戻せます。)
- □ 操縦席を一度止めて(Ctrl+C)もう一度起動すると、**引っ越しの報告は出ず**、写しのフォルダも増えない。

## 2. 設定の画面の形(計画 §6-6)

- □ 設定のダイアログのタブが「配信の準備 / ロール / 運転 / 記憶 / ログ」の 5 つ。開いたときは「配信の準備」。
- □ 「配信の準備」で、ゲームの窓と声の出力先が **前に保存した値で選ばれている**(空や先頭の項目になっていない)。マイクも前に選んだもの。
- □ 「運転」タブに口数・話し始めの行が無い(これらはロールのタブに移った)。
- □ 上の帯にロールの名前(チャッピー)が出ている。
- □ 場が閉じている(配信していない)間は、手動の Fire と、記憶タブの「今日を記録」が **押せない**。

## 3. runtime-player なしでは場が開かない(計画 §6-3)

- □ runtime-player を起動しない(または channel を閉じた)状態で、メイン画面の中央の「配信を始める」を押す。
  → 中央に **赤い枠** で「runtime-player が起動していないか、channel が開いていない」旨が出て、場は開かない。
- □ そのあと runtime-player を起動して channel を開き、もう一度「配信を始める」を押すと、ちゃんと開く。ターミナルに二重の起動のような警告が出ない。

## 4. チャッピーでふだん通りに配信する(計画 §6-2)

- □ ロールのタブで今日のロールが「チャッピー」になっていることを確かめて、「配信を始める」。
- □ **最初の返事は少し(約 12 秒)待つ感じ** になる。頭の準備を配信の始まりでするようになったため。2 回目以降の返事はいつもの速さ。
- □ 声も口の動きも今まで通り。
- □ 配信の間は、ロールの選択・マイク・文字起こし・口数・話し始めが **触れない**(灰色になる)。YouTube の URL・Connect・ゲームの窓は触れる。
- □ YouTube の URL を配信の途中で入れて Connect でき、コメントに反応する。

### YouTube の自動でつなぐ動き(仕上げと人間ゲート前の直しで直した所)

- □ 前回の起動の URL が欄に残っているだけのときは、欄の横に「前回の URL(自動ではつながない…)」と出て、「配信を始める」を押しても **自動ではつながらない**。
- □ 配信を始める前に、欄に今日の URL を入れて欄を離れる(または Enter)。案内が「配信を始めるとつなぐ」に変わる → 「配信を始める」で **場はすぐ開き**(YouTube の応答を待たない)、YouTube は **少しあとから付く**(コメントが流れ始める)。
- □ わざと間違った URL を入れて始めても、場はすぐ開く。少しあとでログのタブに YouTube の 1 行(「配信を始めるときに YouTube につなげなかった…」)が出る。場は開いたまま。Connect でつなぎ直せる。
- □ URL 入りで始めた直後(YouTube がまだつながっていない間)でも、「配信を終える」(2 回押し)で **断られずに** 終えられる。終えたあとに YouTube がつながったままになっていない(状態の表示が「つながっていない」)。
- □ 「始めてる」の表示は、YouTube の有無に関わらず短い(頭の準備の分だけ)。始めている途中で勝手にしゃべり出さない(自発の発火は場が開いてから)。
- □ (見ておいてほしいこと)URL を入れて、欄にカーソルを置いたままダイアログを閉じたとき、ちゃんと保存されて「配信を始める」でつながるか。

## 5. 配信を終える(計画 §6-5)

- □ 下の帯の歯車の左にある「配信を終える」を押す。1 回目で「もう一度押すと配信を終える」に変わり、続けてもう一度押すと終わる。
- □ 上の帯のピルが「記録中」になり、しばらく(最大 90 秒くらい)して「配信を始める」に戻る。
- □ 記憶が `memories/chappy/` に書かれ、記憶の git にコミットが 1 つ増える:
  `git -C apps/soul/agent/memories/chappy log --oneline -3`
- □ もう一度配信を始めて、今度は **ターミナルで Ctrl+C** で終える。同じように「記録中」を経て、コミットが 1 つ増える。
- □ 配信していないときに Ctrl+C すると、記録の行は出ずにすぐ終わる。
- □ 「記録中」の間に YouTube の Connect を押すと、「配信を終えている途中」の旨が出てつながらない。

## 6. 体を使わないロールで声だけでしゃべる(計画 §6-4)

- □ 場が閉じている間に、ロールのタブでコーディ(cody など)を選び、「体」のチェックを外して「ロールを保存」。
- □ 「配信の準備」タブで器の URL の欄が消え、「このロールは体を使わない」と出る。器の状態の表示が「体なし」。
- □ **runtime-player を起動しないまま** 「配信を始める」→ 場が開き、声が出る。
- □ 返事の中に表情の指示の言葉(タグ)が声に出ない。
- □ 割り込み(しゃべっている途中にこちらが話す)が効き、途中で止まった分がきちんと記録に残る。
- □ ターミナルの返事の遅れの行の末尾に `body=none` が付く。
- □ ロールの編集(名前・性格の指示・声・体)が、次の「配信を始める」から効いている(新しい名前・指示で答え、選んだ声で鳴る)。

## 7. 新しいロールを作る

- □ ロールのタブで新しいロールを作る(今のロールを写して作られ、すぐ選ばれる)。名前を付けて保存し、「配信を始める」→ 少し話して「配信を終える」。
- □ `apps/soul/agent/memories/<新しいロールの id>/_conventions.md` ができていて、中の呼び名が新しいロールの名前になっている。
- □ チャッピーの `memories/chappy/_conventions.md` は変わっていない。

## 8. Codex の頭が記憶のフォルダから上へ探しにいかない

Codex(記録を書く係・思い出す係の頭)は、作業するフォルダから上へたどって git の根を探します。ロールの記憶のフォルダにそれぞれ git があるので、そこで止まるはずです。わかる範囲の見方:

- □ `git -C apps/soul/agent/memories/chappy rev-parse --show-toplevel` が `.../memories/chappy` を返す(リポジトリ全体の根を返さない)。
- □ 配信を終えて記録が書かれたあと、リポジトリの根で `git status` を見て、記憶やロール関係のファイルが変更として出てこない。記録は `memories/chappy/` の中だけに増えている。
- □ ログのタブやターミナルに、記録を書く係・思い出す係がリポジトリの上の方のファイル(`AGENTS.md` など)を読んだらしい行が出ない。

## 9. 終わったら

- 全部 □ がつけば合格です。master へのマージに進めます。
- 違ったところがあれば、項目の番号とメモを Undine に渡してください。
- 元に戻したくなったときは、写し(`apps/soul/agent/tmp/restructure-backups/restructure-<日時>/`)が残っています。自分で消したり上書きしたりせず、相談してください。
