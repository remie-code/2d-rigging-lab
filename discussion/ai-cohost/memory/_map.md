## 4. Decisions(ユーザー 2026-10-21)

- **直近でやる**
  1. 記憶の構造化: トピック(ゲーム)ごとに分け、目次(地図)と本体を分ける。
  2. 思い出すのをオンデマンドにする: 起動時に全部読むのをやめ、頼まれたとき・頭が目次で気づいたときに取りに行く。頭のツール制限の見直しが要る。
  - 配信前は、動作確認の対話で配信者が「思い出して」と明示する。今日のゲームを選ぶ仕組みは作らない。
- **長い目でやる**
  3. きっかけで思い出す: 基本は「索引を頭が見て自分で気づく」。連想係(Decisions API などで横から連想を判定する)は今のところ過剰。
  4. 記憶の整理の段階: 配信の終わりに、専用の会話で整理する。3 が自然にできるかは、ここの整理の仕方に大きくかかる。
- 配信中に自分から思い出して話題に出すのは歓迎。ただし自然な形で本当に可能かは要検討。
- 耳の Stop でも記憶を残すようにする(対応候補)。Stop → Start 後の「新しい分だけ渡す」の空振りは、運用上ほぼ起きないので気にしない。
- ~~視聴者の名前は当面残さない~~(2026-10-28、§9)→ **名前を残してよい**(2026-10-31、[recall-flow.md](recall-flow.md) §10。縛りの 1 文だけを外す)。
- **整理(③)は棚と目次の作り直しだけ。抽象的な索引は作らない。本体はそのまま**(2026-11-04、[organization-inventory-2026-11.md](organization-inventory-2026-11.md) を受けて)。記憶の責務は「探しやすくなっている」ことだけで、探すのは思い出し役が頑張る。構図で思い出すのは、構造と目次が手助けする(ユーザー「合っている、構造とmapがその手助けをする感じだね」)。そういう思い出し方をしてほしければ、思い出し役にそう頼めばよい(ユーザー「そういう思い出し方をしてほしいなら、そういう思い出し方をしてくれと思い出す役に言うだけでいいんじゃないかな？」)。1 件に話題が混ざるので、本体を話題ごとに切り分けて書き直す案(B)は採らず、本体は 1 回 1 件のまま、話題ごとの目次で引けるようにする案(A)(ユーザー「(A)の方が適切だと感じるね」)。10/21 の「整理の段階で抽象的な索引を付ける」はこれで上書き。
  - 置き方: 本体は**年と月の棚**(例 `cohost-dev/2026/11/`)へ動かし、話題は目次だけで引く(A3 + 年の段。ユーザー「運用を数年続ける可能性を考えると、ディレクトリ構造は年と月でさらに分けた方がスケールするかも」)。
  - 頻度: **週 1**(ユーザー「一旦週1にしようか」)。きっかけ: 体験を閉じるときの書き出しが終わったあと、前の整理から 1 週間たっていれば続けて整理する。操縦席に「整理中」と出し、終わるまで閉じない。「前に整理した時刻」は最後まで終わってコミットしたときだけ進める(途中で止まれば次の閉じでやり直す)(ユーザー OK)。
  - 頭: **ロールで指定されている頭**(ユーザー「ロールで指定されている頭、というつもりだった / ロールはそのままでもモデルは変わりうる」)。書き出し役と同じく使い捨てのセッション。
  - 目次: 書き出し役が本体を書くたびにトピックの目次へ 1 行足すのは**維持**。整理役は `_conventions.md` を**書き換えてよい**(ユーザー「もちろん書き換えていい」)。目次の書式はがちがちにせず、チャッピーの裁量に任せる(ユーザー)。
  - 名前: 本体のファイル名を soul が決めるのをやめ、`_conventions.md` とチャッピーの裁量に任せる(ユーザー「チャッピーが書きたいように記憶を書けばよくないか？」)。途中保存で前回のファイルに書き足すために、soul は 1 回目の保存のコミットで足されたファイルを git から読み、次の保存で伝える(ユーザー「まさにこのイメージだった」)。書き出し役は既に記憶のフォルダに書ける(workspace-write)ので、権限は増えない。
  - 安全: 材料の指示の混入は、コメントを Decisions API でも弾いているので一旦安全とみなす。最悪の場合への大がかりな備えは要らない(ユーザー)。見張りは 2 つ入れる: 走る前と後で git の先頭が変わっていないこと(コミットは soul だけ)・整理役のあと本体の中身の一覧が同じこと(違えば取り消す)(ユーザー OK)。整理役は外の材料を読まないので入口が狭いことは、役を分ける理由の 1 つ(ユーザー)。外に置く控え(`git bundle`)は直近 4 個を残す(2026-11-04 時点で 1 個約 240 KB・ユーザー OK)。置き場所は `apps/soul/agent/memory-backups/`(git に入れない・ユーザー OK)。
  - 書き出し役への頼みの文面は変えてよい: 「ファイル名は魂が決めた」の段落を外し、「前回の保存ではこのファイルに書いた」に置き換える(②の文面を一字も変えない方針の例外・ユーザー OK)。
