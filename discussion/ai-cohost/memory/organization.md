# 記憶の整理(③整理役)の設計

> 状態: 設計の案(2026-11-04)。2026-11-05、人間ゲート 1 回目の所見から §2・§3・§5 を直した(サブトピックの目次を必須に・頼みの上限を外す)。決まったことはすべてユーザーの言葉付きで [_map.md](_map.md) §4 にある。ここはそれを 1 本にまとめ、棚卸しで出た細部をうちの案で埋めたもの。うちの案には【案】と付ける。
> 根拠: [organization-inventory-2026-11.md](organization-inventory-2026-11.md)(これまでの議論の棚卸し)、[organization-code-inventory-2026-11.md](organization-code-inventory-2026-11.md)(コードの棚卸し・file:line はこちら)、[recall-flow.md](recall-flow.md)(役と置き場)。

## 1. 割り切り

- 記憶の責務は「探しやすくなっている」ことだけ。探すのは思い出し役(④)が頑張る。
- 整理は**棚と目次の作り直しだけ**。抽象的な索引は作らない。構図で思い出してほしければ、思い出し役にそう頼めばよい。
- **本体の中身は変えない**。1 回の場の 1 件のまま。話題が混ざっていても切り分けない。話題では目次で引く。
- 10/21 の「整理の段階で抽象的な索引を付ける」はこれで上書きした。

## 2. 置き方

```
_conventions.md
_map.md                          全体の目次(トピックごとに 1 行。記録の数・最後の日付。書き出し役が直す)
<topic>/                         トピック
  _map.md                        入口: 何の話かの一言 + すぐ下のサブトピックの一覧(整理役が書く)
  <YYYY>/                        年(目次は置かない)
    <MM>/                        月の棚
      _map.md                    その月の時系列の目次(書き出し役が 1 行足す)
      <YYYY-MM-DD>[-N].md        本体(書き出し役が最初からここに書く)
  <サブトピック>/                   サブトピック(目次だけ。整理役が作る)
    _map.md                      本体へのリンク + すぐ下のサブトピックの一覧
    <さらに細かいサブトピック>/
      _map.md
```

- 言葉: **トピック**は置き場の直下のフォルダ(`cohost-dev` など)。**サブトピック**はトピックの中に作る、目次 `_map.md` だけを入れたフォルダ。サブトピックの中に、さらにサブトピックを掘ってよい(入れ子)。全部のサブトピックをトピックの直下に平らに並べる、という意味ではない。名前はトピックと同じく英小文字とハイフン。
- 本体はサブトピックに入れない。年と月の棚に置いたまま、サブトピックの目次から指す。1 件に話題が混ざるので、1 件をいくつのサブトピックの目次に載せてもよい。
- サブトピックの目次は**必ず作る**(件数の少ないトピックでも)。分け方・粒度・どこまで掘るかはチャッピーの裁量(2026-11-05、[_map.md](_map.md) §4)。
- 時系列の目次は**月の棚ごと**。トピックに 1 本だと数年でスケールしないため。年のフォルダには目次を置かない。
- トピックの直下の `_map.md` は**入口**。何の話かの一言と、すぐ下のサブトピックの一覧。サブトピックを作るのも一覧を書くのも整理役の同じ回なので、食い違いにくい。
- ファイル名はそのまま残す。日付が年と月のフォルダと重なるが、名前だけで「いつの回か」が分かるようにするため。
- 目次の書式はがちがちに決めない。決めるのは「探しやすい」ことだけで、形はチャッピーの裁量に任せる。
- 探し方が 2 本立つ: 直近の話・日付の分かる話は月の目次、話題はトピックの入口からサブトピックの目次。サブトピックの目次は前の整理までの本体を載せ、それより新しい分は月の目次で探す(`_conventions.md` に整理役が書く)。週 1 のままでよいのは、この境目がはっきりしているため。
- たどり方の決まりは `_conventions.md` に一本化する。②・④の頼みは「`_conventions.md` に従って」とだけ書く。

## 3. 役の分担

| 役 | すること |
|---|---|
| ②書き出し役 | 今の場の本体を月の棚に書き、`_conventions.md` に従って当たる目次の行(月の目次・全体の目次)を足す・直す。本体のファイル名も自分で決める |
| ③整理役(ユーザーの呼び名「夢を見る」) | 週 1 回。直下に本体があれば棚へ動かし、月の目次をそろえ、まだどのサブトピックの目次にも載っていない本体をサブトピックの目次に足し(分け方の見直しも)、入口と全体の目次を直し、`_conventions.md` を今の置き方に合わせて書き換える |
| ④思い出し役 | `_conventions.md` のたどり方に従って目次をたどる |
| soul | 役を呼ぶ・コミットする・見張る。**本体の名前は決めない** |

## 4. 書き出し役まわりの変更

- 本体の名前を soul が決めるのをやめる。`resolveStreamRecordBaseName`・`findStreamRecordFiles`・`createStreamRecordIdentity` と、操縦席の場ごとの名前の持ち回り(`streamRecord`)は外す。
- **前回の続き**: soul は、場の各保存のコミットで足された本体のファイルを git から読んでためておく。次の保存の頼みで「この場の前回までの保存では、このファイルに書いた: …」と伝える。【案】伝えるのは 1 回目だけでなく、その場の保存で足されたファイルを全部にする(2 回目以降に別のトピックが増えることがあるため)。
- **書いていないの判定**【案】: 名前ではなく「そのコミットで本体(`_` で始まらない `.md`)が 1 つも足されても変わってもいない」で見る。足りなければ、今どおり 1 回だけやり直す。
- 頼みの文面: 「ファイル名は魂が決めた」の段落を外し、上の「前回までに書いたファイル」の行に置き換える。②の文面を一字も変えない方針の、ユーザー OK の例外。固定のテスト(`stream-wording-pin-expected.mjs` の `writer.request.new` / `writer.request.existing`)も合わせて直す。④の文面はこの時点では変えなかった(2026-11-05 に手順 2 だけ変えた。§2)。
- 新しいロールの置き場の決まりの種(`src/memory/conventions-seed.md`)は、名前の段落(soul が番号を付ける旨)を直す。【案】名前は「日付。同じ日付の本体が、どのトピックのどの棚にあっても、次の番号を付ける」とする。
- 化けの検査(Domain L)は、書き出し役のコミットには今どおり掛ける。

## 5. 整理役

- **きっかけ**: 場を閉じる操作(配信を終える・通話を終える)で、閉じの書き出しが終わったあと、前の整理から 7 日以上たっていれば(または一度も整理していなければ)続けて走る。【案】新しい文字起こしが無い閉じでも走らせる。
- **前に整理した時刻**: 記憶の git で、最後の `整理役 ` で始まるコミットの時刻(`Revert` は除く)。別の置き場は作らない。【案】整理役が何も変えなかったときも、soul が空のコミット(`整理役 <日時>(変更なし)`)を作る。そうしないと、閉じるたびに整理が走ってしまう。
- **頭**: 書き出し役と同じ扱い。ロールの頭が Codex ならそれ、違えば Codex の Terra(`resolveWriterBrainDef`)。使い捨てのセッションで、作業フォルダは記憶の置き場、`workspace-write`、最後の答えだけ。頼みに待つ上限は**付けない**(2026-11-05 ユーザー「上限の30分は邪魔だな / ない方がいいと思う」。1 回目は 30 分の上限付きで実装していた)。止めるのは Ctrl+C だけ。
- **頼みの中身**(2026-11-05 改訂。文面の全文は実装計画 §4b と固定のテスト):
  1. `_conventions.md` と全体の目次を読む。
  2. 各トピックの直下に本体があれば、名前の日付の `<YYYY>/<MM>/` へ動かす。**本体の中身は一字も変えない。**
  3. 月の棚ごとの時系列の目次をそろえる(載っていない本体を足す・無ければ作る・トピックの目次に残る時系列の行は月の目次へ移す)。
  4. どのサブトピックの目次にも載っていない本体を読み、当たるサブトピックの目次に足す。サブトピックが無ければ作る。分け方・どこまで掘るかはあなたが決め、話題が増えたら分けたり合わせたりしてよい。
  5. トピックの目次を入口として書き直し(一言 + すぐ下のサブトピックの一覧)、全体の目次を直す。
  6. `_conventions.md` を書き換える。サブトピックの目次がいつの整理までの本体を載せているか、新しい分は月の目次で探すこと、書き出し役がどこに書きどの目次に行を足すかも書く。
  7. 書き終えてから「済み」とだけ答える。
- 頼みは「前の整理から増えた分」ではなく**今の状態**で書く。だから一発の移行のコードは要らない。直下の本体の棚への引っ越しは手順 2、トピックの時系列の目次から月の目次への移しは手順 3、棚にある本体のサブトピックの目次への登録は手順 4 で、それぞれ自然に済む(ユーザー「こんな一発マイグレーションを入れるだけみたいなロジックを実コードに入れたくない」)。
- **最初の整理**: 今ある本体(2026-11-04 時点で 40 件)の引っ越しも、最初の整理でやる(ユーザー OK)。2026-11-05 の 1 回目の整理で済んだ(43 件、全部中身そのまま)。
- 化けの検査は、整理役のコミットには掛けない(動かした本体が全部「足された行」に見えるため)。本体の中身の見張り(§6)がその代わりになる。

## 6. 見張り・後始末・控え

- **始める前**: 書き出し役・整理役を呼ぶ前に、コミットされていない変更があれば捨てる。記憶はチャッピーしか書かない前提なので、作業ツリーは普段 clean のはず(ユーザー)。
- **整理役のあと、コミットの前に**: 次の 2 つを確かめる。
  1. git の先頭が走る前と同じであること(コミットするのは soul だけ)。
  2. 本体の中身の一覧(中身のハッシュの組)が走る前と同じであること(場所は変わってよい)。

  だめなら変更を捨て、コミットしない。前に整理した時刻は進まない。【案】警告は中身を書かない英語の 1 行にする(Domain L に合わせる)。
- **控え**: 整理役を呼ぶ前に、記憶の git を丸ごと `git bundle` で `apps/soul/agent/memory-backups/<role>/` に固める(git に入れない)。直近 4 個を残し、古いものは消す。【案】控えが作れなかったら、その回の整理は走らせない(警告を出す)。

## 7. 閉じの流れ

- 場を閉じる操作では、閉じの書き出しのあと、整理が終わるまで**上限なしで待つ**(整理役の頼みにも上限は無い。§5)。画面には「整理中」と出す。今の閉じの段階(`closing`)の中に、整理中であることが分かる印を足す。
- 書き出しの 90 秒の上限(`SHUTDOWN_MEMORY_TIMEOUT_MS`)は今どおり。
- **Ctrl+C**: 書き出しは今どおり 90 秒待つ。整理は**すぐ打ち切る**(セッションを閉じ、変更を捨てる。時刻は進めない)。次の閉じでやり直す。
- 運用では、場を閉じる操作で終える(ユーザー)。
