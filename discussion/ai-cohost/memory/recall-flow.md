# 思い出す流れ(オンデマンドの想起)— 合意の途中経過

> Status: 形のイメージを合意(ユーザー 2026-10-21)。仕組みの細部(目印の書式、思い出す役の材料と出力、2 回目の判定の問い)は未決。
> 前提の調査: [research/brain-tools-2026-10.md](research/brain-tools-2026-10.md)(頭のツール制限)、[research/associative-recall-literature-2026-10.md](research/associative-recall-literature-2026-10.md)(文献)。

## 1. 形のイメージ(ユーザー)

- しゃべっているチャッピー本人(今の会話のセッション)が、記憶を探しに行くのではない。**思い出す役が別にいる。** 思い出す専用のセッションが記憶の目次と本体を読み、見つけた結果だけを持って帰る。
- たとえるなら「サブエージェントに探させる」形。サブエージェントという技術に固定する意図はなく、形を伝えるための一例。
- チャッピーは頼む側で、しゃべる場面が 2 回ある。
  1. 頼んだとき(例:「ちょっと前の記録探してくるね」)
  2. 結果が来たとき(例:「見つかったで、前回は○○で止まっとったわ」)
- 「探すからちょっと待ってね」と言うのはむしろ自然(相手は AI。[_map.md](_map.md) §1)。

## 2. 決めたこと(ユーザー 2026-10-21)

1. **探している間も、チャッピーは会話を止めない。**
2. **2 回目をいつ言うかは、チャッピー側で決める。** 話題が変わっていれば言わないこともある。この判定は Decisions API でよいかもしれない(ユーザー)。
3. **頼むきっかけは、チャッピーが返事の中に目印を書く形に揃える。** 配信者の「思い出して」も、チャッピーが自分で「前にあったな」と気づいた場合も同じ。
   - 配信者の「思い出して」を魂の側で拾う案は採らない(拾うのが難しい)。
4. 実験的な機能(Codex の dynamicTools)に頼るとは限らない。やり方は比べて決める(ユーザー「これしかないなんてことはないんじゃないか」)。

## 3. 今の仕組みへの当てはめ(うちの案・未合意)

- **頼み方**: すでにある演出の目印(返事の中の `[笑顔]` などを、声にする前に魂が抜き取る仕組み)と同じように、`[思い出す: エルデンリング 前回どこまで]` のような目印を書かせる。道具の仕組みを使わないので、Codex でも Claude でも同じに動く。
- **思い出す役**: 配信のまとめを作るときと同じく、使い捨てのセッションを立てる。記憶は今全部で約 36KB なので、最初は道具を持たせず、魂が目次と関係しそうな本体をまとめて渡して読ませるだけでも成り立ちそう【推測】。
- **結果の返し方**: 魂がチャッピーに「思い出した結果」を届けて 2 回目の発火を起こす。忙しい間のコメントをあとで拾う仕組み(after-busy)や自発の発火と同じ通り道が使えそう【推測】。
