# 書き出し役の書き込みが「?」に化けた件(2026-11-01 の配信)

> 状態: 原因は推定。直し方はユーザー OK(2026-11-01「OK、両方やっていいよ」)。記憶の掃除は済み、コードの直しは計画 [../implementation/orchestration/discord-mode-wave-plan.md](../implementation/orchestration/discord-mode-wave-plan.md) §8 Domain L。
> 調べた人: Undine(記憶のフォルダの git の履歴と本体を直接読んだ。ユーザーの了承の範囲)。

## 1. 起きたこと

- 2026-11-01 夜の配信(エンドフィールド)の記憶のうち、`cohost-dev/2026-11-01-4.md` と `arknights-endfield/2026-11-01-4.md` の前半が `?` だらけだった。
- 化けたのは**最初の途中保存(20:56・記憶の git `7cdaa82`)で書いた分だけ**。同じ回に 2 つのトピックの目次 `_map.md` に足した 1 行も化けた(目次のもとからある行は無事)。
- 21:19・21:40・22:03・22:25・22:46 の書き込みは正常。どれも化けた部分を消さずに「## 今回の記録(既存部分を残して追記)」として後ろに足していた(頼みの「今ある内容を残したまま」に従った)。前半だけ化けて見えたのはこのため。
- 後ろに足された正常な部分は配信の頭からの話を書き直しており、中身は失われていなかった。
- 同じ日の昼の通話の記憶(12:20・12:33)と、ほかの日の記憶は無事。

## 2. 手がかり

- 日本語も「—」も **1 文字が `?`(0x3F)1 個**。英数字(TRPG・@j.h8989・OBS)は残る。文字化け(別の文字コードで読んだ崩れ)ではなく、書いた時点で `?` に置き換わっている。
- 目次はもとの行が残り、足した行だけが化けた → ファイルを丸ごと ASCII で書き直したのではなく、**足す文だけが ASCII を通った**。

## 3. 原因の推定

Windows PowerShell 5.1 は、外のプログラムへパイプで文字を渡すとき、何も指定しなければ ASCII に変換する(`$OutputEncoding` の既定)。書き出し役(Codex)がこの回だけ、書き込み用のスクリプトを PowerShell のパイプで Python などに渡し、渡された側が UTF-8 でファイルに書き足した、と見ている。どの書き方を選ぶかは毎回 Codex 任せなので、1 回目だけ悪い書き方を引いた。

確かめられないこと: 書き出し役のセッションは使い捨て(`ephemeral`)でやり取りが残らず、`~/.codex/sessions` は触らない約束なので、実際のコマンドは分からない。このブランチ(`ai-cohost/discord-mode`)で書き出し役のコードは変えていないので、ブランチ由来ではない。

ついでに見えたこと: 途中保存は 20:56 → 21:19 → 21:40 → 22:03 → 22:25 → 22:46 と、約 20 分おき(書き出しの時間ぶん少し延びる)に走った。Domain H のタイマーが配信でも効いている。

## 4. 掃除(済み)

- 2 つの本体から `?` の部分と「## 今回の記録(既存部分を残して追記)」の見出しを除き、ファイルの見出しを付け直して小見出しを 1 段上げた。中身の文は変えていない。目次は 21:19 の書き込みで直っていたので触っていない。
- 記憶の git に Undine の手でコミット(`a88289c`「手直し: 2026-11-01-4 の「?」に化けた部分を除き、見出しを整える」)。

## 5. 再発を防ぐ直し(ユーザー OK・Domain L)

両方入れる(Undine の見立て・ユーザー OK)。

1. **指示を足す**: 書き出し役の固定の指示(`buildWriterSystemPrompt`・配信と通話の両方)に、「ファイルは直接書き換える道具で書く。シェルのパイプやスクリプトに日本語を通すと `?` に化ける」の旨を足す。配信の文面の固定テスト(`stream-wording-pin`)はこの 1 か所だけ意図して変わる。
2. **確かめて取り消す**: 書き出し役の書き込みをコミットしたあと、そのコミットで足された行を見て、化けていたらそのコミットを `git revert` で取り消し、同じ材料で 1 回だけやり直す(今の「書かずに答えたら 1 回だけやり直す」と同じ枠。やり直しは理由を問わず合わせて 1 回)。
   - 化けの見分け方: 足された行のうち、`?` が 4 つ以上続き、かつ日本語などの ASCII 以外の文字を 1 つも含まない行が 1 行でもあれば化けとみなす。今回の形(行ぜんぶが ASCII に落ちる)を拾い、ふつうの日本語の文の「??」は拾わない。
   - やり直しでも化けたら、それも取り消して「記録できなかった」扱い(記録時刻を進めない)にし、次の定期保存で書き直させる。
   - 知らせは中身を書かない警告だけ(例「memory: the writer's text came out as question marks; reverted」)。
   - 取り消しは履歴に残す(`revert`。履歴を書き換えない)。そのコミットに書き出し役以外の未コミットの手直しが混ざっていた場合も一緒に取り消される(今のコミットのしかたと同じ限界。注記のみ)。
