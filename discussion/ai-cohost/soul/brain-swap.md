# 頭脳の差し替え: ChatGPT サブスク(Codex)経由 GPT-5.6 Terra

> Status: 議論中(2026-07-17)。前提討議①([llm-access-path.md](llm-access-path.md) = Max 20x + Agent SDK 一本)の**多頭化拡張**。
> 動機(ユーザー): GPT-5.6 Terra の応答速度を試したい。運用想定=**配信前に頭を選ぶ**(配信中の差し替えは運用外)。
> 調査: Sylph(opus)による Web + リポジトリ事実調査(2026-07-17)。

## 1. 視座(議論で確立)

- 差し替わるのは魂やなく**頭脳**(mind/llm-session.mjs の向こう側の借り物エンジン)だけ。耳・声・発火・転写・演出・操縦席・安全弁は全部うちらの資産で不変。
- 「転写バッファが正、SDKセッションは使い捨てキャッシュ」(討議②)により、頭が替わっても会話の連続性は正本から再注入されて保たれる。**こーでぃー ≠ Claude の証明**になる実験。
- **S8 の安全弁(TTS 直前検問所・キル)は頭の外側**——どの頭でも全発話が同じ弁を通る。頭の差し替えは安全網を弱めない。

## 2. UX 裁定(2026-07-16 ユーザー)

- **正のフロー**: 「魂を起動し、LLM を選び、動作確認をして、配信を開始する」——配信前選択が本線。
- ライブ差し替えは「タダなら対応」(一級 UX にはしない)。
- v0 の選択肢は**フラット 2 項目**(Claude (Opus 4.8) / Codex (GPT-5.6 Terra))。provider×model 行列は将来の梯子。
- 設定層に「頭脳」区画(資格情報の健康表示つき・操縦席は資格情報そのものを扱わない)・観測層に発話ごとの頭の名前+応答レイテンシ。

## 3. 調査結果の要点(詳細は調査 Sylph 報告・2026-07-17)

**経路は実在し、機材は既に揃っている**:

- `@openai/codex-sdk`(npm・Node18+)実在。CLI を spawn して JSONL 往復する設計。`codex.startThread({model})` → `thread.run(input)` → `finalResponse`。`runStreamed` あり。
- 認証 = `codex login`(ChatGPT サブスク OAuth)→ `~/.codex/auth.json`。**ローカルは codex CLI 0.141.0 導入済み・ログイン済み・Node v22.14.0**(SDK 要件充足)。
- **GPT-5.6 Terra 実在**(2026-07-09 GA): Codex で `-m gpt-5.6-terra` 選択可・**画像入力対応**・1.05M context・出力 137.6 tok/s。ただし **reasoning モデルで TTFT が長い可能性**(要実測)——`model_reasoning_effort`(minimal〜xhigh)が体感速度のダイヤル。
- サブスク固定ガード(env-guard 相当)= `forced_login_method = "chatgpt"`(API キー従量課金への化けを防ぐ公式スイッチ)。
- レート枠 = 5h ローリング窓+週次キャップの二段。
- Windows ネイティブ対応(WSL 不要・experimental ラベル)。

## 4. 現行契約との段差(スパイクで潰す未知)

| # | 段差 | 中身 | 扱い |
|---|---|---|---|
| ① | **常駐性と速度(最優先)** | SDK が温かいプロセスを保つか run() 毎 spawn か不明。Anthropic 側で観測した「毎回 spawn ≈12s」が出るか。reasoning_effort minimal/low での TTFT 実測 | スパイクの本丸。「速い」動機がここで立つか崩れる |
| ② | **素チャット化** | Codex は本質コーディングエージェント。`sandbox_mode=read-only`+`approval_policy=never`+`shell_tool=false`+`web_search=disabled` でツール封じ→日本語一問一答が安定するか | スパイク実測 |
| ③ | **画像の渡し方** | 現行= base64 インメモリ(ディスク非書き込みが S5 の流儀)。Codex= `local_image`(ファイルパス)のみ | 製品裁定(下記問い 1) |
| ④ | **systemPrompt 注入** | per-ask 動的注入の口が無い(config/AGENTS.md/入力埋め込み)。**ただし現行契約もセッション生成時固定**(createLlmSession({systemPrompt}))なので実質段差なし | 起動時固定で整合。スパイクで注入方式だけ確定 |
| ⑤ | **セッションのディスク永続**(L0 追加発見) | Codex は Thread を `~/.codex/sessions` に自動永続。現行は persistSession:false(転写の写しをディスクに残さない)。**視聴者コメント込みの注入文が Codex 側でディスクに残る**流儀差 | スパイクで無効化可否を確認。不可なら受容裁定が要る |

## 5. 裁定(2026-07-17 ユーザー・3 問クローズ)

1. **画像契約 = (a) 一時ファイル書出+即削除を許容**。ただし設計制約(ユーザー明示): **この仕組みが魂の他機能に漏れ出す設計は不可**。今後も「ローカルファイルしか読めない LLM」は現れ得るので、再利用性を考えつつ余計な依存を生まない形。
   → **L0 の設計翻訳**: 知性契約は現行どおり **base64 インメモリのまま**(目も発火も転写も何も変わらない)。base64→一時ファイル→`local_image`→即削除の橋渡しは **Codex アダプタ内部の私事**として封じ込める。第二の「ファイルしか読めない頭」が現れた時点で初めて共有ヘルパへ昇格(それまでアダプタ内に留める=余計な依存を作らない)。
   → **昇格予約のドキュメント義務(2026-07-17 ユーザー追加裁定)**: 「二人目の客が来た時のために、こういう品があること」をドキュメントに残す。具体的には (1) 本節がその正本 (2) 実装 wave で **Codex アダプタのモジュールヘッダに「この一時ファイル橋渡しは provider 追加時に共有ヘルパへ昇格可能(brain-swap.md §5 参照)」の一文** (3) **README の provider 追加手引きに同旨**を必須成果物とする。将来の実装者が第二の頭を足すときに必ず目に入る場所に置く。
2. **規約 = 一旦許容方向**。根拠(ユーザー): Claude Code での実測から類推してトークン使用量はほぼタダ同然の想定= OpenAI 側にかかる負荷は実質なし。innertube と同型のグレー受容。
3. **速度 = ユーザー体感で裁定**(事前の数値ラインなし)。**重要な追加観測(ユーザー)**: 現行 Opus は**セッションが長くなると応答まで 10 秒程度かかる**ことがある。→ 比較は「短いセッション同士」だけでなく長回し劣化も視野に。

### 5-1. 長回し 10 秒劣化への設計候補(L0 メモ・本問題のスコープ外候補)

現行アーキ(転写が正・セッションは使い捨てキャッシュ)は、**セッションの定期リサイクル**(一定発話数/時間で dispose→再生成。連続性は正本からの再注入で保たれる)という対策を最初から許している。Terra 移行と独立に Claude 経路の改善候補として台帳に残す(着手はユーザー裁定)。

## 6. 次の段取り

1. **ユーザー install**: `apps/soul/agent` で `npm install @openai/codex-sdk`(魂は独立 npm・root lockfile 不変)。
2. **スパイク**(install 後に L0 が Gnome へ委任・experiments/ 流儀・実 Terra 消費はユーザー了承済みの実験):
   - **S-1 速度(本丸)**: startThread→run 縦貫通。cold(初回)/warm(2 発目以降)のレイテンシ・TTFT(runStreamed)。`model_reasoning_effort` = minimal / low / medium の 3 点比較。同一 Thread 連続 10 往復での劣化有無。
   - **S-2 素チャット安定性**: ツール封じ設定(`sandbox_mode=read-only`+`approval_policy=never`+`shell_tool=false`+`web_search=disabled`)下で、FIRE_SYSTEM_PROMPT 相当+日本語短文注入→短い日本語一言が安定して返るか(10 本・ツール混入/英語混入/長広舌の率)。
   - **S-3 流儀差の確認**: セッションの `~/.codex/sessions` 自動永続の無効化可否(config)・usage(`turn.completed.usage`)の実形・`forced_login_method="chatgpt"` 下での API キー非干渉。
   - **S-4 画像**(余力があれば): 一時ファイル橋渡しで `local_image` 一発(書出→run→削除まで計測)。
3. 実測→ユーザー体感裁定→(立てば)知性契約+操縦席 UX の wave 計画へ。

## 7. スパイク結果(2026-07-17 実測・正本 = [../experiments/brain-swap-terra.md](../experiments/brain-swap-terra.md))

実 Terra 16 発(予算 20 以内・429 ゼロ・課金非干渉をエラー経路で裏取り)。要点:

| 観点 | 結果 |
|---|---|
| **速度(本丸)** | **Terra @none は速くない**: warm 中央 ~4.0s vs Claude Opus warm ~3.2s。cold≈warm(spawn は ~310ms と安い・律速はモデル往復)。10 往復(in_tok 117k・cache 追随)でレイテンシ概ね平坦・turn10 のみ 6.45s |
| **ストリーミング** | codex 経路は**トークン delta が無い**(完成一括)。今日の実装同士なら僅差やが、「先頭文先行 TTS」という将来の伸びしろが**構造的に閉じている**(Claude 経路には TTFT ~1.2s の土台がある) |
| **素チャット安定性** | **15/15 満点**——短い日本語一言・ツール/英語混入ゼロ・**表情タグまで persona 語彙どおり**。仮面(FIRE_SYSTEM_PROMPT)は完全に可搬 |
| **effort** | `minimal` 非対応(400 実測)。選択肢は none/low/medium/high/xhigh。短文雑談では reasoning 不発火(=none/low/medium 同速)。既定候補 = `none` |
| **永続(段差⑤)** | **SDK 経由ではディスク永続は不可避と確定**(`--ephemeral` は CLI のみ・SDK 非露出・SDK のマルチターンは resume=ディスク依存)。回避するなら fork/パッチ+毎発火使い捨てスレッド("転写が正"思想と合致)か、永続受容の二択 |
| **画像** | 一時ファイル橋渡し成立(撮影→書出→run 4081ms→即削除) |

**L0 所見**: 速度動機に対しては**否定寄り**。ユーザーの痛点「長セッションで ≈10s」に対しては、Terra の平坦さ(≦117k で ~4s)は魅力やが、Claude 経路の**セッション定期リサイクル**(§5-1)が同じ痛点をより安く解く可能性が高い。一方「差し替え自体の成立性」(素チャット・仮面可搬・画像・認証)は**満点で証明**された——動機とは独立に、多頭化の道は開通しとる。

**開いた問い(ユーザー裁定)**: ①この数字で速度動機は立つか(統合 wave へ進む/スパイク回答で一旦閉じる) ②進むなら永続は fork か受容か ③進むなら既定 effort=none でよいか。
