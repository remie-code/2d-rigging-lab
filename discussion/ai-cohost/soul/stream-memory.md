# 配信間記憶: セッションダイジェストと自動搭載

> Status: 議論クローズ・裁定確定(2026-07-19)。[s-series-decomposition.md](../implementation/s-series-decomposition.md) §4 で保留しとった「配信をまたぐ記憶」の解禁。
> 前提原則: **記憶は一級資産**([brain-swap.md](brain-swap.md) §5-1・2026-07-17 昇格)——「これ、さっきのやつだよね」の配信間バージョン(「昨日のアークナイツの続きやな」)が本件のゴール。
> 発端: 1:40 配信の完走後、ユーザー「セッションのダイジェストを残す形で、魂起動時にセッション要約を選択できるようなイメージ」→ 議論で「選択」から「自動搭載」へ反転。

## 1. UX の核(議論で確立)

**相方は記憶を選ばへん。覚えとるのが自然な状態で、忘れさせるのが例外操作。**

- 「起動時に要約を選ぶ」はセーブデータのロード=道具のメタファー。相方には「既定で覚えとる・OFF が例外」が正しい向き(ユーザー承認)。
- 「今日はゲーム B やから A の記憶は不要」という選別は不要どころか有害——別ゲーム中の「この前のアークナイツでな…」いう脱線こそ人間味の源泉。全部覚えとってよい(圧縮されとる限り)。

## 2. 裁定一覧(2026-07-19 ユーザー確定)

| # | 論点 | 裁定 |
|---|---|---|
| 1 | デフォルトの向き | **起動時に直近 N 件のダイジェストを自動搭載**(選択の儀式なし)。設定層「記憶」区画に状態表示+**「記憶なしで起動」の例外スイッチ** |
| 2 | 視聴者情報 | **ダイジェストに視聴者名を残さない**(v0・生成指示で除外)。視聴者データの跨ぎ蓄積を入口で断つ |
| 3 | 搭載件数 N | **初期値 3 件**(体感で調整) |
| 4 | 生成タイミング | **「一つの操作・三つの引き金」**: ①定期チェックポイント(15〜30 分ごと自動・同一ファイル上書き) ②手動「今日を記録」ボタン ③Ctrl+C(SIGINT)時の最終版。クラッシュ/停電でも最悪直近十数分の損失のみ |
| 5 | 記憶の主権 | **人間可読 Markdown のローカルファイル**(1 配信 1 ファイル・gitignore)。読める・直せる・消せる——主権は UI やなくファイルシステム(「転写が正」と同じ思想) |
| 6 | 注入点 | **セッション生成時**(仮面 FIRE_SYSTEM_PROMPT の隣)。知性契約は両頭とも起動時固定 systemPrompt ゆえ **Claude 頭でも Codex 頭でも同じ形** |
| 7 | 生成の実行形 | **常駐セッションを汚さん別の使い捨て ask**(常駐の履歴に「要約してくれ」のやり取りを混ぜない)。要約するのはその時選ばれとる頭 |

補足事実: ユーザーの終了習慣は毎回 Ctrl+C(=SIGINT・shutdown() が走る正常終了)——③は既に習慣と一致。ブラウザを閉じても魂は生きとる/ターミナル×は不確実、という事実確認も済み(チェックポイントが保険)。

## 3. ダイジェストの中身(生成指示の骨子)

- 配信の出来事(ゲーム・進行・ハイライト)/交わした話題・ジョーク・言い回し(callback の種)/配信者について分かったこと。
- **視聴者名・個人を特定する情報は書かない**(裁定 2)。
- 分量は注入に耐える短さ(数百〜千数百字目安・詰めは wave で)。

## 4. 開示との整合(L0 直轄)

[pre-stream-checklist.md](../operations/pre-stream-checklist.md) §1 の注記どおり、記憶導入時は開示文言の更新が前提。「配信内容の要約を次回配信の参考として保存することがあります(視聴者を特定する情報は保存しません)」の趣旨を開示文言に追記する(文言起草は L0・貼るのはユーザー)。

## 5. 将来の梯子(v0 外)

- ダイジェスト群の**日記への合本・再圧縮**(件数が溜まってからの課題)。
- 起動時の個別選択 UI(ファイル削除/移動で代替できとる間は作らん)。
- 長回し対策(セッション内圧縮・候補 B)とは別問題として維持——ただしチェックポイント機構は将来そちらの部品になり得る(縫い目だけ意識)。
