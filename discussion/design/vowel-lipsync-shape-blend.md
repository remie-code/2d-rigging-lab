# 母音リップシンクの形状ブレンド — 単一勝者(argmax)から正規化凸ブレンドへ

> Status: **Draft**（設計合意 2026-07-08。ユーザーとの往復で方針・τ 接地・え 目視・強度 s まで合意。未実装）。
> 関係: [vowel-lipsync-mouth-open-coupling.md](vowel-lipsync-mouth-open-coupling.md)（Wave22, Implemented）の後続。Wave22 の「mouth_open = 勝者 w」を「mouth_open = ブレンド強度 s」へ一般化し、[vowel-lipsync-mapping.md](vowel-lipsync-mapping.md) のリグ契約 **cp17「単一 Vowel 非ゼロ」を意図的に解除**する。
> データ基盤: `test_data/iFaceMocap/vowels/vowel-captures.json`（推定器と同一の8次元縮約・`weightedDistance` で解析。母音間距離 中央値≈0.51 等 → §6）。

## 1. 問題（病巣）

Wave22 で口の開きが直った結果、**それまで開きの潰れに隠れていた「母音の"形"の不連続（切替時のパチつき）」が可視化された**。「あ↔い」等の母音切替で口形が飛ぶ。

### 1.1 パチつきの正体は cp17 そのもの（設計事実）

現行の母音出力は **argmax の単一勝者**（一度に1母音だけ非ゼロ。cp17）。「い」の形から「う」の形へ**連続的に**渡るには、途中で**両方が少しずつ効く瞬間**を必ず通る必要がある。それを避ける道は「一度 neutral まで閉じて開き直す」だけで、これはより不自然。

→ **形の連続な受け渡しは cp17（厳格な単一勝者）が構造的に禁じている。** 「平滑化だけ（ブレンド無し）」で形のパチつきは消せない。切替の連続性(i)も、狙った中間口(ii)も、行き着く先は同じ:「**単一勝者を緩めて母音を連続的に重ね合わせる**」。

### 1.2 リグは重ね合わせに耐える（ユーザー実機確認）

cp17 は「リグが母音の重ね合わせに耐えるか不明」だったために置かれた制約。ユーザーが editor プレビューで確認: **合計≈1 の凸ブレンド（2混ぜ〜5混ぜ）で口形は破綻しない**（Mouth Open=1・5母音合計≈1.1 でも自然）。→ cp17 を外す前提が満たされた。

## 2. 設計判断（採用方針）

**cp17 を解除し、母音を「合計≈1 に正規化した凸ブレンド」で同時出力する。** 単一勝者は「分布が一点に尖った特殊ケース」に一般化される。

### 2.1 パイプライン

```
距離 distanceByVowel
  → [① softmax  raw_v = exp(−d_v / τ) ]        … 鋭さ(温度 τ)はここ（非線形）
  → [② × strength_v ]                          … 母音ごとの bias（線形・既存 strength）
  → [③ ÷ Σ_j(raw_j × strength_j) ]             … 正規化（合計=1・凸性＝リグ非破綻条件）
  → 正規化重み_v
  → [④ × 強度 s ]
  → param_mouth_vowel_v = s × 正規化重み_v ,   param_mouth_open = s
```

### 2.2 ① 生重み: softmax + データ接地した温度 τ

- `raw_v = exp(−d_v / τ)`。`d_v` は推定器の `weightedDistance`（Δ空間、現状 次元重み全1）。
- **τ = k × (較正済み参照の母音間距離 中央値)**、**k ≈ 0.30（レンジ 0.25〜0.35）**。実測データ解析（§6）由来のスケール相対値。較正で参照が変われば中央値を再計算して同じ k を掛ける（移植可能）。
- τ→0 で argmax（単一勝者）に収束 → **Wave22 の挙動を後方互換で内包**。τ を上げるほど混ざる。
- **鋭さ(τ)は本増分では固定定数(A)**。ユーザー可変ツマミ(B')は保留（§4）。

### 2.3 ② strength = 正規化前の per-母音 bias

既存の per-slot `strength`（母音ごと5本・既定1・範囲0〜2）を**正規化の前段**に掛ける。

- 合計≈1 の凸性は正規化の中で保たれる。
- `strength_v = 0` で「その母音をブレンドから外す」現仕様が連続版でもそのまま生きる。
- ユーザーは母音ごとの相対 bias（例: 自分のモデルで い が弱ければ底上げ）を調整できる。
- **注意（重要）**: strength は**鋭さ(τ)ではない**。線形スケールは正規化で約分され、一律変更は分布の尖りに効かない（鋭さは①の非線形操作の担当）。strength ＝ 相対 bias、τ ＝ 鋭さ、と役割を分離する。

### 2.4 ④ 強度 s と mouth_open

- **`s = activity / (activity + d_min)`**。`activity` = 中立からの距離、`d_min` = 最近傍母音参照までの距離。
- **`param_mouth_open = s`**、各母音 = `s × 正規化重み`（合計 = s）。
- τ→0 で d_min→勝者距離 となり `s = activity/(activity+勝者距離)` ＝ **Wave22 の w に一致**（後方互換）。
- 各母音で正規化された量（どの母音でも「半分作れば s≈0.5」）。母音ごとの絶対 |Δ| 差（あ=0.82 vs い=0.32）に振り回されない。
- 喋りの強弱を拾う（弱い動き→ activity 小・d_min 大→ s 小、明瞭発音→ s≈1）。
- **副次的効用**: え が Δ空間中心に居るため（§2.5）、母音遷移の途中でも d_min が小さく保たれ、**s が途中で落ちない＝箱がポンプ状にパクつかない**。遷移中も口が開いたまま繋がる。

### 2.5 え寄生は「素の softmax」で許容（ユーザー目視で確定）

解析で、**え が Δ空間中心に居座り**（え-あ collinear: cos 0.974・大きさ約4割、かつ え-い が全体最小距離 0.167）、softmax ブレンドの多くの中点で え が最大重みを取る（例 あ↔い 中点で え≈0.42）ことが判明（§6）。これは τ では治らない幾何学的性質。

**しかしユーザー目視で「変な"え"顔にはならず、まともな中間口」と確認**（あ↔い 中点 え0.42/あ0.22/い0.22/お0.11、お↔あ 中点 あ0.25/え0.35/お0.25 を editor で確認）。え-あ collinear ゆえ え質量は「あ寄りの開き」に溶ける。

→ **判断: 素の softmax ブレンドで進める。top-k=2 制限・次元重み手術・え ゲートは入れない。** （将来 artifact が出れば §4 の対策候補を再検討。）

### 2.6 cp17 の解除（意図的な契約変更・記録要）

[vowel-lipsync-mapping.md](vowel-lipsync-mapping.md) が明言し写像層が構造的に強制していた **cp17「単一 Vowel 非ゼロ」を解除**する。写像層は「勝者なら w、他は 0」→「**各母音に `s × 正規化重み` を配る**」へ変わる。リグが凸ブレンドに耐える実機確認（§1.2）が根拠。

## 3. 実装面（見立て・"計画"前に bounded inventory で確定する）

Wave22 と異なり、**本増分は推定器本体に手が入る**。以下は現時点の見立てで、Wave23 計画前に棚卸しで確定する。

- 推定器 `vowel-lipsync-estimator.ts`: 内部で計算済みの `distanceByVowel` / `activity`（現状 `estimate()` で破棄）を使い、softmax 重みベクトルと `s` を派生。返り値を「勝者+w」から「正規化重みベクトル + s」へ拡張。**離散ヒステリシスは撤去**（連続ブレンドでは離散勝者が消え役目を失う）。ゲート（中立閾値）は維持し s=0 で口閉じ。τ は距離中央値ベースで導出。
- 写像層 `runtime-parameter-frame.ts`: 母音スロット評価を「勝者のみ」→「全母音に重み配分」に変更（cp17 解除）。mouth-open は `s` 駆動（Wave22 の readVowelEstimate 経路を一般化）。strength は正規化前 bias として適用。
- トグル（[vowel-lipsync-mapping.md](vowel-lipsync-mapping.md) §3.2 / Wave22）は維持: 有効→ブレンド、無効/非対応→ jawOpen フォールバック。

## 4. 本増分に入れない（保留 / 設計判断の留保）

- **(B) 時間平滑化**: ブレンド化で切替の飛びは消えるが、生重みのジッタ（特に **う** は解析で揺れ 0.22〜0.33 と桁違い・§6）が残る可能性。実機で気になれば重みベクトルの時間平滑化を足す（先行実装しない。Wave22 で棚上げした(B)とここで合流）。
- **(B') 鋭さ τ のユーザーツマミ**: まず固定 τ(A) で実機を見てから、可変ツマミ化を判断。
- **jawOpen 味付け(a)**: 物理オーバー表現を残したくなれば s に jawOpen 残差を足す second term を再検討。
- **え 寄生対策**（top-k / 次元重み / ゲート）: §2.5 で不要と判断。artifact が出た場合の候補として保持のみ。
- **カーブ整形**（s や重みの非線形整形）: チューニング事項。

## 5. 検証観点

1. **オフライン**: 各母音参照点で自母音優勢・隣接中点で滑らかな2〜3母音配分・え-あ 共活性が程よい範囲、を τ=k×中央値 で確認（解析スクリプト再現可・§6）。τ→0 で単一勝者に一致することの回帰。
2. **実機ユーザー gate**: リップシンク有効で発話し、(a) 母音切替のパチつきが解消し滑らかに繋がるか、(b) え 寄生が実発話でも benign か、(c) う のジッタで口が暴れないか（→(B)平滑化の要否）、をユーザー目視。
3. **フォールバック / 回帰**: 無効・非対応で従来挙動。母音分類の妥当性・トグル・body follow・strength スライダの効きに回帰なし。
4. **後方互換**: τ→0 で Wave22（単一勝者 + mouth_open=w）に一致。

## 6. データ基盤（実測解析・事実）

`vowel-captures.json` を推定器と同一の8次元縮約・`weightedDistance`（次元重み全1）で解析（縮約・距離は実コードと一致確認済み）。

- **参照 Δ の大きさ |Δ|**: a=0.824 / i=0.318 / u=0.598 / e=0.337 / o=0.383（a が突出・i/e が最小）。
- **母音間距離**: 最小 0.167（i-e）/ 中央値 0.510 / 最大 0.808（a-u）。
- **え-あ collinearity**: cos(Δe,Δa)=0.974・|Δe|/|Δa|=0.409・dist=0.501。「え は あ の縮小版」が実測成立（方向のみの分類=cos は不可 → 距離ベースが正しい、の裏付け）。え は i にも最近接（0.167）で Δ空間中心寄り。
- **母音内スプレッド（ジッタ）**: u が桁違い（0.216〜0.327）。a/i/e は安定（≤0.05）、o は中間（0.089〜0.145）。u の funnel/pucker 暴れが u/o 混同・ジッタ源。
- **τ 推奨**: 3基準（参照点で優勢 / 隣接で滑らか / え-あ 共活性が程よい）の交差で **τ ≈ 0.25〜0.35 × 中央値、中心 0.30**（実値 ≈0.13〜0.18）。推奨であり確定でない。
