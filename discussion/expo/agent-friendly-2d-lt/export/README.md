# UnaSlides用の出力

- [動画](agent-friendly-2d-lt-unaslides.mp4)：UnaSlidesに読み込むためのMP4。5枚、1枚1秒、合計5秒。
- [確認用PDF](agent-friendly-2d-lt.pdf)：同じ5枚を同じ順番で収録。
- [出力記録](export-manifest.json)：入力画像のハッシュ、動画仕様、キーフレーム時刻。

## 会場での設定

1. MP4を会場が利用する動画ホストに配置する。YouTubeを使う場合は公開または限定公開でアップロードし、処理完了を待つ。
2. UnaSlidesのURL欄に、配置した動画のURLを入力する。
3. Durationを **1.0秒**、Offsetを **0.5秒** にする。
4. 1〜5枚目を順送り・逆送りして、内容とQRの読み取りを確認する。

動画全体が5秒なのは、UnaSlidesが各秒の位置に移動してページとして停止表示するため。発表時間が5秒になるわけではない。

会場のURL利用方針と実機の表示は未確認。ローカルMP4から公開URLは自動では作られない。この作業では外部へのアップロードを行っていない。

## 出力仕様

- 1920×1080、30fps、150フレーム、H.264 Constrained Baseline、yuv420p。
- Bフレームなし。0・1・2・3・4秒にキーフレーム。faststart有効。音声トラックなし。
- 承認済み1600×900のプレビューを動画では1920×1080へ拡大。PDFは元画像を保持する画像ベースの5ページ。編集用原稿は親フォルダのHTML/CSS/SVG。
- 順序：表紙 → 今回開発したもの → モデリングツール → 配信用ツール → 開発期間のオチ。

## ローカル検証（2026-10-04）

- ffprobeで5秒、150フレーム、30fps、Bフレームなし、1秒ごとのキーフレームを検証。
- 各ページの中央時刻0.5・1.5・2.5・3.5・4.5秒のフレームを抽出し、順番と見た目を確認。
- MP4の0.5秒から取り出した表紙のQRを読み取り、元のアーカイブURLと一致。
- PDFの5ページに埋め込まれた画像が承認済みプレビューとピクセル一致。Popplerで描画確認。
- 全体図HTMLの欠けていた説明文と期間を承認済み内容へ復元。再描画が承認済みプレビューとピクセル一致。
- アップロード後の再エンコードと会場のVRChat/UnaSlidesでの動作は未検証。

## 再出力

親フォルダの `build-unaslides.py` をPythonで実行する。Pillow、ReportLab、PATH上のFFmpeg/ffprobeが必要。入力は親フォルダにある承認済み `*-preview.png` 5枚で固定している。HTMLを編集した場合は、先に該当プレビューを1600×900で再描画して確認する。
