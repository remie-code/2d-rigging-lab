# LTスライドの設計

## ユーザー合意（2026-10-04）

- タイトルは「エージェントフレンドリーな2Dモデリングシステム」。7分、表紙の導入約1分、本編は最大4枚。
- 表紙にユーザー提供QRを「展示物紹介配信アーカイブ」として置く。発表ノートは不要。
- 本編1は「今回開発したもの」の全体図。画像素材を外から入れ、自作のモデル制作／会話・実行を経て、枠外のOBS・YouTube配信へ出す。
- 自作の登場人物は「2Dモデル編集ツール」「AI用のモデル編集窓口」「2Dモデルプレイヤー」「AI会話・行動システム」。前二者は共通モデルへの別の入口。
- 人間・AIエージェント・外部LLM／音声サービス・トラッキングの外部ノードはこの図から除く。
- 内部は箱・文字・矢印。画像素材・OBS・YouTubeのアイコンは残す。配置、中心線、等間隔が重要。
- 画像生成の配置調整では満足できなかったため、HTML/CSS＋SVGに切り替え。共通のタイトル・下線・余白などを先にベースとして持たせる。
- 後続AはEditorとCodexのスクリーンショット、BはPlayerとAI会話・行動システムのスクリーンショット。Cは来訪者の関心を集めた「開発期間2週間」の話。
- 各スライドの内容を合わせてから次へ進む。
- 本編1に「AIエージェントが読み書きしやすい2Dモデリング環境と、配信用ツール群を開発」「開発期間：約2週間」を掲載する。情報はユーザー提供で、文言の微調整は委任された。
- OBSとYouTubeのアイコンは画像生成版へ差し替える。図の配置は引き続きSVGで数値制御する。
- 上記を反映した本編1にユーザーの「いいね」を受領し、QR付き表紙の作成へ進んだ。
- 表紙に「OK、次にすすもう」を受領。本編Aはユーザー添付1枚目をEditor、2枚目をCodexとして使用する。
- 本編Aのタイトルは「モデリングツール：人間とAI、それぞれの入口」。説明文は「人間用のGUIとエージェント用のCLIをそれぞれ用意」。見出しは左「人間用GUI」、右「エージェント用CLI（Codexから利用）」。「AIが編集→人間が確認」等の説明は追加しない。

## 今回提示するベース案（未承認の具体値）

本編Aに「いいね、次に移ろう」を受領。本編Bはタイトル「配信用ツール：モデルの実行とAIの会話・行動」、説明文「モデルを動かすPlayerと、AIの会話・行動を制御するシステムを用意」で初稿を作る合意。ユーザー提供3画像を用い、左上がPlayer、左下がAI会話・行動システム、右がモデル表示例。追加説明は載せない。

本編Aの追加文言として、ユーザーが「基本的なモデリング機能は、Live2D Cubism Editorと同程度を想定」を承認。GUI／CLIの説明の下に掲載する。これは本LTに対する明示的な表現判断であり、機能同等性や形式互換性の検証済み主張ではない。

本編Aの説明2行は同じ本文スタイル（30px・weight 500・濃紺）に統一。2行目のみ小さく薄くした初稿は、ユーザーから見た目の不一致を指摘され修正した。

- 1600×900、白背景。左右72px。タイトル上端60px、48px。下線はy=148、2px、淡い青灰色。
- 内容領域はy=210から836。日本語書体はYu Gothic、なければMeiryo等へフォールバック。
- 説明付きの本編1では共通の追加バリエーションを使い、説明文y=177、図の領域y=284から868とする。標準のタイトルと下線は共通のまま。
- 色は濃紺の文字、青のシステム境界、薄い青／青緑の領域背景。
- ページ番号とフッターは初稿では置かない。
- 全体図は手書きSVGを使用。領域幅432pxを左右共通にし、素材→モデル→プレイヤー→OBS→YouTubeの矢印はy=420に統一。

## 本編Cの合意と初稿（2026-10-04）

本編Bに「よさそうだね」を受領。最後は「Live2Dに興味を持った人よりも、開発期間に興味を持った人の方が多かった」というユーザーの会場体験をオチにする。開発期間の画像案に「そう、これ」を受領し、最後のスライド作成を依頼された。

タイトルは「結局、会場で来客の気を引いたのは……」。共通のタイトル・下線・余白を使い、その下に承認済みの集中線画像を大きく中央配置する。追加の説明文は置かず、画像の「開発期間：約2週間」でオチを示す。
