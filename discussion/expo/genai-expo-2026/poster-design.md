## 1. 出展の前提(申込内容・確定事実)

- イベント: 生成AI EXPO(<https://www.genai-expo.com/>)。出展形式=**ポスター展示、パネル 高さ180cm × 幅90cm**。
- サークル名 **CitF** / 参加者 **Remie** / X ID **remie_m**。
- 出展タイトル: **生成AIが操作する2Dモデリングシステム**。
- 申込概要(原文要旨): 生成AIが直接操作できる独自の2Dモデリング Editor/Player と AITuber システムの紹介。画像素材からのリギング、表情・リップシンク・物理演算の設定、音声対話、音声合成、モデル操作までを一つの流れとして構築。システム開発自体も生成AI主体で、Editor/Player は GPT-5.5、2Dモデリングは GPT-5.6 Sol および Claude Fable、AITuber 関連は Claude Opus 4.8 を中心に構築。

## 2. 読者像(裁定)

- 生成AIに関心のある来場者。**VTuber と Live2D は知っている**が、リギングやメッシュ編集の内部は知らない。
- → **読者に伝わる言葉を前面に出す**(ユーザー裁定)。「2Dモデリング」より「Live2D のようなモデル」。内部語彙(メッシュ・デフォーマ等)を出すなら一行の翻訳を添える。

## 3. 「何を見せるか」の核(議論の到達点)

### 3-1. 足を止めさせるもの = 絵

来場者は1枚あたり数秒。文字は読まれない。生成AI EXPO の客は「AIが描いた絵」「AIが喋る」は見飽きている。止まるのは**見慣れた形 × 聞いたことのない主張**:

> **キャラクター2体の絵**(Cody / GPTちゃん)+「**この体は、AI自身が組み立てた**」

Claude Code が自分用の体を、Codex が自分用の体を、それぞれ自分でリギングし**両方ゲート通過**(§source-facts)。配信のスクショより強い(配信画は "VTuber の配信" にしか見えず驚きが一段落ちる)ため、**キャラ2体を最上段に置く**。

### 3-2. 読者が一番知りたいこと(二層)

| 層 | 問い | この展示の答え |
|---|---|---|
| 表層(ほぼ全員) | **人間はどこまでやったのか** | コードも書いていない・絵も描いていない・リギング操作もしていない。やったのは議論・裁定・合格判定・PSDにまとめること |
| 深層(技術者) | **どうやってAIにやらせたのか** | ①どうやって"見せた"か(盲目の彫刻家→目を付けた) ②どうやって暴走を防いだか(dry-run→承認→1操作1コミット・型で自動コミット禁止・人間ゲート) |

深層の2つは**持ち帰れる知見**であり、立ち止まって読まれる=名刺交換に繋がる層。よって**規律の話を下段の隅に追いやらない**。

### 3-3. 動機の温度(ユーザー裁定)

- **「既存より優れている」という主張はしない**(定量比較も存在しない・§source-facts の「書けない線」参照)。
- 動機は「**作れそうだから作った、それだけ**」(ユーザー原文)。誇らない分だけ信用される、という判断でこの温度をポスターの声に採用。

## 4. 印刷形態(裁定)

**A2×6枚(2列×3行)= 84cm × 178.2cm。** パネル 90×180cm にほぼ収まる。

- 大判1枚(900×1800mm)は**実コスト面で非現実的**としてユーザーが不採用。
- 分割の利点: 論点1枚=1シート/差し替えが1枚で済む/印刷が安く失敗の傷が浅い。
- 版面は**一つの連続した絵として設計し、シートの境目が論点の境目と一致するように組む**(遠目には一枚に見え、近づくと論点で区切られている)。
- 実務: 各シート隅に貼り順の番号を小さく入れる。上下左右に 3mm 程度の余白を持たせて貼りズレを逃がす。
- **6枚の密度は揃えなくてよい**(写真1枚でスカスカのシートと文字びっしりのシートが同居してよい)。

## 5. 6枚の割り当て(現在の合意案)

```
┌────────────────┬────────────────┐
│ ① 表題          │ ② 二体のキャラ  │ ← 上段: 遠くから足を止める
│  + 全体地図(粗) │ 「この体はAIが │
│                │  自分で組んだ」 │
├────────────────┼────────────────┤
│ ③ AIが体を作る  │ ④ 人間は何を    │ ← 中段: 目の高さ = 一番読ませる
│  目・判定の梯子 │   したか        │
│  craft          │  (分担と規律)   │
├────────────────┼────────────────┤
│ ⑤ AIが体を着て  │ ⑥ 器と数字      │ ← 下段: 拾い読み・大きい字
│   喋る(相方)    │  入口/出口・実績 │
└────────────────┴────────────────┘
```

配置原則: **上段=遠くから見える(大きい字・写真)/中段=一番読ませたい本題/下段=しゃがまず拾えるもの(数字・図)、長文を置かない。**

各シートの中身(⚠ **以下は L0 が一方的に書いた叩き台であり、ユーザーと突き合わせていない**。合意状況の管理と、各シートの「一言 → 要素 → 捨てるもの」の詰めは [sheet-plan.md](sheet-plan.md) が正):

- **① 表題+全体地図**: 「生成AIが作り、生成AIが操作する」。誰が何をしたかの地図(絵の生成→リギング→相方→配信)。**粗く**描き、詳細は各シートに委ねる(L0 推奨・未確定)。残り5枚の目次を兼ねる。
- **② 二体のキャラ**: 最大の写真。文字は少なく。到達点でなく**入口**として使う。
- **③ AIが体を作る**: 絵も GPT-Image 2.0 製で人間は PSD にまとめただけ/双子の体/**「盲目の彫刻家」に目を付けた話**(コンタクトシート実物・判定の梯子5段・「画像は納得のため、判定は数値で」)。**密度を最も濃くする**。
- **④ 人間は何をしたか**: やったこと(議論・裁定・ゲート判定・PSD・違和感の言語化)/やっていないこと(コード・絵・リギング操作)。「作れそうだから作った」もここ。
- **⑤ AIが体を着て喋る**: こーでぃー(耳・目・声・自発発火・視聴者・操縦席)。頭は配信前に選べる4種。安全弁と配信間記憶を一言ずつ。**配信の画(集大成)をここの主役写真にする案が有力**(未確定)。
- **⑥ 器と数字**: 入口が二つ(人間=Editor GUI / AI=コマンドライン。**触っている物は同じ**)・出口が一つ(Player=作ったものを現実に引き上げる)。数字と実績。

### 5-1. 経緯: 「器(Editor/Player)」を独立シートから降ろした

当初案では⑤に「器」を単独で置いたが、**並べると弱い**とユーザーが判断。器は単体で人を呼べないため、⑥で数字と並べて「実在の証拠」として機能させる。空いた枠に**「人間は何をしたか」**を新設(表層の問いへの正面回答)。

### 5-2. Player の位置づけ(ユーザー裁定)

> 「実はこれは AITuber 側の機能だとも取れる。**作成したものを現実に引き上げるためのもの**であり、主役ではない」

→ 主役にしない。器のシートで「入口/出口」の対として見せる。

## 6. 表現の裁定

- **authoring-host は箱の名前として図に出さない**。読者に効くのは名前でなく構図——「人間の入口: Editor(GUI)/AIの入口: コマンドライン(JSONを1個投げると1個返る)/**触っている物は同じ**」。固有名は本文の小さい字で一度だけ。
- **「AIが Editor を使っている」とは書かない**(事実と異なる。§source-facts 1)。

## 7-2. 追加裁定(2026-07-25)

### ①②の役割: 「集大成」の位置が動いた

**②=キャラ2体で確定**(ユーザー裁定)。加えて重要な視座の移動:

> 「まあ**これが集大成**だな、よく考えたら。そもそも**やり始めた段階ではこれはできると思ってなかった**しな」(ユーザー原文)

当初「集大成=二人で配信している画」としていたが、**作った本人が予想していなかったもの**——AI が自分の体を自分で組み上げたこと——が到達点だという認識に移った。整理:

- **地図(①)の流れは配信に着地する**(工程としての終点は変えない)
- **感情の頂点は②のキャラ2体**(「ここまで来た」を語るのはこちら)

②のキャプション案(L0 起草・未確定): 「**こうなるとは、始めた時は思ってなかった。**Claude Code が自分用の体を、Codex が自分用の体を、それぞれ自分で組み上げた。」——ユーザーの実感をそのまま一行目に置く形。誇るより効く、という判断。

### Cubism は名指ししない(確定)

ユーザー裁定: 「**あんまりしたくないな、怖いし**」。

これは既存方針と一致する——`concept/modified_concept.md:36` は Cubism 互換/Live2D 代替の主張を禁じ、[../../_conventions.md](../../_conventions.md) §7 も Cubism 固有名詞の使用文脈を限定している。**回避は臆病ではなく元からの規律**。

名指しせずに動機を語る一行 → **2 + 3 の併用で確定**(ユーザー裁定 2026-07-25):

1. ~~「既存の2Dリギングツールは、人間の手を前提にしている。AIが触れる口が無い。だから土台から作った」~~(不採用。「既存ツール」でも比較の匂いが残る)
2. **「AIが読める保存形式と、AIが呼べる操作。それを最初から持っている土台が欲しかった」**(否定を含まない・前向き)
3. **「作れそうだから作った」**(ユーザー原文)

→ **2 で「何が要ったか」を言い、3 で温度を落とす**。
