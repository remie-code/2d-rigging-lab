## Residual Risks

- Canvas / Viewer visual parity is inferred from shared texture id + UV projection behavior and core tests, not directly browser/pixel verified in Domain A. Domain B or final integration should verify generated atlas texture resolution after UI routing.
- Editor-hidden Parts are passed through `editorHiddenPartIds` options; Domain B must pass the current editor hidden state into `selectTextureAtlasTargets()` so hidden Parts are surfaced as included-but-hidden.
- Source texture dimensions still depend on the existing raw RGBA / mesh-bounds inference convention. Generated atlas entries record explicit dimensions, but source texture dimension migration was not part of Domain A.
- Apply stale guards cover preview-not-ready, missing targets, drawable texture id changes, and mesh UV changes (`packages/authoring-core/src/texture-atlas-mutations.ts:213`, `packages/authoring-core/src/texture-atlas-mutations.ts:233`, `packages/authoring-core/src/texture-atlas-mutations.ts:238`, `packages/authoring-core/src/texture-atlas-mutations.ts:246`). Domain B should still implement the screen-level stale guard for settings, target set, texture source/bounds, and related input changes described in the Texture Atlas Task spec.

## User-Decision Points

- Whether v0 should add a human preview asset record for generated atlas pages, or keep generated atlas output as binary/layout-only.
- Final UI default for page size (`Auto` vs fixed choices) remains a Domain B decision.
- Multi-page atlas remains future scope; current behavior is deterministic single-page failure.
- Workspace Directory Export remains explicitly deferred outside Wave87 Domain A (`discussion/implementation/orchestration/wave87-plan.md:131`, `discussion/implementation/orchestration/wave87-plan.md:639`).
