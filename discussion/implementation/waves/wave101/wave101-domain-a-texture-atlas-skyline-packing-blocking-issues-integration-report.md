## Algorithm / Packing Evidence

- Added `TEXTURE_ATLAS_SKYLINE_ALGORITHM_ID` and made it `DEFAULT_TEXTURE_ATLAS_PACKING_ALGORITHM_ID`.
- Kept the existing shelf packer as an internal compatibility path when settings explicitly carry `single-page-shelf-v1`; no user-facing selector was added.
- Skyline sort order is deterministic:
  packed area desc, max side desc, packed height desc, packed width desc, stable target order asc, drawableId asc.
- Candidate x is each skyline node x; candidate y is max skyline y over the covered x span; candidates overflowing page bounds are rejected.
- Candidate tie-break is top edge asc, y asc, horizontal waste asc, x asc.
- Skyline update inserts the placed top edge, trims/removes covered nodes, merges adjacent same-y nodes, and preserves x ordering.
- Shared placement construction keeps:
  sourceRectPixels as full source texture, content rect = padded rect + padding, uvRect from content rect, hidden metadata unchanged.
- `selectTextureAtlasTargets()` was not edited.

Focused test coverage:

- New `texture-atlas-packing.test.ts` covers Skyline default, shelf compatibility path, mixed-size non-overlap, page bounds, deterministic layout, padding/content/source/uv rects, deterministic cannotFit, and algorithm identity in source-signature digest.
- Existing mutation tests still cover generated bytes and edge extrusion behavior.
