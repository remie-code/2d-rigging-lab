# Wave40 Domain D: Approval Transcript Evidence Bridge

## Verdict

- Implementation verdict: `pass`
- Date: 2026-06-04
- Domain: `wave40-approval-transcript-evidence-bridge`

## Scope Implemented

- Added a Codex proposal approval lifecycle bridge in `packages/ai-interface`.
- Connected validated proposal preview state to the existing `AiApprovalPolicy` approval gate.
- Added approval-request, approval-decision, and approved-commit helpers:
  - approval request records proposal receipt, validation, diff preview, and rerun validation evidence refs in the AI transcript;
  - approval request and commit paths enforce the existing AI command capabilities before registering approval or calling commit;
  - commit attempts before approval return `needs_approval` and do not call the commit host;
  - approval decisions append approval transcript entries with approval-decision evidence refs;
  - approved commits execute the proposal operation sequence through the existing operation host and record commit-result / operation-log evidence refs.
- Kept transcript entries compatible with existing Editor transcript projection by reusing current `command` and `approval` entry shapes.
- Added focused ai-interface and editor-session coverage for transcript evidence, approval gating, and real editor-session commit behavior.

## Fix Loop

- Fixed Review-Sylph high finding: approval decisions and commit attempts now require the supplied `approvalRequestId` to match the proposal-specific approval request id generated by the lifecycle bridge. Reusing another proposal's approved request id is rejected before the commit host is called.
- Fixed Review-Sylph medium finding: approval readiness now requires `diffPreview.basePackageRevision` to match `proposal.packageContext.basePackageRevision`, preventing stale/mismatched diff evidence from passing when the final preview revision happens to line up.
- Added focused negative tests for approval id reuse/mismatch and stale diff-preview base revision; both prove the commit host is not called.
