# メッシュ自動生成の商用風改修 — 概念設計

> Status: Accepted 2026-07-07 → Implemented(Mesh Wave 1)
> Owner: Undine(ユーザーとの対話で更新)

## 1. 目的

パーツ画像(アルファ付き)からの変形用メッシュ自動生成を、商用リギングツールの自動生成に近い出力特性へ改修する。

現行出力(v6系)の特性: アルファ境界に忠実な輪郭、ほぼ等間隔で密な頂点。実用上の支障はない(ユーザー確認済み)が、目標出力の特性は次の3つで、**3つ揃って初めて「同等」と認知されるゲシュタルト**(ユーザー判断)。個別に実現しても意味はない。

1. シルエットの外側にマージンを取った、簡略化された滑らかな外周輪郭
2. 疎な頂点(少ない三角形)
3. 細部(毛先など)を忠実に分割せず、少数の細長い三角形でざっくり包む

設計の骨格: **「元シルエットを半径 r で外側に太らせたマスク」を最初に作り、以降の全工程はその膨張マスクだけを見る。** 3特徴はここから連鎖的に出る。逆に、アルファ境界に忠実な輪郭を出発点に据える限り、後段をどう変えても目標出力には近づかない。

## 2. パイプライン(合意済み設計判断)

1. **マスク膨張**: アルファ二値化 → 半径 r で膨張(dilation)+平滑化。細い毛先は太らされ、近接する房は融合し、微細な凹みは埋まる(特徴3の発生源)。膨張マスクは元マスクを必ず包含するため、被覆保証が構成的に成立する。**膨張・平滑化は元キャンバスにクランプしてはならない**: 作業空間を全周 pad(≈ ⌈r + ぼかし半径⌉)拡張した座標系で全工程を行い、最終メッシュの bounds は元 drawable bounds の外へ広がる(評価往復1の設計修正、2026-07-07)
2. **輪郭抽出と簡略化**: 膨張マスクから輪郭追跡 → Douglas-Peucker系簡略化(許容誤差 ε)→ 目標間隔 L でほぼ等間隔再サンプル(高曲率部のみやや密)。特徴1はここで完成する
3. **内部点配置**: 間隔 R(≈ L)で疎に等間隔配置。除外則2つ — (a) 輪郭から R/2 以内には撒かない(潰れた三角形の防止)、(b) 局所幅 < R の細長領域には撒かない(距離変換で判定)。毛先や細い房は内部点ゼロとなり、輪郭同士を直結する少数の細長い三角形で覆われる(特徴3の仕上げ)
4. **三角形分割**: 輪郭を制約辺、内部点をシュタイナー点とする制約付きドロネー(CDT)。品質改善のための頂点追加(refinement)はしない(頂点数を増やさないことが目的)。仕上げに内部点のみ Lloyd 緩和2〜3回(輪郭頂点は固定)
5. **パラメータ**: ユーザーには3プリセットのみ提示 — 「大きく動く」「標準」「あまり動かない」。プリセットが動かすのは **L(=R)だけ**。r は全プリセット共通の固定定数(テクスチャ解像度比率+ピクセル下限/上限クランプ)、ε は r から導出(例: ε = 0.8r)

| プリセット | 頂点間隔 L | 意図 |
|---|---|---|
| 大きく動く | 小(密) | 大変形でも曲げが滑らか |
| 標準 | 中 | — |
| あまり動かない | 大(粗) | 動かないパーツに頂点を浪費しない |

## 3. 不変条件

| 不変条件 | 内容 |
|---|---|
| 被覆保証(絶対条件) | 不透明ピクセル(α > 閾値)は1ピクセルたりともメッシュ外に出ない。膨張により構成的に担保する |
| ε < r 結合則 | 簡略化は輪郭を最大 ε 内側に削り得るが、輪郭は元絵から r 外側にあるため、ε < r である限り被覆保証は破れない。マージンと簡略化強度は独立ノブではなく、片方が他方の安全域を担保する関係 |
| 決定性 | 同一入力 → 同一出力。コードベース全域の要求(tie-break付きソート、座標丸め、安定始点回転のイディオム)。乱数を使う素朴なポアソンディスクは不可 |
| 膨張の非クランプ(評価往復1で追加) | 膨張マスクは drawable キャンバスの端で切り立ってはならない(端に張り付いた外周点の整列は欠陥)。作業空間の仮想パディングで担保し、頂点はテクスチャ外に出てよい(UV は 0..1 クランプ = 端テクセル参照。レンダラは bounds 外頂点を許容済み) |

既知の許容リスク: 固定マージンのため、極端な変形では絵がマージンをはみ出し得る。これはリガーの責任域として許容する(参照した商用ツールも同様の挙動と推定)。

## 4. 現状調査を受けた設計修正(合意済み)

調査の詳細は [current-implementation-survey.md](current-implementation-survey.md)。

- **内部点は「間隔 R の明示制御を足した farthest-point 貪欲選択」にする**: ポアソンディスクの決定的代替。既存実装(決定的・挙動が近い)の小改修で、設計意図(疎で等間隔)を保つ
- **穴あきポリゴンは初版では全部埋める**: 現行全経路が穴未サポート(検出・報告のみ)のため、穴対応は切り離す。髪などの有機的パーツでは実害がまず出ない(ユーザー合意)
- **多島(複数連結成分)**: valid な島はすべてメッシュ化し、独立サブメッシュとして1つの MeshDto に併置する。v6d-adaptive の既存機構を踏襲

## 5. 実装方針(合意済み)

- **新 method ID(v7系)として追加する**。既存 method の in-place 変更はしない(provenance・決定性の観点。v6a→v6f と増殖してきたコードベースの既定路線)
- **v6/v7 は UI 上で切り替え可能にする**(method 選択の仕組みは operation を既に貫通しており、枠は既存)
- **v7 は v6系ファイルを import しない自己完結構成にする**。流用部品(輪郭追跡・多島検出・expandMask・CDT等のアルゴリズム中立部品)は、中立な共有モジュールへ先に抽出してから v6/v7 両方に使わせる。将来の v6削除を「v6系ファイル削除+フォールバック連鎖と method 一覧から抜く」だけの機械的作業にするため
- **後続フェーズ**: v7実装 → UI切替による品質評価 → v7が高品質なら v6系コードを削除する(ゾンビコードを残さない、ユーザー方針)。評価基準(何をもって「v7の品質が高い」とするか)は評価フェーズの入口でユーザーと合意する(未決)

## 6. 実装委任時の優先順位(合意済み)

実装者(Opus想定)への委任は次の3層で与える。「v6d-adaptive を土台にする」のではなく、「v6d-adaptive が使う中立部品と統合規約を土台に、アルゴリズム本体は本文書から新規に書く」。

| 層 | 対象 | 扱い |
|---|---|---|
| 統合層 | 契約(mesh-generation-contract.ts)、generate-mesh.ts の operation フロー、MeshDto 構造、stableId 規約、previewMesh 検証、決定性イディオム | **読んで従う**。既存コードが正 |
| 中立部品 | 多島検出(v6-alpha-islands)、expandMask、輪郭追跡(traceBoundaryLoops)、CDTバックエンド3系統 | **流用してよい**(中立モジュールへの抽出を経て) |
| v6系アルゴリズム | v6系の密度設計・サンプリング方針・パラメータ表 | **設計の参照元にしない**。v7の設計の正は本文書のみ。食い違えば本文書が勝つ |
