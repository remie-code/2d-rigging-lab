## 往復1(2026-07-07)

### ユーザー所見(スクリーンショット付き評価)

1. **[欠陥] 境界張り付き**: drawable 境界付近で外周点が境界の直線に張り付いて整列する。膨張・ぼかしで領域を広げるアルゴリズムなのに、処理が現 drawable の境界を越えられない。「ぼかして広げるなら drawable 境界ごと最終的に広がっていなければならない」
2. **[欠陥] 密度が密すぎる**: 現行の「あまり動かない」(L=28px)相当の密度が「大きく動く」に妥当なくらい
3. **[肯定] v6/v7 切替 UI は良い**。恒常的に残す可能性に言及(確定ではない)

### 機序診断(Undine)

1は v7 パイプラインが drawable のテクスチャキャンバス座標系にクランプされており、キャンバス端近くでは膨張の「太る先」が存在せず、膨張マスクが端で切り立つ → 輪郭がキャンバス端をなぞる、という設計漏れ。v6d-adaptive の `VIRTUAL_PADDING_PIXELS = 4` の先行事例を v7 が踏襲していなかった。

### 裁定(ユーザー確定)

1. **作業空間の仮想パディング**で修正: pad ≈ ⌈r + ぼかし半径⌉ を全周拡張した座標系で全工程を回し、最終 bounds は元 drawable bounds の外へ拡張。concept-design §2-1 と §3(不変条件「膨張の非クランプ」)に反映済み
2. **L = 28/42/64px**(大きく動く/標準/あまり動かない)へ再調整(現行 12/18/28 の等比を1段粗い側へシフト。R=L 連動)
3. **トグルの寿命(v6を残すか/器だけ残すか/予定通り削除か)は未決のまま保留** — v7 修正が収束してから改めて判断

### 対応

修正は Mesh Wave 1.1(単一ドメイン)として実施 → [implementation/orchestration/mesh-wave1.1-plan.md](implementation/orchestration/mesh-wave1.1-plan.md)
