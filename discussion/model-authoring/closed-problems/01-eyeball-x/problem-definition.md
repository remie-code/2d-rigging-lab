# Closed Problem 01: Eyeball X Rigging

> 第一閉問題。眼球のメッシュ生成からEyeball_X 移動 rigging、白目クリッピングまで。2026-07-02 定義（操作列はユーザー提示の実手順）。

## 問い

- **A.** この問題を解くために Fable に必要な API は何か（未調査 → 調査後 `api-requirements.md` に記録）
- **B.** 実際に Fable が眼球の移動を設定し、ユーザーが満足できるか（実験後 `results.md` に記録）

## スコープ（操作列）

1. **眼球 drawable へのメッシュ生成** — ツールのメッシュ自動生成機能で 3 プリセットから選択する操作。ほとんどのケースで standard を選べば問題なく、判断力を要求されるタイミングはほぼない。
2. **ワープデフォーマ作成** — ツール提供機能。縦横分割数の論点はあるが、大きな drawable でなければデフォルト値で問題を起こさない。この問題空間に閉じれば判断力要求はほぼ無い。
3. **Eyeball_X パラメータへの keyform 打ち** — 両端と中央に keyform を打つエディタ機能を実行するだけ。これ以外の位置への keyform は見た目微調整の話であり、本問題空間には**含めない**。
4. **片側端（例: 右移動）での眼球移動** — このシーンではデフォーマの変形はほぼ使わず、基本的に**平行移動と横幅のスケーリングのみ**。★この位置調整に**視覚的判断が必要**。
5. **反対側の眼球にも同様の操作**。
6. **白目 drawable によるクリッピング設定** — ツール提供機能。Fable 側の判断は「どれが白目 drawable か」に閉じ、これは **drawable 名称を見れば一意に特定できるレベルの課題**として設定する。

## 判断の所在

- 視覚判断は**工程 4（および 5）に集中**する。虹彩の端位置での置き場所（平行移動量 + 横幅スケール）の妥当性判定。
- 工程 1, 2, 3, 6 は判断がほぼ不要であり、**API 疎通・操作実行の検証**が主目的となる。

## 除外事項

- 両端・中央以外への keyform（見た目の微調整）
- デフォーマ格子の変形による表現

## 成功基準
