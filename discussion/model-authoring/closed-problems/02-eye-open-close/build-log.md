ユーザーが PSD を差し替え（表情セットの位置整列。半目セットが通常セットと水平整列、閉じ目も再配置）、ワークスペース初期化。**眼球X〜目の開閉まで全 67 operations を再構築、reject ゼロ**（rev 2→69、r3- 接頭のコマンド群）。発見: drawableId はレイヤー同一性由来で**差し替え後も不変**（座標だけ変わる）→ 手順は完全再生可能、数値はジェネレータが実測から自動再導出。

**半目→閉じ目のエッセンス修正を実装**: Half の形状キーを3キー構成に変更（identity@0.5 → 88%閉じ@0.07 → 完全閉じ@0.0）。開口の消滅は**区分線形の縦写像**（まつげ上帯→閉じ線上部 / 白目帯→まぶた線に潰す / 下縁→閉じ線下端）で変形側が完遂し、フェード窓では線から線の交代のみが起きる。アフィン1本では開口が位相的に消せない（旧失敗の原因）ため、格子行を独立に動かす区分写像が正道。検証: r3-02-fade-0.03.png（開口消滅を確認）、r3-01-sweep（11段連続性）、r3-03-composite（開閉×視線合成）。

## ユーザー gate 結果（部分通過 + エッセンス指摘）

- **通常→半目: 「完璧だな」（通過）**
- **半目→閉じ目: エッセンス不足（要修正）**。ユーザーの実例画像との比較で確定した本質:
  - Fable 版の欠陥: 写像が半目セットを閉じまつげ線の bbox へ寄せただけで、param 0 でも白目・虹彩の開口が残存 → フェード窓で「薄く開いた目がいきなり消える」感覚
  - あるべき姿: **フェード開始（~0.07）時点でまぶたは閉じ切っており、交代は「閉じたまぶた → 閉じ眉線」（線から線）**
  - 一般則（craft 不変量候補）: **opacity フェードは「同じ形をした二者」の間でだけ許される。形の遷移は変形が済ませ、交代だけを opacity に渡す**。Open→Half は 0.5 での形一致でこれを守れていた。Half→Close は開口の消滅を変形に含め忘れた
  - 修正方針: Half の形状キーに中間キー追加（~0.07 までに開口高さ→ほぼ0）。キー打ち直しのみで可能
- **修正は保留**: ユーザーが表情まわり drawable の位置に不満があり **PSD 素材を差し替える**意向。素材差し替え後のワークスペースで再走する可能性が高い（drawableId はソースハッシュ由来で変わるが、全操作は名前ベース同定 + レシピで再現可能。experiment/ に全コマンド記録あり）

> 定義: [problem-definition.md](problem-definition.md)。実行機材は 01 の experiment/ を共用（apply-op.mjs / run-batch.mjs、コマンドは commands/ の 92〜102 番台、レンダは renders/ の cp02-02〜06）。

## 実行サマリ

**34 operations、reject ゼロ、rev 36→70**（前哨戦と合わせ cp02 系は 52 ops 連続 reject ゼロ）。

1. **構造**（14 ops）: 通常目6枚の可視性復元 / 閉じまつげ l/r メッシュ生成 / 状態デフォーマ6基（`rig_eye_{l,r}_{open,half,close}`、Open/Half は既存眼球デフォーマを `childRigControlIds` で子に取るネスト構造 = ref と同型）
2. **opacity キー**（12 ops、addCurrent）: Open `1@0.6→0@0.5` / Half `1@0.05→0@0.0` / Close `1@0.0→0@0.07`。Half の出現側キーは**打たない**（ユーザー裁定: param≥0.5 では Open が描画順で半目領域を完全に覆う。「上位状態が覆うなら出現キーは描画順が只で払う」）
3. **形状キー**（8 ops）: Open は 1.0(identity)→0.5(半目形)、Half は 0.5(identity)→0.0(閉じ形)。**写像はまつげ/白目 bbox 対応から導出した1本のアフィン写像**（例: 左 Open→Half `y'=0.583y+190` — まつげ・白目・虹彩の3部品が同時に誤差1px台でフィット）。格子オフセット = `map(p) − p` を restControlPoints から点ごとに計算

## 検証

- **数値**: Open@0.5 のまつげ bbox (1023.9, 419.8, 99.3×44.3) vs 半目 rest 実測 (1024, 419, 99×46) — 1px台一致。白目は幅3px差
- **視覚**: 11段 sweep（cp02-04）で 閉→半→開 が連続変形として読める。0.5→0.6 の担当交代（Half rest → Open変形形）の輪郭がほぼ一致。0.03 のクロスフェード窓（cp02-03）も設計どおり
- **合成**: 開閉0.7 × 眼球X+1（cp02-06）で両パラメータが正しく合成、クリッピング健在。ネストデフォーマ評価の実証
- **右目**: 独立導出の写像で左右対称動作（cp02-05）

## craft 蒸留候補（gate 通過後に確定）

- 状態切替 rigging の一般形: 「変形で形を繋ぎ、opacity は食み出す状態だけ消す」+ 出現側は描画順に任せる
- **形状オラクル法**: 目標形が別セットの rest として実在する場合、bbox 対応 → アフィン写像 → 格子オフセットで機械的に初期形状キーが導出できる（審美イテレーション前の初手として強力）
- addCurrent の性質: 初回呼び出しで keyform set が生成され、以降のキーが追記される（任意値・2キー以上の構成法）
- 幅の相場: 状態デフォーマも 5×4 格子で足りた

## 残イテレーション余地（gate 判定次第）

- 0.6/0.5 の切替窓幅・0.05/0.07 のクロスフェード窓幅の調整（キー値の打ち直しのみで可能）
