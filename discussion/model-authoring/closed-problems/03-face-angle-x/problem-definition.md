# 閉問題 03: Face Angle X の最小核（顔・鼻・左目）

> 2026-07-03 定義。最終目的地 =「フェイストラッキング由来パラメータ × デフォーマ親子関係」の世界への入口。Face Angle X は 15 要素に影響するが、閉問題は**新技能 3 つが閉じる最小構成**に切る（ユーザー承認済み: 「あまりにも正しい問題設定」）。

## スコープ: 3要素

| 要素 | 難度 | 閉じる技能 |
|---|---|---|
| 鼻 | 低 | パララックス量の適用（純平行移動、warp 0） |
| 顔（輪郭） | **高** | **シルエットの作り替え**（移動は小、変形が本業）。本問題の最難関 |
| 左目 | 中 | **既存リグ塔への親デフォーマ挿入**（`Eye_L_FaceX` を `Eye_L_Open/Half/Close` の上に被せる）+ 非対称移動 |

残り 12 要素（右目・口・眉・眼鏡・髪・耳・後ろ髪等）は通過後の craft 適用（機械的反復）であり閉問題ではない。髪は別種の問題（揺れ・房）を孕むため意図的に除外。

## 選定理由（ユーザー）

1. FaceX 単独要素では人間の認知でも正誤判定が困難——**複数要素の位置関係**で「おおむね良い」と判定する工程であり、座標系の絶対解は無い
2. 難度配分が絶妙（顔=高、目=中、鼻=位置決めのみ）
3. エッセンスを全て含み、髪という別問題を含まない

## 奥行きモデル（ref 実データからの抽出、2026-07-03）

ref の `param_face_angle_x` keyformSets 14 本の +30/-30 オフセット統計から:

> **dx は「回転軸からの奥行き距離」に比例する。軸は頭蓋中心（headwear がほぼ不動 = 軸上）、最前の鼻が最大（+53.7）、軸の後ろの後ろ髪は負（逆方向）。顔輪郭だけは移動でなく変形が本業（dx 23 / warp ±21.7 で全要素中最大）。向かう側の要素は縁で縮む（foreshortening、Eye L/R の非対称: +30 で R=45 / L=28.4、-30 で鏡像逆転）——この非対称性が「回転」を絵にする。**

- 数値表は**このキャラ専用の較正データ**（ref と本ワークスペースは同一 PSD 系 = drawableId まで一致するため直接利用が合法）。**一般化されるのは上記の言語**（craft へ）
- ref からのエッセンス抽出はユーザー明示承認済み（「もちろん合法だ、そのための ref だからね」）。ただし結果に対する Fable の審美眼での言語化が craft の要件

## 実施順

1. A検証: `wrapChildren` による既存 rigControl 塔への親挿入の作法
2. 鼻（メッシュ生成 → FaceX デフォーマ → 三点キー）
3. 顔（FaceX デフォーマ → 輪郭 warp field の設計。ref の格子オフセット空間分布を読み込み、必要ならユーザーに言語化を質問——ユーザーは「不明点への回答ならできる」と表明済み）
4. 左目（挿入 + 非対称キー）
5. 3要素同時 sweep でゲシュタルト判定（Fable 初実測）→ ユーザー gate

## 成功基準

- 3要素が ±30 で整合的に動き、「顔が横を向いた」と読めること（ユーザー判定）
- 挿入後も既存機能（目の開閉・眼球X・クリッピング）が無傷であること（回帰確認）
