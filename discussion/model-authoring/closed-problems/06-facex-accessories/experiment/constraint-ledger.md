## この台帳の目的と維持規則

**目的**: 帽子 field には fix を3周する間に複数の独立した設計原理が重畳した。次の fix 委任のたびに「今どの拘束が効いているか」を再発見せずに済むよう、全拘束を1枚に固定する。

**維持規則（運用、一行）**: fix を委任するたび L0（オーケストレータ）は本台帳の全行を委任文に積み、各拘束を **保存 / 置換 / 意図的変更（処置理由付き）** のいずれかに明示分類する。委任先が触れない拘束も「保存」として明記し、drift（式の意図せぬ崩れ）を assert で検出できる状態を保つ。

**検証コマンド（本台帳の全数値の再現元、cwd = 本 experiment ディレクトリ）**:
- 帽子 dx/dy 現物グリッド + 式照合: scratchpad の `inspect-hat.mjs` / `inspect-hat-dx.mjs`（本調査で作成。committed vs fix/fix2 式の per-node diff）
- 隣接所有権マップ: `node fix2-ownership.mjs`
- 変形頂点による帯別実測・slip・接線: `node fix2-analyze.mjs`（`commands/fix2-measure-{rest,plus30,minus30}.response.json` を読む）
- btr/btl 共有行照合: scratchpad の `inspect-btr.mjs`（本調査で作成）
- 生成器（数値の一次ソース）: `gen-fix-hat.mjs`（八代目）, `gen-fix2-hat.mjs`（九代目A）, `gen-fix2-g1.mjs`（九代目B）, `gen-fix3-hat.mjs`（十代目 F2, λ=4）, `gen-fix3-g1.mjs` + `gen-fix3-g1b.mjs`（十代目 F1）
- 下隅の相手選択・接線・可視区間の実測: `node fix3-corners.mjs`（SRC=fix3c で最終状態。`commands/fix{2,3,3b,3c}-measure-*.response.json` を読む）

## Q2. dy 揺れの生存範囲（現物 keyforms 確定）

**結論: dy は全169ノードで生きている。v ランプ従属化は dy を一切上書きしていない。全滅でも部分死でもない。**

委任プロンプトの前提「九代目の v ランプ従属化（従属先=前髪 field は dy=0）が八代目の dy を上書きしたか」は **成立していない**。理由: gen-fix2-hat.mjs の `hatFieldFix2` は dx のみ `(1−v)·dx_fix + v·dx_fh` でブレンドし、dy は `y: f.max.y` / `y: f.min.y`（八代目値）をそのまま保持している（gen-fix2-hat.mjs L222-223）。前髪 field の dy=0 は dx ブレンドに使う `dx_fh` の話であって、dy 成分の合成には登場しない。

**現物実測（scratchpad/inspect-hat.mjs、committed keyforms.json）**:

- +30 キーの dy グリッド: 全13行（r0 y79 〜 r12 y392）が **完全に同一**。列ごとに `dy = −0.025·u`（例: c0 u−206 → +5.15、c6 u7 → −0.16、c12 u219 → −5.47）。
- −30 キーは符号反転（c0 → −5.15、c12 → +5.48）。
- 行方向（y）の変化ゼロ = 従属帯 r9-r12 でも上部凍結帯 r0-r3 でも dy は同じ式。

**非対称の生死**: 「向く側上がり・逆側下がり」は **今も全行で出る**。+30（右向き, u>0 が向く側）では右側 dy<0（画面上へ = 境界が上がる）、左側 dy>0（下がる）。前髪従属域（下縁 r10-r12, y340-392）でも dy はそのまま効いており、下縁の非対称上下ずれは前髪従属化後も保存されている（C7 は下縁の dx を前髪に合わせるが、dy の傾きループは消していない）。

| 領域 | 行/y | dy の状態 | 数値（+30, 代表列） |
|---|---|---|---|
| 凍結帯・クラウン | r0-r8 / y79-288 | 生存 | c0=+5.15, c12=−5.47（−0.025·u） |
| 前髪従属帯（v>0） | r9-r12 / y314-392 | **生存（不変）** | c0=+5.15, c12=−5.47（上と同一） |

**含意（次の fix への注意）**: C7（前髪従属）と C5（dy 揺れ）は直交している。下縁を前髪に「完全一致」させたいなら dy も別途扱う必要がある。現状は「dx は前髪に吸着、dy は帽子独自のループを保持」という混成であり、前髪自体は dy=0（C7 の z_fh は dy を持たない）なので、下縁で帽子は前髪に対し dy=±(0〜5.5)px の縦差動を持つ。これが意図（傾きループの演出）か過剰（前髪と縦にずれる）かは要目視（未確定節参照）。

## Q4. back_top_hair 共有境界の現状（現物検証）

**結論: 九代目の主張「v=0 の行のため式不変・再打ち不要」は現物で正しい。縫い目の整合は式レベルで保たれている。**

根拠: scratchpad/inspect-btr.mjs（committed keyforms.json の btr/btl 最上段行を八代目 fix 帽子式と照合）。

- **btr（rig_facex_back_top_hair_r, domain y0=257）最上段行**: committed = 八代目 fix 帽子式（dx+dy 両方）の点評価と **全5ノード diff (0.000, 0.000)**。
  - 例 +30: c0 u−218 committed=(5.48, 5.45) = fix式(5.48, 5.45)。dy(=5.45) も乗っている。
  - 7代目式（dx のみ, anchor なし）とは大きく食い違う（c0: committed 5.48 vs 7代目 18.85）→ 八代目で確かに occiput 係留式に打ち直され、九代目で不変。
- **btl（domain y0=252）最上段行**: 同様に全5ノード diff (0.000, 0.000)。例 +30 c4 u217 committed=(−5.45, −5.43) = fix式。
- r1（2段目）以降: dy=0 の cp05fix 値（例 btr r1 first cell (4.38, 0)）がバイト保存。

**なぜ帽子の下帯が前髪従属化されても縫い目が保たれるか（式レベルの説明）**: 共有境界行は帽子ドメインの **y257/y252** を評価している。C7（前髪従属）が働くのは帽子ドメインの **y314(r9) 以降**。両者は y で分離しており、共有行の高さでは帽子式は依然 C4（occiput 係留）モードのまま。よって「帽子式が共有行で変わっていない → 受け手の再評価不要」が正しい（gen-fix2-hat.mjs L255-268 の assert がこれを機械確認: `hatFieldFix(x,257) == hatFieldFix2(x,257)`）。
