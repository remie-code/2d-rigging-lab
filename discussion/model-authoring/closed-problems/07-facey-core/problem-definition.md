# 閉問題 07: FaceY 顔面コア（顔・鼻・口・両目・両眉）

> 定義日: 2026-07-04。FaceX 完結（cp06 着地）を受けた FaceY 戦線の第一手。選定はユーザー承認済み（「FaceYの閉問題をここで切るのは賛成」）。planning-gate 実施済み（L0 コンテキスト十全判定 + FaceX 塔7基の存在裏取り）。

## 位置づけ

**回転射影則の転置テスト。** FaceY（`param_face_angle_y`、preset）は基本理論を FaceX と共有する——球面理論の適用と、ステッカー↔立体物スペクトラムの判定（ユーザー言語化）。顔面コアはステッカー極の住人であり、**新しい法則はゼロのはず**。本問題は同時に「craft（レシピ06/07）が軸の転置だけで再利用できるか」= **craft の言語の抽象度の測定**を兼ねる。

新しい未知は2つだけ:

1. **上下の非対称**: 左右（X）はほぼ鏡像+役割交代だったが、俯き（頭頂が見えてくる）と見上げ（顎裏が効く）は絵として非対称が一段強い。min/max patch の独立設計（既存作法）の範囲で解くが、演出領域が広い
2. **縦の回転軸 cy**: 新しい設計対象。耳の高さ相場から開始しレンダで較正

## ポリシー（2026-07-04 ユーザー決定——本問題の前提）

- **1デフォーマ = 1パラメータ責務**。FaceY は要素ごとに専用デフォーマを新設し、既存 FaceX 塔を `wrapChildren` で包む（**FaceY が親、FaceX が子**。ユーザーの実作の積み順と同じ向き。現物確認済み: 目の状態塔の親は rig_facex_eye_l/r）
- **対角成分（X≠0 かつ Y≠0）は Runtime の階層評価の責務 = 設計対象外・品質保証対象外**。「問題が出る場合のすべてを言語化できるとは到底思えない」（ユーザー）。gate では対角レンダを**監視として1枚出すのみ**、判定軸に入れない。問題が見えたら人間が直す割り切り

## 対象: 7要素 = 7 FaceY デフォーマ

既存 FaceX 塔（rev175+ の committed 現物）を包む:

| 要素 | 包む対象 |
|---|---|
| 顔 | rig_facex_face |
| 鼻 | rig_facex_nose |
| 口 | rig_facex_mouth |
| 目L / 目R（タワー全体） | rig_facex_eye_l / rig_facex_eye_r |
| 眉L / 眉R | rig_facex_brow_l / rig_facex_brow_r |

## 転置ノート（レシピ06をこう読み替える）

- **dy = v·(cosΔ−1) + z·sinΔ**、v = y − cy（縦の軸距離）。dx ≈ 0（Y回転は縦の営み。X の dy≈0 例外則と対をなす——コアでは傾きループ級の例外は想定しない）
- z プロファイルは FaceX と同じ殻の**縦断面**が出発点（鼻 = 突出で最大移動・純平行移動、額と顎 = 弦で軸へ縮む、造作の先行はXと同じ層差の現れ）
- ゲイン: 鼻から決める。FaceX 鼻（±30px 級）と同格の「上品」レンジを縦に。上下で非対称なゲインも可（演出）

## 除外事項（新問題の階層分離）

- **髪系**（前髪・房・後ろ髪）: Y では変位方向が垂れ方向と一致する**新テンプレ**（垂れ物の Y 応答 = 根本駆動・毛先減衰）が要る見込み → cp08 候補
- **帽子・眼鏡・耳**: 帽子は Y で面の交代が劇的（クラウン頂面の出現・縁ループの画面内回転）、耳は軸高さで v≈0 → cp09 候補に同梱
- 対角品質（上記ポリシー）
- **帽子の縁領域は人間補正済み（台帳 C10）**——本問題は帽子に触らないが、回帰確認で帽子を機械再生成しないこと

## 成功基準

- **A（API）**: 新 API 不要の見込み（createWarpDeformer wrapChildren / editKeyformKey / 巻尺 / renderView）
- **B（ユーザー満足）**: 上下 sweep で「**うなずき・見上げが読める**」ゲシュタルト + 既存機能の回帰無傷。対角レンダは監視のみ

## 実行様式

- クリーン Fable 委任（封じ込め継続: `ref/`・03 文書・01 実験アーカイブ・git 履歴遮断、委任文に答え数値なし）
- 設計ログ義務（cy の決定過程・上下非対称の言語化——これが FaceY の craft 原料）
- エスカレーション権 / 目視イテレーション予算付き / wrapChildren 挿入後の既存機能回帰確認必須（FaceX sweep・目の開閉・眼球移動）
