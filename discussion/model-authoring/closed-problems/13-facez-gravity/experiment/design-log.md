### 等価性の判定: **成立**

- **機械検証（assert-facez-gravity.mjs、±30 両端）**: 各要素の実測変位 = 設計メカニズムの予測と max err **1e−10〜1e−12**（前髪 = R(p + bilinear(c)(p))−p、房・カーテン = bilinear(全量場)(p)）。メカニズムは完全に理解どおりに動いた
- **正味則への残差**: 前髪 2.404px は、房・カーテンの純粋な格子離散化残差（1.28〜2.52px）と**同一クラスに収まった**——2合成は「同じ正味則の異なる書き方」として実測上等価
- **前髪の残差の内訳は合成の O(θ²) 項**: 実行時正味は `rot + R·c` であって `rot + c` ではない（親回転が補正ベクトルを回す）。差 = `(R−I)·c`、設計格子上の理論 max **2.853px**（毛先隅・±10°）、実頂点上の実測 max 2.404px。問題定義が許容した弧/弦差 (1−cos5°)·r と同じ O(θ²) クラス
- **恒等式（cp08fix の型）**: `field − T_root = W·(回転場 − T_root)` を①設計格子の全節点（両合成の設計正味、誤差 1e−9 未満で厳密）②実測頂点（= 正味則残差と同一値に一致）の2層で機械確認。W はここでも「回転性成分の混合比」として振る舞った

## 重力テンプレの汎用性検証（球面場→回転場の差し替えで何が変わったか）

**不変だったもの（テンプレの本体）**:

- 式の型 `W·場 + (1−W)·場(root)`、恒等式検証の型、「付け根の並進を運ぶ」拘束——**場の中身に一切依存しなかった**
- W 境界・遷移距離・y_root（前髪 500..773 wTip0.7 / 房 550..900 / カーテン 500..1000）——「頭蓋接触を失う行」の物理的意味は軸にも場にも依らない（cp08 の値を無修正で再利用し、レンダ較正も不要だった）
- 格子次元・domain margin 規則（BodyX 子 domain + x±36/y±40 = cp08 FaceY と同一 domain に一致することを実測で確認してから流用）

**変わったもの（差し替えの現物）**:

- 場が**2成分ベクトル**になった（球面場は dy のみ、回転場は dx・dy 両方。cp08 の grid 生成の {x:0, y:…} が {x:…, y:…} になるだけ）
- **回転場はアフィン** → 固定 y で x に厳密線形 → **bilinear 格子は列方向に厳密**。格子の分解能議論が「行方向（W の smoothstep × アフィンの3次）だけ」に半減した。cp08 の行密度（房11行・カーテン13行）流用で残差 ≤2.5px
- T_root が「その列の y_root における**回転場**の値」になった——列ごとの運搬量は回転場が自動で払う（球面場の殻と同じ役割分担）

## craft への指摘（レシピ06 重力テンプレ節への追補）

1. **重力テンプレは場非依存**: 「W·場 + (1−W)·場(root)」の場スロットには球面場（Y）も回転場（Z）も入る。テンプレの本体は W 境界の物理（頭蓋接触）と「付け根の並進を運ぶ」拘束であり、場の中身は差し替え自由——**軸横断に加えて場横断の資産**であることが確定
2. **回転場は格子に優しい**: アフィン場 × W(y) は列方向厳密・行方向のみ3次。格子規則「素材の大きさ × field の曲率」の曲率評価は、回転場では「W の遷移帯を跨ぐ行数」だけ見ればよい
3. **回転の中の補正ワープは親に回される**: 正味 = rot + R·c。±10° 級は素の c で許容（O(θ²)）、大角度は c' = R⁻¹·(正味 − rot) で厳密化（上記4.）
4. **「回転メンバー × ワープ髪」の縫い目**は、端点では W=1 帯がフル回転場を書くことで構成的に閉じる（実測 0.06px）。中間では弧/弦差（実測 1.34px @θ=5°）が固有に残る——θ² で開くので、大角度 Z では付け根帯だけ回転デフォーマに入れる等の再設計が要る
5. verify 型の拡張（中間挿入の childRigControlIds スロット置換）は上記2.

### 実装した式（F1）

> **netF1(u,y) = W(y)·回転場(u,y) + (1−W(y))·回転場(u, y_att)**

- **W(y) は不変**（回転性の消滅は不変）。変わるのは並進コピーの標本点だけ: 「頭蓋接触を失う行」→「**毛束が視覚的にぶら下がる付着帯**」（懸架点）。恒等式 netF1 − rot(att) = W·(rot − rot(att)) を全格子節点で assert（C）
- 付け根帯（W=1、y≤yHead）は数値不変（assert B）——**back_top×カーテン縫い目は fix を素通り**（回転メンバーとの構成的一致が保存）
- 各列は自分の列の rot(u, y_att) をコピー——付着帯の行が回転で傾く分（dy の x 勾配 sinθ·(x−px)）も列ごとに運ばれる。毛先帯が付着帯と同じ剛体傾きを持つ = 「生え際の右側が下がれば右の毛束ごと下がる」
- 副産物: 房の dx は strand に沿って S 字（付着帯55 → y550 6 → y600 0.8 → 毛先55）。W=1 帯は頭面に貼り付き（頭面の点は pivot 至近で X 微小）、自由帯は懸架点の並進へ戻る——レンダで折れ・裂けなし（fix-zoom-hairR/L-*）

### F2 プラム項（作画の嘘の翻訳、カーテン毛先帯のみ）

> **δ(u,y) = κ·P(y)·|rot(att)|·(û_plumb − û_offset)**、û_offset = normalize((u,y) − att)、û_plumb = (0,1)

### craft への訂正（レシピ06 重力テンプレ節——fix1 指摘1. のさらに上流）

1. **W 境界は「本当の接触帯」を要求する**。Y（球面場）で cp08 の甘い W 帯が許されたのは**場が y 一様だった偶然**にすぎない——貼り付き成分と運搬成分がほぼ同じ値を書くから、どこで混ぜても絵が変わらなかった。場が y 依存する軸（回転場の dx = θ·(y_pivot−y)）では、**貼り付き帯の嘘がそのまま動きの嘘になる**。とくに遷移帯が場の符号反転線（pivot 行）を跨ぐと、混合は運搬を相殺し「付け根静止・毛先振れ」という物理の逆転を生む。fix1 craft 指摘1.（W 境界と標本行は別の量）に加えて: **W 境界そのものも「頭蓋接触」ではなく「描かれた付着」で引く**。実際の毛束は付着帯（こめかみ/生え際、テクスチャのメッシュ上端帯で実測できる）から先はほぼ自由に垂れている
2. **W_new の実測レシピ**: 貼り付き 100% = 付着帯（メッシュ上端の切り縁帯 60px）+ 数十px（幹の拡幅点・遮蔽物の被覆下端で決める）、遷移は数十px の smoothstep、遷移終端は場の符号反転線から十分離す。遮蔽物（back_top 等）の x 被覆から毛束が出る行が実測できるなら、それが W=1 帯の自然な下端（カーテンR: 拡幅点=可視化行=424 が一致した例、カーテンL: 遮蔽が 120px を要求した例）
3. **格子行間隔 > 遷移長のとき、bilinear が遷移を行間隔へ引き伸ばす**（本件: 60px 設計 → 実効 130〜160px）。設計値は格子節点でのみ実現される——遷移を短くする設計変更は、行密度を変えられない（rig-controls 不触の）fix ラウンドでは「行間隔までの短縮」が実効下限。隠れ帯の回転同期からの偏差もこの軟化そのもの（設計値と実測が px 単位で一致することを assert できる）
4. 「懸垂部は d_att を一様に運ぶ」設計は、**遷移帯より下の格子行がすべて同一値（列ごとの d_att）になる**ことを意味する——格子分解能の議論が遷移帯の 1〜2 行だけに縮む。プラム項のような付加項は独立に上乗せでき、fix 間で byte 保存を機械 assert できる（assert D の型）

## fix3 ラウンド（cp13fix3、rev 393→401）— 最終モデル「3帯」: 生える髪は頭と回り、垂れる髪は控えめな斜めベクトルで付いてくる

fix2 は中帯の凍結を解いたが、**境界をメッシュ上端（描かれた切り縁 = 付着帯）まで上げすぎた**: こめかみ・生え際の「髪が生えている領域」まで懸垂化され、高い標本行の d_att（dx 41〜55px）で頭皮帯ごと振り回された（gate 判定: 振り回し過剰。原版の X 欠落と対をなす過補正）。ユーザー言語化の最終モデル:

> **net3(u,y) = W3(y)·rot(u,y) + (1−W3(y))·d_scalp(u) + plum(u,y)**、d_scalp(u) = rot(u, **y_scalp**)

1. **頭皮帯**（drawable 上端 〜 y_scalp）: 髪が生えている領域 = 頭皮の一部。**フル回転**（Z 回転デフォーマの世界から逸脱しない）

### 3ラウンドの総括（craft 重力テンプレ最終形の原料）

3ラウンドは**3つの独立な設計自由度を1つずつ暴いた**:

| ラウンド | 暴かれた自由度 | 敗因/学び |
|---|---|---|
| 原版 | **遷移の鋭さ・置き場**（境界行 550 はほぼ正しかった） | 350〜500px の甘い遷移が pivot 符号反転線 y=596 を跨ぎ、逆向きの場を混ぜて運搬 X を相殺 |
| fix1 | **標本行**（W 境界と T_root 標本行は別の量） | 標本行を付着帯へ→毛先の X 回復。だが嘘の W 帯が中帯で相殺を続けた（付け根静止・毛先振れ） |
| fix2 | **境界の行**（接触帯は「本当の接触帯」） | 境界を切り縁（メッシュ上端）へ→中帯凍結は解けたが、頭皮帯まで懸垂化して振り回し過剰 |
| fix3 | ——3つの自由度の**縮退** | 境界 = 生え際（描かれた付着の下端）に置くと、**W 境界と標本行が同じ行に一致**し、遷移は「鋭く・反転線の上で」の2制約だけが残る |

**最終テンプレ（Z 回転場・重力髪）**: `W3(y_scalp, 40px sharp)·rot + (1−W3)·rot(u, y_scalp) + plum`。ダイヤルは **y_scalp（毛束ごと1個）+ κ（演出）** の実質2個。y_scalp の実測レシピ: 側頭髪 = 毛束メッシュ内縁 vs 顔シルエット外縁の深度符号反転行（解剖学クロスチェック: 虹彩下端・耳下端）、後頭髪 = neck 上端直上（横フレア可視化行は生え際ではない）、上限 = 場の符号反転線 − 遷移長。

### craft への指摘（レシピ06 重力テンプレ節の最終形）

1. **Y 球面場で3つの自由度が見えなかったのは全て縮退のため**: 場が y 一様だと (a) どこで混ぜても値が同じ（遷移の置き場が消える）(b) どの行を標本にしても同じ（標本行が消える）(c) 境界の嘘が絵に出ない（境界の行が消える）。**場を y 依存に差し替えた瞬間、3つが順に独立変数として復活する**——テンプレ再適用時のチェックリストそのもの
2. **Z 回転場の正解は「y_scalp ワンノブ」**: W 境界 = 標本行 = 描かれた生え際。この一致は偶然でなく物理: 毛束は生え終わった行からぶら下がる。fix1 craft 指摘1.（W 境界と標本行は別の量）は「境界を間違った場所に置いている間だけ」有効な中間命題だった——正しい境界では再び1つに戻る
3. **符号反転線は場の不変量として最初に引く**: pivot 行 y=596 は設計前に分かっている。「遷移帯（設計値も格子実効値も）は反転線を跨がない」を assert E の2層（設計 + 格子ノード）で最初から機械化しておけば、原版の敗因はコーディング時に検出できた
4. **境界較正はワンノブ・ダイヤルを生成器の先頭に**: センス領域（描かれた生え際の読み）は gate で1回で決まらないことがある。DIALS を先頭に置き「数字1個→再 gen→PRE assert→8 op」の再調整ループを 1 コマンド化しておく——ユーザーの「実際結果を見た方が早い」への実行系の答え
5. 標本行 = 境界行の設計は**格子軟化の絵的コストも消す**: 引き伸ばされた遷移の両端値がほぼ同一ベクトルになるため（rot(u,境界行) ≈ rot(u,y_scalp)）、行密度を上げられない fix ラウンドでも sharp 遷移の意図が実効的に保たれる
