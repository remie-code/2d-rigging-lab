# 閉問題 16: 髪揺れ（Hair Sway X 3系統 = 揺れモード場の設計 + dynamics v3 の初運用）

> 状態: Problem defined（2026-07-05）
> 前提: wave106 で dynamics エンジンは世界系 Verlet チェーン（`dynamics-file-v3`）へ置換済み・ユーザー実機確認済み（「アルゴリズムは完璧」）。設計文書: [../../../design/dynamics-world-frame-chain.md](../../../design/dynamics-world-frame-chain.md)

## この問題の新しい未知（1問題1未知の原則に対する申告）

主未知は **「加速度駆動の揺れモード場」の設計**。FaceZ 重力テンプレ（cp13）の親戚だが、場の意味が違う:

- 重力ワープ = 定常場（保持した姿勢での垂れ）。揺れワープ = **過渡場**（振り子が振り切った瞬間の形）
- キーフォーム端 ±1 = 振り切りポーズ。時間方向の運動はエンジンが角度→パラメータで駆動する（rigging は「モード形状」だけを持つ）
- 「どこから揺れ始めるか」= 頭皮支配帯と自由帯の分割 = **固定線の実測3型（レシピ06）がそのまま再利用できるはず**——この転用可否も検証対象

副次の未知（初運用系）: dynamics グループの headless 設計（createDynamicsGroup の rigging 実戦初）、物理定数の実測導出（メッシュ実測長 → segmentLengths、コミット済みキーフォーム実測 → input scale）。

## スコープ（操作列）

1. **パラメータ3本の作成**（プリセット準拠）: Hair Front Sway X / Hair Side Sway X / Hair Back Sway X
2. **揺れワープデフォーマ5基**: front_hair・房L/R・後ろ髪L/R の各 drawable **直上（塔の最内側）**に挿入。ref 実証済みの慣習に従う（BodyZ 追従の内側に置く配置で問題が出ないことは ref で動作確認済み）
3. **キーフォーム**: 各デフォーマ 3キー（−1 / 0 / +1）。0 = 恒等
4. **dynamics グループ3個**（1出力 = 1グループ）:
   - inputs（全グループ共通）: Face Angle X（kind: positionX）/ Body Angle X（kind: positionX）/ Face Angle Z（kind: angle）/ Body Angle Z（kind: angle）
   - kind 割当の物理的根拠: X系 = 支点並進（過渡のみ、保持で定常寄与ゼロ）、Z系 = 座標系回転（保持で −φ 静定）。v3 意味論の教科書的適用
   - output: 対応する Sway パラメータ、segmentIndex 1
   - chain: segmentLengths は各房のメッシュ実測長から px→cm 宣言スケール経由で導出。damping / gravityScale は設計 §8 hair プリセット帯を初期値とする

## 設計規約

- **ゲイン=1 の規定世界線**（ユーザー決定 2026-07-05）: キーフォーム端 ±1 = 出力写像の既定「1.0 = 30°」に対応する振り切り（固定線まわり ±30° 相当の横振り）。振幅の好みは後段の出力 scale / player の outputScale ダイヤルで調整し、場の形とゲインを分離する（cp03 のゲイン=1 正典と同思想）
- **左右は同一パラメータ・同一グループ**: 揺れ場は左右で鏡映（+1 = 画面右への振り切りを両側が共有）。左右で変わる要素がほとんど無いというユーザー判断による
- 場の形: 固定線から下へ Φ ランプで横変位が育つ。固定線の行は実測（生え際 = 食い込み符号反転行 ほか実測3型）。隠蔽維持拘束・格子規則など craft 拘束は全て適用
- 前髪 / 房 / 後ろ髪でパラメータを分ける理由 = 長さの違い = 周期の違い（√則）。dynamics が正しくなったことで初めて意味を持つ分割（ref の「全部1本」慣習は旧エンジン下の妥協であり踏襲しない）

## 判断の所在

| 判断 | 所在 |
|---|---|
| 揺れ場の形（Φランプ・曲率・固定線） | Fable（craft テンプレ + 実測） |
| ±30° = ゲイン1 の規定 | 合意済み（本定義） |
| chain 定数の初期値 | Fable（実測長 + §8 帯。物理根拠付き一回勝負） |
| 揺れの気持ちよさ（damping 等の最終値） | センス領域 = ユーザー（Editor プレビュー gate → player 微調整）。停止条件付き: 視覚イテレーション予算1、以降は人間ダイヤル領分 |

## 除外事項

- Y 揺れ（縦バウンド）: ユーザーが審美 gate を張れないためスコープ外（2026-07-05 決定)
- ネクタイ: 閉問題 17（Body 入力のみ + 結び目固定線の変奏)
- 多段セグメント / 複数出力: 1段・1出力で開始（v3 は対応済みだが未知を増やさない）
- 後頭部2枚・眼鏡・帽子など他部位の揺れ

## 成功基準

- **A（API 十分性 + 機械検証）**: 静的 sweep レンダ（各パラメータ −1/0/+1）で場が craft 拘束を満たす（固定線不動・振り切りの自然な曲率・左右鏡映・隠蔽維持・0キー恒等 = 既存レンダのバイト不変）。dynamics グループ3個が validator green で committed
- **B（ユーザー満足）**: ユーザーが Editor Dynamics Tool / Viewer で実際に揺らし、「イメージ通りの揺れ」と判定
