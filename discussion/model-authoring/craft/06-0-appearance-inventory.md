# レシピ 06-0: 見えの目録（合成世界の意味論採寸）

> 由来: 3周目 claude-chan 周回・FaceX fix 3ラウンド（2026-07-12）。回転系工程（レシピ06・07 の全軸）が場の設計を始める**前に**、合成世界の意味論——可視性・所属・所有権——を一度だけ採寸して4表に固定する。場の設計はこの目録の**純関数**になる（レシピ06 の実測手順から素材 alpha の直接参照を排除する）。
> **本レシピは周回内の視覚判定の集約点である**: 「機械測定で決めてよい値」と「視覚・意味論判定が要る値」の区別を、ここで一括して済ませる。他レシピの実測は機械のままでよい。

## なぜ要るか（3つのカテゴリ錯誤——すべて実走で顔を出した）

場の設計に必要な入力を単層素材の機械測定で代用すると、次の錯誤を必ず踏む:

1. **素材 alpha 縁 = 可視シルエット** の錯誤 → 髪に隠れた側縁・上縁まで係留し、目の外半分の皮膚が凍る
2. **見えている = シルエット** の錯誤 → 髪の隙間から覗く頬の縁（interior）を係留し、その外の帯が丸ごと凍る
3. **素材幅 = 殻幅** の錯誤 → 素材は担い手曲面上の「窓」なのに窓の縁で z=0 にし、素材端帯が死帯化（両キー同向ピンチ = 回転の証言ゼロ）

## 成果物（`<PKG>-notes/appearance-inventory.md` + 機械可読 json。全回転軸の共通入力）

### 表1: 曲面カタログ

回転に参加する曲面（頭蓋・髪殻・体幹殻…）の一覧。各曲面の **limb（回転軸面との交線）の実測源を素材でなく解剖で指定**する:

- 頭蓋 limb = **耳の外端**（耳は頭蓋側面の解剖学的目印。素材 alpha の細りは髪の食い込みや意匠であり limb ではない）
- 髪殻 limb = 髪素材の広がり全幅（髪は自身が最外周の可視質量）
- 体幹 limb = 肩幅・胴幅の実測（衣服込みの可視質量で読む）
- ⚠ **「窓」素材（下記表2）の alpha 幅を limb に使うことを禁止**（錯誤3）

### 表2: 素材→曲面の張り付き表

各素材に「どの曲面の上の何者か」を割り当てる。クラスは付着物3クラス（invariants §5）+ **窓**:

- **窓**: 担い手曲面の一部だけが描かれた素材（顔・胸元など）。**窓の縁は曲面の縁ではない**——z プロファイルは担い手曲面の limb まで生きる
- 密着物 / 剛体 / 立ち付属物 / 垂れ物（既存クラス）

### 表3: 縁の3分類地図（視覚判定の本体）

全対象素材の縁（alpha 輪郭）を画素区間単位で3分類する:

1. **可視シルエット区間**: その高さの集合体外形の所有者としての縁（例: 顎線弧）。→ 係留対象（接線滑り射影。レシピ06）
2. **隠れ縁**: 他素材に覆われた描き縁（例: 髪の下の側縁・上縁）。→ 係留しない・場のまま流す。隠蔽維持 assert で保護
3. **接触縁**: 二層の重なりの見た目を決める縁（invariants §6 の所有権）。→ 従属/差動の設計対象

**機械化された可視判定の手順**:

- 合成 rest レンダ（全可視素材）と「対象素材のみ一時非表示」レンダ（レシピ04 の足場 op 往復。レンダは sha 確認の上で固定資産化してよい）を画素比較し、対象の輪郭画素ごとに「消すと合成が変わるか」で可視/被覆を判定 → 連続区間化
- **測定罠2つ**: ①レンダ境界帯損失（レシピ01 既知の罠）→ 輪郭の内向き 2〜4px を多点サンプル ②低コントラスト線のストロークモアレ → チェーン方向 ±2px 窓の max で読む
- **★目視確認必須**: 機械判定の区間を overlay レンダで自分の目で確認する。「可視シルエット」への昇格は目視で裏取りしてから（可視でも interior なら区間2の亜種——錯誤2）。想定と大きく違う結果（例: 想定「顎線のみ」に対し頬側面に長い可視区間）は機械値を優先し、報告に相違を明記

### 表4: シルエット所有権の行別表

各高さ（行帯）の集合体外形を所有する層（レシピ07 技法1・invariants §6 の成果物化）。縁係留の係留先・接触縁の従属先の解決に使う。
