# レシピ 06: Face Angle X（顔の横回転 rigging）

顔の横回転パラメータ（`param_face_angle_x`、preset、レンジは parameters を確認。min=画面左向き / max=画面右向き）に対し、要素ごとの FaceX 層デフォーマを積んで擬似3D回転を作る。閉問題03の蒸留。

## 前提状態

- 対象要素のメッシュ・下位リグ（目の開閉塔など）が完成済み
- 対象要素の選定: 最小核は「鼻・顔輪郭・目」。鼻は**基底鼻**（face 階層の part に属する nose。表情セット配下の nose 群とは別物なので partId で見分ける）

## 構造

- **要素ごとに FaceX 専用デフォーマを1枚**作る（1要素×1パラメータ = 1層の原則）。5×5 格子が相場、顔輪郭のみ高解像（7×7）
- 既存リグ塔（例: 目の状態デフォーマ群）の上に被せる場合は `createWarpDeformer` の **`wrapChildren`**（`[{kind:"rigControl",id:...}...]`）で挿入する。既存塔の parentId が自動で書き換わる。**`wrapChildren` は `childDrawableIds`/`childRigControlIds` と併用不可**（排他モード）。**挿入後は既存機能の回帰確認が必須**（開閉・眼球移動・マスクを合成レンダ1枚で見る）
- 素の drawable（鼻・顔）は `childDrawableIds` 直接指定でよい
- domain = 子要素の**生成後の実頂点範囲**の union + 移動量ぶんのマージン（宣言 bounds は実頂点範囲より狭いことがある。メッシュ生成後に測り直す）

## ゲインと構造の分離（2026-07-03 盲目再構成実験で確立）

**field = 構造 × ゲイン。**

- **構造** = 奥行き比率・左右非対称・field の位相（帯・スパイク・固定縁）。客観であり、本レシピの原理から導出可能（盲目実験で内部比率が完成参照と誤差2割以内で一致）
- **ゲイン** = 全体の振幅スカラー。**モデルオーナーの演出意図**であり正しさの軸ではない（控えめ=上品 / 大きめ=楽しい、はどちらも満点になりうる）
- 手順: **構造をゲイン1で組み、ユーザー gate でゲインのダイヤルを回す**。ゲイン1の基準 = 鼻の振幅 ≈ 頬幅の10%（上品な回転として満点実証済み。演出強めなら〜20%）。調整は全 FaceX キーへの一様乗算（updateCurrent 一括）で機械的に反映できる
- 完成参照から抽出する場合も同じ分離を適用する: **比率は essence（持ち越せる）、絶対値はゲイン込みの較正データ（そのモデル専用）**

## 奥行きモデル（量の設計原理）

> **dx は「回転軸からの奥行き距離」に比例する。** 回転軸は頭部のほぼ不動な要素（頭蓋・帽子級）を通る。最前面の鼻が最大移動、軸より後ろの要素（後ろ髪）は**負 = 逆方向**に動く。dy はほぼゼロ（X回転は水平の営み）。

- **鼻 = 純平行移動**（warp 0、全格子点一様）。位置だけが仕事
- **顔輪郭 = 移動小・変形大**。仕事は「動く」でなく「シルエットの作り替え」:
  - 上顔面（額〜目の帯）の肉を向く方向へ大きく流す（この帯が field の最大値を持つ)
  - 顎先は独自に向く方向へ振る（最下行に局所スパイク）
  - **髪などに隠れる縁だけ**動かさない（ゼロ固定は「隠れる縁」に限る。顎先スパイクは最下行でも打つ——「外周全固定」と読むと矛盾する。どの縁が隠れるかはレンダで実測）
- **目・眉など顔表面の造作 = 左右非対称**が立体の鍵:
  - 向かう側（縁に近づく要素）: 移動量小 + **横に縮む**（格子の列方向に単調勾配をかける: 顔中心側の列は大きく、縁側の列は小さく動かす。端点比率は中心側:縁側 ≈ 0.65T:0.25T が実証値——勾配自体が横縮みを兼ねる）
  - 遠ざかる側: ほぼ一様に大きく顔面を渡る（微膨張も可）
  - +max と −min のオフセットは**鏡像にならない**（左右の要素で役割が入れ替わる）

## 量の設計手順（完成参照が無い場合）

1. 巻尺で頬幅（顔メッシュ bbox 幅）と各要素の rest bbox を取る
2. **鼻から決める**: ゲイン1の基準（鼻振幅 ≈ 頬幅の10%）で三点キーを打ち、±max の sweep で「向いた」と読めるか確認（鼻は判定が一番簡単な要素や——位置だけ見ればええ)。ゲイン調整は gate 後のダイヤルに委ねる
3. 鼻の移動量を基準に、奥行き順で各要素の比率を内挿する（目・口・眉は鼻の8〜9割見当から開始、輪郭の流しは鼻より大きくてよいが**輪郭全体の平均移動は小さく**、後ろ髪は負)
4. ★各要素を足すたびに**複数要素同時の sweep** でゲシュタルト判定（単独要素の正誤は人間にも判定困難——位置関係の整合で見る）

## 完成参照（ref 等）がある場合の移植作法

参照の keyformSets から field を抽出できる。domain と格子次元を参照と同一にすれば restControlPoints が一致し patch を点対点移植できる（**移植前に格子一致アサーション必須**）。不一致なら field を関数化して自前格子に区分線形で再標本化する。数値はモデル専用の較正データであり、他 PSD へは持ち越さない——持ち越すのは本レシピの言語だけ。

## キー

`editKeyformKey action:"createEndsCenter"`、targetProperty `controlPointOffsets`、parameterId `param_face_angle_x`（パラメータレンジ端がキー位置なら三点キーで足りる）。min/max の patch は独立に設計する（非対称）。

## 完了チェック

1. ±max・rest のレンダ3枚で「顔が向いた」と読める（★ゲシュタルト判定）
2. 挿入した要素の既存機能が無傷（回帰合成レンダ）
3. 【ユーザー gate】位置関係の整合の判定

## エスカレーション条件

- 「向いた」ではなく「ずれた」に見える → 要素間の比率が奥行き順に単調でない可能性。設計ログの比率表を見直す
- 輪郭の変形で顔の絵が破綻する → 流しの帯が広すぎるか外周固定が漏れている
