# レシピ 08: 揺れ物 rigging（揺れモード場 + dynamics v3）

> 由来: 閉問題16（髪4系統 + タイ、2026-07-05 通過）。前提エンジン: dynamics v3 世界系 Verlet チェーン（[../../design/dynamics-world-frame-chain.md](../../design/dynamics-world-frame-chain.md)）。
> 対象: 髪・タイ・紐など、固定線から下が慣性で揺れる吊り物の Sway rigging。

## 0. 構成の全体像

1系統 = **Sway ワープ1基**（塔の最内側、drawable 直上）+ **dynamics グループ1個**（1出力 = 1グループ）。

- ★ パラメータの分割: **自由長が違う房はパラメータを分ける**——周期 T = 2π√(L/g) の差は分割しないと永久に出ない。左右は物理がほぼ同じなら1本に共有（場は同方向: 振り子は左右いっしょに流れる）
- 分割基準は直交する2本（2周目実証）: **パラメータの分割は物理（周期）、ワープの分割は塔の構造**——同塔の2房は1ワープ、別塔の左右は2ワープ1パラメータ。物理と器を混ぜて数えない
- プリセットパラメータ（Hair Front/Side/Back Sway X, Accessory Sway X 等、range −1..+1）は**常在**——parameters.json に無くてもサーフェスに存在する。createParameter 不要・禁止（locked）

## 1. 揺れモード場（キーフォーム。等長写像が必須不変量）

キーは {−1, 0, +1} の3点。0 = 恒等。±1 の場は各格子**列ごと**に:

```
y ≤ y_fix（固定線）: 完全不動
y > y_fix:  s = y − y_fix
  θ(t) = ±Θ_max × (t / L_free)^κ
  位置(s) = (x, y_fix) + ∫₀ˢ ( sin θ(t), cos θ(t) ) dt    （刻み ≤1px の台形則、決定論）
```

- **等長写像**: 接線が常に単位長 → 弧長厳密保存。**弦配置（点をピンから距離 s に置く）は禁止**——θ 成長がある限り伸長率 √(1+(sθ′)²) で必ず伸びる（毛先 13% 実測、ユーザーに視認される）。検証は「列折れ線長 vs rest ≤0.1%」の1本
- **板の回転の禁止**: 単一ピンでの全格子回転は、幅のある素材で「斜めの重力 + 伸縮」に見える（右端が沈み左端が浮く）。必ず列ごと
- κ = 剛性ダイヤル（唯一のセンスノブ）: →0 で剛体振り子（根元だけ滑らかに曲がる）、1 で鞭。初期値 0.5
- Θ_max = 30°（**ゲイン=1 の規定世界線**: 出力写像の既定 scale 0.0333 = 「パラメータ 1.0 = 30°」と対応。振幅の好みは後段の outputScale ダイヤルで、場の形とゲインを分離）
- 固定線 y_fix は**格子行にスナップ**（直上へのバイリニア漏れが 22.9px→0.00px。cp10 行スナップ則の完結）。固定線の実測はレシピ06 の3型（生え際 = 食い込み符号反転行 / 結び目下端 = 幅プロファイル極小プラトー / イン線 = 上縁フラット行）
- 検証: 等長 assert / 毛先の持ち上がり dy < 0（振り子の上方遷移の存在）/ 固定線以上 0.000px / 0キー恒等（rest レンダ sha 一致）

## 2. dynamics グループの設計

### 2.1 ★ 最初に様式を見極める（最重要の分岐）

**このモデルの静的リグは重力の定常状態を焼き込んでいるか？**（cp13/15 の重力テンプレ様式 = yes）

- **yes → 全入力 positionX（過渡のみ）**。angle 入力は重力の二重計上になり、静定が真下を通り越す。「揺れが収まったら静的ポーズと同一」が構造保証（定常出力 ≡ 0）になり、**dynamics 定義に angle 入力ゼロ、を機械 assert する**
- no（静的リグが剛体追従のみ）→ Z 系は angle（エンジンが重力静定 −φ を出す）

### 2.2 入力 scale の導出（全て実測 or 幾何）

- **X 系（首振り・体振り）**: パラメータ責務ワープ（rig_facex_* / rig_bodyx_*）の **own 格子**を固定線行で実測（evaluatedControlPoints は自身のキーフォーム変位のみを映す——1デフォーマ=1責務が巻尺に効く）。scale = 平均dx_px ÷ 宣言スケール(px/cm) ÷ param 振幅。**符号も実測に従う**（後頭部 z<0 の房は負 = 顔と逆方向に励起される）
- **Z 系（傾き）のレバー線形化**: scale = |y_fix − pivot_y|/宣言スケール × (deg/unit × π/180)。rootOffset は positionX 様式では不活性 → (0,0)
- 宣言スケール: px→cm をモデルごとに一度宣言（例: 18px = 1cm、全身 px と想定身長から）

### 2.3 chain

- segmentLengths = **L_eff = (2/3) × 自由長cm**（一様質量棒の等価振り子長）。自由長 = 固定線→drawable 下端の実測 px
- damping / gravityScale 初期値は設計文書 §8 のプリセット帯（hair 2.5 / 長物 2.2 / タイ 3.0、gravity 1.0）。最終値はユーザーの Editor プレビュー / player ダイヤル領分（停止条件付き一回勝負）

## 3. 罠と運用

- 向きは用語でなく**観測量**で規定する（「時計回り」等の語は座標系で裏返る。「+1 = 画面右」を三度明記し assert）
- 触らないグループ・キーは **op を発行しない**のが最強の無傷保証（部分 payload / 対象外グループ無発行）
- CLI バッチは**フォアグラウンド直列**で回す（バックグラウンド化 + 完了待ちターン終了は委任エージェントの停止事故源）
- ユーザー gate の違和感は数式の欠陥に一対一翻訳できる前提で聞く（「伸びて見える」= 実伸び、「収束がおかしい」= 平衡点の二重計上）
- **editKeyformKey createEndsCenter は statePatches に default（全ゼロ）が必須**（3周目実証: 省くと dry-run reject。0 = 恒等のキーも明示的に発行する）
- **dynamics 定義の数値は整数正規化されて再直列化される**（1.0→1）。発行値と committed の照合はバイト一致でなく**数値等価**で行う
- **軸上ピボット素材（耳付けのイヤリング等）の X 系入力は実測ゼロになりうる**（cos 偶応答で線形成分が構造的にゼロ）——scale 実測が 0 なら入力ごと不発行が正（「実測 or 幾何」原則と「触らないものは発行しない」の交点）。Z 系レバーだけで揺れる系統は正常

## 静的重力場との合成と補間の等長性（Astra gate・2026-09-08）

揺れの向きを世界系で保つには、静的な入れ子回転の座標系を区別する。rest座標で標本する加算warpの前後へ、既存FaceZ+BodyZと等しい角度の正逆rotation2dを対で挿入すると、ゼロ揺れで両者は相殺され、揺れ変位だけが逆回転される。外側の既存回転を通した後の揺れ変位は世界系の列積分と一致する。ネクタイなど頭に属さない素材にはBodyZだけを用いる。実頂点差分で全角度における方向不変性と固定線不動を確認すること。これは運動責務の追加でなく座標変換の対である。

±1/0キー自体が等長でも、その線形補間は短縮する。列長の0.1%検査は中間値にも適用する。必要な場合は角度キーを細分化する（今回の30度・kappa0.5では11点で通過）。揺れモードの自由度は1本のまま維持する。

物理系統の共有は周期だけで決めない。自由長が近くても、固定線のX入力が前側と後側で逆符号なら、共有すると励起を打ち消す。測定した入力の符号と接続場所も分割判断に含める。プリセット外の系統が必要な場合は理由を明示し、周回のユーザー許可範囲に従う。

静止画CLIで時系列を扱えない場合は、変更していない実エンジンのstepDynamicsにcommitted定義と固定dtを渡し、入力と出力の時刻付き標本を実runtime rendererで描画できる。これは物理式の自作による近似ではないが、Editor/player実機検証とは区別して記録する。停止入力・非ゼロ保持入力の両方で静定ゼロ、決定性、チェーン長、clamp有無を確認してから画像で判断する。


## 縮尺を持つ担い手と世界系の揺れ（astra-chan 揺れgate・2026-09-08）

飾り等を準剛体のFaceX/Yで運び、縮尺も変えている場合、Swayをdrawable直上へ置くと外側の縮尺が揺れ変位にも掛かる。世界系の規定振幅を保つには、縮尺を含む担い手の外側、静的な加算重力場とZ回転の内側へSwayを置く。正逆回転の対で世界系の増分を作り、ゼロ揺れで担い手の変形を保存する。配置は「最内側」を機械的に適用せず、どの変換が揺れ増分に作用するかで決める。

正逆回転の相殺は浮動小数点では微小な丸めを伴う。生のRGBAで透明縁のRGBに差が出た場合は、alpha・実頂点・複数背景へ合成した表示画素を分けて照合し、形の変化か透明色の丸めかを特定する。PNGバイト一致でない結果を一致と報告しない。今回、alphaは不変で透明縁の数画素だけRGB最大1の差があり、黒・白・確認用背景への合成は完全一致した。
