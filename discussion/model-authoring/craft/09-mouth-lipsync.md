# レシピ 09: 口パク（最大情報素材の単一変形 + 素材参照 morph 場）

> 由来: 閉問題17（2026-07-05 通過）+ 3周目リップシンク追試（2026-07-17、い・う・え・おで矩形支持場を実証）。対象: Mouth Open × 母音（あいうえお）の口 rigging。同型の「参照素材への morph」全般に流用可能（表情差分の口・目の変形バリエーション等は未検証）。

## 0. 方式原理（2つの不変量）

1. **最大情報素材を正とする**: 変形は情報を潰せるが**発明できない**。歯・舌・口内を持つ最大情報の絵（全開の「あ」）を唯一の生きた drawable にし、他状態は変形で作る。opacity 切替の直積（母音×開き量）は組合せ爆発する——切替は一方向1境界のときだけ（レシピ05）。PSD に旧デフォルト口（閉じ・中間）の drawable が別にある場合は永久非表示化し、mouth_a を唯一の生きた drawable にする
2. **パッケージ内参照素材 = 合法オラクル**: ユーザーが「答えの形」を drawable として供給（永久非表示）し、エージェントがシルエットを実測して場に翻訳する。ref/ 封じ込めと両立する唯一のオラクル経路

## 1. 塔（入れ子の順序が物理）

```
既存追従塔（最内側） ⊃ MouthOpen ワープ ⊃ 母音ワープ i/u/e/o ⊃ mouth_a
```

- 母音が形を作り、Open が外から潰す →「い の半開き」「閉じたら母音が消える」が合成から自動で出る。rest 素材と同形の母音（あ）はワープ不要
- **通し周回の工程2時点では追従塔は未存在**——MouthOpen を最外に独立で建て、追従塔（工程3）が後から外を包む。上図は包まれた後の最終形。また param_mouth_vowel_a にはキーを打たない（あ=rest 同形）——runtime が a=1 を送っても無反応なのは仕様（開きは MouthOpen が担う）
- MouthOpen: キー1 = 恒等（rest = 全開）/ キー0 = 閉じシルエットへの潰し。**閉じは純変形**（配信縮尺では潰しの方が専用閉じ素材より視認性が高い——ユーザー裁定 2026-07-05）
- default open=0 → rest レンダの口は「潰した基準素材」になる（旧素材と画素が変わるのは方式の帰結。差分局在で機械確認）

## 2. シルエットの実測

- **メッシュ境界方式が一次**: 自動メッシュは alpha 輪郭に沿う → `inspectEvaluatedGeometry`（includeVertices）の頂点群から、口角（水平極値）と列プロファイル（水平 N 帯の y_top/y_bot）を取る。**非表示のままで測れる**（幾何は可視性と独立）
- プロファイルは3点移動平均で平滑化（決定論）
- 一時表示 → フォーカスレンダ → 非表示（op 往復）は目視照合用。合成レンダは背後の肌が写るため数値の正にしない

## 3. morph 場（基準 B → 目標 T の2段写像）

```
1. 水平（口角アフィン）: u = (x − x_L^B)/(x_R^B − x_L^B) → x' = x_L^T + u·(x_R^T − x_L^T)
2. 垂直（列ごと上下縁対応）: v = (y − y_top^B)/(y_bot^B − y_top^B)
   v∈[0,1]: y' = y_top^T + v·(y_bot^T − y_top^T)
   帯域外（v<0 / v>1 / 口角の外）: 最寄り縁のデルタで平行運搬（連続性）
statePatch = (x', y') − rest
```

- ★ **潰し場は高曲率**——折れ線がシルエット線に乗る場は格子解像度を要求する。9×7 は +4.9px 不足、25×23 で +2px gate 通過（実測）。数値 gate（±2px）を先に決め、格子は gate が決めさせる
- 検証: プロファイル残差（列平均 ≤3px・最大 ≤6px）/ 潰し高さ ≤ 閉じ参照 +2px / rest 差分の対象領域局在 / 既存キー無傷
- **差分の対象領域局在の手続き**: 変更前後の rest レンダを PNG デコードし、差分画素の bbox が対象領域（口 bbox + マージン）内に閉じることを数える。リメッシュや意図した画素変更を含む変更ではレンダ sha 一致が原理的に不成立——差分画素の数値局在化が回帰確認の正しい形

## 4. 輪郭外まで含む矩形支持場（3周目で確立）

### 4.1 原理: 可視輪郭は輪郭外の格子点にも支配される

drawable のある頂点が輪郭内にあっても、その変位は所属セルの四隅から双一次補間される。したがって、**口の輪郭内の制御点だけを目標形へ動かしても、輪郭外の制御点が早く rest へ戻れば、可視輪郭は外へ引かれる**。

典型症状:

- 左右端の手前までは母音形へすぼむが、実際の口角では再び広がる
- 上下縁は中央だけ滑らかで、口角付近にギザギザ・V字・切れ込みが残る
- 格子を細かくするほど凹凸が明瞭になる（粗格子が偶然ローパスとして隠していただけ）

この症状を「素材の癖」「点数不足」「輪郭の微調整不足」と誤診しない。最初に見るべきは**場が効いている空間範囲**である。

### 4.2 禁止形: 輪郭追従カラー

輪郭の各 x 列で `y_top/y_bottom` のすぐ外から rest へ解放する場は使わない。口角へ近づくほど輪郭高さが小さくなるため、支持帯まで同時に細くなり、ちょうど曲率が大きい左右端で外周格子の影響が勝つ。

「口の輪郭 + 一定距離」のカラーは見かけ上自然だが、morph の支持領域としては狭すぎる。

### 4.3 正形: 矩形支持場

基準輪郭 B の大域 bounds と格子セル幅から、支持領域を矩形で取る。

```text
x_active = [B.x_left − margin_x, B.x_right + margin_x]
y_support = [B.y_top_global − margin_y, B.y_bottom_global + margin_y]
```

`y_support` は **x に依存させない**。左右口角を越えるまで同じ上下幅で場を保つ。

各 x 列の y 写像は次の3区間を連続に繋ぐ。

```text
support top  → source column top    を target support top → target column top へ
source top   → source bottom        を target top         → target bottom     へ
source bottom→ support bottom       を target bottom      → target support bottom へ
```

- target support の上下余白は、基準→目標の大域縦スケールに合わせる
- `x_active` の内側ではこの写像を全面適用する
- `x_active` の外側だけ、domain 外周へ向けて smoothstep で「外側の平行移動」へ解放する
- 水平方向も active 内は口角アフィン、外は端の並進を運ぶ。輪郭端そのものでは解放しない

これにより、輪郭内だけでなく**可視輪郭を補間する外周セル全体**が同じ母音形を支持する。

### 4.4 解像度と支持幅を別々に決める

格子の総解像度、口領域に実効参加するセル数、輪郭外の支持余白は別のダイヤルである。

3周目で通過した実証プロファイル（普遍値ではなく再現開始点）:

| 項目 | 実証値 |
|---|---:|
| 総格子 | 33 × 25 points |
| 口領域 | 実効 21 × 14 cells（約 22 × 15 points） |
| 支持余白 | 横 4 cells / 縦 3 cells |

手順は **支持幅を正す → 必要なら解像度を上げる → 最後に輪郭を微調整する**。支持幅が不足したまま点を増やすと、不適切な場を高精度に標本化してギザギザを悪化させる。

### 4.5 目標輪郭と alpha 余白

参照素材の drawable bounds をそのまま口形状とみなさない。透明・半透明の余白が素材の周囲にある場合、alpha 外縁込みの輪郭へ合わせると口が太る・歪む。

- 複数 alpha threshold の輪郭を比較し、実際に色が成立する意味的輪郭を選ぶ
- 数値候補は必ず reference drawable の高倍率レンダと照合する
- 目標は「素材矩形」ではなく、**人間が口として知覚する輪郭**

ただし alpha threshold は素材依存の測定値であり、レシピ固定値にしない。

## 5. 診断・再構築・gate の順序

1. **素材オラクル取得**: 基準 mouth_a と対象母音 drawable の意味的輪郭を取得する
2. **支持場を可視化**: 変形後の格子線を口レンダへ重ねる。左右口角の上下で、格子行が輪郭を越えても母音形を保っているかを見る
3. **矩形支持を確立**: 口角外・上下縁外まで一定幅を持たせる。ここで輪郭点の手修正はしない
4. **機械検算**: 全セルの normalized Jacobian > 0、対象外 keyform 不変、差分局在、非永続 preview で package revision 不変
5. **視覚 gate**: reference / 変更前 / 候補 / 格子 overlay を並べ、ギザギザ・V字・口角での再拡張を判定する
6. **必要時だけ輪郭微調整**: 場の範囲が正しいことを確認した後、素材固有の癖を視覚で点調整する

★ **不完全な場への人間補償は新しい場へ継承しない**。狭い支持場を前提に入れた局所調整は、場を矩形支持へ再構築すると二重補償になる。旧 field を真実扱いせず、素材オラクルから再生成して比較する（2026-07-17 ユーザー裁定）。

「滑らかな数式で格子点を動かせば描画も滑らかになる」とは限らない。最終評価は描画結果に属する。ただし、視覚的な点 sculpt へ進む前に、支持領域・alpha 輪郭・格子密度という構造条件を順に潰す。

## 6. 品質の帰属

- 場の精度の上限 = **参照素材の品質**（例: 口周辺の肌の写り込みはシルエットを歪める）。崩れの一次対応は素材更新（ユーザー領分）。gen スクリプトが数値一次ソースなら素材差し替え後の再キーは決定論で再現できる
