# 周回指揮書（Run Conductor）

> **これは楽譜である**: クリーン Fable（L0）が craft と premises だけを持って、1体のモデルを最初から最後まで rigging するための全体工程手順。1周目（閉問題01〜19、2026-07-03〜06）の蒸留。
> **具体性の契約**: 対象の what は意味論で書く（実 ID は工程0の解決表が持つ）/ how の文法はレシピ参照で書く（再記述しない）/ **数値は書かない**（正典値実測シートが唯一の置き場。本書に数値が現れたらそれ自体が設計ミス）。

## 0. 体制と読み物

- **体制**: 2周目は**再現性シリーズ**（2026-07-06 ユーザー設計）——(1) **Fable 統制走**（craft 自体の検証。Fable 期限 2026-07-07 までに実施）→ (2) **Opus 4.8** → (3) **Codex GPT-5.5**（本命 = 期限後も使えるモデルへの craft 可搬性）。統制走が失敗すれば craft の欠陥、統制走のみ成功ならモデル能力差、と切り分ける
- 各周回の役割: L0 = 指揮・設計・gate 対話・蒸留、実装は工程単位でクリーン委任。**実装モデル（L0・工程委任とも）= 当該周回の被験モデル**（2026-07-06 ユーザー裁定: 検証対象は「言語化された craft だけで別モデルが完走できるか」であり、指揮も被験の一部）。調査・棚卸しの大物は非被験モデル（opus 級）へ委任可——craft 検証を汚染しない読み取り系のみ
- **周回の起動**: ユーザーが Editor でワークスペース作成 + PSD インポートまでを行い、被験 L0 の新規セッションへワークスペースパスを渡す。起動文に含めるもの: リポジトリパス / 本書エントリ（読み順: premises → _map → 本書）/ ワークスペース・STATE・`<PKG>-notes/` のパス / 封印規約の宣言。gate はそのセッションでユーザーと直接対話する
- **ユーザー gate** = why と審美の最終審級。gate の置き場は「機械 assert が利かない場所」だけ（§4）
- 初読: [premises/](../premises/)（可解性・運用方針・閉問題アプローチ・craft 設計・モデル配分）→ [_map.md](_map.md)（レシピ索引・共有不変量・2周目実施事項）→ 本書
- **2周目の封印規約（craft 自己完結性の検証として走る場合）**: closed-problems/ と research/ は読まない（答えの混入防止）。**封印は被験 L0 自身にも適用される**（L0 も被験モデル）。行き詰まったら L0 がユーザーと相談して緩和してよい——ただし緩和した事実を記録する

## 1. 一級規則（全工程に優先）

1. **意味論→実 ID の解決は棚卸しで行い、gate で表明する。不一致は推測で埋めず質問として停止**（1周目実証: この規律が30代の委任を無事故にした）
2. dry-run → commit、**1 op = 1 git commit**、工程タグ接頭辞（書式 `[stageN]`）。数値は巻尺（inspectEvaluatedGeometry）から取る
3. 検証は機械 assert 優先: sha256 恒等 / 巻尺照合 / 不変量 assert（等長・angle ゼロ・可視集合・恒等検算…各レシピ所定）。**「〜のはず」は assert で裁く**。既存キー無傷の照合は三点セット——keyformSets ファイル単位の sha 名指し / 対象外への op 不発行（構造保証）/ 合成レンダの差分画素局在（wrap 挿入等で package 全体 sha が使えない場合の一般形）
4. **委任規律パック**（委任文に必ず含める）: 封じ込め verbatim（§5）/ モデル・呼び出し元・最終テキスト=データの明示 / CLI バッチはフォアグラウンド直列 / report.md 漸進書き / 向きは用語でなく観測量で規定 / 停止条件付き一回勝負
5. 満点通過した実装は違和感が出るまで触らない（遡及の物差し）
6. **planning-gate**: 同一 field に fix 2ラウンド以上 or 原理3つ以上が重畳 → 拘束台帳を起草してから次の fix（レシピ07）
7. gate の違和感は物理に翻訳できる前提で聞く（ユーザーの知覚は実測に先行する精密センサー。翻訳実例: 「伸びて見える」=等長違反 / 「収束がおかしい」=定常の二重計上）
8. 人間仕上げ境界を尊重する: 帽子際・襟の非対称など、Fable は土台まで・仕上げは人間（レシピ07）

## 2. 工程列（6工程。順序の根拠 = 機構ファミリの思考連続性 + 依存の位相順）

### 工程0: 開眼と棚卸し

- レシピ00（ワークスペース開眼・CLI 疎通・git 管理確認）
- **意味論解決表**: parts / drawables / parameters（プリセットは常在）を全棚卸しし、ユーザー語彙 ⇄ 実 ID の表を作る。ユーザー語彙列は displayName からの仮案を書き gate で確認する（先に呼び名リストは求めない）。パラメータはプリセットから解決し、**プリセットに無いパラメータの新設は停止・ユーザー裁定**
- **素材マニフェスト**: 全工程の素材前提を一括照合（工程2: 目の状態素材・口の開き素材+母音参照 / 工程5: 衣装差分…）。**不足はここで一括依頼**（1周目の律速 = 素材供給の後出し、を構造で消す）。供給の手段 = **ユーザーが Editor で PSD インポートを行う**（2026-07-06 裁定。ワークスペース作成〜インポートまでがユーザー、被験者はパス受領から）。既存ワークスペースへの再供給が起きる場合は revision・生成済みメッシュ・ID 安定性への影響を都度ユーザーと確認し、工程1着手との順序を合意する。目の状態素材は左右別が要求仕様（左右一体なら停止・相談）
- **正典値実測シート**: canvas 寸法・px→cm 宣言（分母の想定身長はユーザーに聞く）・頬幅・各部 bbox（白目・虹彩は高さも——眼球Y転置用）・回転 pivot 候補（FaceZ=首 bbox 中心 / BodyX=胴 alpha 重心 / BodyZ=腰線相場）・warp 軸候補（FaceX cx=頭蓋/顔輪郭 x 中心相場 / FaceY cy=耳の高さ相場）の採寸。以後の全数値の唯一の出所。**二段構え**: 工程0=宣言 bounds 列 → 工程1後=実頂点範囲列を追記して確定（頬幅などゲインの分母は後段の値を正とする）
- 可視旗の明示化（「空メッシュで偶然隠れている」素材を旗で明示に。false 方向は漏れ出し予防でレシピ10 順序則と整合、工程5の variant ゲートへ引き継ぐ恒久措置である旨をシートへ記録）
- 【gate】スコープ合意: rigging 対象の意味論列挙・除外の確認（裁定済み 2026-07-06: **BodyY は除外が設計**——リターン小 / **眼球Y は採用**——1周目未実装、X の転置で新規実装）・演出ゲインの初期方針（X ゲイン・Y 方向別2値・Z/BodyZ 角度・体幹変位比・頭部同調の物理的読みの裏取り）・ユーザー語彙の確定・想定身長・variant 所属の意味論の先行合意（正式設計は工程5冒頭）・素材供給の手段と順序

### 工程1: メッシュ一括（レシピ01）

- 全対象の generateMesh（**参照素材・永久非表示物も対象**——シルエット実測はメッシュ境界方式のため）。出口 = 対象全数にメッシュ + rest レンダの差分が意図（出現すべき素材）に局在。完了時に実測シートへ実頂点範囲列を追記して確定（二段構えの後段）。gate なし

### 工程2: 局所器官（レシピ02・03・04・05・09）

- 眼球X→Y（統一原理の狭域近似 = 平行移動。**Y は1周目未実証**——レシピ02 の転置として設計し初実証として扱う。採用は 2026-07-06 ユーザー裁定済み。実装構造 = **Y 専用ワープを wrapChildren で入れ子新設**——1デフォーマ=1パラメータ原則、同一ワープへの複数パラメータ keyform 合成は未保証のため。挿入後は X の回帰レンダ必須）→ 白目クリッピング → 表示切替足場 → 目の開閉 → **口パク**（参照素材 morph。切替/変形の選択基準はレシピ05 末尾）
- 回転物理と無縁の最内側ワープ群——追従塔より先に作ってよい（塔は工程3が外から包む）
- 出口 = 各レシピの完了チェック + 0キー恒等 sha（**目系のみ**——口は default=閉じ潰しで rest が変わる方式のため、差分の口領域局在で代替: レシピ09）+ プロファイル残差 + **足場旗の返却**（opacity キーが制御を引き継ぐ半目/閉じセットは true へ——キー完成後に旗を立てる順。永久非表示物は false 維持、最終可視集合を意図集合と照合）。合成検証は同一器官内の直積のみ（器官間は工程6）。【gate】器官 sweep 束1回

### 工程3: 回転の射影（レシピ06——**末尾の統一原理から読む**——+ レシピ07）

- 転置はしご順: **FaceX → FaceY → FaceZ → BodyX → BodyZ**（導出の連続性が最大。Z は rotation2d、BodyX は相似、BodyZ は入れ子）
- 立体物（帽子・眼鏡・耳・房）はレシピ07。**2周目実施事項**（_map 参照）: 房の立体化・前髪3帯を今回は正規適用
- 立体物の隠面素材（後頭部・帽子背面弧等）の不足が判明したら提案付き停止（「変形で出す」への一本化を独断しない）
- 出口 = 各軸の完了チェック + 既存機能の回帰レンダ + 干渉監視 + **様式宣言をシートへ記録**（重力の定常を静的リグへ焼き込んだ旨——工程4 の全入力 positionX 分岐の入力）。【gate】顔系1回・体系1回（sweep 束）

### 工程4: 揺れ（レシピ08）

- 依存: 工程3の committed 場（入力 scale の実測元）。最初に**様式判定**: 静的リグが重力定常を焼いているか → yes なら全入力 positionX
- 出口 = 等長 assert・angle ゼロ assert・0キー恒等。【gate】プレビュー1回——センス領域。残ダイヤル（κ・damping・outputScale）を明示して渡す

### 工程5: 構成管理（レシピ06 末尾「空間再標本化」+ レシピ10）

- 衣装差分の rigging 複製（再標本化。服の固定型の一致を先に確認）→ Variant グループ（順序則4段）→ 在庫の形式所属（アトラス仕様）
- 出口 = Default rest sha 不変・可視集合 assert・恒等検算。【gate】着替え1回（Editor + player ライブ切替）

### 工程6: 通し確認と出荷

- 全パラメータ同時 sweep（対角の Runtime 責務の監視）・干渉チェック・**弦の項の採否判定**（2周目実施事項）・validatePackage・export・player 実機
- 【最終 gate】ユーザーの通し目視

### 工程横断の規約（置き場所）

- 成果物（意味論解決表・素材マニフェスト・正典値実測シート・gate 提出文）の置き場 = `<PKG>-notes/`（**<PKG> の外**・STATE dir と並置・独自 git 管理。<PKG> 内に置くと op の git 巻き戻しに道連れになる）
- レンダ出力 = STATE dir 隣の `renders/`。gate 提出はパス列挙で渡す
- command 封筒の session フィールドは周回名+工程名でよい
- **座標規約**: stage は y-down（+x=画面右・+y=画面下）。キーの符号は本規約 × パラメータ preset の意味論（例: eyeball.y は max=上視線 → max キーは −y 変位）で決め、周回初回のキー設計時に既知2部位の y 比較で機械確認する
- 実測 gen スクリプト（線芯・シルエット・差分計数等）も `<PKG>-notes/` 配下（素材差し替え後の決定論再キーの担い手）
- シートの所有範囲: 後工程が参照する基準値はシートへ、工程内で閉じる作業実測は都度巻尺（迷ったらシートへ追記）

## 3. 委任の切り方

- 1委任 = 1工程 or 工程内の1バッチ（コンテキストウィンドウ制約: 塔+キー+検証で1委任が相場。1周目実測: 40〜100 tool uses / 委任）
- 工程0 の分担: クリーン Fable が受け、大量列挙（目安: drawable 100超）のみ opus へ孫委任。解決表の曖昧判定は Fable が持つ
- 委任文の骨格: 身分（第N代）・呼び出し元 L0・最終テキスト=データ / 読み順（問題定義 or 工程指示 → design-notes → craft 遅延ロード）/ CLI 実行手段1行 / 封じ込め verbatim / 規律パック / 停止条件 / 報告様式（判定・op 数・検証証跡・レンダパス・craft への示唆）
- **設計ノート（L0 が委任前に書く）**: 場の式・実測定数・検証の合否基準を一字一句で。「式の解釈に迷ったら選ばず停止」を明記（L0 誤訳対策）
- 委任の較正記録: 被験 L0 は**周回ローカル**（`<PKG>-notes/` 内の較正ログ）へ記帳し、周回後に research/delegation-calibration-log.md へ統合する（被験 L0 にも封印が適用されるため）。型: 第N代 / モデル / タスク / tool uses / tokens / 時間 / reject 数 / 停止・質問の質 / craft への示唆

## 4. gate 提出様式（定型）

1. sweep レンダ束（全身 + フォーカス、±端・中間。束が大きい工程はフォーカス主体・全身は代表に圧縮——判定の梯子の認知負荷保護）+ 差分局在の証跡
2. 機械 assert の結果一覧（何が構造保証済みか）
3. **残ダイヤルの明示**（ゲイン・κ・damping 等「あんたの好みで回す場所」を列挙）
4. 定型文: 「違和感があれば言語化してくれ。物理に翻訳する」——修正は視覚イテレーション予算1の一回勝負、以降は人間仕上げ/ダイヤル領分として引き渡す

## 5. 封じ込め（委任文へ verbatim 転記）

- `ref/` という名のディレクトリを読まない
- （2周目封印時）`discussion/model-authoring/closed-problems/` と `research/` を読まない。**例外**: 実行ランナー `closed-problems/01-eyeball-x/experiment/apply-op.mjs` / `run-batch.mjs` の読込・実行のみ合法（実行系コードであり答え値を含まない）
- rigging ワークスペースの git 履歴・ブランチを調べない。状態確認は `git status` のみ可（git log 禁止。レシピ00 完了チェックの「git log に baseline」は自分の commit コマンド出力の記録で代替する）
- エディタリポジトリのソースコードを変更しない
- 委任文に答え数値を書かない（実測シート・design-notes の参照で渡す）

## 6. 本書の較正（使う前に検証する）

工程単位の**空実行テスト**で具体性を較正する: クリーン Fable に「本書と craft だけで工程N の実行計画と質問リストを出せ」（計画のみ・op 不発行）。質問の一つ一つが記述の穴、質問ゼロ + 計画正 = 足りた、の判定。穴は本書を改訂してから実走に入る（書き戻しループの指揮書版）。

較正の原則: テスターの推測が妥当なら**推測どおりを正典化**する（クリーン Fable が自然に置く仮定 = 最小驚きの規約）。
