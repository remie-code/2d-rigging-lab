## 実行系の改善（2周目で追加）

- 連続 op は `closed-problems/01-eyeball-x/experiment/run-batch.mjs` を使う: batch JSON（op スペック列 + gitMessage）を渡すと、**basePackageRevision を manifest.json から自動充填**し、1 op = 1 git commit で流す。1周目の revision 手動追跡ミス（罠）を構造的に消した

## 全工程共通の原則

- **dry-run → 自動承認 → commit** の 2 段階が強制。reject は無傷（何も変わらん）——原因を調べ、設計を直し、再実行する。reject を失敗と数えるな、craft の発見源や
- **1 committed operation = 1 git commit**（作業ワークスペース側。巻き戻し単位）
- **数値は巻尺（inspectEvaluatedGeometry）から取る。画像の目測を数値に使わない**
- 判断点は ★ 印、ユーザーの目が要る点は【ユーザー gate】印。それ以外は決定論的に流してよい
- 各操作の `basePackageRevision` は直前の commit が返した `packageRevision`。ズレたら reject されるだけ（安全）

## 共有不変量

まだ独立ファイル化するほど溜まっとらん。現時点の種（レシピ内に埋込済み）:

- 振幅設計 = 白目と虹彩の幅差から導出（初出時）
- **視線の一致**: 眼球移動量は「視線」の属性であり「まぶた状態」の属性ではない。**同一パラメータに繋がる全表情セットの眼球は同じ振幅を使う**（半目で実証: 通常と同じ ±11 を採用、狭い眼窩の超過分はクリッピングが自然に処理）
- マスク効果の検証はピクセル差分か高倍率ズーム（低倍率目視は不可）
- 計測 bounds は rest=宣言値・変形時=頂点範囲で意味が違う
- **フェードは同形の二者の間でだけ**（2026-07-03 ユーザー実例で確定、同日精密化）: opacity 交代の**窓の全域**で、両状態は同じ形を追跡し続けなければならない（一点で一致では足りない——半透明で透ける側が静止していると二重像の違和感になる。両側に同じ輪郭へ向かう形状キーを打つ）。形の遷移は変形が済ませ、opacity は交代だけを担う。bbox 一致では不十分——「開口の消滅」など位相的な変化も変形側で完了させる。潰し先は次状態の線の芯に**重ねる**（下に置くと交代時に絵が跳ぶ）
- **区分線形写像の外挿はクランプ**: 格子行がアンカー帯域の外にある場合、端区間の傾きで外挿すると暴走する（×5 の傾きで最下行が +67px 飛んだ実例）。帯域外は傾き 1（平行移動の継続）で打ち切る
- **線の芯は画素の暗度重心で測る**: 線状アートの視覚的中心は bbox 中央ではない（2〜5px ずれ、ユーザーが知覚できる差）。テクスチャの行ごとに `Σ alpha×(1−luminance)` を取った重心行が芯。位置合わせの基準はこれを使う
- 出現側の opacity キーは、上位状態が描画順で完全に覆うなら不要（描画順が只で払う）。必要なのは覆いから食み出す状態の消失側のみ
- **隠蔽維持拘束**: rest で隠れている描き縁（髪の付け根など）は全キーでも隠れ続ける——破れると素材が浮遊物に見える。遮蔽層自身の弦縮みも露出に加算される（二重苦）。実装は縦プロファイルと独立の乗数 q(y)（詳細はレシピ06）
- **接触縁の所有権**: 二層が重なる場所の見た目は手前の層（知覚上の前後。描画順と食い違うことがある）が所有し、奥の層は接触帯で手前の field へ従属する。ただし**完全一致は従属の上限であって最適ではない**——外殻の物理差動を λ で残す（詳細はレシピ07）
- **拘束台帳（planning-gate の実体化）**: 同一 field に fix 2ラウンド以上 / 原理3つ以上が重畳したら、次の fix 前に全拘束の台帳を起草し、委任には全行を「保存/置換/意図的変更」の処置付きで積む。保存行は assert で drift 検出。人間補正が入った field への機械再生成は禁忌（詳細はレシピ07）
- **変位と縮尺の一致則**: ゲインは sin 系（変位）にのみ掛ける。cos 系（縮尺）は「変位から読み取られる実効角」の強度で入れる——矛盾すると破綻に見える（詳細はレシピ06）
- **付け根の並進を運ぶ（軸横断の不変量）**: 垂れ物・立ち付属物は付け根の変位を先端まで運ぶ。減衰させてよいのは回転性成分のみ——収束先を空間ゼロにすると軸ごとに別の絵（裂け/杭）で同じ誤りが出る（詳細はレシピ06）
- **式の形は場非依存・ダイヤルの値は場依存**: テンプレの場差し替え時（球面→回転等）は、各ダイヤル（境界行・遷移・標本行）の意味を実測で再証明する。y 一様な場では自由度が縮退して見えないことがある（詳細はレシピ06 重力テンプレ最終形）
- **場の符号反転線を跨がない**: 遷移帯が場の構造的特異線（回転場の pivot 高さ等）を跨ぐと逆向きの場が混ざり物理が逆転する。特異線は設計前に引けるので assert を機械化する（詳細はレシピ06）
