# Authoring Solvability Analysis

> LLM（Fable）によるモデル制作は現状なぜ不可能か、何が欠けているかの合意分析。2026-07-02 の Undine × ユーザー対話に基づく。このトピックの根本前提。

## 根本の問い

「Fable はワークスペースへのアクセス、ツールへのアクセス、ユーザーの知覚評価結果へのアクセスがあれば、それだけで 2D モデルを作成できるか？」

これが可解ならプロジェクトは API 整備のみで完了する。可解でないなら、欠けているものの建造がプロジェクトの本体になる。

## 合意された答え: 実用的に不可解

- 原理的には収束し得るが、実用的に破綻するタイプの不可解。
- 最小構成の Fable は盲目の彫刻家になる。数千自由度の連続空間（格子制御点 × keyform × parameter）に対し、フィードバックは 1 ラウンド数ビットの人間知覚評価（「頬の流れが変」等）のみ。
- これは**ユーザーが勾配になる**構図であり、収束までのラウンド数は人間の忍耐を桁で超える。またそのとき実質の作者はユーザーであり、Fable はノイズの乗ったアクチュエータに過ぎない。「Fable がモデルを作る」の定義を満たさない。

## 欠けている二つの器官

1. **内側の知覚ループ** — 操作結果（格子点を動かした結果がどう見えるか）を Fable 自身が安く高頻度に確認する経路。座標数値だけからは「頬骨が回って見えるか」は導出できない。内ループ（Fable: 操作→描画→自己判定を数百回）と外ループ（ユーザー: 質感 gate を数十回）の二層が必要で、最小構成は全てを外ループに畳んでいる。
2. **内在化された価値基準と手筋** — 完璧なフィードバックが返っても「次の一手はどの格子点をどれだけ動かすか」に答えるのは知識の側。Fable は概念知識（warp deformer とは何か、標準パラメータ体系）は持つが、「3/4 振り向きで頬のシルエットがどう変わるべきか」という暗黙知との間に断層がある。

## 可解性の境界

- 最小構成でも到達可能: **構造的に妥当な（壊れていない）パッケージ**。スキーマ準拠・Validate 通過まで。
- 最小構成で不可能: **「良い」モデル**。
- 二器官を装備しても成功は保証されない。残る中心的未知は「**描画されたコマ列に対する Fable の視覚弁別力が、keyform の良し悪しを判定できる粒度に達しているか**」。これは議論では決着せず、実測でのみ決着する（→ 第一閉問題が最小投資の実測を兼ねる）。

## ユーザー側の不可解性

- 「可解であるか」の問いはユーザーにも適用される。ユーザーは「2D rigging とは何たるか」の粒度で正解を定義・言語化できない（人間の認知負荷限界。観点は必ず漏れを含み、言語化できないものも含む）。
- この帰結として「ref を複数姿勢で描画したもの + 意図的に壊した変種による弁別テスト」案は**棄却**された。採点基準の準備コスト自体が最難問の先取りになるため、理論上成立するが現実に不成立。
- ただし**範囲を区切れば可解に近づく** — これが閉問題アプローチの動機（→ [closed-problem-approach.md](closed-problem-approach.md)）。
