# Model Allocation Policy

> Fable トークンをどこに使うかの配分合意。2026-07-02 合意。

## 制約（Fact）

- Fable の利用は **2026-07-07 までに制限**され、かつ **weekly limit の半分まで**しか使用できない。貴重な消耗資源として扱う。
- Fable のサブエージェント委任（Agent ツール）は呼び出しごとにモデル指定が可能: `sonnet` / `opus` / `haiku` / `fable`。優先順位は「呼び出し時指定 > エージェント定義 frontmatter > 親から継承」。
- **罠**: Sylph / Gnome のエージェント定義は意図的に `model` frontmatter を省略している（縛らない方針）ため、**無指定の委任は親モデル = Fable を継承し、Fable 枠を消費する**。委任のたびにモデルは意識的に決める。

## 配分原則（Accepted）

1. **弁別力実験そのもの = 絶対に Fable。** 本挑戦の中心的未知は「Fable の視覚弁別力が足るか」であり、視覚判定を別モデルに代替させると測定対象が消え、実験が無効になる。代替不能な支出。
2. **ユーザーとの対話・設計・調査の設計と統合・craft 蒸留 = 原則 Fable。**「開発の大半は対話が占める」方針の主戦場であり、判断基盤（L0 コンテキスト）はここに宿る。
3. **調査・実装の委任（L1 以下）= 原則 Fable 以外**（opus / sonnet / haiku）。implementation-orchestration の中間層構造は、コンテキスト保護と同時に**予算保護**としても機能する。Gnome の実装 wave も同様。

## 調査モデルの選定基準（Accepted）

「調査は安いモデルで」という一般論は粗すぎる。次で切り分ける:

- **機械的列挙**（ファイル探索、export 洗い出し、operation ID 追跡）: 判断負荷が低く、出力（パス・引用）が統合時に安く検証可能 → 中位以下で足る。高いモデルは過剰投資。
- **解釈的調査**（成立性の見立て、ギャップの特徴づけ、「問われていないが重要なこと」への気づき）: 危険は事実誤認ではなく**沈黙の失敗**（訊かれたことにだけ答え、訊くべきだったことを落とす）→ 上位モデル。
- 危険な組み合わせは「**曖昧な問い × 安いモデル**」。問いの狭さ・証拠要求・「問いの外の気づきも報告せよ」の明示など、委任設計が締まるほど実行側の判断負荷は下がる。設計と統合は L0（Fable）が持つ。

## planning-gate への拡張（Accepted）

- 本課題の planning-gate では、Delegation plan の各委任に**使用モデルを明記し、選定理由を添える**ことを検討対象に含める。

## 較正ループ（Accepted）

- 委任のたびに L0 が報告品質（証拠の精度、問いの外への気づき、見落とし）を採点・記録し、tier 選定を実測データで更新する。
- 第 1 回較正: Sylph A（操作面の追跡 = 機械的列挙寄り）= `sonnet`、Sylph B（知覚経路の存否と見立て = 解釈的寄り）= `opus`。
