# Operating Policies (Model Authoring)

> Fable がモデル制作を行う際の運用合意。2026-07-02 合意。

## ヘッドレス専有運用（Accepted）

- Fable は deterministic API 経由の**ヘッドレス操作**で作業する。制作セッション中は**ディスク上のパッケージが唯一の真実**。
- 役割分担: **Fable が作業し、ユーザーは見て確認する**。エディタ GUI がメモリ上に未保存状態を持つ横で Fable が同時に触る運用はしない（desync 防止）。この分担は運用として守られなければならない（ユーザー決定）。

## Git による巻き戻し（Accepted）

- 手戻り機構は Git を用いる。パッケージは非バイナリ JSON 群としてディスク上で自己完結しており、`operations/log.jsonl` / packageRevision もパッケージ内にあるため、**パッケージディレクトリごとアトミックにコミットすれば**巻き戻しても内部整合が崩れない。
- コミット粒度（例: 検証を通過した状態ごと）は**未決**。実運用開始時に規約化する。

## 判定の梯子（Accepted）

安い層で落とせる失敗は安い層で落とす。上の段ほど高コスト。

1. スキーマ整合（ツール）
2. 構造 lint / Validate（ツール既存機能。API 整備に含まれる）
3. 静止画レンダリングの自己判定（Fable）
4. コマ列（コンタクトシート）による幾何判定（Fable）— 軌跡の破綻、変形の連続性、めり込み、対称性
5. **動きの質感 gate（ユーザー）** — タイミング、イージング、揺れの「生きてる感」

ユーザーの注意力も有限資源として同じ保護原理で扱う。Fable の梯子を通過したものだけを段 5 に持ち込む。

## Fable の知覚能力（Fact — 自己申告）

- 静止画像（PNG 等）は読める。**動画は読めない**。アニメ GIF は実質先頭フレームのみ。
- 従って動き知覚の上限は**パラメータスイープをコマ列グリッド画像に焼いたもの**。
- コマ列で判定できるのは幾何の問題（上記 段 4）。**時間の質感は原理的に判定不能**であり、段 5 のユーザー gate は妥協ではなく構造的必然。

## 素材とスコープ（Accepted）

- 素材はユーザー所有の PSD。ツールの PSD 読み込みで editable な状態になる。
- **Fable の仕事はリグ（構造）**であり、原画制作はスコープ外。

## ref/ の位置づけ（Accepted）

- ワークスペース直下 `ref/` は実際に配信で使われ問題なく動いた実モデル（open-model-package-v1）。
- **ref は採点器ではなく教材**。数値 diff で測れるのは「再現度」であって「良さ」ではない（同じ数値を別の原画に貼れば誤りになる。ref の値はある一枚の絵にエッセンスを適用した一実例に過ぎない）。
- 抽出すべきは**不変量**（メッシュ密度と変形需要の関係、物理係数と質量感の対応、など）。
- ref の参照範囲は閉問題ごとにスコープする（情報量が多すぎるため、閉じた問題設定が「今どこを見るか」を規定する）。
