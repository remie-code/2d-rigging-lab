# 参照画像からデフォーマへ

## 合意した流れ（成立は未実証）

1. **元絵と参照画像の位置・大きさを合わせる。** Canvasの違いを運動として拾わない。Face-X試作では変位させない身体の特徴を基準にし、顔・帽子・髪を位置合わせの固定点にしない。全体の等方スケールと平行移動から始め、回転・縦横独立拡縮・局所変形は必要性がわかるまで加えない。
2. **正面→中間、中間→最大の順で対応を推定する。** 2026-09-25、ユーザーの指摘と後続のOKにより、まず隣接画像間のフローを試す方針へ変更。目頭/目尻、鼻、顎、眼鏡の橋、帽子や髪の特徴点を可視化して誤対応を見つける。隣接画像は変化が小さく対応を取りやすい可能性がある一方、誤差の蓄積もありうる。どちらも今回の画像では未実証。必要に応じて正面→最大の直接推定と比較する。
3. **パーツごとの格子へ当てはめる。** 画像上の各点を目標位置へ動かすよう、格子点の変位をまとめて求める。滑らかさ・格子の折り返し等は診断や調整の参考にし、数値的最適化の終了を見た目の合格にしない。
4. **中間と最大を別々のキーとして持つ。** 正面を共通のrestとし、中間・最大それぞれの正面基準の変位を記録する。最大への対応は隣接フローを合成して導くため、推定誤差まで独立になるという意味ではない。区間内の補間が自然かは実際の描画で見る。
5. **実際のrendererで元素材を動かし、比較する。** 元絵・参照・rig表示・格子を並べ、ズレの原因を参照/対応/格子/素材/合成に切り分けて修正する。

## 設計上の区別

画像全体で得た可視面のフローを、同じ座標の全レイヤーに適用してはいけない。前髪、顔、眼鏡、後ろ髪は重なり、同じ画素で見えているのは一つの面。PSDのパーツ情報と可視性を使い、隠れた面の対応は別扱いにする。

「変形は情報を潰せるが発明できない」。新しく見える面は対応の推定だけでは素材にならない。素材追加・表示の切り替え・遮蔽の扱いが必要となりうる。どれを使うかは未決。

既存の目・口の局所rigとFace-Xの上位変形を共存させる。既存Face-X変位との二重適用や、親子warpの合成を推測で済ませず、実際の評価器で確かめる。

## 隣接フローの合成（2026-09-25合意）

正面の点pが中間でq = p + F01(p)へ移るなら、最大の位置はr = q + F12(q)。正面基準の最大変位はF02(p) = F01(p) + F12(p + F01(p))。同じ座標pの二つの矢印を単純加算しない。途中の対応先で次のフローを評価し、遮蔽や画像外への移動で対応が切れる箇所は不確実なものとして扱う。フローのforward/backward方向、画素座標系、リサイズ倍率を揃える。

次に取り組む単位は隣接フローの試作と可視化。格子への当てはめと実際のrig適用は後続工程。現時点で推定器・学習済み重み・解像度・マスク・信頼度の具体的方式は未選定。
