# Body X・Zの制作で得た教訓

2026-09-27。通常衣装の制作結果とユーザー判断を、craft v2へ蒸留するためのメモ。一般的な人体法則や、すべてのキャラクターで成立する処方とは区別する。

## 到達点とユーザー判断

- Face X/Y/Z、Body X/Zの両方向の姿勢造形が揃った。Body-Xは首追従を撤回したrevision1330、Face-Zはrevision1820でユーザー承認。これらを継承したBody-Zの現行保存モデルはrevision1967。
- Body-Z正側はrevision1922を承認。反対側revision1967の提示後、ユーザーは「初めからこうすればよかったな」「これでriggingはおおむね終わったかな」と受領した。本記録ではBody-Z両側の外観受領として扱う。
- この到達点は通常衣装の姿勢変形についてのもの。全機能の技術検証、全表情・別衣装・物理揺れとの網羅確認、最新版Runtime Exportの完了は意味しない。

## Body X：参照の形から、素材が自然に表現できる範囲を作る

### 実際に行ったこと

1. 旧SolのBody-Xデフォーマとキーを外し、Face X/Yを保持したまま独立したBody-Xの構造を作った。
2. 生成参照をユーザーと確認し、root自身が胸・襟・ネクタイ・袖口・腰・髪などの対応を読んだ。対応座標を滑らかなTPSで格子点変位へ展開した。RAFTは使っていない。
3. 当初の強い振り向きでは、胸の陰影・面の見え方に無理が出た。ユーザーは正面素材を大きく回す限界と判断し、弱い参照に切り替えた。
4. 新しい最大姿勢に対して各パーツを読み直して造形。旧変位に共通倍率をかけただけではない。反対側も参照を読み、個別に制作した。
5. 首を襟へ追従させた処理はユーザー指摘で撤回。参照では首の線はほぼ定位置で、動くのは手前の襟・衣服だった。首用Body-Xデフォーマ自体を削除した。

### 再利用したい判断

- 参照画像は生成できても、その姿が正面素材の変形だけで自然に表せるとは限らない。胸の面・陰影などで無理が出たら、目標の変位量そのものを見直せる。
- パーツは「同じ変形を受ける範囲」で分ける。見た目の部位名だけで首・襟・胴体を一括追従させない。
- 首と襟の接続問題は、どちらの線が実際に動くか、どちらが重なって隠れるかを分けて読む。隙間を隠すために参照にない首の移動を足さない。
- このモデルのBody-X値±10はパラメータの範囲であり、実測のyaw角10°を保証する値ではない。
- 中間キー±5は最大変位の半分として制作した。独立した中間参照の再現ではないため、途中姿勢は実描画で確認する。

詳細：[Body-Xの制作記録](body-x-reference-rig.md)。

## Body Z：回転を土台に、重力へのなじみを追加する

### 実際に行ったこと

1. 旧Body-Z構造を撤去し、腰付近を支点とする回転デフォーマを作った。ユーザーが実際の回転表示から最大10°を選んだ。
2. 体を傾けたときの自然な髪・腕・ネクタイ・服を参照として確認。全体回転は維持し、その内側の部位別ワープで重力へのなじみを補正した。
3. 前の房が伸びて見えたため、参照自体をZ=0と同じ長さの印象へ修正し、その後rigを短くした。生成参照にも誤りがあるため、参照の形を無条件に正しいとはしない。
4. 反対側の参照生成は、髪形の変化や不自然な服の接続を繰り返した。ユーザー判断で生成を打ち切り、承認済みの片側参照・rigを手がかりに反対側を直接制作した。
5. 反対側は既存の非対称なDrawableを保持。正側の変位場を左右の対応する部位へ反映して初期値とし、実描画で髪・リボン・房の長さ・裾・腕・ネクタイを確認した。完成画像そのものを反転して素材にしたわけではない。

### 再利用したい判断

- Zはまず回転デフォーマで角度を決めるのが有効。姿勢全体を最初からワープだけで作る必要はなかった。
- 重力に沿う動きは、房の形・長さ・分かれ方・重なりを保った上での向きの変化。強いS字への描き替えや房の伸長は、髪形を変えてしまう。
- 生成へ渡す回転rigは角度の手がかり。回転によって生じた隙間や輪郭まで固定条件にすると、不自然さを保存してしまう。今回の脇腹では、上半身とスカートの接続の無理を「座標を保つ」指示で固定していた。
- 自然な姿の生成が必要なら、正面の元絵から始め、衣服の連続性や姿勢全体が成立する余地を残す。「元の髪形・服装を保つ」と「すべての画素位置を保つ」は別。
- 反対側の生成は必須工程ではない。片側の成功例から自然な挙動を理解できるなら、同じ素材に対して反対側を直接造形し、左右の非対称性を実画像で確認する方が速く安定する場合がある。今回はこちらが成立した。Body-Xのような新しい面の見え方にも無条件で適用できる、という結論ではない。
- 体の回転に対する静的な補正と、時間的に揺れる物理は別工程。

### 実装の要点（今回のモデル）

- 回転：`rig_oracle_body_z_upper`、支点はstage座標(998,1160)、キーは−10/0/+10°。stageは2048×3072、比較画像は1024×1536。
- 補正：`rig_oracle_body_z_settle_*`の11ワープ。前髪、前の房2、後ろの長い髪2、上側の髪2、袖＋手2、ネクタイ、シャツ。各軸の既存サブツリーを包み、Face X/Y/Z・Body Xのキーと分離。
- 正側の補正キーは0/2.5/5/7.5/10、負側は−2.5/−5/−7.5/−10を追加。ワープは回転の内側なので、画面上で意図した変位ベクトルをそのBody-Z角度の逆回転で親座標へ戻して格納する。
- 負側の初期値は、正側最大キーを画面上の変位へ戻し、左右を対応付けた部位の格子で反射位置を双線形サンプリングし、横成分を反転。その後、負側回転の内側へ戻した。元パーツの形状・左右の装飾はそのまま。
- これは今回の静的な造形手段。全軸合成に対する厳密な重力シミュレーションや長さ保存ソルバではない。

## 確認と残件

- 比較は同位置・同倍率で切り替え、単独最大だけでなく途中姿勢・正面へ戻る動き・代表的な他軸合成を見る。数値は制作と保持確認の参考であり、自然さの合格条件にしない。
- 負側の追加では11姿勢とFace X/Y/Z・Body Xの8複合端点を描画。正側の既存キー、他軸キー、デフォーマ構造を保持し、Z=0の画素一致も確認した。
- 今回の完成範囲：通常衣装のFace X/Y/Z・Body X/Zの主要な姿勢造形。Body Yは今回の対象として制作していない。
- 残る完了確認：現行保存モデルをEditorで通して操作すること、表情・まばたき・口・物理揺れ・別衣装との最終確認、現行revisionでの技術検査とRuntime Export。既存機能がないという意味ではなく、今回の最終状態で確認済みとはしていない。
- 旧Solの`runtime-export`はrevision690の成果物であり、今回のrevision1967を含まない。過去にstrict検証のfailが記録されているが、現行revisionの結果として転載しない。再検査が必要。
