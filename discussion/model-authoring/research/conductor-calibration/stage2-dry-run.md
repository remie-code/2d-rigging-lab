### バッチA: 眼球X→Y + 白目クリッピング（レシピ02・03 + 06末尾統一原理）

A1. **巻尺**: 白目L/R・虹彩L/R（通常セット+半目セット）の rest bbox を `inspectEvaluatedGeometry` で取得し、実測シートの実頂点範囲列と照合 assert（ズレ=工程1以後の意図せぬ変更の検出）
A2. **設計値導出**: T =(白目.width−虹彩.width)/2（左右差は大きい方基準の対称値）、s=0.92。Y転置: T_y =(白目.height−虹彩.height)/2（推測・質問2）、s_y=0.92 転用（推測・質問3）
A3. `createWarpDeformer` ×2（Eyeball L/R Warp）。domain = 白目 bbox を X 振幅+マージンで拡張（Y を同一ワープに畳む場合は縦も +2T_y 拡張——構造は質問1の裁定待ち）。5×4 格子。commit 後 `<PKG>/model/rig-controls.json` から restControlPoints 20点を読む
A4. `editKeyformKey` `createEndsCenter`、param_eyeball_x、`controlPointOffsets` 畳み込み: offset(p)={x: T_key+(s−1)(p.x−cx), y:0}、min=−T/default=0/max=+T。value 要素数=格子点数 assert。**translation は打たない（warpLattice2d では reject される罠）**。**createParameter は発行しない**（preset 常在、duplicateParameter 罠）
A5. **眼球Y（1周目未実証・初実証扱い）**: 統一原理の狭域近似=純平行移動の Y 転置。offset(p)={x:0, y: T_y_key+(s_y−1)(p.y−cy)}、min(下視線)/max(上視線) の符号は 2.0-3 の +y 判定に従う。実装構造は仮置きで「Y 専用ワープを `wrapChildren` で X ワープの外側に新設」（レシピ06 の既存塔挿入様式。挿入後は**既存機能=X 移動の回帰レンダ必須**）——同一ワープへの2パラメータ keyform set 加算合成が文書上未保証のため（質問1）
A6. **半目セットの虹彩にも同構造を再適用**（レシピ05 前提「半目眼球デフォーマ」+ 共有不変量「視線の一致」: 同一パラメータに繋がる全表情セットは同じ振幅 ±T・±T_y。眼窩超過はクリッピングが刈る）
A7. `setMaskRelation`: eyewhite→irides 片眼ずつ、通常×2 + 半目×2 = 4リレーション。selfMask・空リレーションは reject
A8. **検証（機械 assert）**:

A9. ★視覚: sweep steps:5 コンタクトシート（-1左寄り/0 rest/+1右寄り、両眼同期）を自分の目で確認。Y も同様

### バッチC: 口パク（レシピ09）

C1. **シルエット実測**: mouth_a（最大情報素材=全開「あ」）・閉じ参照・母音参照 i/u/e/o の**メッシュ境界**を `inspectEvaluatedGeometry` includeVertices で取得（**非表示のまま測る**）。口角=水平極値、列プロファイル=水平 N 帯の y_top/y_bot（N は質問11）、3点移動平均で平滑化。一時表示→フォーカスレンダ→非表示の op 往復は目視照合用のみ（合成レンダは肌が写るため数値の正にしない）
C2. **塔の構築**: 工程2時点で追従塔は未存在（工程3が外から包む）ので MouthOpen を最外に独立で建てる（質問20）: `MouthOpen ワープ ⊃ 母音ワープ i/u/e/o（直列入れ子・順序は仮置き）⊃ mouth_a`。あ は rest と同形なのでワープ不要・param_mouth_vowel_a にはキーを打たない（質問10）
C3. **MouthOpen キー**: キー1=恒等（rest=全開）/ キー0=閉じシルエットへの**純変形**潰し。2段写像: (1) 口角アフィン u=(x−x_L^B)/(x_R^B−x_L^B)→x'=x_L^T+u·(x_R^T−x_L^T)、(2) 列ごと縦 v 対応、帯域外（v<0/v>1/口角外)は最寄り縁デルタの平行運搬。statePatch=(x',y')−rest。**潰し場は高曲率**——格子は数値 gate（±2px）が決める。初期値 25×23（1周目実測の通過値・質問12）
C4. **母音キー**: 各母音ワープに param_mouth_vowel_* の 0=恒等 / 1=母音シルエットへの同形式 morph
C5. **検証**: プロファイル残差（列平均≤3px・最大≤6px）/ 潰し高さ≤閉じ参照+2px / rest 差分の口領域局在（「cp14 手続き」の中身が封印下で参照不能——差分画素 bbox が口領域内に収まる確認と推測・質問13）/ **既存キー無傷**（バッチA/B の keyform JSON 恒等 or 巻尺再照合）/ default レンダの画素変化は方式の帰結（open=0 で潰し口）なので 0キー恒等 sha は**目系のみに適用し口は差分局在で代替**（質問8）
C6. 残差 gate 不通過なら格子解像度を上げて再キー（gate 駆動）。崩れの一次対応が素材品質なら素材更新=ユーザー領分へエスカレーション

## 3. 質問リスト（指揮書+craft だけでは決められない点。推測仮置きは明記）

**眼球Y（1周目未実証の初実証——質問が集中するのは構造的に当然）**

1. **Y の実装構造**: 同一ワープデフォーマに param_eyeball_y の第2 keyform set を追加するのか、Y 専用ワープを `wrapChildren` で入れ子新設するのか。同一 rigControl 上の複数パラメータ keyform set が加算合成される保証が craft のどこにも書かれていない。【推測で仮置き: 別ワープ入れ子（レシピ06 の既存塔挿入様式が文書化済みのため安全側）】
2. **T_y の導出式**: X の類推で (白目.height−虹彩.height)/2 と仮置きした。ただし縦方向は上下まぶたの遮蔽が支配的で、幅差由来の式が縦にそのまま転置できるかは審美判断を含む。半目セットにも同 ±T_y を打つ（視線の一致のパラメータ単位適用）でよいか
3. **s_y（縦 squash）**: X の 0.92 を転用してよいか。遠近 squash の物理的根拠が縦方向で同じかは未実証【推測で仮置き: 0.92 転用】
4. **stage +y の画面方向**: レシピ02 は「stage +x = 画面右」のみ規定し、+y の向きが craft に無い。param_eyeball_y は min=下視線/max=上視線（preset 実読で確認）なので符号を間違えると視線が上下反転する。【推測で仮置き: 既知2部位の y 値比較で機械判定して自前で確定——指揮書に規約1行あるべき】
5. **X ワープ domain の Y 対応**: 単一ワープ案を採る場合、レシピ02 の domain 設計（縦マージン5px）は Y 移動 T_y を包含しない。domain 式の Y 拡張版が要る（別ワープ案なら不要）
6. **まつげ bbox の採寸リスト所属**: 指揮書工程0の採寸リスト（頬幅・白目・虹彩・pivot 候補）に開/半/閉まつげ bbox が無い。実測シートが「全数値の唯一の出所」なら工程0 リストへ追加すべきか、それとも「正典値=不変の基準のみシート、工程内の作業実測は都度巻尺」という線引きか。**シートの所有範囲の規約が未定義**

**素材・解決表まわり**

7. **状態素材の左右一体ケース**: レシピ05 は左右別パラメータ（left/right_open）前提で片目3基×2。半目/閉じ素材が左右一体1枚だった場合の分岐が craft に無い。素材マニフェストの要求仕様として「左右別」を明記すべきか
8. **0キー恒等 sha の適用範囲**: 指揮書工程2出口の「0キー恒等 sha」は、口が default open=0 で rest 画素が変わる（方式の帰結、レシピ09）ため工程2全体には適用できない。【推測で仮置き: 目系=sha 恒等、口=差分の口領域局在で代替。指揮書の出口条件に1行の明文化が要る】

## 5. 自己判定

**穴があり条件付き**。工程の骨格・op 列・検証 assert は craft から一意に組めた（レシピ02/03/04/05/09 の自己完結性は高い）。ただし (1) 眼球Y の実装構造（Q1）と符号規約（Q4）は初実証ゆえ裁定なしに op を発行できない、(2) 「cp14 手続き」参照（Q13）は封印下で実行不能な craft の穴、(3) 0キー恒等 sha の適用範囲（Q8）と可視旗返却（Q14）は出口条件の明文化不足——この4点はユーザー/L0 の裁定か指揮書改訂が無いと実走で停止する。残る質問は推測仮置きで前進可能（最小驚きの規約として正典化候補）。
