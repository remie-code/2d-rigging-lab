# シナリオ: Mesh Structure

> 参照元AC: [203_Mesh_Structure.md](../../acceptance-criteria/02_DomainAcceptanceCriteria/203_Mesh_Structure.md)
> 状態: 粒度確認用ドラフト

## 0. このドラフトの目的

このファイルは、`AC-MESH` を「人が Cubism Editor で ArtMesh とメッシュを準備・編集・検証するときの操作粒度」まで降ろした場合、Undine がどの程度のシナリオを書けるかを確認するための試作である。

ここでは、Cubism Editor の画面構成や内部データ構造を模倣することを目的にしない。ただし、Cubism Editor での参照操作を明示し、その操作によって成立している制作能力を Open Editor の検証可能な期待結果として書く。

## 1. 公式事実

- Live2D Cubism では、PSD 画像をモデルワークスペースに読み込むと、各レイヤーまたはグループにメッシュが自動的に割り当てられ、キャンバス上の ArtMesh として配置される。ArtMesh は、テクスチャに頂点と線で構成されるポリゴン集合を割り当て、頂点を動かすことで画像を変形して表情や動きを作る。
  参照: [About ArtMeshes](https://docs.live2d.com/en/cubism-editor-manual/concept-of-artmesh/)
- Cubism の ArtMesh は、配置直後はデータ量を抑えるため最小限の頂点で構成される。必要に応じて、変形したい画像に合うように詳細編集できる。
  参照: [About ArtMeshes](https://docs.live2d.com/en/cubism-editor-manual/concept-of-artmesh/)
- メッシュ編集には、自動生成と手動編集がある。自動生成では点の密度などの値を指定して ArtMesh のメッシュを生成でき、手動編集では点を1つずつ打って編集できる。
  参照: [Automatic Mesh generator](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit/), [Edit Mesh manually](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit-manual/)
- 手動編集では、頂点追加、頂点や辺の削除、辺接続、自動接続などを使う。メッシュは三角形ポリゴンの集合であり、構築するには頂点が辺で接続され、最小単位が三角形になる必要がある。
  参照: [Edit Mesh manually](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit-manual/), [Mesh Edit mode menu](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit-menu/)
- 選択した ArtMesh の頂点は、移動、回転、拡大縮小によってテクスチャを変形できる。ArtMesh やデフォーマの頂点を選択すると、インスペクタでキャンバス座標を確認・編集できる。
  参照: [How to edit](https://docs.live2d.com/en/cubism-editor-manual/how-to-edit/), [Edit Vertices in Canvas Coordinates](https://docs.live2d.com/en/cubism-editor-manual/edit-vertices/)
- パラメータにキーを追加すると、変形の形状をキーフォームとして登録し、モーションに適用できる。
  参照: [Add/Delete Keys to/from parameters](https://docs.live2d.com/en/cubism-editor-manual/edit-parameters/)
- テクスチャアトラス編集では、ArtMesh の重なりやフレームからのはみ出しを検出できる。メッシュ編集後は、周辺 ArtMesh との重なりやテクスチャアトラスからのはみ出しに注意する必要がある。
  参照: [Edit Texture Atlas](https://docs.live2d.com/en/cubism-editor-manual/texture-atlas-edit/)

## 2. シナリオ記述方針

各シナリオは、次の2層を分けて書く。

- Cubism参照操作: 人が Cubism Editor で行う実用操作を、手順が再現できる粒度で書く
- Open Stack期待結果: このプロジェクトの Open Editor が、UI模倣ではなく同等の制作能力として満たすべき観測・編集・保存・検証結果を書く

また、各シナリオは `Given / When / Then` の形にする。

- Given: 初期状態、対象 ArtMesh、制作上の制約
- When: Cubism参照操作
- Then: Open Stack期待結果

データモデル、永続化形式、API、画面I/Fの具体設計はこのファイルの範囲外とする。期待結果は、後続設計で検証可能にするべき能力として記述する。

## 3. 仮説

- Open Editor でも、Cubism の ArtMesh に相当する「テクスチャ画像とメッシュが結びついた描画単位」を扱う。名称は後続設計で変更される可能性がある。
- ここでの「面」は、Live2D 公式ドキュメントで説明される三角形ポリゴンを基本にした検証対象として扱う。
- 「不自然な折れや潰れ」の定量閾値は、現時点では未定である。このドラフトでは、制作時に検出・説明できるべき品質観点として扱う。
- Open Editor がメッシュ品質を自動判定する場合でも、最終的な修正方針を自動適用するか、人が確認して適用するかは未決である。

## SC-MESH-001: PSD由来の眉レイヤーをメッシュ付き描画単位として扱える

### Given / 前提条件

- PSD から取り込まれたモデルが読み込まれている。
- 左眉に相当する描画要素 `Brow_L` が存在する。
- `Brow_L` は、まだ制作上の詳細変形を追加していない初期配置状態である。

### When / Cubism参照操作

1. `Brow_L` を選択する。
2. キャンバス上で、`Brow_L` のテクスチャ、メッシュ線、頂点を表示する。
3. 選択ツールで `Brow_L` の1頂点を少し上へ動かす。
4. `Brow_L` 以外の眉、目、肌パーツが同時に変形していないことを確認する。

### Then / Open Stack期待結果

- `Brow_L` は、テクスチャ画像だけでなく、頂点、辺、面を持つ変形可能な描画単位として扱われる。
- `Brow_L` のメッシュは、対象テクスチャと対応していることを観測できる。
- `Brow_L` の1頂点を動かした結果、`Brow_L` の画像だけが局所的に変形する。
- `Brow_L` 以外の描画要素は、明示的な親子関係や制御関係がない限り、この頂点編集では変形しない。
- 編集前後の差分として、対象描画単位、変更された頂点、隣接する辺と面、テクスチャとの対応関係を確認できる。

### 検証するACの項目

- AC-MESH-001: メッシュ付き描画単位を扱えること

## SC-MESH-002: 前髪ArtMeshに自動生成メッシュを割り当て、変形に必要な分割を増やせる

### Given / 前提条件

- 既存モデルが読み込まれている。
- 前髪に相当する ArtMesh `HairFront_L` が存在する。
- `HairFront_L` は、PSD 取り込み直後に近い粗いメッシュで、髪先の曲線に沿う頂点が不足している。
- 透明度の低い不要なゴミ領域が、髪先付近に残っている可能性がある。

### When / Cubism参照操作

1. `HairFront_L` を選択する。
2. `[Automatic Mesh generator]` を開く。
3. `Deformation (large)` に相当する細かめの設定を選ぶ。
4. 外側と内側の点間隔、境界マージン、透明とみなすアルファ値を調整する。
5. 自動生成を実行する。
6. 髪先の輪郭に沿って頂点が増え、不要な透明ゴミ領域がメッシュ範囲に含まれていないことを確認する。

### Then / Open Stack期待結果

- `HairFront_L` に、変形可能な描画単位としてのメッシュが割り当てられる。
- 自動生成の結果、髪先の曲線や細い領域に追従できる程度に頂点と面が増える。
- 不要な透明ゴミ領域は、制作意図に反するメッシュ範囲として扱われず、必要に応じて除外または警告対象として確認できる。
- 自動生成後も、`HairFront_L` と元テクスチャの対応関係は維持される。
- 頂点数、面構成、境界付近の余白、描画要素との対応関係を検証できる。

### 検証するACの項目

- AC-MESH-001: メッシュ付き描画単位を扱えること
- AC-MESH-002: メッシュを編集できること
- AC-MESH-004: メッシュ品質を検証可能であること

## SC-MESH-003: 口角ArtMeshを手動編集し、細かな変形に耐える三角形メッシュを作れる

### Given / 前提条件

- 既存モデルが読み込まれている。
- 右口角に相当する ArtMesh `MouthCorner_R` が存在する。
- `MouthCorner_R` は、笑顔や口開閉で大きく曲がるが、現在のメッシュは頂点数が少なく、口角の折れ目を表現しにくい。

### When / Cubism参照操作

1. `MouthCorner_R` を選択する。
2. `[Edit Mesh manually]` でメッシュ編集モードへ入る。
3. 口角のしわ方向と輪郭に沿って頂点を追加する。
4. 不要な頂点または辺があれば削除する。
5. 自動接続または手動接続で、四角形以上の不安定な面を三角形に分割する。
6. 追加した頂点を少し動かし、口角の曲がりに追従することを確認する。
7. メッシュ編集を終了する。

### Then / Open Stack期待結果

- `MouthCorner_R` の頂点配置を、制作意図に合わせて手動編集できる。
- 追加・削除・接続後のメッシュは、頂点が辺で接続され、面の最小単位が三角形として扱える状態になる。
- 口角の折れ目や輪郭に沿った頂点配置を保持できる。
- 頂点を動かしたとき、口角のテクスチャが意図した方向に変形し、隣接しない領域へ不自然に引っ張られない。
- 編集後の頂点数、辺の接続、面構成、孤立頂点や未接続辺の有無を確認できる。

### 検証するACの項目

- AC-MESH-002: メッシュを編集できること
- AC-MESH-004: メッシュ品質を検証可能であること

## SC-MESH-004: 眉の上下変形をパラメータのキーフォームとして保持できる

### Given / 前提条件

- 左眉に相当する ArtMesh `Brow_L` が存在する。
- `Brow_L` は、頂点を編集して眉の上下変形を作れるメッシュを持っている。
- パラメータ `ParamBrowLY` が存在し、値域は `-1`, `0`, `1` を含む。

### When / Cubism参照操作

1. `Brow_L` を選択する。
2. `ParamBrowLY` に3点のキーを追加する。
3. `ParamBrowLY = -1` で、`Brow_L` の頂点を下げて困り眉形状を作る。
4. `ParamBrowLY = 0` で、元画像に近い中立形状を確認する。
5. `ParamBrowLY = 1` で、`Brow_L` の頂点を上げて驚き眉形状を作る。
6. パラメータスライダーを `-1`, `0`, `1` の間で動かし、各形状が再現されることを確認する。

### Then / Open Stack期待結果

- `Brow_L` のメッシュ形状変化を、パラメータ値に結びつくモデル状態として保持できる。
- `ParamBrowLY = -1`, `0`, `1` の各状態で、同じ ArtMesh に対する異なる頂点位置を再現できる。
- パラメータ値を切り替えたとき、対象外の ArtMesh は明示的な関連付けがない限り変形しない。
- 元画像に近い中立形状と、上下に変形したキーフォームを区別して確認できる。
- パラメータに結びついたメッシュ変形が失われていないか、対象 ArtMesh とキーごとに検証できる。

### 検証するACの項目

- AC-MESH-003: メッシュ変形をモデル状態として保持できること
- AC-MESH-004: メッシュ品質を検証可能であること

## SC-MESH-005: ワープデフォーマによる目の変形を、ArtMeshの変形状態として確認できる

### Given / 前提条件

- 左目に相当する ArtMesh `EyeL_White`, `EyeL_Iris`, `EyeL_Highlight` が存在する。
- これらの ArtMesh は、それぞれ頂点、辺、面を持つ。
- 左目全体を動かすワープデフォーマ `Warp_EyeL_Smile` が存在する、または作成可能である。

### When / Cubism参照操作

1. `EyeL_White`, `EyeL_Iris`, `EyeL_Highlight` を選択する。
2. `Warp_EyeL_Smile` を作成し、選択した ArtMesh の親にする。
3. `Warp_EyeL_Smile` の制御点を動かして、笑顔時の目のカーブを作る。
4. 各 ArtMesh のメッシュ表示を確認し、白目、瞳、ハイライトが同じ目の動きに追従していることを確認する。
5. 必要に応じて `EyeL_Highlight` だけを選択し、局所頂点を微調整する。

### Then / Open Stack期待結果

- `Warp_EyeL_Smile` による変形結果を、配下の ArtMesh のメッシュ変形として確認できる。
- ワープデフォーマによる大きな形状変化と、`EyeL_Highlight` だけの局所頂点調整を区別して扱える。
- デフォーマを動かしたとき、配下 ArtMesh の頂点位置の見かけの変化を検証できる。
- ArtMesh 自体のメッシュ構成と、変形制御構造から受ける変形結果を混同せずに確認できる。
- 目を構成する複数 ArtMesh が、同じ制作意図に沿って追従しているかを確認できる。

### 検証するACの項目

- AC-MESH-001: メッシュ付き描画単位を扱えること
- AC-MESH-003: メッシュ変形をモデル状態として保持できること
- AC-MESH-004: メッシュ品質を検証可能であること

## SC-MESH-006: 変形時に破綻するメッシュを検出し、修正対象を説明できる

### Given / 前提条件

- 既存モデルが読み込まれている。
- 髪房に相当する ArtMesh `HairSide_R` が存在する。
- `HairSide_R` は長く細い形状だが、現在のメッシュは頂点数が少なく、髪先付近に長い三角形が集中している。
- `HairSide_R` には揺れ変形または顔角度変形のキーフォームが設定されている。

### When / Cubism参照操作

1. `HairSide_R` のパラメータまたはデフォーマを動かし、髪房を左右へ大きく曲げる。
2. 髪先付近でテクスチャが折れる、潰れる、または不自然に伸びる箇所を確認する。
3. メッシュ編集モードで、問題箇所の頂点数、辺の流れ、面の形を確認する。
4. テクスチャアトラス表示または配置検証で、`HairSide_R` のメッシュが周辺 ArtMesh と重なる、またはフレームからはみ出す状態がないか確認する。
5. 問題箇所に追加頂点や分割変更が必要かを判断する。

### Then / Open Stack期待結果

- `HairSide_R` のメッシュが意図した変形に耐えられるかを検証できる。
- 検証結果は、頂点数、面構成、変形時の破綻、不自然な折れや潰れ、描画要素との対応関係を含む観点で説明できる。
- 問題がある場合、どの ArtMesh のどの領域を修正すべきかを制作上の判断材料として示せる。
- テクスチャアトラス上の重なりやはみ出しが、モデル表示の破綻につながる可能性を警告として扱える。
- 品質検証は、即時に自動修正する前提ではなく、制作時に確認・調整できる情報提供として扱える。

### 検証するACの項目

- AC-MESH-004: メッシュ品質を検証可能であること
