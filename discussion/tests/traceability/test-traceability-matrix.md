## Scope Policy

- P0 covers all MVP AC IDs `AC-MVP-001` through `AC-MVP-016`.
- Active scenario coverage includes scenario files marked Current or Accepted for the Private Prototype, the Minimum Open Dynamics v1 current MVP scenario, documentation baseline scenarios, the accepted hygiene track, and `SC-SAMPLE-001` for private rights-clean fixtures.
- Optional or Future-only scenarios are not P0 gates. They are excluded from the active scenario set unless their file explicitly includes a current private fixture or hygiene boundary.
- Expected artifact paths are planned evidence destinations for later implementation and are workspace-relative.
- Oracles are internal project-defined contracts, deterministic runtime semantics, validator diagnostics, operation logs, snapshots, diffs, GUI semantic evidence, rights/provenance metadata, and demo-safe preflight reports. No external proprietary format, SDK/Core, viewer matching, physics compatibility, or existing third-party model is used as an oracle.

## Field Semantics

| Field | Meaning |
|---|---|
| Test ID | Machine-readable P0 test design ID with no spaces. |
| Fixture | Fixture ID expected to produce the evidence. Fixture IDs are planned or already named in the contract docs. |
| Operation flow | Ordered user, GUI, runtime, validator, or AI operation sequence. |
| Expected artifact | Planned workspace-relative artifact path(s) the later runner should emit. |
| Oracle | Internal basis used to decide pass, fail, or needs_review. |
| Automation | `auto`, `hybrid`, or `manual`. |
| Gate | `mvp-blocking`, `warning`, or `optional`. |
| Owner module | Primary module responsible for the test evidence. |
